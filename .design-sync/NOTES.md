# Синхронизация дизайн-системы WETOP → Claude Design

Заметки для следующего прогона `/design-sync`. Читать **до** любой работы.
Проект: `WETOP`, `projectId` в `config.json`.

## Устройство: почему конфиг такой

- **Отдельного пакета дизайн-системы нет.** Компоненты живут внутри приложения Next
  (`apps/web/src/components`), собранного `dist/` у них не бывает. Поэтому:
  - вход задан руками — `.design-sync/ds/entry.tsx`, он реэкспортирует **ровно рабочий набор**;
  - список компонентов задан `componentSrcMap` целиком (37 ключей). Автоматическое обнаружение
    здесь не работает: у корня репозитория нет `.d.ts`, а синтезированный вход из всей папки
    `components/` затянул бы `shell/account-menu.tsx` — серверный компонент с импортом server action,
    и сборка в браузер упала бы.
  - `PKG_DIR` при заданном `--entry` определяется подъёмом вверх до первого `package.json` с именем,
    то есть это **корень репозитория** (`pms-lux`). Все пути в конфиге — от корня.
- **`next/link` и `next/navigation` подменены заглушками** (`.design-sync/ds/shims/`) через
  `compilerOptions.paths` в `.design-sync/ds/tsconfig.json`. Конвертер читает эти `paths`
  (`lib/bundle.mjs`, `tsconfigPathsPlugin`). Код продукта не тронут. Без подмены девять компонентов
  падали бы с «expected app router to be mounted».
- **CSS склеивается, а не импортируется.** `cfg.cssEntry` дописывается в конец `_ds_bundle.css`, а
  `@import` в середине файла по спецификации CSS не работает. `.design-sync/ds/build-css.mjs`
  склеивает 14 файлов стойки в порядке `layout.tsx`; запускать **перед** конвертером
  (это и есть `cfg.buildCmd`). Результат `styles.generated.css` в git не едет.

## Грабли, на которых уже наступили

- **Имена ячеек превью — только латиница.** Карточка собирает список ячеек фильтром
  `/^[A-Z]/.test(k)` (в `<Name>.html`), а кириллическая «Т» ему не удовлетворяет: превью с
  экспортами `Тона`, `Размеры` компилируется без ошибок, но капча отвечает
  «preview module evaluated to no exports (window.__dsCells is empty)». Имена групп — тоже латиница:
  `category` из frontmatter проходит через `lowercase + [^a-z0-9]`, и кириллица схлопывается в пустое,
  после чего компонент остаётся в группе `general`.
- **Умолчание `guidelinesGlob` тянет `docs/*.md` от корня репозитория** — то есть `docs/deploy.md`
  (эксплуатация сервера) и `docs/history.md` (хроника объекта). Всё, что попало в guidelines,
  попадает **в каждый макет**. Задано явно: `["DESIGN.md", "design/*.md"]`. Не снимать.
- **Превью импортируют из `'@pms/web'`** — это `cfg.pkg`, конвертер подменяет его на `window.Wetop`.

## Решения, которые не надо перерешивать

- **`[FONT_MISSING] Inter` — не дефект.** `DESIGN.md` §6: системный стек
  (`-apple-system, BlinkMacSystemFont, Inter, 'Segoe UI', sans-serif`), веб-шрифт не поставляется по
  решению, а `Inter` в стеке «не подключён и на машине без него ни на что не влияет» — снимется
  вместе с ответом на Q-138. Поэтому `runtimeFontPrefixes: ["Inter"]`. Если Q-138 закроют выбором
  гарнитуры — класть woff2 через `cfg.extraFonts` и снимать эту строку.
- **Каркас приложения в дизайн-систему не грузится** (`Sidebar`, `TopNav`, `GlobalSearch`,
  `DataFreshness`, `RouteDrawer`, `RefreshButton`, `AccountMenu`): это части конкретного приложения,
  завязанные на роутер Next и меню WETOP, а макет рисует свою навигацию. Решение владельца 20.09.2026.

## Что не отрисовывается статически

- **`ActionMenu` в открытом виде.** Открытие — внутреннее состояние по щелчку, пропа «открыто» нет.
  Превью показывает кнопку «⋯» в строке списка и недоступный пункт с причиной.
- **Наведение и перетаскивание** — по построению. `Tooltip` открыт через `autoFocus` на своём
  триггере (компонент открывается и по фокусу), это настоящий путь компонента, а не подделка.

## Порядок повторной синхронизации

```sh
node .design-sync/ds/build-css.mjs
node .ds-sync/resync.mjs --config .design-sync/config.json --node-modules ./node_modules \
  --entry .design-sync/ds/entry.tsx --out ./ds-bundle --remote .design-sync/.cache/remote-sync.json
```
Перед этим — перекопировать скрипты конвертера в `.ds-sync/` (`cp -r` из каталога навыка) и
поставить его зависимости (`esbuild`, `ts-morph`, `@types/react`).

## Чем рискует следующий прогон

- **Состав дизайн-системы задан списком.** Новый компонент в `apps/web/src/components` сам сюда не
  попадёт: его надо дописать в `entry.tsx` и в `componentSrcMap`, иначе он тихо отсутствует.
  Та же обратная беда: удалённый в продукте компонент здесь останется до правки конфига.
- **Список CSS в `build-css.mjs` задан вручную.** Новый файл стилей экрана (`apps/web/src/app/**.css`)
  в дизайн-систему сам не попадёт — дописывать. Проверено 20.09.2026: ни `@import`, ни `url()` в этих
  файлах нет, поэтому склейка безопасна; если появятся — склейка их сломает.
- **Документы компонентов написаны вручную** (`.design-sync/ds/docs/*.md`) и могут разойтись с кодом:
  при изменении пропа документ не обновляется сам. Сверять с `<Name>.d.ts` из свежей сборки.
- **Сборка опирается на глобальный `React`.** `tsconfig` приложения ставит `jsx: "preserve"`, esbuild
  откатывается на классический трансформ и эмитит `React.createElement` **без импорта** — работает
  потому, что среда кладёт `window.React`. Если однажды превью массово упадут с «React is not
  defined», причина здесь.

## Итог первой синхронизации (20.09.2026)

Загружено 198 файлов: бандл 76 КБ (37 компонентов), стили 186 КБ, 37 превью, 37 документов,
правила из `DESIGN.md` и `design/*.md`, заголовок соглашений в README. Проверка отрисовки — 37 из 37
чисто; `bad`, `thin`, «одинаковые варианты» и запасные карточки — ноль; все ячейки оценены `good`.

**Что нашла проверка по листам, а не тесты:** документ `Row.md` утверждал, будто `align="end"`
прижимает действие вправо. В CSS это `align-items: end` (по нижнему краю), а раздвигает
`className="row--between"`; в коде WETOP `align="end"` не используется вообще. Исправлены документ,
`PanelTitle.md` и три превью. Урок на будущее: сверять каждое утверждение документа с CSS, а не с
предположением об имени модификатора.

**Правки раскладки карточек** (`cfg.overrides`): `Select` и `Tooltip` — `column` (ячейки шире колонки
сетки), `ConfirmDialog`, `Overlay`, `ToastRegion` — `single` (это слои, они выходят за клетку
по построению). Это предписания самого конвертера из `[GRID_OVERFLOW]`, не выдумка.

**Подсказка открывается фокусом.** `Tooltip` в превью раскрыт через `autoFocus` на своём триггере —
компонент открывается и по фокусу, так что это настоящий путь, а не подделка разметки. Подсказке
нужен запас слева (~150 px): она центрируется над триггером и иначе режется краем ячейки.
