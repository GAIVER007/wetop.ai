# PMS MVP — инструкции для AI-агента

Этот файл загружается автоматически в любой сессии, открытой в этой папке.
Он не заменяет [AGENTS.md](AGENTS.md) — он говорит, в каком порядке читать и что запрещено.

Здесь только правила и ссылки, до 200 строк (ADR-137, 02.10.2026): файл читает каждая сессия. Хроника дней в
`docs/history.md`, решения в `DECISIONS.md`, вопросы в `QUESTIONS.md`.

## 2. Хроника и статус

- Записей дней здесь нет (ADR-137). Запись о сделанной работе: абзац `**дд.мм.2026, тема (сессия, ветка, план или
  отчёт).**` в конец `docs/history.md`, раздел «Записи дней с 02.10.2026».
- Решения живут в `DECISIONS.md`, открытые вопросы в `QUESTIONS.md`; хроника не заменяет ни то, ни другое.
- Что выложено: ветка `release` (`docs/deploy.md` §1д). Что доказано тестами: `npm run test:status`.

---

## 3. Что запрещено делать самостоятельно

Из AGENTS.md §15, повторено здесь, потому что нарушается чаще всего:

- менять модель данных (сначала правка `DATA_MODEL.md`, потом код);
- придумывать бизнес-правила бронирования;
- выбирать fiscal provider или способ авторизации eQonaq;
- впервые проектировать интеграцию с Channex;
- менять финансовую логику;
- делать production migration;
- отправлять production ARI, eQonaq submissions, фискальные чеки;
- изменять что-либо в архивный источник production, OTA production.

Если развилка влияет на данные, деньги, бронирование, availability, тариф,
статус гостя, фискализацию, eQonaq или channel manager — **записать вопрос
в `QUESTIONS.md` и перейти к задаче, которая от него не зависит.**

## 4. Что делать можно без отдельного разрешения

Импорт CSV, UI по утверждённой модели, тесты, рефакторинг, валидация ввода,
сообщения об ошибках, доступность, логирование, документация, скрипты сверки,
фикстуры, производительность.

## 5. Жёсткие технические правила

| Правило | Почему |
|---|---|
| Деньги — **integer minor units** (тиын). Никаких float | ADR-008. Расхождение в копейках ломает сверку |
| Stay dates — `DATE` в timezone объекта (Asia/Almaty). События — UTC `timestamptz` | AGENTS.md §13 |
| Каждое внешнее событие: external ID, received_at, статус, retry, audit trail | ADR-007. Дубль или потеря OTA-брони недопустимы |
| Channex SDK и vendor ID — только внутри `packages/integrations` | ADR-004. Домен не знает про Channex |
| Ничего не выводить из номера единицы | Нумерация в архивный источник не сплошная: 1–4 номера, 5–40 койки, 41–48 номера, 49–84 койки, 85–88 номера |
| Integration code — только по документации из `/docs` | AGENTS.md §5. Нет документации → STOP → вопрос |
| Red before green | AGENTS.md §6. Тест, который не был красным, не доказательство |
| В тестах только вымышленные гости | ADR-010. Реальные ФИО, паспорта, телефоны запрещены |
| Секреты только через env / secret storage | `SECURITY.md`. `.env` в gitignore |
| Задача не закрывается словом "done" | Нужен тест, скриншот, отчёт сверки или ответ из sandbox |
| `.env`, `secrets/`, реальные выгрузки закрыты от чтения агентом (`.claude/settings.json`) | `SECURITY.md` §3. Не обходить через Bash или скрипты. Значения ключей вписывает только владелец |
| Коммит — только своих файлов, явным списком. `git add -A` и `git commit -a` запрещены | В одном дереве параллельно работают другие сессии: их правки уезжают в чужой коммит, история врёт |
| Перед каждым `git commit` — сверить `git diff --cached --name-only` со своим списком. `git add <мои файлы>` не защищает: `commit` берёт ВЕСЬ индекс | 16.09.2026: пока шла работа, соседняя сессия положила в общий индекс миграцию `20260915000013_accounts`, `schema.prisma` и свой тест — и они уехали в чужой коммит `e5e2877` с сообщением про шахматку. Историю не переписывали: ветка общая, `rebase` оборвал бы работу той сессии |
| Перед большой правкой — коммит текущего состояния. Испорченный файл возвращать из истории (`git restore --source=<коммит> -- <файл>`), не переписывать по памяти | Откат возвращает только то, что было закоммичено |
| Незавершённое слияние или rebase, маркеры `<<<<<<<` / `>>>>>>>` в `CLAUDE.md` или `AGENTS.md` — разобрать до любой другой работы | Файл правил грузится как инструкция, обе версии станут правилом. Незавершённое слияние отклоняет каждое следующее, а в скрипте или хуке ошибка теряется |
| Удалённый репозиторий — только приватный. `.claude/settings.local.json` в git не едет | В истории финансы объекта и рабочие контакты сотрудников (`SECURITY.md` §4). Уехавший ключ меняется сразу: история помнит и после удаления |
| Тесты — только через `npm run test:record -- <набор>`; до прогона — `npm run test:status`. Лог и строку журнала коммитить вместе с правкой | Журнал с логами едет в репозиторий: доказанное на том же коде не гоняется повторно, упавшее разбирается по логу (`TESTING.md`) |
| Cowork-сессия на Mac коммитит из VM только после разрешения владельца на удаление в папке проекта и с `git -c core.fileMode=false -c core.createObject=rename`. Даже `git status` из VM — только как `git --no-optional-locks status` | Без разрешения git в VM не может удалить `.git/HEAD.lock` после коммита и запирает репозиторий и владельцу (19.09 и 22.09.2026); 23.09.2026 так же остался `.git/index.lock` после простого `git status`; `tmp_obj_*` копятся сотнями. `core.fileMode=false` — иначе VM видит все скрипты «изменёнными» |
| Путь к папке проекта вшит в plist launchd абсолютно. Переименовали или перенесли папку — `scripts/ops/repo-sync.sh --relink`; перед сменой на Mac — `scripts/ops/repo-sync.sh` без флагов | 16.09.2026: папка «Pms Lux» стала «WETOP», launchd не может сделать chdir и молча не поднимает службы; 15.09 та же папка отставала от `main` на 62 коммита, и API работал на старом коде |
| Сторонние навыки дизайна (`impeccable`, `hallmark`, `design-taste-frontend`, `redesign-existing-projects`, `ui-ux-pro-max`, `frontend-design`) — советники, а не правила: при расхождении с `DESIGN.md` прав `DESIGN.md`. Без решения владельца не создавать `PRODUCT.md`, не включать хук impeccable (`/impeccable hooks on`) и не переписывать `DESIGN.md` командами навыков | Навыки стоят глобально на Mac владельца с 23.09.2026 и решений проекта не знают: impeccable считает ошибкой градиентный текст, taste — стекло «где попало», а стекло и градиент главной кнопки стойки (ADR-069) и металлический знак сайта (ADR-070) выбраны владельцем. Находка навыка против ADR — спор с решением, а не дефект |
| **Длинное тире (символ U+2014) не используем нигде в новых текстах**: ответы и сообщения агента, документы, комментарии, коммиты, тексты интерфейса, письма, ответы бота. Вместо него запятая, двоеточие, скобки, точка или перестроенная фраза. Дефис в словах и короткое тире в диапазонах можно | Распоряжение владельца 01.10.2026: такое тире выдаёт текст ИИ. Старые вхождения (около 30 000 в 2957 файлах, в том числе в тестах, сверяющих тексты) массово не переписываются; правишь строку с этим тире, убери его в ней. Чистить без риска: документы и комментарии |

## 6. Контрольные числа объекта

Держать в голове при любой работе с инвентарём:

```
88 единиц продажи = 16 отдельных номеров + 72 койко-места
92 гостя максимум
20 физических комнат = 12 одноместных + 4 двухместных + 4 dorm × 18 (со слов владельца; Q-095 отложен — до списка PhysicalRoom импортируется 1:1)
5 категорий, 8 каналов OTA, 6 тарифов (3 без продаж)
Загрузка августа 2026: 80,8% (2203 из 2728; аудит считал 79,7% без гостей с заездом до июля)   |   1044 заезда   |   15 688 018 ₸
На 07.09.2026: занято 78, свободно 10, блокировок 0
209 будущих проживаний на 4 743 535 ₸, из них 96,5% не оплачено
```

Расхождение при сверке с архивный источник допускается **нулевое**. Не 99,5%. Ноль.
