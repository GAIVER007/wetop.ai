**15.09.2026 — webhook действительно встал на постоянный адрес; найден дефект «рапорт без проверки» (`reports/webhook-check-2026-09-15.md`).** Перерегистрация webhook, записанная выше как сделанная, на деле не применилась: в Channex оставался адрес мёртвого быстрого туннеля, сторож держал класс А `webhook.unreachable`, брони доходили только опросом ленты. **16.09.2026 — разбор «всё тормозит» и «выбираю период, и ничего не открывается» (замечания владельца).**
Нашлось три разных причины, две уже закрыты кодом.
**(1) Лишние рейсы в базу.** `property.findFirst({ where: { name } })` стоял в девяти репозиториях и
выполнялся при каждом обращении: дашборд платил его восемь раз за один запрос, шахматка трижды. Объект
один и на ходу не переименовывается, поэтому id теперь держится в памяти процесса
(`apps/api/src/database/property-ref.ts`, ключ — имя объекта плюс схема, чтобы прогон в `pms_test` не
получил рабочий id; отказ не запоминается). **(2) Главная собирала показатели по очереди:** пять выборок
периода одна за другой, и так дважды (текущий отрезок и предыдущий) — десять рейсов подряд. Выборки
независимы: внутри периода идут одновременно, периоды по-прежнему по очереди (пул API — 5 соединений).
Итого дашборд за месяц: было ~20 рейсов подряд, стало ~6. Тест честный — поддельный репозиторий не
отвечает, пока не соберутся все четыре запроса; на прежнем коде тест виснет (`dashboard.service.test.ts`).
**(3) Экран не открывался вовсе, когда показатели не пришли.** `dashboardApi.period` шла без `catch` в
общем `Promise.all`, и отказ любого из четырёх вызовов ронял всю страницу — ни заголовка, ни выбора
периода. Теперь «Главная» открывается сразу: заголовок и период не ждут данных, показатели и стойка
приходят своими кусками (`Suspense`, `today/dashboard-section.tsx`, `today/desk-section.tsx`), а отказ
называется словами (`dashboard-error`, `desk-error`), не выдавая нули за данные. Доказано в браузере:
`tests/ui/dashboard-resilience.spec.ts` (красный до правки — экран не открывался), проверка «сбой API не
выдаётся за пустую базу» в `workspace.spec.ts` приведена к новому поведению с тем же правилом.
**Счётчик запросов на экран:** фикстура считает обращения по путям (`GET /__test/hits`), сторож
`tests/ui/requests.spec.ts` держит правило «путь с данными — один запрос на показ»; замер 16.09: на экран
уходит 4–6 вызовов, дублей нет, то есть лишнее было не в стойке, а в API. **Что осталось и решается не
кодом:** база в Сингапуре, а стойка в Алматы — каждый рейс это десятки миллисекунд, и на пул из 5
соединений накладывается очередь; плюс сама машина (8 ГБ памяти при свопе 16 ГБ держит API, стойку,
туннель и синхронизацию разом). Чтобы не гадать, замерщик: `npm run slow` (`scripts/ops/cli-slow.ts`) —
меряет `SELECT 1`, вызовы API по экранам с числом запросов в базу на вызов, сами экраны и машину, и
печатает, где уходит время (`scripts/ops/slow-report.ts`, 8 тестов). **Запустить на машине стойки и
прислать вывод** — по нему видно, что дороже: дорога до базы, сами запросы или своп.

## 5. Жёсткие технические правила

| Правило | Почему |
|---|---|
| Деньги — **integer minor units** (тиын). Никаких float | ADR-008. Расхождение в копейках ломает сверку |
| Stay dates — `DATE` в timezone объекта (Asia/Almaty). События — UTC `timestamptz` | AGENTS.md §13 |
| Каждое внешнее событие: external ID, received_at, статус, retry, audit trail | ADR-007. Дубль или потеря OTA-брони недопустимы |
| Channex SDK и vendor ID — только внутри `packages/integrations` | ADR-004. Домен не знает про Channex |
| Ничего не выводить из номера единицы | Нумерация в Exely не сплошная: 1–4 номера, 5–40 койки, 41–48 номера, 49–84 койки, 85–88 номера |
| Integration code — только по документации из `/docs` | AGENTS.md §5. Нет документации → STOP → вопрос |
| Red before green | AGENTS.md §6. Тест, который не был красным, не доказательство |
| В тестах только вымышленные гости | ADR-010. Реальные ФИО, паспорта, телефоны запрещены |
| Секреты только через env / secret storage | `SECURITY.md`. `.env` в gitignore |
| Задача не закрывается словом "done" | Нужен тест, скриншот, отчёт сверки или ответ из sandbox |
| `.env`, `secrets/`, реальные выгрузки закрыты от чтения агентом (`.claude/settings.json`) | `SECURITY.md` §3. Не обходить через Bash или скрипты. Значения ключей вписывает только владелец |
| Коммит — только своих файлов, явным списком. `git add -A` и `git commit -a` запрещены | В одном дереве параллельно работают другие сессии: их правки уезжают в чужой коммит, история врёт |
| Перед каждым `git commit` — сверить `git diff --cached --name-only` со своим списком. `git add <мои файлы>` не защищает: `commit` берёт ВЕСЬ индекс | 16.09.2026: пока шла работа, соседняя сессия положила в общий индекс миграцию `20260915000013_accounts`, `schema.prisma` и свой тест — и они уехали в чужой коммит `e5e2877` с сообщением про шахматку. Историю не переписывали: ветка общая, `rebase` оборвал бы работу той сессии |
| Перед большой правкой — коммит текущего состояния. Испорченный файл возвращать из истории (`git restore --source=<коммит> -- <файл>`), не переписывать по памяти | Откат возвращает только то, что было закоммичено |
| Незавершённое слияние или rebase, маркеры `<<<<<<<` / `>>>>>>>` в `CLAUDE.md` или `AGENTS.md` — разобрать до любой другой работы | Файл правил грузится как инструкция, обе версии станут правилом. Незавершённое слияние отклоняет каждое следующее, а в скрипте или хуке ошибка теряется |
| Удалённый репозиторий — только приватный. `.claude/settings.local.json` в git не едет | В истории финансы объекта и рабочие контакты сотрудников (`SECURITY.md` §4). Уехавший ключ меняется сразу: история помнит и после удаления |
