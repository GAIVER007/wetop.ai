# DESIGN.md — правила интерфейса стойки WETOP

**Статус:** принят как свод действующего дизайна 14.09.2026 (ADR-046, план `plans/design-system-2026-09-14.md`);
дополнен по отчёту проверки на дыры `reports/design-system-gaps-2026-09-14.md` (шаг 3) и странице
`/design-system` (шаг 4).

Перед любой задачей по интерфейсу прочитай этот файл. Сначала ищи готовый компонент на странице
`/design-system` (только при разработке). Новый компонент — только если такого нет, и сначала допиши его сюда.

Источник правил — документ ментора «План продукта и дизайн-система» от 14.09.2026, части 2–7. Значения — из
действующего интерфейса WETOP (ADR-029, ADR-035…039). На шаге 2 они не менялись (скриншоты до и после
генерации совпали, `design/README.md`); на шаге 4 изменено одно значение — `--danger-soft` в светлой теме
(`#fff0f2` → `#fff2f4`), чтобы красная кнопка и плашка проходили 4,5:1. Где действующее значение ещё нарушает
правило, это записано в правиле с шагом, на котором чинится.

Токены живут в [`design/tokens.json`](design/tokens.json) (W3C DTCG 2025.10, спецификация сохранена в
`design/docs/dtcg-2025.10/`). CSS-переменные `apps/web/src/app/tokens.css` **только генерируются**:
`npm run design:build`; ручная правка валит тест `scripts/design/src/tokens-css.test.ts`. Контраст считается
в `design/contrast.md` тем же скриптом.

У каждого правила есть строка «почему». Правило меняется сначала здесь, потом в коде, потом в Claude Design (§17).

## 1. Принципы стойки

1. **Статус брони читается за секунду без наведения.** На клетке шахматки и в списках — цвет плюс слово или
   значок; подсказка только дополняет. Почему: администратор смотрит на шахматку через плечо гостя.
2. **Частое действие — в одно касание и с клавиатуры.** Заселить, принять оплату, продлить, переселить —
   одной кнопкой на карточке; перетаскивание дублируется пунктом «Переселить» в меню действий (компонент есть с
   шага 4, на шахматку встаёт на шаге 7.1). Почему: смена делает это десятки раз в день, а мышь не всегда под
   рукой (Q-133).
3. **Плотно, но читаемо.** Текст не мельче 12 px, цель нажатия не меньше 24×24 px, на телефоне — 44 px.
   Почему: 88 строк шахматки должны помещаться на экран, но не ценой ошибок нажатия.
4. **Смысл не держится только на цвете или наведении.** Всё важное — словом, значком или числом, видимым сразу.
   Почему: дальтонизм, тёмная тема, планшет без наведения.
5. **Шахматка остаётся на экране.** Карточка брони открывается панелью сбоку; окно поверх — только для
   необратимого: переселение в другую категорию и отмена со штрафом. Почему: контекст дня нельзя терять.

## 2. Токены

Три уровня, как требует документ: **примитив → семантика → компонент**. Почему три: примитив меняется в одном
месте, семантика даёт имени смысл («тревога», а не «красный-600»), компонент собирается из семантики и не знает
про оттенки — так тёмная тема получается из тех же классов.

| Уровень | Где | Пример | В CSS |
|---|---|---|---|
| Примитив | `sets.primitives` → группа `palette` | `palette.blue.700 = #085fba` | не выходит (`$extensions["ai.wetop"].css = false`) |
| Семантика | `sets.semantic` (без темы), `sets.light`, `sets.dark`, контекст `contrast` | `color.primary = {palette.blue.700}` | `--primary` — имя листового токена |
| Компонент | классы `.btn`, `.badge`, `.stat`, `.toast` … в `globals.css`, `premium.css`, `workspace.css`, `components.css` | `.btn--danger { background: var(--danger-soft) }` | через семантические переменные |

Правила и почему:
- Имя CSS-переменной = листовое имя токена; среди токенов, выходящих в CSS, имена уникальны (тест
  `scales.test.ts`; у примитивов ступени `50`, `700` повторяются между оттенками — в CSS они не выходят).
  Почему: одно имя в JSON, CSS и Claude Design — нечего сопоставлять руками.
- Компонент не берёт примитив напрямую и не пишет цвет литералом; тест `css-vars.test.ts` следит, чтобы каждая
  `var(--…)` была токеном или локальной переменной компонента (`--dot` точки бейджа, `--min` сетки, ширины
  колонок шахматки — они объявлены в том же классе и ссылаются на семантику). Почему: литерал в одной теме
  невидим в другой.
- Псевдоним на семантику остаётся `var(--…)` в CSS (`--info: var(--primary)`), на примитив — значением.
  Почему: тёмная тема меняет `--primary`, и `--info` следует за ним без второй записи.
- Темы — модификатор `theme` резолвера: `light` (по умолчанию), `dark` (светлая плюс отличия), `contrast`
  (светлая плюс границы и кольцо фокуса, проходящие 3:1; переключателя в интерфейсе нет — это цель для
  границ шага 4). Печать — модификатор `media`. Почему один файл-резолвер, а не набор `.tokens.json`: три темы
  и печать при одной семантике; имя `design/tokens.json` закреплено в ADR-046; спецификация советует
  расширение `.resolver.json` (SHOULD, не MUST) — отступление записано здесь.
- Устаревшее помечается `$deprecated` с причиной, а не удаляется молча: `--purple`, `--purple-soft`, `--space-3`,
  `--space-5`, `--topbar-h`. Почему: код, который на них ссылается, ловит тест, а не тихая пропажа.
- Уровень «компонент» намеренно не токенизирован: классы компонентов живут в CSS и меняются по экранам на
  шаге 7; токены компонентов удвоили бы файл без второго потребителя. Claude Design получает код компонентов
  и снимки `/design-system`, а не токены компонентов.
- Состояния — свои токены (группа `state`, §8): `--hover-bg`, `--selected-bg`, `--selected-fg`, `--disabled-fg`,
  `--disabled-bg`, `--error-border`, `--error-ring`, `--ring`, `--pressed-shift`. Почему: восемь состояний
  описываются одними и теми же именами у всех компонентов.

Палитра (значения действующие):

| Имя в токенах | Светлая | Тёмная | Смысл |
|---|---|---|---|
| `blue` | `#085fba` | `#48a5ff` | акцент, ссылки, «подтверждена» |
| `green` (в т. ч. `green.500` — второй ряд графиков, в документе «teal») | `#06735e` | `#38d2ae` | норма: оплачено, заселён, обработано |
| `amber` | `#94600b` | `#f6ba52` | внимание: не подтверждена, требует действия |
| `red` | `#cc384e` | `#ff7a87` | тревога: ошибка, долг, отмена, блокировка |
| `gray` 0…10 | `#ffffff` … `#101827` | — | нейтральная шкала светлой темы |
| `navy` 0…15 | — | `#f7f9fc` … `#060b14` | нейтральная шкала тёмной темы |

Нарушения, закрываемые на шагах 4 и 7: нейтральная шкала из 11 и 16 ступеней вместо семи; почти чёрный
подкрашен (`#101827`, `#060b14`); `purple` без смысла.

## 3. Отступы

Шкала: **4, 8, 16, 24, 32, 40, 48, 64** (`--space-1 … --space-16`). Между блоками — только отступ снизу первому,
не сверху второму. Почему: одна шкала держит ритм, а двусторонние отступы складываются непредсказуемо.

Как сейчас: 749 значений отступов в CSS, 458 вне шкалы (12 px — 100 раз, 10 px — 71, 20 px — 68). `--space-3`
и `--space-5` помечены устаревшими. Перевод — по экрану со сравнением скриншотов
(`scripts/design/src/compare-shots.ts`), не заменой по всему CSS (план §9). Новые компоненты шага 4
(`components.css`) написаны только шкалой.

## 4. Раскладка и плотность

- Боковое меню 232 px (`--sidebar-w`), сворачивается; шапка 72 px (`--header-h`); контент на всю ширину.
  Почему 232: помещается самое длинное имя раздела «Управление отелем» со значком в одну строку.
- Высота кнопки и поля 38 px (`--control-h`); на телефоне 44 px — правило `workspace.css:665` перекрыто
  `premium.css:77,88`, чинится на шаге 7.4. Почему 38: две строки таблицы по 46 px вмещают поле с подписью.
- Шахматка: колонка ячеек и шапка дат закреплены; строка категории сворачивается и показывает свободные места
  по ночам; ширина дня — по виду: «Неделя» 120 px, «14 дней» 84 px, «Месяц» — по ширине окна
  (`--week-unit-width`, `--month-unit-width`, локальные переменные `premium.css:407–441`, войдут в токены на
  шаге 7.1 вместе с высотой строки 46 px). Почему: 88 строк и 7–31 колонка должны читаться без горизонтальной
  прокрутки на 1280 px.
- Карточка брони — панель сбоку 480 px (`app/@drawer`), четыре вкладки: Обзор, Счета, Действия, История.
  Почему 480: две колонки фактов и таблица счёта помещаются, а шахматка слева остаётся видна.

## 5. Радиусы и тени

| Уровень | Токен | Значение | Где |
|---|---|---|---|
| Контрол | `--radius-sm` | 8 px | кнопка, чип, клетка брони, пункт меню |
| Поле | `--radius-control` | 10 px | поле ввода, select, уведомление |
| Карточка, панель | `--radius` | 16 px | плитка, таблица в панели, панель сбоку |
| Лист, окно | `--radius-lg` | 20 px | окно подтверждения |
| Круг | `50%` | — | аватар, точка статуса; единственный допустимый литерал радиуса |

Почему по уровню: радиус говорит, «насколько это отдельный предмет» — контрол внутри карточки, карточка
внутри страницы, окно поверх всего; четыре ступени различимы глазом, 23 — нет.

Тень — **только у слоя над страницей**: `--shadow-floating` у панели сбоку, окна, меню действий, уведомления.
Плоские блоки на странице — граница, без тени. Почему: тень означает «это поверх», и если она у всего, знак
пропадает.

Как сейчас: 23 разных радиуса и `--shadow` у плиток, карточек, таблиц и шахматки (`premium.css:93…342`).
Сводится к уровням на шаге 7.

## 6. Шрифт

Действующий стек: `-apple-system, BlinkMacSystemFont, 'Inter', 'Segoe UI', sans-serif` (`--font`). Это разные
шрифты на macOS и Windows, Inter указан, но не подключён. Заголовки тем же шрифтом (`--font-head`); почему один
шрифт: второй шрифт — второй набор метрик и файлов ради двух заголовков на экран.
Моноширинный `--mono` — только для кода, ключей и журналов, не для подписей и номеров броней. Почему: в
моноширинном номер брони на треть шире и читается как код, а не как имя; табличные цифры дают ровные колонки
без него.

**Проверка кандидатов** — `npm run design:fonts -- <файлы>` (`scripts/design/src/check-fonts.ts`): казахские
буквы ә ғ қ ң ө ұ ү һ і в обоих регистрах, латиница, кириллица, ширина цифр, возможность `tnum`, снимок листа
«1 l I 0 O» в 12 и 13 px. Отчёт 14.09.2026 — `design/reference/fonts/report.md`:

| Кандидат | Казахские буквы | Табличные цифры | Итог |
|---|---|---|---|
| IBM Plex Sans | все 18 | по умолчанию | **подходит**; записан в ADR-027, в коде отсутствует |
| Inter | все 18 | через `tnum` | подходит при `font-variant-numeric: tabular-nums` |
| PT Sans | все 18 | по умолчанию | подходит, но узкий: 0,545 em на цифру |
| Golos Text | все 18 | через `tnum` | подходит |
| Manrope | **нет ә ғ қ ң ұ** | через `tnum` | **не подходит** для казахских фамилий (был в направлении 12.09) |
| Действующий системный стек | на macOS SF и на Windows Segoe UI файлами не доступны; проверен подставной DejaVu Sans среды проверки: все 18, цифры одной ширины | — | что стоит у смены — Q-133; до ответа стек считается непроверенным |

Снимки листа «1 l I 0 O» (`design/reference/fonts/*-12px.png`, `*-13px.png`, просмотрены 14.09.2026): у IBM Plex
Sans и PT Sans единица, строчная l и заглавная I различимы в 12 px за счёт засечки у I и хвоста у l; у Inter,
Manrope и Golos Text заглавная I и строчная l в 12–13 px совпадают по форме — номера броней вида «SHOWTN» и
коды ячеек читались бы хуже. Проверены файлы одного начертания (переменные шрифты — экземпляр по умолчанию);
перед сменой шрифта прогнать `design:fonts` по всем начертаниям, идущим в сборку (400, 500, 600).

**Решение шага 2:** шрифт не меняется (значения токенов заморожены до совпадения скриншотов). Кандидат по
умолчанию для смены шрифта — **IBM Plex Sans**: полное покрытие казахских букв, цифры одной ширины без
настроек, записан в ADR-027 как выбранный. Ставится через `next/font/local` из файла в сборке, стойка не ходит
в интернет. Смена шрифта — отдельная правка с пересборкой эталонных снимков (план §9). Если по Q-133 стойка на
Windows, системный стек даст Segoe UI — тогда IBM Plex нужен тем более, чтобы экран был одинаковым на всех
машинах.

Шкала размеров: **12, 13, 14, 16, 18, 22, 28** (`--fs-12 … --fs-28`), высота строки `--lh-tight 1.25` для
заголовков и чисел, `--lh-base 1.45` для текста. Ничего мельче 12 px. Почему: на 13 px строки таблицы
вмещают 88 ячеек, ниже 12 px «1 l I» неразличимы.

Как сейчас: 26 размеров и 3 `clamp`, 10 px — 11 раз, 11 px — 18 раз. Сводится к шкале на шаге 7.

## 7. Иконки

Один набор — `lucide-react` через `components/icon.tsx`, 20 px и 16 px (в строках, бейджах, меню), толщина
линии 1,7. У кнопки-значка обязателен `aria-label`. Почему один набор: два набора — две толщины линии рядом.

ассистентом и стрелками (§15).

## 8. Компоненты — размеры, токены, восемь состояний

Каждый интерактивный компонент имеет восемь состояний: **обычное, наведение, нажатие, фокус, отключено,
загрузка, ошибка, выбрано** — все показаны на `/design-system`, тест `tests/ui/design-system.spec.ts`
проверяет, что у каждого интерактивного раздела есть все восемь ячеек. Где состояния нет, на странице
написано почему (например, у переключателя вида нет «отключено»: все три вида всегда доступны).

Общие правила состояний и их токены (группа `state` в `tokens.json`):

| Состояние | Как выглядит | Токен | Почему |
|---|---|---|---|
| Наведение | подложка `--hover-bg` (строка, пункт меню, второстепенная кнопка); главная кнопка — `--primary-hover` | `--hover-bg`, `--primary-hover` | видно, куда попадёт клик, без смены цвета текста |
| Нажатие | сдвиг на `--pressed-shift` вниз; клетка при перетаскивании — пунктирная рамка `--primary` | `--pressed-shift` | ответ на действие за 120 мс, без анимации |
| Фокус | кольцо `--ring` (3 px `--ring-color`) или `outline` 2 px `--primary` с отступом 3 px; никогда `outline: none` без замены | `--ring`, `--ring-color` | клавиатура должна видеть, где она |
| Отключено | текст `--disabled-fg`, поле на `--disabled-bg`, курсор not-allowed; не прозрачность | `--disabled-fg`, `--disabled-bg` | прозрачность роняет контраст ниже нормы (axe на `/design-system`) |
| Загрузка | текст на кнопке («Принимаю…»), `aria-busy`, скелетон для блока; без крутилок | — | слово говорит, что происходит; крутилка — нет |
| Ошибка | поле: граница `--error-border`, кольцо `--error-ring`, `aria-invalid` и текст ошибки рядом; блок: `role="alert"` | `--error-border`, `--error-ring`, `--danger-soft` | ошибка читается словом (§1 п. 4) |

## 9. Статусы

Статус всегда **цвет + слово или значок** (§7). У цвета один смысл на всех экранах: синий — подтверждена и
акцент, зелёный — норма, янтарный — внимание, красный — тревога, серый — прошло. Почему: администратор
запоминает пять смыслов, а не тридцать оттенков; в тёмной теме и на планшете слово остаётся, когда цвет
меняется. Цвет «успеха» не красит выходные и счётчики (сейчас красит: `workspace.css:1108`,
`today/desk.css:155,171` — шаг 7.1).

Сопоставление с моделью данных (`DATA_MODEL.md` §2, §4; развилки — план §4):

| Статус на экране | В модели | Токен, значок | Слово |
|---|---|---|---|

## 10. Контраст

Нормы WCAG AA: текст на фоне **4,5:1**, граница и кольцо фокуса на фоне **3:1**, в обеих темах. Почему AA, а не
AAA (7:1): AAA не выполнит ни один из кандидатов палитры для второстепенного текста без потери иерархии;
AA — норма документа. Таблица — `design/contrast.md`, считается скриптом для светлой, тёмной и контрастной тем
по 39 парам: текст на всех фонах, где он лежит (`--surface`, `--bg`, `--surface-muted`, `--surface-elevated`,
`--row-hover`, `--warning-bg`, `--sidebar`, `--glass`, заливки статусов, подложки), цветной текст на своей
подложке, границы и кольца. Тест `scales.test.ts` не пропускает пару без нормы, кроме записанных исключений с
причиной и сроком, и валит протухшее исключение.

Исключения на 14.09.2026 (чинятся на шаге 7 сменой значений границ и кольца — цель записана контрастной темой):

| Пара | Светлая | Тёмная | Норма |
|---|---|---|---|
| `--border` на `--surface` | 1,21 | 1,26 | 3 |
| `--border-input` на `--surface` | 1,29 | 1,65 | 3 |
| `--ring-color` на `--surface` | 1,11 | 1,29 | 3 |

Закрыто на шаге 4: `--danger` на `--danger-soft` (было 4,48) — `--danger-soft` светлой темы `#fff2f4`, 4,54.
Контрастная тема проходит все пары без исключений.

## 11. Цели нажатия

Не меньше **24×24 px** на компьютере, **44 px** на телефоне и планшете. Клетка шахматки в виде «Неделя»
120×32 px, в «Месяце» — по ширине окна, но не меньше 24 px. Кнопки-значки 34×34 px, кнопка закрытия
уведомления 24×24. Почему: правило документа и ошибки нажатия на планшете; какие устройства у смены — Q-133.

## 12. Клавиатура

Обязательные: `Tab` по всем действиям, `Escape` закрывает панель, окно, меню и подсказку с возвратом фокуса
(фокус внутри панели и окна заперт нативным `<dialog>`; панель с несохранённой формой закрывается без вопроса —
ввод сохраняется в форме и восстанавливается при повторном открытии, ADR-036, ADR-040),
`Enter` отправляет форму и подтверждает окно, стрелки переключают вкладки карточки и пункты меню действий,
`⌘K` / `Ctrl+K` — быстрый поиск. Почему: без этого стойка не работает с телефоном у уха (§1 п. 2).

Сетка шахматки: клетки броней — в порядке `Tab` (ссылки), свободные клетки из обхода исключены (их до 2 728,
и они забили бы навигацию; то же действие есть кнопкой «Новая бронь»). Переселение с клавиатуры — пункт
«Переселить» в меню действий карточки (шаг 7.1), а не перетаскивание. Стрелки по клеткам сетки не вводятся до
ответа администраторов — Q-133, опросник блок 10. Сочетания для действий стойки (новая бронь, заселить) — тоже.

## 13. Анимация и слои

Анимация только в ответ на действие: `--dur-fast` 120 мс для наведения и нажатия, `--dur-base` 180 мс для
панели, окна и раскрытия; кривая `--ease-out` (cubic-bezier 0, 0, 0.58, 1); готовый переход `--ease` = 180 мс
с той же кривой — так его берёт существующий CSS (`transition: background var(--ease)`). При
`prefers-reduced-motion` — 0 (обработано). Почему 120 и 180: короче — не видно, дольше — тормозит стойку;
две длительности, а не пять, чтобы движение было одинаковым везде. Крутилок и бесконечных анимаций нет,
кроме скелетона загрузки.

Слои: `--z-base` 0 → `--z-raised` 10 (закреплённые колонки) → `--z-sticky` 20 (шапка, меню) → `--z-dropdown` 30
(меню действий, подсказка) → `--z-drawer` 40 → `--z-modal` 50 → `--z-toast` 60. Почему шаг 10: место для
локального `+1`, и порядок читается по числу. Литералы 1…100 в CSS переводятся на шаге 7.

## 16. Что берём из Exely и чего не берём

Берём: паритет смыслов — «Без ячейки» как «Без номера», виды шахматки по периодам, карточка брони со счетами
на каждое проживание, статусы уборки из справочника. Не берём: экран в экран (PLAN.md «Чего не делаем»),

Скриншоты Exely с закрашенными фамилиями — только для промптов макетов, `design/reference/exely/`, в git и
Claude Design не попадают (Д7).

## 17. Как меняются правила

1. Правило меняется здесь, с «почему»; значение — в `design/tokens.json`.
2. `npm run design:build` → `tokens.css` и `contrast.md`; `npm run test:record -- unit scripts/design/src`.
3. Скриншоты до и после: `tests/ui/design-reference.spec.ts` → `scripts/design/src/compare-shots.ts`; отличия
   должны быть только там, где правило изменилось (пример шага 4: `--danger-soft` — изменился только экран
   «Каналы продаж» с красной плашкой).
4. Страница `/design-system`: новый или изменённый компонент, `npm run test:record -- e2e --config
   tests/ui/playwright.config.ts tests/ui/design-system.spec.ts --update-snapshots`, эталон в
   `design/reference/kit`.
5. Затем Claude Design (шаг 5). Правка через Remix в Claude Design переносится сюда в тот же день.
6. После первой живой смены — только по замечаниям администраторов (ADR-027, ADR-046).
