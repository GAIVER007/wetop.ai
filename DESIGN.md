# DESIGN.md — правила интерфейса стойки WETOP

**Статус:** принят как свод действующего дизайна 14.09.2026 (ADR-046, план `plans/design-system-2026-09-14.md`).
Перед любой задачей по интерфейсу прочитай этот файл. Сначала ищи готовый компонент на странице `/design-system`
(шаг 4 плана). Новый компонент — только если такого нет, и сначала допиши его сюда.

Источник правил — документ ментора «План продукта и дизайн-система» от 14.09.2026, части 2–7. Значения — из
действующего интерфейса WETOP (ADR-029, ADR-035…039): на шаге 2 они **не меняются**, скриншоты
`design/reference/current/` до и после генерации совпадают. Где действующее значение нарушает правило, это
записано прямо в правиле с шагом, на котором чинится.

Токены живут в [`design/tokens.json`](design/tokens.json) (W3C DTCG 2025.10, спецификация сохранена в
`design/docs/dtcg-2025.10/`). CSS-переменные `apps/web/src/app/tokens.css` **только генерируются**:
`npm run design:build`; ручная правка валит тест `scripts/design/src/tokens-css.test.ts`. Контраст считается
в `design/contrast.md` тем же скриптом.

У каждого правила есть строка «почему». Правило меняется сначала здесь, потом в коде, потом в Claude Design.

---

## 1. Принципы стойки

1. **Статус брони читается за секунду без наведения.** На клетке шахматки и в списках — цвет плюс слово или
   значок; подсказка `title` только дополняет. Почему: администратор смотрит на шахматку через плечо гостя.
2. **Частое действие — в одно касание и с клавиатуры.** Заселить, принять оплату, продлить, переселить —
   одной кнопкой на карточке; перетаскивание дублируется пунктом меню. Почему: смена делает это десятки раз в день,
   а мышь не всегда под рукой (Q-133).
3. **Плотно, но читаемо.** Текст не мельче 12 px, цель нажатия не меньше 24×24 px, на телефоне — 44 px.
   Почему: 88 строк шахматки должны помещаться на экран, но не ценой ошибок нажатия.
4. **Смысл не держится только на цвете или наведении.** Всё важное — словом, значком или числом, видимым сразу.
   Почему: дальтонизм, тёмная тема, планшет без наведения.
5. **Шахматка остаётся на экране.** Карточка брони открывается панелью сбоку; окно поверх — только для
   необратимого: переселение в другую категорию и отмена со штрафом. Почему: контекст дня нельзя терять.

## 2. Токены

Три уровня, как требует документ: **примитив → семантика → компонент**.

| Уровень | Где | Пример | В CSS |
|---|---|---|---|
| Примитив | `sets.primitives` → группа `palette` | `palette.blue.700 = #085fba` | не выходит (`$extensions["ai.wetop"].css = false`) |
| Семантика | `sets.semantic` (без темы), `sets.light`, `sets.dark`, контекст `contrast` | `color.primary = {palette.blue.700}` | `--primary` — имя листового токена |
| Компонент | классы `.btn`, `.badge`, `.stat` … в `globals.css`, `premium.css`, `workspace.css` | `.btn--danger { background: var(--danger) }` | через семантические переменные |

Правила:
- Имя CSS-переменной = листовое имя токена; имена уникальны во всём документе (тест `scales.test.ts`).
- Компонент не берёт примитив напрямую и не пишет цвет литералом. Сейчас так и есть (план §3.1); тест
  `css-vars.test.ts` следит, чтобы каждая `var(--…)` была токеном или локальной переменной.
- Псевдоним на семантику остаётся `var(--…)` в CSS (`--info: var(--primary)`), псевдоним на примитив — значением.
- Темы — модификатор `theme` резолвера: `light` (по умолчанию), `dark` (светлая плюс отличия), `contrast`
  (светлая плюс границы и текст, проходящие 3:1 и 7:1; переключателя в интерфейсе пока нет — цель шага 4).
  Печать — модификатор `media`.
- Почему один файл-резолвер, а не набор `.tokens.json`: у нас три темы и печать при одной семантике; документ
  ментора просит один файл `design/tokens.json`, и это имя закреплено в ADR-046. Спецификация советует
  расширение `.resolver.json` (SHOULD, не MUST) — отступление записано здесь.
- Устаревшее помечается `$deprecated` с причиной, а не удаляется молча: `--purple`, `--purple-soft`, `--space-3`,
  `--space-5`, `--topbar-h`.

Палитра (значения действующие):

| Имя | Светлая | Тёмная | Смысл |
|---|---|---|---|
| blue | `#085fba` | `#48a5ff` | акцент, ссылки, «подтверждена» |
| green | `#06735e` | `#38d2ae` | норма: оплачено, заселён, обработано |
| amber | `#94600b` | `#f6ba52` | внимание: не подтверждена, требует действия |
| red | `#cc384e` | `#ff7a87` | тревога: ошибка, долг, отмена, блокировка |
| teal | `#20b298` | `#38d2ae` | второй ряд графиков |
| gray 0…10 | `#ffffff` … `#101827` | — | нейтральная шкала светлой темы |
| navy 0…15 | — | `#f7f9fc` … `#060b14` | нейтральная шкала тёмной темы |

Нарушения, закрываемые на шаге 4: нейтральная шкала из 11 и 16 ступеней вместо семи; почти чёрный подкрашен
(`#101827`, `#060b14`); `purple` без смысла.

## 3. Отступы

Шкала: **4, 8, 16, 24, 32, 40, 48, 64** (`--space-1 … --space-16`). Между блоками — только отступ снизу первому,
не сверху второму. Почему: одна шкала держит ритм, а двусторонние отступы складываются непредсказуемо.

Как сейчас: 749 значений отступов в CSS, 458 вне шкалы (12 px — 100 раз, 10 px — 71, 20 px — 68). `--space-3`
и `--space-5` помечены устаревшими. Перевод — по экрану со сравнением скриншотов
(`scripts/design/src/compare-shots.ts`), не заменой по всему CSS (план §9).

## 4. Раскладка и плотность

- Боковое меню 232 px (`--sidebar-w`), сворачивается; шапка 72 px (`--header-h`); контент на всю ширину.
- Высота кнопки и поля 38 px (`--control-h`); на телефоне 44 px — правило `workspace.css:665` перекрыто
  `premium.css:77,88`, чинится на шаге 4.
- Шахматка: колонка ячеек и шапка дат закреплены; строка категории сворачивается и показывает свободные места
  по ночам; ширина дня — токенами по виду: «Неделя» 120 px, «14 дней» 84 px, «Месяц» — по ширине окна
  (`--week-unit-width`, `--month-unit-width`, локальные переменные `premium.css:407–441`, войдут в токены на
  шаге 7.1 вместе с высотой строки).
- Карточка брони — панель сбоку `app/@drawer`, четыре вкладки: Обзор, Счета, Действия, История.
- Почему: 88 строк и 7–31 колонка должны читаться без горизонтальной прокрутки на 1280 px.

## 5. Радиусы и тени

| Уровень | Токен | Значение | Где |
|---|---|---|---|
| Контрол | `--radius-sm` | 8 px | кнопка, чип, клетка брони |
| Поле | `--radius-control` | 10 px | поле ввода, select |
| Карточка, панель | `--radius` | 16 px | плитка, таблица в панели, панель сбоку |
| Лист, окно | `--radius-lg` | 20 px | окно подтверждения |
| Круг | `50%` | — | аватар, точка статуса |

Тень — **только у слоя над страницей**: `--shadow-floating` у панели сбоку, окна, выпадающего. Плоские блоки
на странице — граница, без тени. Почему: тень означает «это поверх», и если она у всего, знак пропадает.

Как сейчас: 23 разных радиуса и `--shadow` у плиток, карточек, таблиц и шахматки (`premium.css:93…342`).
Сводится к уровням на шагах 4 и 7.

## 6. Шрифт

Действующий стек: `-apple-system, BlinkMacSystemFont, 'Inter', 'Segoe UI', sans-serif` (`--font`). Это разные
шрифты на macOS и Windows, Inter указан, но не подключён. Заголовки тем же шрифтом (`--font-head`).
Моноширинный `--mono` — только для кода и журналов, не для подписей и номеров броней (§14).

**Проверка кандидатов** — `npm run design:fonts -- <файлы>` (`scripts/design/src/check-fonts.ts`): казахские
буквы ә ғ қ ң ө ұ ү һ і в обоих регистрах, латиница, кириллица, ширина цифр, возможность `tnum`, снимок листа
«1 l I 0 O» в 12 и 13 px. Отчёт 14.09.2026 — `design/reference/fonts/report.md`:

| Кандидат | Казахские буквы | Табличные цифры | Итог |
|---|---|---|---|
| IBM Plex Sans | все 18 | по умолчанию | **подходит**; записан в ADR-027, в коде отсутствует |
| Inter | все 18 | через `tnum` | подходит при `font-variant-numeric: tabular-nums` |
| PT Sans | все 18 | по умолчанию | подходит, но узкий: 0,545 em на цифру |
| Golos Text | все 18 | через `tnum` | подходит |
| Manrope | **нет ә ғ қ ң ұ** | через `tnum` | **не подходит** для казахских фамилий (был в направлении 12.09) |
| Системный стек | зависит от ОС | зависит от ОС | проверить нельзя, пока нет ответа Q-133 |

**Решение шага 2:** шрифт не меняется (значения токенов заморожены до совпадения скриншотов). Кандидат по
умолчанию для шага 4 — **IBM Plex Sans**: полное покрытие казахских букв, цифры одной ширины без настроек,
записан в ADR-027 как выбранный. Ставится через `next/font/local` из файла в сборке, стойка не ходит в интернет.
Смена шрифта — отдельная правка с пересборкой эталонных снимков (план §9). Если по Q-133 стойка на Windows,
системный стек даст Segoe UI — тогда IBM Plex нужен тем более, чтобы экран был одинаковым на всех машинах.

Шкала размеров: **12, 13, 14, 16, 18, 22, 28** (`--fs-12 … --fs-28`), высота строки `--lh-tight 1.25` для
заголовков и чисел, `--lh-base 1.45` для текста. Ничего мельче 12 px. Почему: на 13 px строки таблицы
вмещают 88 ячеек, ниже 12 px «1 l I» неразличимы.

Как сейчас: 26 размеров и 3 `clamp`, 10 px — 11 раз, 11 px — 18 раз. Сводится к шкале на шагах 4 и 7.

## 8. Компоненты — размеры, токены, восемь состояний

загрузка, ошибка, выбрано**. Загрузка — текстом на кнопке («Сохраняю…»), без крутилок. Фокус — кольцо
`--ring` (3 px, `--ring-color`), никогда не `outline: none` без замены.

## 9. Статусы

Статус всегда **цвет + слово или значок**. У цвета один смысл на всех экранах: синий — подтверждена и акцент,
зелёный — норма, янтарный — внимание, красный — тревога, серый — прошло. Цвет «успеха» не красит выходные
и счётчики (сейчас красит: `workspace.css:1108`, `today/desk.css:155,171` — шаг 7.1).

Сопоставление с моделью данных (`DATA_MODEL.md` §2, §4; развилки — план §4):

| Статус на экране | В модели | Токен | Слово на клетке |
|---|---|---|---|
| Не подтверждена | `ReservationItem.status = TENTATIVE` (перенесённые из Exely; Q-130 вариант (а)) | `--st-tentative` | «не подтверждена» |
| Подтверждена, ждём | `CONFIRMED` | `--st-confirmed` | «ждём» |
| Заселён | `CHECKED_IN` | `--st-checked-in` | «заселён» |
| Выселен | `CHECKED_OUT` | `--st-checked-out` | «выехал» |
| Отменена, незаезд | `CANCELLED`, `NO_SHOW` — на шахматке не показываются | бейдж `--danger` в списках | «отменена», «незаезд» |
| Блокировка | `InventoryBlock.type` MAINTENANCE / MANAGEMENT / OUT_OF_ORDER / OTHER с причиной | `--st-blocked`, штриховка | «ремонт: кондиционер» |
| Уборка | `HousekeepingStatus` DIRTY / CLEAN / INSPECTED; ремонт — это блокировка, не статус уборки | бейдж warn / ok / info | «грязно», «убрано», «проверено» |
| Конфликт | проживание без ячейки (`stay.unassigned`) или ночь категории сверх мест (`stay.overbooked`); двух броней на одну ячейку не бывает (`allocations_no_overlap_per_unit`) — Д3 | `--warning` | «Без ячейки», «сверх мест: 37 на 36» |
| Входящая бронь требует разбора | ревизия Channex `FAILED` без брони (ADR-024, Q-109) | плашка `--warning-bg` | «Обработать заново» |
| Долг | баланс счёта > 0 (`Folio`) | `--danger` | сумма |

Нет в модели и не придумывается: «способ гарантии» и «теги» (Q-131), задачи смены со сроками (Q-132).

## 10. Контраст

Нормы WCAG AA: текст на фоне **4,5:1**, граница и кольцо фокуса на фоне **3:1**, в обеих темах.
Таблица — `design/contrast.md`, считается скриптом; тест `scales.test.ts` не пропускает пару без нормы, кроме
записанных исключений с причиной и сроком, и валит протухшее исключение.

Исключения на 14.09.2026 (значения заморожены до совпадения скриншотов, чинятся на шаге 4):

| Пара | Светлая | Тёмная | Норма |
|---|---|---|---|
| `--border` на `--surface` | 1,21 | 1,26 | 3 |
| `--border-input` на `--surface` | 1,29 | 1,65 | 3 |
| `--ring-color` на `--surface` | 1,11 | 1,29 | 3 |
| `--danger` на `--danger-soft` | 4,48 | — | 4,5 |

Все пары «текст / фон», включая текст на заливках статусов, проходят. Контрастная тема проходит всё без
исключений — её значения и есть цель шага 4 для границ и кольца.

## 11. Цели нажатия

Не меньше **24×24 px** на компьютере, **44 px** на телефоне и планшете. Клетка шахматки в виде «Неделя»
120×40 px, в «Месяце» — по ширине окна, но не меньше 24 px. Кнопки-значки 36×36 px. Почему: правило документа
и ошибки нажатия на планшете; какие устройства у смены — Q-133.

## 12. Клавиатура

Обязательные: `Tab` по всем действиям, `Escape` закрывает панель и окно с возвратом фокуса, `Enter` отправляет
форму, стрелки переключают вкладки карточки (есть), `⌘K` / `Ctrl+K` — быстрый поиск (есть). Перетаскивание на
шахматке дублируется пунктом меню «Переселить» (шаг 7.1). Сочетания для действий стойки (новая бронь, заселить)
не включаются до ответа администраторов — Q-133, опросник блок 10.

## 13. Анимация и слои

Анимация только в ответ на действие: `--dur-fast` 120 мс для наведения и нажатия, `--dur-base` 180 мс для панели,
окна и раскрытия; кривая `--ease`. При `prefers-reduced-motion` — 0 (уже обработано). Крутилок и бесконечных
анимаций нет, кроме скелетона загрузки.

Слои: `--z-base` 0 → `--z-raised` 10 (закреплённые колонки) → `--z-sticky` 20 (шапка, меню) → `--z-dropdown` 30
→ `--z-drawer` 40 → `--z-modal` 50 → `--z-toast` 60. Литералы 1…100 в CSS переводятся на шаге 4.

## 15. Чего не делать — и что вместо

## 16. Что берём из Exely и чего не берём

Берём: паритет смыслов — «Без ячейки» как «Без номера», виды шахматки по периодам, карточка брони со счетами
на каждое проживание, статусы уборки из справочника. Не берём: экран в экран (PLAN.md «Чего не делаем»),
30 отчётов, цветные подложки без слова, номер единицы как источник смысла (CLAUDE.md §5).
Скриншоты Exely с закрашенными фамилиями — только для промптов макетов, `design/reference/exely/`, в git и
Claude Design не попадают (Д7).

## 17. Как меняются правила

1. Правило меняется здесь, с «почему»; значение — в `design/tokens.json`.
2. `npm run design:build` → `tokens.css` и `contrast.md`; `npm run test:record -- unit scripts/design/src`.
3. Скриншоты до и после: `tests/ui/design-reference.spec.ts` → `scripts/design/src/compare-shots.ts`; отличия
   должны быть только там, где правило изменилось.
4. Затем страница `/design-system` и Claude Design (шаг 5). Правка через Remix в Claude Design переносится сюда
   в тот же день.
5. После первой живой смены — только по замечаниям администраторов (ADR-027, ADR-046).
