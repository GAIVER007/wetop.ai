## 3. Подключить новую AI-сессию

### Вариант А — сессия открыта прямо в папке

`CLAUDE.md` подхватывается автоматически. Достаточно:

```
Проект PMS для Luxx Aparts. Прочитай CLAUDE.md, затем в указанном там порядке:
AGENTS.md, SPEC.md, OBJECT.md, FINDINGS.md, DATA_MODEL.md, DECISIONS.md,
QUESTIONS.md, PLAN.md.

Ничего не программируй и не создавай файлов.

Дай ответ:
1. Что представляет собой объект — своими словами.
2. Границы MVP.
3. Противоречия между документами, если найдёшь.
4. Чего не хватает для начала работы.
5. Хватает ли данных для утверждения DATA_MODEL.md.
6. Что именно ты НЕ имеешь права решать сам.

Пока я не подтвержу этот анализ, код не менять.
```

```
Проект: собственная PMS для хостела Luxx Aparts, Алматы. Замена Exely.

Загрузка августа 2026 — 79,7%, 1044 заезда, оборот проживания 15 688 018 ₸.

Прочитай в этом порядке и ничего не программируй:
CLAUDE.md, AGENTS.md, SPEC.md, OBJECT.md, FINDINGS.md, DATA_MODEL.md,
DECISIONS.md, QUESTIONS.md, PLAN.md

ЖЁСТКИЕ ПРАВИЛА:
- Модель данных меняется только через DATA_MODEL.md, потом код. Не наоборот.

- Деньги — integer minor units, никаких float.
- Integration code только по документации из /docs. Нет документации — STOP.
- В тестах только вымышленные гости. Реальные паспорта и ФИО запрещены.
- Задача не закрывается словом "done" — нужен тест, скриншот или отчёт сверки.

РАЗРАБОТКА ЗАБЛОКИРОВАНА тремя решениями владельца: Q-080 (модель койки),
Q-091 (Folio на бронь или на проживание), Q-092 (знаменатель загрузки).
```

## 4. Первый промпт после разблокировки

Использовать **только** когда Q-080, Q-091 и Q-092 отвечены, ответы записаны
в `QUESTIONS.md`, соответствующие ADR перенесены из «ПРЕДЛОЖЕНО» в принятые,
а `DATA_MODEL.md` переведён из DRAFT в утверждённый.

```
DATA_MODEL.md утверждён. Работаем только над Slice 1: Inventory.

Цель: импортировать реальный номерной фонд объекта и показать его в интерфейсе.

Контрольные числа (OBJECT.md §2):
  88 единиц продажи = 16 ROOM + 72 BED
  Одноместная с окном      4
  Одноместная без окон     8
  Двухместная              4
  Общая мужская (койка)   36
  Общая женская (койка)   36
  Максимум гостей         92

Доказательство готовности: reconciliation report, в котором каждая из этих строк
совпадает с контрольной выгрузкой. Допустимое расхождение — 0.

Требования:
1. Используй утверждённый DATA_MODEL.md. Не меняй модель самостоятельно.
2. До реализации покажи тесты, которыми докажешь правильность импорта.
3. В automated tests только synthetic data.
4. Импорт обязан быть идемпотентным и транзакционным.
5. Ничего не выводить из номера единицы — нумерация в Exely не сплошная.
6. Если реальные данные не помещаются в модель — НЕ меняй schema,
   запиши проблему в QUESTIONS.md.
```
