## 3. Как поднять локально

```bash
scripts/ops/repo-sync.sh                       # та ли папка: remote, отставание от GitHub, службы; --fix чинит
npm install                                    # Node 24 (.nvmrc); Prisma Client генерируется сам (postinstall)
npx tsx scripts/imports/src/cli-check-env.ts   # секреты на месте, значения не печатает
npm run dev -w apps/api                        # API 127.0.0.1:3001
npm run dev -w apps/web                        # стойка 127.0.0.1:3000
npm run db:local                               # локальная PostgreSQL 16 для integration и e2e (порт 55432)
npm run test:status                            # что уже доказано на текущем коде — прогонять повторно не надо
npm run test:record -- unit                    # прогон с записью в журнал; так же integration / e2e / typecheck / lint
```

Правила прогонов — `TESTING.md`: тесты только через `test:record`, лог и строка журнала коммитятся вместе
с правкой. Integration и e2e ходят только на локальную базу; нелокальная требует явного `PMS_TEST_REMOTE_DB=1`
(ADR-074). CI: быстрые наборы (lint, typecheck, unit, главная, бот) на каждый пуш и PR (`checks.yml`, свой раннер
на сервере); база, integration, сквозные и весь UI на кандидата в выкладку (`release-checks.yml`, раннеры GitHub,
ADR-139).

Замок включён по умолчанию: непубличные маршруты API отвечают 401 без сессии, выключается только явным
`AUTH_REQUIRED=0`. `.env` агенту не читается (`.claude/settings.json`), значения ключей вписывает только
владелец; `PII_STORAGE` пуст везде, кроме будущей базы в Казахстане (`CUTOVER.md`); архивный источник, OTA и Channex
production не трогать (предохранитель `CHANNEX_PRODUCTION`, ADR-074).
