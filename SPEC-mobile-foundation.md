## Цель и границы модуля

Создать нативную основу WETOP для iOS и Android, которой владелец и сотрудник могут пользоваться одной рукой. Модуль предоставляет оболочку, навигационные элементы, тему и общие состояния. Авторизация и серверные данные принадлежат следующему модулю mobile-access; рабочая сводка принадлежит mobile-today.

Предположения: русский интерфейс первого среза, телефон как основной формат, системные шрифты, существующие брендовые материалы WETOP. Поддержка планшета означает корректную адаптацию, отдельный планшетный интерфейс пока не включён. Цвета берутся из актуального дизайна проекта и проверяются на контраст, а не заменяются произвольной палитрой.

## Пользовательский интерфейс

- Основная оболочка: заголовок текущего раздела, место для контекста бизнеса/филиала, прокручиваемый контент и нижняя навигация.
- Полная навигация целевого приложения: «Сегодня», рабочий раздел направления, «Клиенты», «Меню». До реализации раздела не показывать кнопку, ведущую в тупик. Состав определяется разрешениями, полученными модулем доступа.
- Каркас принимает список разрешённых пунктов и выбранный пункт. Не вычисляет бизнес-права самостоятельно и не подменяет серверную проверку.
- Один заметный основной призыв к действию на экран. Для чисел и списков предпочтительны строки и ясная типографика, без декоративной сетки карточек.
- Нажатия: минимум 44pt на iOS и 48dp на Android. Небольшая иконка получает расширенную область нажатия. Иконки единообразные, с подписью у пунктов навигации.
- Отступы кратны 4/8, базовые боковые отступы телефона 16. Размеры текста системно масштабируются. При увеличении текста строки растут по высоте, подписи не обрезаются ради плотности.
- Светлая/тёмная темы следуют системной настройке. Обычный текст имеет контраст не ниже 4.5:1, значимые иконки и границы контролов не ниже 3:1.
- Контент, кнопки и сообщения не перекрываются вырезом экрана, системными панелями, нижней навигацией и клавиатурой.
- Системная кнопка Android «Назад» и жест iOS сохраняют ожидаемую историю. Закрытие вложенного экрана сохраняет положение списка.

## Состояния и интерфейсы между модулями

Общие компоненты: Screen, ActionButton, FormField, StateView, NavigationShell. Названия предварительные; не создавать дополнительную библиотеку ради этих компонентов.

StateView принимает состояние loading, empty, offline, forbidden или error, видимое объяснение и необязательное действие с подписью. Ошибка не отображает сырые ответы сервера. Загрузка объявляется для screen reader; индикатор не пересобирает всю структуру экрана.

NavigationShell получает только разрешённые элементы, выбранный идентификатор и обработчик перехода. Подпись, значок и выбранность доступны VoiceOver/TalkBack. Никаких токенов сессии внутри визуальных компонентов.

При отсутствии данных выводится честное пустое состояние. Демонстрационный экран явно помечается «Демонстрация» и содержит только синтетические значения. Offline не означает разрешение на локальное сохранение бронирований или платежей.

## Структура и стиль

Предлагаемое расположение: apps/mobile для приложения; src/ui для общих контролов; src/theme для адаптированных токенов; src/navigation для оболочки; tests для изолированных проверок. Экран входа появится в mobile-access, без зависимости от Next.js server modules.

TypeScript strict. Именованные экспорты, компоненты PascalCase, функции camelCase. Пример ожидаемого контракта:

```ts
type ScreenState = 'loading' | 'empty' | 'offline' | 'forbidden' | 'error';

type StateViewProps = {
  state: ScreenState;
  message: string;
  action?: { label: string; onPress: () => void };
};
```

Тексты простые и конкретные: «Нет соединения», «Повторить», «Нет доступа к этому разделу». Новые тексты без U+2014.

## Команды и проверки

Проверенные существующие команды корня: `npm run lint`, `npm run typecheck`, `npm run test:record -- unit`. Они сами по себе не подтверждают корректность нативного приложения.

После выбора и разрешения зависимостей определить в apps/mobile/package.json команды, вызываемые как `npm --prefix apps/mobile run start`, `npm --prefix apps/mobile run typecheck`, `npm --prefix apps/mobile run test`, `npm --prefix apps/mobile run ios`, `npm --prefix apps/mobile run android`. Эти scripts реализованы в отдельном мобильном пакете. Конкретный native build и test runner фиксируются в техническом плане после выбора стека.

Проверки модуля изолированы от базы. Проверить выбор пункта навигации, отсутствие недоступных пунктов, однократное выполнение действия и отсутствие вызова disabled-кнопки. Визуально проверить маленький телефон, большой телефон, landscape, обе темы, крупный системный текст и reduced motion. VoiceOver/TalkBack проверяются отдельно от статического анализа.

Снимки и журнал проверок: reports/mobile-foundation-2026-10-24/. Отдельно обозначать simulator, emulator и физическое устройство. Web preview не является доказательством нативной сборки.

## Критерии готовности

1. Оболочка запускается на iOS simulator и Android emulator либо явно документирован недоступный SDK.
2. Нет перекрытого контента и горизонтальной прокрутки обычных форм на ширине 375 логических единиц.
3. В обоих цветовых режимах читаются подписи и состояния.
4. Увеличение системного текста не скрывает действия. Навигация имеет доступные имена и выбранное состояние.
5. Все пять состояний различимы; повторный запрос вызывается только явным доступным действием.
6. Проверки типов, целевые тесты и lint проходят; ошибки не скрываются suppress-комментариями.
7. Снимки и результаты сборки сохранены, ограничения перечислены. Наличие оболочки не объявляется завершением всего приложения.

## Открытые вопросы и блокеры

- Предлагается Expo + React Native + TypeScript, development builds, Expo Router; в mobile-access добавить expo-secure-store. Для компонентных тестов jest-expo и React Native Testing Library. Точные совместимые версии фиксируются перед установкой. Зависимости разрешены владельцем и установлены: Expo 58, React Native 0.88, React 19.3, отдельный lockfile. Bare React Native оставляем для подтверждённых ограничений Expo; Flutter потребует отдельного Dart/toolchain и хуже использует существующую React/TypeScript основу.
- Владелец разрешил отдельную рабочую копию без общей dev-базы. Создан чистый managed worktree wetop-mobile от ff3e1bc211f9cb6fb23162262d799723279885ae.
- Спецификация не утверждает готовность публичного API. Контракт транспорта и безопасной сессии проверяется в mobile-access до подключения реальных данных.

Основание UX: ui-ux-pro-max/references/pro-rules.md. Автоматический поиск общего design-system вернул маркетинговый паттерн Hero + Features + CTA, неприменимый к рабочему приложению; он отклонён. Использованы явно адресованные нативному интерфейсу правила справочника, без сохранения сгенерированной дизайн-системы.
