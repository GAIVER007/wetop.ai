# apps

Четыре приложения одного репозитория. Всё, что ниже, лежит в ветке `main`; отдельных папок и веток
для частей проекта больше нет (ИИ-агент переехал сюда 24.09.2026 — см. последний раздел).

| Папка | Что это | Запуск на Mac | Где работает |
|---|---|---|---|
| `web/` | Next.js 16 + React 19 — стойка администратора: шахматка, брони, гости, финансы, настройки, «ИИ-продавец», «Платформа» | `npm run dev -w apps/web` (127.0.0.1:3000) | `app.wetop.ai`, контейнер `web` в `deploy/compose.yml` |
| `api/` | NestJS — API стойки, сайта, каналов и ботов | `npm run dev -w apps/api` (127.0.0.1:3001) | контейнер `api`, туннель — только публичные пути (`deploy/cloudflared.example.yml`) |
| `site/` | Next.js, статическая главная `wetop.ai` | `npm run dev -w apps/site` (127.0.0.1:3002) | Cloudflare Pages: `npm run site:deploy` (`docs/deploy.md` §2) |
| `ai-seller/` | ИИ-агент на Python (FastAPI): один образ — два экземпляра. **Продавец** (`BOT_ROLE=seller`) отвечает гостям гостиниц в чате сайта и в WhatsApp; **помощник** (`BOT_ROLE=support`) — техподдержка платформы | `cd apps/ai-seller && docker compose up -d --build`; тесты — `pytest` в этой папке | сервер платформы: `/opt/wetop-bot/seller` и `/opt/wetop-bot/assistant`, каждый своим compose (`docs/assistant/README.md` §6) |

Правила: общие для репозитория — `AGENTS.md` и `CLAUDE.md` в корне; у ИИ-агента свои —
`ai-seller/AGENTS.md` (ядро движка под клиента не правится, изоляция гостиниц — в каждой двери).

## Как части связаны

ИИ-агент в образ стойки не входит и базу платформы не читает: он ходит в API узкими ключами по внутренней
сети `wetop-internal`, платформа — в его панель своим служебным ключом. Одинаковые значения стоят в `.env`
платформы (корень клона на сервере) и в `.env` экземпляра бота; полный список пар и порядок включения —
`docs/assistant/README.md` §5–6.

| Кто → кому | Зачем | Ключ (платформа ↔ бот) |
|---|---|---|
| стойка (раздел «ИИ-продавец») → панель продавца | профиль и факты гостиницы, знания, диалоги, «Проверка», ключ модели, WhatsApp | `SELLER_SERVICE_KEY` ↔ `SELLER_SERVICE_KEY` (заголовок `X-Service-Key`, гостиница — `X-Organization`) |
| «Платформа → Техподдержка» → панель помощника | диалоги, правила и модель помощника | `ASSISTANT_SERVICE_KEY` ↔ `SELLER_SERVICE_KEY` помощника |
| продавец → API `GET /bot/availability` | «есть места?» и «сколько стоит?» по тарифу сайта гостиницы | `SELLER_QUOTE_KEY` ↔ `INTEGRATION_API_KEY` продавца |
| помощник → API `/assistant/errors`, `/guard/status`, `/assistant/organization` | ошибки, которые видел человек; состояние платформы; подписка организации | `ASSISTANT_READ_KEY` ↔ `INTEGRATION_API_KEY` помощника |
| стойка и главная → чат помощника | виджет с подписью вошедшего | `WIDGET_IDENTITY_SECRET` (одинаковый) |
| сайт гостиницы → чат продавца | тег из «ИИ-продавец → Код для сайта» (`data-key` гостиницы, только её домены) | публичный ключ гостиницы, выводится из служебного |
| Meta → продавец | вебхук WhatsApp гостиницы: снаружи открыт только `/channels/whatsapp/webhook/<uuid>` | подпись секретом приложения гостиницы |

Расширение «ИИ-продавец» включает и выключает главный администратор («Платформа → Организации»); платформа
раз в минуту сверяет с продавцом список гостиниц — у гостиницы с истёкшим расширением продавец молчит
на сайте и в WhatsApp.

## Старая папка ИИ-агента

До 24.09.2026 бот жил отдельной папкой на Mac — `~/Desktop/Проекты/Чат агент/WETOP` — на ветке `ai-seller`
этого же репозитория. Ветка перенесена в `apps/ai-seller/` со всей историей и заморожена
(`PEREEHAL-V-MAIN.md` на ней); новые правки агента — только здесь. Старая папка больше не нужна.
Если её переложили внутрь рабочей папки WETOP, `scripts/ops/repo-sync.sh` это покажет, а
`scripts/ops/repo-sync.sh --archive-nested` перенесёт её целиком (с `.env` и данными) в `WETOP-архив` рядом —
только когда вся её работа уже на GitHub. Файлы из старой папки, положенные поверх `apps/ai-seller`,
тот же скрипт узнаёт по совпадению с замороженной веткой, а `--fix` возвращает им версию `main`.
