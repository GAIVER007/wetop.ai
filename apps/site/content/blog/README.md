# Как писать статьи блога: логика SEO

Формат файла и поля описаны в `kak-dobavit-statyu.md`. Здесь правила содержания: зачем статья,
для кого и как она приводит посетителя к регистрации. Правило текстов сайта действует и тут
(DESIGN.md §19.9): только то, что есть в продукте; никаких чисел клиентов, отзывов, цен подписки
и обещаний результата. Длинное тире не используем (CLAUDE.md §5).

## Зачем блог

Поисковый спрос по нашим темам живёт в вопросах: «как вести записи в салоне», «что такое шахматка»,
«как подключить Booking.com». Лендинги на такие запросы не отвечают, статья отвечает и ведёт на
лендинг направления. Одна статья = один вопрос = один целевой запрос.

## Темы по направлениям

У каждого направления свой куст запросов. Первые статьи закрывают по одному вопросу на направление,
дальше раз в одну-две недели по статье, чередуя направления.

| Направление | Куст запросов | Куда ведёт |
|---|---|---|
| Гостиницы | PMS для хостела и мини-отеля, шахматка, продажа коек, менеджер каналов, двойные брони | `/for/hotels/`, `/for/hostels/`, `/calculator/` |
| Салоны | журнал записи, записи клиентов, график мастеров, база клиентов салона | `/for/salons/` |
| Рестораны | бронирование столов, план зала, посадка гостей, журнал брони ресторана | `/for/restaurants/` |

## Структура статьи

1. **Заголовок** = вопрос или задача словами читателя, с ключевой фразой. Один H1 даёт шаблон, в
   тексте только `##` и `###`.
2. **Первый абзац**: ответ по сути в двух-трёх фразах, без разгона. Поисковик берёт его в сниппет.
3. **Тело**: 400-800 слов, подзаголовки `##` каждые 2-4 абзаца, списки вместо простыней. Сначала
   проблема и ручной способ, затем как это устроено в системе. Названия разделов продукта пишем
   как в интерфейсе («Календарь размещений», «План зала»).
4. **Внутренние ссылки**: 2-4 на лендинги и соседние статьи, естественным текстом, не «кликните сюда».
   Внешние ссылки не ставим.
5. **Финал**: одна фраза с ссылкой на лендинг направления. Призыв без давления: регистрация и так
   на каждой странице.

## Поля и адрес

- `slug` (имя файла) = ключевая фраза транслитом, коротко: `kak-vybrat-pms-dlya-khostela`.
- `title` до 60 знаков, `description` до 155: это сниппет выдачи, пишется как ответ.
- `date` = день публикации; `draft: true`, пока статья не вычитана.

## Чего в статьях не бывает

Выдуманных кейсов и имён, процентов роста, сравнений с конкурентами по названиям, скриншотов живых
объектов (только мокапы или экраны с демо-данными и подписью), обещаний функций, которых нет в
продукте. Сомнение решается не в пользу красивой строки.
