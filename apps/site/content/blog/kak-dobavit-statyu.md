Это служебный черновик. Он лежит рядом со статьями как образец и **никогда не публикуется**: у него стоит `draft: true`, поэтому его нет ни в списке статей, ни в `sitemap.xml`, ни в собранном сайте.

## Где лежат статьи

Одна статья — один файл Markdown в папке `apps/site/content/blog/`.

Имя файла становится адресом статьи: файл `kak-podklyuchit-kanaly.md` откроется по адресу `/blog/kak-podklyuchit-kanaly/`. В имени допустимы только строчные латинские буквы, цифры и дефисы. Кириллица, пробелы и заглавные буквы остановят сборку.

Файл `README.md` в этой папке статьёй не считается и пропускается.

## Блок полей

Файл начинается с блока полей между двумя строками `---`:

```markdown
---
title: Как подключить каналы продаж
date: 2026-09-20
description: Одна фраза для списка статей и превью в соцсетях
draft: true
---

Текст статьи.
```

| Поле          | Обязательно | Что писать                                                      |
| ------------- | ----------- | --------------------------------------------------------------- |
| `title`       | да          | Заголовок статьи                                                |
| `date`        | да          | Дата публикации в формате ГГГГ-ММ-ДД, например `2026-09-20`     |
| `description` | да          | Одна фраза: показывается в списке статей и в превью ссылки      |
| `draft`       | нет         | `true` — черновик, `false` или строки нет — статья опубликована |

Каждое поле — на своей строке, в виде `поле: значение`. Двоеточие внутри значения допустимо. Других полей быть не должно: опечатка вроде `drat: true` остановит сборку, а не опубликует черновик.

## Черновики

- `draft: true` — статья лежит в репозитории, но на сайт не попадает.
- Чтобы опубликовать, поставьте `draft: false` или удалите строку `draft`.
- Статьи в списке идут по полю `date`: новые — первыми. Три последние опубликованные статьи показываются на главной.

## Текст статьи

Текст пишется в Markdown. Заголовок страницы берётся из поля `title`, поэтому разделы начинайте с `##`, подразделы — с `###`. Строка с одним `#` тоже станет разделом второго уровня.

Работают списки, **выделение**, [ссылки](https://wetop.ai), таблицы, цитаты и блоки кода:

> Цитата оформляется символом `>` в начале строки.

Картинки кладите в папку `apps/site/public/images/blog/<имя-статьи>/` (создайте её при первой картинке) и вставляйте так:

```markdown
![Что изображено на картинке](/images/blog/kak-podklyuchit-kanaly/shakhmatka.png)
```

Не используйте снимки экрана с настоящими гостями, телефонами и документами — только вымышленные данные.

## Как проверить перед публикацией

1. Запустите сайт локально: `npm run dev -w apps/site` и откройте `http://127.0.0.1:3002/blog/`. Черновики там не видны: чтобы посмотреть статью, временно поставьте `draft: false` и не сохраняйте это в репозиторий, пока статья не готова.
2. Соберите сайт: `npm run build -w apps/site`. Если в блоке полей ошибка, сборка остановится и назовёт файл и причину, например «нет обязательного поля «description»» или «поле «date» — настоящая дата в формате ГГГГ-ММ-ДД».
3. Готовая сборка лежит в `apps/site/out/`. Выкладка на сайт — отдельный шаг владельца.
