# Пакет для Claude Design — проект «WETOP — стойка» (план, шаг 5)

**Статус 20.09.2026:** пакет собран, вход `/design-login` владелец выполнил на своём Mac,
**загрузка не выполнена**.

Почему её не делает агент. `/design-login` кладёт разрешение на ту машину, где выполнен, — на Mac.
Облачная сессия агента живёт не на этой машине и к её разрешению доступа не имеет: инструмент
синхронизации отвечает отказом и просит выполнить вход «на этой машине». Значит, саму синхронизацию
запускает владелец оттуда же, из своей сессии Claude Code: одна команда `/design-sync`, список путей
ниже она покажет на подтверждение.

Второй путь — загрузить файлы руками через настройки Claude Design. Список файлов ниже утверждает
владелец до загрузки (ADR-048, Д6): что загружено, попадёт в каждый макет.

## Что не загружается

- `design/reference/exely/` — скриншоты Exely (даже с закрашенными фамилиями): что загружено, то
  попадёт в каждый макет;
- `.git`, `node_modules`, `.env`, `secrets/`, `project-input/`;
- `reports/`, `tests/runs/`, данные объекта, `DECISIONS.md`, `QUESTIONS.md` (там финансы и контакты);
- код API и домена (`apps/api`, `packages`).

## Как загрузить

**Путь 1, из Claude Code на Mac владельца:** в интерактивной сессии выполнить `/design-login`, затем
`/design-sync` — инструмент покажет список путей выше на подтверждение и загрузит по одному компоненту.
Проект создать как «WETOP — стойка» типа «дизайн-система» (тип нельзя поменять после создания).

**Путь 2, руками:** Claude Design → настройки организации → Design system → загрузить те же файлы.

**После загрузки владелец:** делает пробный макет по `design/prompts/01-desk-layout.md`, проверяет цвета
статусов, шрифт, радиусы и имена компонентов; если всё верно — включает Published.

**Правило (DESIGN.md §18):** главный источник — репозиторий; правка в Claude Design через Remix в тот же
день переносится в `DESIGN.md` и `tokens.json`, затем синхронизация заново.
