# 05 · Журнал интеграции — экран для показа Channex

**Зачем:** проверяющий Channex должен увидеть цепочку «действие в интерфейсе → отправленная задача → ответ и
task id → время». Сегодня это экран `/channels` (`design/reference/current/channels-light.png`): три
плитки очереди, статус webhook, кнопки, таблица входящих событий с «Обработать заново», маппинг.

## Промпт

Переработай экран «Каналы продаж — Channex» в журнал интеграции по DESIGN.md. 1440×900, светлая тема.

**Сверху:** три плитки показателя — «В очереди 0», «Отправлено 16», «Ошибок 0» (ошибки > 0 — красным
значением); строка фактов «Объект Channex: создан · Webhook: https://api.wetop.ai/… · Последняя задача:
15:43»; кнопки — одна залитая «Отправить очередь сейчас», остальные белые: «Забрать брони», «Полная
выгрузка (500 дней)», «Проверить webhook».

**Исходящие (ARI)** — таблица, новая на экране: колонки «Когда» (время объекта, 24 ч), «Что» («остаток
Двухместный номер 16–19 сент.», «цена Стандартный 20.09.2026»), «Откуда» («бронь 20260916-DSG-BDC»,
«правка на /rates»), «Статус» бейджем словом («в очереди», «отправлено», «ошибка»), «Task id» моноширинным,
«Попыток», «Ошибка» текстом. Строка с ошибкой — кнопка «Отправить заново» и причина.

**Входящие (ревизии)** — таблица как сейчас, но: время объекта, а не UTC; «Как дошло» — «webhook» или
«опрос ленты»; статус словом; ревизия `FAILED` — красным с причиной «Несколько перенесённых броней
подходят: 20260913-TEST1, 20260913-TEST3 — разобрать руками» и кнопкой «Обработать заново»; успешная — со
ссылкой на бронь, которую создала.

**Вид на сотни записей:** фильтр по статусу и типу, период, постраничность по 50, и сверху «показать
только ошибки». Покажи экран с 3 записями и экран с 200 (прокрутка внутри таблицы, шапка липкая).

Ни одного нового компонента; если чего-то не хватило — списком.

## Что решает владелец

Одна таблица «все события» с фильтром направления или две отдельные (исходящие / входящие).
