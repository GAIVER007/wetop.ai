# Бронь из диалога

Утверждённый владельцем сценарий: после явного согласия гостя подтверждённая бронь занимает место без обязательной предоплаты. План реализации — [whatsapp-booking-2026-09-30.md](../../plans/whatsapp-booking-2026-09-30.md).

1. Уточнить даты и число гостей. Уже известный контакт WhatsApp повторно не запрашивать.
2. Получить варианты и цену из PMS в области выбранного агента/объекта.
3. Показать вариант, даты и итог; получить явное согласие именно на это предложение.
4. Сервер повторно проверяет наличие, срок предложения и цену. При изменении — новое предложение и новое согласие.
5. В одной транзакции создать бронь, назначить место и записать связь с подтверждением. Повтор сообщения возвращает прежний результат.
6. Сообщать номер брони только после commit. Повтор доставки не создаёт новую бронь.
7. Проверить чтение брони в шахматке; отмены/переносы требуют своих разрешённых операций.

## Состояние при аудите 01.10.2026

Чтение наличия и цены реализовано через bot-quote. В `src/integrations/factory.py` для seller `leads=stub`: заявка в диалоге не доказывает запись брони. Мастер показывает предупреждение о незавершённом подключении. Полную цепочку нельзя объявлять рабочей без теста записи, идемпотентности и обратного чтения. Изменение схемы — только по DATA_MODEL и с отдельно разрешённой production-миграцией.
