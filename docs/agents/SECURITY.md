# Безопасность агентов

## Границы доверия

Гость, WhatsApp webhook, загруженный документ, текст инструкции и ответ модели — недоверенные источники. Организация, агент и объект определяются проверенной сессией/подписанным каналом и серверными связями. Модель не выбирает чужой tenant и не назначает себе права.

- Каждое чтение/изменение проверяет organization_id и agent_id; филиал принадлежит организации.
- Знания, диалоги, промпты, ключи и каналы одного агента не становятся fallback для другого.
- Секреты только в secret storage/environment. Не помещать их в промпт, UI, Git, логи, ответы, CSV и диагностические снимки.
- Персональные данные маскируются перед моделью; проверки и fixtures используют вымышленных гостей.
- Инструкции из переписки/сайта не могут отключить подтверждение, назначить цену, вызвать произвольный URL или изменить права.
- Наличие и стоимость берутся из PMS. Итог считает сервер в minor units, не LLM.
- Проверять подпись webhook, повтор события, лимиты, таймауты и журнал обработки. Сбой не считается успехом.
- Доступ к чтению котировки не даёт права записывать бронь. Платёж, возврат и изменение роли не делаются по свободному тексту модели.
- Бот не выдаёт себя за человека. Передача сотруднику обозначается только при реальной передаче.

## Где проверять

`apps/ai-seller/src/security`, `src/ai/guardrails.py`, `src/agent_scope.py`, `src/channels`; PMS `apps/api/src/auth`, `ai-seller`, `web-booking`. Сохранять установленный порядок обработки движка; клиентские настройки не подменяют ядро.

Отказ показывать пользователю понятной фразой без stack trace и секретов. Подробности — только в закрытой диагностике с безопасным идентификатором события.
