## Что реализовано

1. Компактные вкладки, статусы и пошаговая настройка действующего продавца гостиницы; мобильная лента шагов; предпросмотр приветствия. Большой блок рассказа находится ниже основной формы.
2. /ai-seller/agents: каталог, карточки, пустое состояние и понятные ошибки без сырого HTTP503.
3. /ai-seller/agents/new: создание черновика сразу в текущей организации. Это основной маршрут из кабинета; он не требует гостевой сессии или повторного входа.
4. /ai-seller/agents/:id: редактирование сохранённого черновика, защита от перезаписи другой вкладкой.
5. POST /seller-agents: идемпотентное создание по UUID запроса. Сервер проверяет OWNER, членство, активный аккаунт/организацию, подтверждённую почту. Audit в той же транзакции. GET/list/PATCH изолированы по организации.
6. Перенос гостевого черновика через /seller-agents/claim реализован отдельно. Старый SellerProfile и его история не перезаписываются.
7. Из шапки /create удалена лишняя ссылка «Войти в аккаунт». Это не удаление необходимой авторизации из приложения.

## Конфигурация

На исходном Mac WIZARD_ENABLED=1 записан только в игнорируемую .env; API перезапущен. На сервер автоматически это НЕ передаётся. После проверки схемы установить WIZARD_ENABLED=1 в серверном environment API и убедиться, что фактический compose/container получает его. Секреты не копировать из чата, не печатать docker compose config или всю .env: там ключи. При диагностике показывать только значения несекретных флагов и признаки наличия секретов.

WIZARD_SESSION_TTL_SECONDS не задан намеренно: гостевой мастер не публикуем как готовый. Не менять пароли, AUTH_REQUIRED, права пользователей, доступность Data API, Channex/Exely workers, ARI, фискализацию. SECURITY.md §12: Data API отключён владельцем, но default grants anon/authenticated в Supabase остались. Не включать Data API; иначе новые таблицы могут стать доступны в обход backend.
