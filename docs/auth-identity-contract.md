# Контракт идентичности, контекста и ошибок (вход, регистрация, доступ)

Для соседних чатов: №1 (записи, брони, клиенты, онлайн-запись), №2 (сотрудники, мастера, графики, финансы),
№3 (оболочка, Главная, навигация, онбординг), №5 (публичный сайт wetop.ai). Составлен 16.10.2026 по `main` `1f9f39c31a325b085f1c3a9f5ed4af01445234f1`
и ветке `claude/auth-identity-1016`. Подробности и доказательства: `reports/auth-identity-2026-10-16/README.md`.

## 1. Кто есть кто (фактическая модель, новой нет)

| Понятие | Сущность | Назначение | Кто создаёт |
|---|---|---|---|
| Человек со входом | `User` (`users`) | одна учётная запись на одну почту (уникальна, нижний регистр) | регистрация, принятие приглашения, платформа |
| Клиент WETOP, граница данных | `Organization` | всё под RLS по `organization_id` | регистрация, главный администратор |
| Бизнес и направление | `Business` (`vertical`) | гостиница, салон или ресторан | регистрация (первый), дальше «Филиалы» |
| Филиал | `Location` | место работы, пояс и валюта | регистрация (первый), «Филиалы» |
| Объект гостиницы | `Property` | 1:1 с филиалом гостиницы; у салона и ресторана его нет | регистрация гостиницы, онбординг |
| Членство и роль | `Membership` (`OWNER`, `MANAGER`, `STAFF`; `ACTIVE`/`SUSPENDED`) | доступ человека в организацию | регистрация (OWNER), приглашение |
| Область | `MembershipScope` | сужает членство до бизнеса или филиала | владелец, управляющий |
| Сотрудник как рабочая карточка | `Employee` (`userId` необязателен) | мастер, официант; логина сам по себе не даёт | чат №2 |
| Клиент бизнеса | `Customer`, `Guest` | посетитель; учётной записи и входа у него нет | чат №1 |
| Главный администратор | `PlatformAdmin` | раздел «Платформа» | только команда на сервере |
| «Проект», `projectId` | нет такого понятия в коде | | не вводить |

Три вида людей (владелец 16.10.2026: «у клиента свой аккаунт, у руководителя свой, у сотрудников свои»):

- **Руководитель** (владелец, управляющий): `User` + `Membership` `OWNER`/`MANAGER`, разделы управления.
- **Сотрудник**: `User` + `Membership` `STAFF` (часто с областью), свои разделы; «Моя работа» (`/my-work`, `/employee-portal/me`)
  находит его карточку только по `Employee.userId = текущий пользователь` в выбранном бизнесе.
- **Клиент бизнеса**: сейчас **без аккаунта**. Видит только публичные проекции (`/w/*`, формы сайта, `/specialists/:slug`).
  Будущий клиентский вход это отдельное направление (Q-AUTH-1, `docs/client-account-proposal.md`, не утверждено);
  к контуру этого документа он не относится.

## 2. Контекст запроса (как сервер решает «кто и где»)

1. Ключ сессии: заголовок `Authorization: Bearer` или `x-wetop-session` (стойка шлёт его со своего сервера из HttpOnly
   куки `wetop_session`). Браузер к API напрямую не ходит.
2. **Организация берётся только из строки сессии** (`sessions.organization_id`). Клиент организацию не выбирает ни
   заголовком, ни телом, ни адресом. Сменить её можно только `POST /auth/organization` (новый ключ, см. §4).
3. Бизнес и филиал: заголовок `X-Wetop-Scope: business=<uuid>;location=<uuid>` (стойка берёт из куки `wetop_scope`).
   Это **выбор, а не право**: сервер проверяет, что бизнес принадлежит организации сессии и активен, филиал принадлежит
   бизнесу, а у человека с областью есть назначение. Чужой, архивный или битый указатель: 403 на маршрутах человека.
4. Каждый маршрут API обязан иметь `@Access(<право>)` или `@Public()`; таблица прав в `apps/api/src/auth/route-access.test.ts`.
   Новый маршрут без строки в этой таблице роняет тест.
5. RLS: запрос с организацией идёт ролью `wetop_app` с `app.org_id` из сессии. Проверять изоляцию тестом под суперпользователем
   нельзя: только через `tests/integration/core-security/scope-world.ts` (настоящий `AppModule`, роль `wetop_app`).

## 3. Что соседям можно и нельзя

- **Чат №1.** Не превращать `Customer`/`Guest` в `User`. Карточки, историю и связь «список → запись → карточка» внутри
  разрешённого бизнеса делать сейчас поверх `Customer`/`Guest`, не дожидаясь клиентского входа. Публичные маршруты отдают
  только белую проекцию. Никакой связи клиента с записью по совпадению телефона или почты (`client-account-proposal.md` §9).
- **Чат №2.** Рабочая карточка (`Employee`) отдельно от учётной записи. Привязка `Employee.userId` только существующим
  приглашением и действием руководителя (`PUT /employee-portal/employees/:id/account`), не по совпадению почты. Второй
  каталог сотрудников не заводить; роли и права ролей не переопределять: матрица в
  `packages/domain/src/accounts/permissions.ts` (§16.5).
- **Чат №3.** Формы входа, регистрации, сброса и подтверждения уже общие для трёх направлений: не копировать. После входа
  все пути идут через `/scope/resolve`. Онбордингу контекст передаётся только сессией и указателем филиала. Переход между
  организациями готов (§4): в шапку можно поставить ссылку на «Профиль → Доступ» или ту же форму.
- **Чат №5.** Кнопки сайта ведут в готовые маршруты (§6), своих форм входа и регистрации на сайте не заводить сверх диалога
  `apps/site/src/components/auth-dialog.tsx`.

## 4. Новое в этой ветке

| Что | Контракт |
|---|---|
| `GET /auth/organizations` (`self`) | `{ organizations: [{ id, name, role, current }] }`: действующие членства в неархивных организациях |
| `POST /auth/organization` (`self`) | тело `{ organizationId }`; 201 `{ token, expiresAt, user }`, прежний ключ погашен, срок тот же; 403 чужой, архивный, битый номер; 401 сессия не годится |
| стойка `POST /auth/organization` (обработчик маршрута) | форма `organizationId`, проверка `Origin`, 303 на `/scope/resolve?next=/today` с новой кукой; ошибка: 303 на `/profile/access?org=denied|signin|failed` |
| «Профиль → Доступ» | список «Ваши организации», когда их больше одной |
| Вход | открывает первую по времени **действующую** организацию, архивные пропускает |
| Отключение сотрудника, архив организации | гасят строки сессий сразу (как приостановка) |
| Адрес в письмах | одно правило: `PUBLIC_APP_URL`, иначе `APP_URL`, иначе `https://app.wetop.ai` |

Меню переключения организаций в шапке (рядом с выбором филиала) это зона чата №3: API и форма готовы, достаточно
показать ссылку на «Профиль → Доступ» или ту же форму в меню профиля.

## 5. Ошибки (что видит человек)

| Ситуация | Код | Текст |
|---|---|---|
| неверная почта или пароль, неизвестный, заблокированный, запертый | 401 | один текст на все случаи |
| почта не подтверждена (пароль верный) | 403 | «Почта не подтверждена…» и кнопка выслать письмо |
| доступ приостановлен | 403 | «Доступ приостановлен. Обратитесь к владельцу или управляющему организации.» |
| организация в архиве | 403 | «Доступ вашей организации приостановлен. Обратитесь в поддержку WETOP.» |
| «Забыли пароль», повтор письма | 200 | нейтральный ответ, существование почты не раскрывается |
| регистрация на занятую почту | 400 | прямо: адрес занят (осознанно, ADR-053) |
| чужой указатель филиала | 403 | раздел недоступен; данные не отдаются |
| переход в чужую организацию | 403 | «Эта организация вам недоступна» |

Пароли, ключи сессий, токены ссылок и куки в журнал и отчёты не пишутся.

## 6. Куда ведут вход, регистрация и приглашение

| Действие | Адрес | Что дальше |
|---|---|---|
| «Войти» | `wetop.ai/#login` (диалог), без JS `app.wetop.ai/auth/fallback` | `/scope/resolve?next=<безопасный путь>` → филиал → раздел направления |
| «Регистрация», «Попробовать бесплатно», «Начать» | `wetop.ai/#register[?vertical=HOSPITALITY|BEAUTY|FOOD_SERVICE]`, без JS `…/auth/fallback?mode=register` | письмо → `/login/verify?token=` → `/register/setup` (салон, ресторан) или `/today` (гостиница) |
| «Забыли пароль» | `app.wetop.ai/login/reset` | письмо → `/login/set-password?token=` → `wetop.ai/?password=set#login` |
| Приглашение | `app.wetop.ai/invite/<token>` → «Принять» | новый человек: `/login/set-password`; уже есть пароль: вход |
| Другая организация | «Профиль → Доступ» → «Перейти» (форма на `/auth/organization`) | `/scope/resolve?next=/today` |
| Выход | меню профиля → «Выйти» | сессия отозвана в базе → `wetop.ai/?next=/today#login` |

Состояния доступа, которые видит стойка: нет сессии, истекла, отозвана или приостановлено членство → любая защищённая
страница ведёт на `wetop.ai/?next=<путь>#login` (проверено в браузере 17.10.2026); почта не подтверждена, доступ
приостановлен, организация в архиве → текст в диалоге входа (§5); указатель филиала чужой или устарел → `/scope/resolve`.
Отдельного сообщения «сеанс истёк» диалог сейчас не показывает (замечание для чата №5, не ошибка доступа).
