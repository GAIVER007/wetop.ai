# Приёмка реального входа и писем после публикации (пакет авторизации)

Выполняется **только после** отдельно разрешённой выкладки кандидата с этим пакетом. Проверять старый код production
этим сценарием бессмысленно: исправления пакета там ещё нет. Агент эти шаги не выполняет: нужны реальные письма и
production-аккаунты, на них разрешения нет.

## Что нужно заранее (допуски, без паролей и токенов в чате)

| Что | Кто даёт |
|---|---|
| Разрешение на выкладку кандидата и на создание тестовых аккаунтов в production | владелец |
| Два-три тестовых почтовых ящика под контролем владельца (например `pilot-owner@…`, `pilot-staff@…` на своём домене); адреса называются в чате, пароли от ящиков нет | владелец |
| Отдельная тестовая организация салона (создаётся регистрацией в шаге 1), которую потом можно убрать в архив | владелец |
| На сервере заданы `MAIL_PROVIDER`, `MAIL_API_KEY`, `MAIL_FROM` и одна из `PUBLIC_APP_URL`/`APP_URL` = `https://app.wetop.ai` | выпускной ответственный проверяет по `.env` сам, значения агенту не показывает |
| Доступ к журналу провайдера почты (Resend), чтобы видеть «принято провайдером» | владелец |

## Сценарий (два браузера: А обычный, Б другой или приватное окно)

| # | Шаг | Ожидаемо |
|---|---|---|
| 1 | А: `https://wetop.ai/?vertical=BEAUTY#register`, регистрация на ящик владельца | «Проверьте почту», без ошибки |
| 2 | Письмо «подтвердите почту» открыть в **Б** | ссылка ведёт на `https://app.wetop.ai/login/verify?...`, открывается настройка салона |
| 3 | А: вход тем же паролем | та же организация, `/register/setup` или «Сегодня» салона |
| 4 | Владелец: «Сотрудники» → пригласить ящик сотрудника администратором | приглашение в списке |
| 5 | Письмо приглашения открыть в Б, «Принять», задать пароль, войти | вход в **тот же** салон, роль администратор, своей организации у сотрудника нет |
| 6 | Б: «Забыли пароль» для сотрудника, письмо, новый пароль | старый пароль не входит, новый входит в тот же салон |
| 7 | Б: «Выйти», затем открыть `https://app.wetop.ai/today` | вход, данных нет |
| 8 | Владелец приостанавливает сотрудника, пока у сотрудника открыта вкладка; сотрудник обновляет страницу | вход; при входе «Доступ приостановлен…» |
| 9 | Владелец возвращает доступ | сотрудник снова входит в тот же салон |
| 10 | Сравнить номера: в «Профиль → Доступ» организация и салон те же, что после шага 3 | номера не изменились |

## Как записывать результат (для каждого письма отдельно)

| Письмо | Запрос принят приложением | Принято провайдером | Получено адресатом | Ссылка отработала | Доступ верный |
|---|---|---|---|---|---|
| подтверждение почты | | | | | |
| приглашение | | | | | |
| восстановление пароля | | | | | |

«Принят приложением» это ответ формы без ошибки. «Принято провайдером» это запись в журнале Resend. Остальное видно глазами
в ящике и в стойке. Письмо в локальном файле стенда и ответ HTTP 200 эту цепочку не заменяют.

## После проверки

Тестовую организацию убрать в архив («Настройки → Организации»), тестовые ящики не использовать для клиентов.
