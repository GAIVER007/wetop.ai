# Beauty workload: сохранённая плановая история

Локальный backend-срез, не разрешение релиза. Основание: утверждённый план `plans/unified-owner-accounting-2026-10-16.md` §4, BOOKED_SCHEDULE. Held migration 117 требует ранее применённой 116 (`restaurant_local_instant`).

## Источник и запись

`BEAUTY_WORKLOAD_CAPTURE=true` включает сбор в существующей `beautyTransaction`: график, интервалы отсутствия, назначения и статус мастера сохраняются атомарно с действием. Сохраняются нормализованные интервалы активных мастеров на текущую локальную дату и 31 день вперёд. SQL-триггеры продолжают сбор для уже наблюдаемого филиала. Отдельные append-only revisions записи сохраняют время, мастера и статус при INSERT/изменении. Первая фиксация существующих записей — observedAt, не createdAt.

`GET owner-summary` читает сохранённые версии, не сегодняшний mutable-список мастеров/графика. Для каждой локальной даты берётся последняя известная к этой дате версия графика; для записи — последняя revision до конца этой даты и не позже времени запроса. Поэтому последующая отмена/перенос не стирает закрытые даты. Публичного backdated correction API этот срез не вводит.

## Формула и полнота

basis `BOOKED_SCHEDULE`, unit `EMPLOYEE_MILLISECOND`. Числитель — union BOOKED/CONFIRMED/DONE отдельно по мастеру, пересечённый с сохранёнными доступными интервалами; CANCELLED/NO_SHOW исключены. Знаменатель — union доступных интервалов по мастеру. Сегодня используется вся плановая смена, не только часы до now. Итоги периода — отношение сумм длительностей, не среднее процентов.

История до observedAt не объявляется известной: первая дата PARTIAL, percent=null, хотя плановая смена текущей даты берётся целиком. Нет сохранённой истории: UNAVAILABLE/HISTORY_NOT_CAPTURED. Истёкший 31-дневный горизонт без новых наблюдений оставляет пробел; отсутствующий источник не превращается в ноль. При выключенном флаге — CAPTURE_DISABLED. Нулевой знаменатель — NO_SCHEDULE, не 0%.
