# Owner summary: фактический контракт, 16.10.2026

GET /owner-summary?period=today|week|month (по умолчанию today). Только проверенный LOCATION, сессия и reports; организация и филиал не принимаются от клиента. Неподдерживаемое направление не подменяется гостиницей.

Источник: apps/api/src/finance/owner-summary.ts, owner-money.ts, beauty/workload.ts, food-service/workload.ts, hospitality/workload.ts. sourceVersion=owner-cash-foundation-v1, state=PARTIAL, generatedAt UTC; scope={locationId,organizationId,vertical}. period={key,timezone,fromDate,toDate,fromUtc,toUtc,isFinalized:false}. today начинается в местную полночь, week включает сегодня и 6 предыдущих дат, month начинается первого числа текущего календарного месяца; денежный конец generatedAt.

current.revenue и current.receipts: {state:READY|PARTIAL,reason:null|UNKNOWN_SOURCE_CURRENCY,unresolvedSources:number,currencies:[{currency,amountMinor:string}]} либо {state:UNAVAILABLE,reason,currencies:null}. current.paidExpenses аналогичен, но currencies=[{currency,paidMinor:string,categories:[{categoryId:string|null,categoryName:string,paidMinor:string}]}]. Строки minor units суммируются BigInt, валюты не складываются. Пустая корзина не доказывает нулевой итог. PARTIAL показывает только известную часть.

BEAUTY revenue: DONE appointments по startsAt, сохранённые price/currency; receipts недоступны PAYMENT_LEDGER_NOT_AVAILABLE. FOOD_SERVICE revenue: CLOSED orders по closedAt плюс POSTED bar sales; receipts: COMPLETED restaurant payments плюс bar sales, без повторного cash. HOSPITALITY revenue: неаннулированные charges по serviceDate и folio currency, созданные до generatedAt; receipts: COMPLETED payments плюс COMPLETED INCOME cash. Историческая валюта гостиничного cash отсутствует, строки unresolved, не текущая Property.currency. Расходы: только COMPLETED EXPENSE cash, не закупочные обязательства, COGS, переводы или бюджеты.

workload имеет state COMPLETE|PARTIAL|UNAVAILABLE, reason:string|null, numerator:string|null, denominator:string|null, percent:number|null, coverage:array и basis. BEAUTY basis=BOOKED_SCHEDULE, unit=EMPLOYEE_MILLISECOND, сохранённые расписания и ревизии записей; requestedFromUtc/requestedToUtc до конца текущей местной даты. FOOD_SERVICE basis=ACTUAL_TABLE_OCCUPANCY, unit=TABLE_MILLISECOND; фактическая занятость и сохранённая доступная мощность до generatedAt. coveredPercent ресторана относится только к покрытой части, не к целому периоду. Только COMPLETE и ненулевой знаменатель дают итоговый percent, отношение сумм мощностей, не среднее процентов. PARTIAL percent=null, причины видны пользователю. CAPTURE_DISABLED не является нулевой загрузкой.

HOSPITALITY basis=SELLABLE_NIGHTS; requestedFromDate/requestedToDate, funds=[{unit:ROOM_NIGHT|BED_NIGHT,state:PARTIAL|UNAVAILABLE,numerator,denominator,percent:null}]. Корневые numerator/denominator/percent=null. Номера и койки не смешиваются; наблюдения не доказывают полную историю (OBSERVED_SOURCE_NOT_COMPLETE_HISTORY). При отключённом захвате или отсутствии property funds=[], reason=CAPTURE_DISABLED_OR_NO_PROPERTY. Неизвестное направление: UNAVAILABLE/UNSUPPORTED_VERTICAL.

previous теперь содержит period и те же revenue/receipts/paidExpenses (включая daily и категории); при невозможном календарном соответствии previous=null с comparisonReason. Дневные ряды подключены (контракт ниже). Классификация включается только EXPENSE_LINKS_ENABLED=1: expense_settlements → expense_documents → expense_categories обогащает уже отобранные канонические COMPLETED EXPENSE, не добавляя суммы документов или обязательств. Связи ограничены выбранными locationId и organizationId; идентичность источника — sourceType + sourceId. Архивная статья сохраняется; categoryName — текущее сохранённое имя статьи, не исторический снимок. categoryId=null, categoryName=«Без статьи» обозначают неподтверждённое назначение, не «Прочее». По каждой доказанной валюте сумма categories.paidMinor равна paidExpenses.paidMinor, VOIDED не участвуют. Гостиничная категория не доказывает историческую валюту: даже связанный cash остаётся unresolved и не образует валютную сумму.

classificationState=UNAVAILABLE и classificationReason=EXPENSE_DOCUMENT_LINKS_NOT_CONNECTED при выключенном флаге: запрос к таблицам expense links вообще не выполняется. При включённом флаге для поддерживаемого направления classificationState=PARTIAL/reason=UNCLASSIFIED_EXPENSE_SOURCES, если хотя бы один выбранный источник без статьи; иначе READY/reason=null (в том числе при пустом наборе). Для неподдерживаемого направления с включённым флагом UNAVAILABLE/UNSUPPORTED_SOURCE. Готовность классификации не означает готовность денежных итогов или всей сводки. UI показывает сохранённые имена с обычным React escaping, не придумывает категорий, линий, сравнения или задач. Единицы мощности API остаются миллисекундами, UI показывает минуты мастеров/столо-минуты; номеро-ночи и койко-ночи не преобразуются.

## Дневные деньги, срез 16.10.2026
Каждая поддерживаемая денежная метрика current содержит daily={state,reason,unresolvedSources,currencies:[{currency,amountMinor}],days:[{date,unresolvedSources,currencies:[{currency,amountMinor}]}]}. В paidExpenses.daily итог называется amountMinor, в самом KPI paidMinor. Недоступные revenue/receipts: daily={state:UNAVAILABLE,reason,currencies:null,days:null}; салонные поступления не превращаются в нули. Web DTO допускает отсутствие daily для старого ответа и показывает явную недоступность.

Даты от period.fromDate до period.toDate включительно. timestamp группируется в timezone проверенного филиала; гостиничный serviceDate остаётся DATE без сдвига. Все события ограничены period.toUtc соответствующего current/previous, не временем формирования ответа. Использованы те же один раз прочитанные canonical rows, без запроса на каждый день. Источник дедуплицируется sourceType:sourceId; категории обогащают те же расходы. Сумма дневных amountMinor каждой известной валюты равна текущему KPI. Нули заполняют только пропущенные даты реально обнаруженной валюты, неизвестная валюта остаётся PARTIAL с unresolvedSources. Без известной валюты корзина пуста.

SSR SVG использует общую lineGeometry. Только относительные ограниченные координаты после BigInt-нормализации преобразуются в Number; подписи, итоги и доступная таблица остаются точными. Валюты переключаются нативными details с одним name, без конвертации и клиентских запросов. Сегодня содержит одну точку, не интерполяцию по часам. Загрузка не добавляется в денежную ось. Ошибки запроса сохраняют существующее состояние ошибки страницы.

## Hotel cash currency: выполненный срез 16.10.2026

Оба owner-reader читают доказанный currency_snapshot, текущий KPI и daily получают одинаковые источники. Tenant scope проверяется по property/location/organization. Через to_jsonb(c) отсутствие held-колонки безопасно; при выключенном EXPENSE_LINKS_ENABLED snapshot не используется, историческая неизвестность остаётся PARTIAL. Property.currency не заменяет валюту прошлого.

Новые FinanceRepository INCOME/EXPENSE, комиссия и поправка сверки, а также обе гостиничные bar cash ветки используют единый insert-only writer. При включённом флаге валюта проверенного объекта блокируется FOR SHARE и записывается сразу в INSERT в исходной транзакции; суммы/правила не менялись. Выключенный флаг сохраняет прежний Prisma writer без обращения к held-колонке. Held114 дополнен запретом UPDATE snapshot, включая NULL; автоматического backfill нет. При откате сохранять совместимые writers и этот guard: старый supplier UPDATE после INSERT несовместим с новым guard.

Доказательства: RED integration d8f0 (UNKNOWN_SOURCE_CURRENCY вместо USD); GREEN полный owner-money-isolated 6/6 без skips `2026-10-16T09-59-17Z-integration-f551`; impacted unit 19/19 `09-59-22Z-unit-3ed0`; root/API/web types `09-59-27Z-typecheck-dfc6`. ## Read-only V4 publication clarification, 17.10.2026

This section supersedes only the earlier blanket rollout restriction for the bounded read-only presentation release (OWNER-HOME-READ-ONLY-20261017 in DECISIONS.md). It does not weaken acceptance of the separate full financial/capture release or authorize migrations-hold in production.

The versioned web deployment default is now `APP_UNIFIED_OWNER_HOME=true`; explicit `0` and `false` remain effective opt-outs. The accepted shared Main is selected only for signed-in, reports-authorized users with a verified selected location. Existing 403/non-reports dispatch and `/today/operations` remain unchanged. No global first-hotel fallback, permissions expansion, accounting changes, backfill or new money writes are introduced.

Canonical source reads support this presentation with `EXPENSE_LINKS_ENABLED=0` and BEAUTY_WORKLOAD_CAPTURE, HOSPITALITY_WORKLOAD_CAPTURE, RESTAURANT_CAPACITY_CAPTURE, RESTAURANT_OCCUPANCY_CAPTURE all `false`. Held tables and hotel cash.currency_snapshot are not prerequisites of this mode. Unknown historical currency remains PARTIAL/UNKNOWN_SOURCE_CURRENCY, not a zero or current-property-currency estimate. Workload and expense classification remain explicitly unavailable with their reasons. This is not a promise of complete financial data or a redesigned non-reports home.

The release gate now invokes a guarded real OwnerSummaryService baseline before held SQL: three verticals times three periods, genuine wetop_app RLS, negative scope/permission cases, real source amounts and rollback-only synthetic fixtures. It also runs the existing three flag-on owner-home HTTP/database/browser tests and rejects missing, skipped or flaky execution using their JSON report. Both new real-runtime gates are pending CI, not locally executed evidence. Normal candidate/main checks and automatic release must pass, followed by authenticated live verification of the published revision, effective flags, shared Main and operational links; an existing explicit runtime OFF requires an authorized operator, not an override here.
