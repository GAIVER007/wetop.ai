# Путь изменений в main: проверка до слияния, общие правила в AGENTS.md, файлы на задачу

Дата: 19.10.2026. Основание: разбор ментора от 19.10.2026 и поручение владельца «сделай всё ровно так, как в ТЗ».

**Проблема.** С 12.10 в `main` влито около 270 запросов, гейт `release-checks` шёл только после слияния (на `main` 29
зелёных прогонов, 103 красных, около 140 отменённых), `release` отставал почти на сто коммитов. Общие файлы правила
каждая задача. Codex и Hermes не читают `CLAUDE.md`, а общие правила лежали там. Открытый репозиторий содержал адрес
боевого сервера, порт SSH и вход под root.

**Варианты по репозиторию.** Закрыть (нужен GitHub Pro для защиты ветки, минуты платные) или оставить открытым и
убрать сведения о сервере. Владелец 19.10.2026 сначала оставил открытым, затем тем же днём закрыл и берёт оплату
Actions на себя. Сведения о сервере убраны в любом случае: репозиторий уже был открытым.

**Решение.**

1. Сведения о сервере (адрес, имя хоста, порт SSH, имя ключа) заменены подстановками во всём текущем дереве;
   сторож сервера берёт имя хоста из `.env` (`WATCH_HOST`). История git их помнит: переписывание истории не делалось.
2. На каждом запросе в `main` идёт быстрая часть `release-checks` (lint, typecheck, unit), полный прогон на `main`;
   `release` двигает только прогон от пуша в `main`. «Вливаем только зелёное» держит ответственный за `main`
   (AGENTS.md §18).
3. Общие правила перенесены из `CLAUDE.md` в `AGENTS.md` (§20-§28), `CLAUDE.md` начинается с `@AGENTS.md`.
4. `DESIGN.md` сокращён до §0 и §2-§8 (378 КБ → 114 КБ); остальное в `docs/design/`; сторож реестра компонентов.
5. Логи и записи прогонов больше не коммитятся; решения пишутся файлом на задачу в `docs/decisions/`.

**Последствия.** Запрос с кодом ждёт быструю часть (минуты, не 40); UI и база ловятся только на `main`.
Раздел `§1` и `§9-§18` `DESIGN.md` лежат в `docs/design/desk-rules.md` и действуют как прежде. `test:status` видит
только прогоны своей машины.
