# «Сколько принёс сотрудник» во всех направлениях

Дата: 20.10.2026. Ветка `hermes/personnel-revenue-20261020`. План: `plans/personnel-revenue-2026-10-20.md`.

**Проблема.** Только у ресторана в «Сотрудниках» была колонка «Продажи сегодня» (сумма заказов, не оплаты).
Владелец: «почему только у ресторана… чтобы видеть сколько какой сотрудник принёс… под все вертикали».

**Развилки и ответы владельца (clarify 20.10.2026).**
- Что считать: начислено / **оплачено, возвраты вычитаются** / обе цифры. Выбрано: оплачено минус возвраты.
- Период: сегодня+месяц / только сегодня / **переключатель день, неделя, месяц**. Выбран переключатель.
- Салон, несколько мастеров в записи: **пропорционально цене их услуг** / всё первому / отдельной строкой. Выбрано
  пропорционально.
- Гостиница, кто «принёс» бронь: **кто создал бронь в системе (журнал, и для старых броней)** / явное поле
  «ответственный» / оба. Выбран создавший по журналу.
- Гостиница, где показывать: **«Персонал → Сотрудники» (/team)** / новый экран «Специалисты» / отчёт. Выбран /team.

**Решение.** Свод считается на лету из существующих таблиц (оплаты, возвраты, строки записи, официант заказа, журнал
создания брони), новых полей и миграций нет. Оплата и возврат относятся к периоду по моменту денег (оплаты
`paid_at`/`occurred_at`, возврата `created_at`/`occurred_at`), окно периода по часам филиала или объекта, неделя с
понедельника. Деление пропорционально в целых тиынах, остаток крупнейшим остаткам. Деньги без привязки к человеку
(заказ без официанта, бронь из канала или сайта) показываются отдельной строкой, а не теряются.

**Причина.** Владелец хочет видеть вклад каждого сотрудника в одной системе для всех направлений.

**Последствия.** Колонка ресторана «Продажи сегодня» (сумма заказов) заменяется на «Принёс» (оплачено минус возвраты) с
периодом. Бронь, созданную одним человеком и изменённую другим, приносит создавший. Чтобы перенести бронь на другого,
потребуется отдельное решение и поле «ответственный» (не сделано).
