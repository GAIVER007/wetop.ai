# 21.10.2026: «Требуют решения» на Главной владельца

## Проблема

На общей Главной (`/today`, `APP_UNIFIED_OWNER_HOME=true`) блок «Требуют решения» показывал две общие строки о
расчётах («Загрузка рассчитана…», «Проверьте оплаченные операции…»). Дел в них не было.

## Варианты

1. Оставить общие строки.
2. Считать дела в браузере из уже загруженных экранов (журнал, зал, брони).
3. Считать дела в API в ответе `GET /owner-summary` полем `attention`, из существующих таблиц, без миграций.

## Решение

Вариант 3. `apps/api/src/finance/owner-attention.ts` (`readOwnerAttention`) читает только выбранный филиал
(`locationId`, бизнес филиала, объект гостиницы через `location.property`), всегда за СЕГОДНЯ по поясу филиала,
независимо от периода. Права те же, что у сводки (`reports` на филиале). Слова, порядок (предупреждения первыми) и
предел 4 строки: `packages/domain/src/owner-summary/attention.ts` (`ownerAttention`). Сбой одного источника убирает
только его строку.

Сигналы:

| Направление | Текст | Ссылка | Правило |
|---|---|---|---|
| Салон | «Не оплачено сегодня: N записей» | `/calendar` | запись DONE сегодня, оплачено (приходы COMPLETED) меньше цены |
| Салон | «Свободные окна: N мастеров» | `/calendar` | активный мастер филиала без отсутствия, есть окно от 2 ч подряд от «сейчас» до конца смены (часы мастера ∩ режим салона); «другой сотрудник» не считается |
| Ресторан | «Открыты дольше 2 ч: N счетов» | `/floor-plan` | заказ филиала NEW/COOKING/READY/SERVED, открыт больше 2 ч назад |
| Гостиница | «N заездов, не убрано: M номеров» | `/inventory?housekeeping=DIRTY` | брони TENTATIVE/CONFIRMED с заездом сегодня; места объекта DIRTY (у койко-мест «мест»). Номера убраны: спокойная строка «N заездов сегодня, номера убраны» → `/reservations?arrival=today`. Без заездов: «Не убрано: M номеров» |
| Гостиница | «N броней без предоплаты» | `/reservations?from=…&to=…+7&date=arrival&payment=unpaid` | заезд в ближайшие 7 дней, к оплате больше нуля и оплат нет (то же правило, что отбор «Не оплачено») |
| Все | «Заканчивается: N позиций» | `/warehouse` | правило «Обзора склада»: бар при остатке не выше минимума, кухня/расходники ниже минимума |
| Все | «Есть расходы без статьи» | `/finance` или `/restaurant-finance` с периодом | только при `classificationReason = UNCLASSIFIED_EXPENSE_SOURCES` |
| Все | «Срочных дел нет» (действие «Открыть день», чтобы не повторять кнопку шапки «Рабочий день») | `/today/operations` | хотя бы один сигнал прочитан и все равны нулю |

Старые строки о загрузке и статьях расходов удалены. Если API не прислал `attention` (старый API) или ни один
источник не прочитан, блок пишет «Сигналы дня пока недоступны» со ссылкой на рабочий день, «всё хорошо» не обещает.

## Пропущено

- Нет. Все предложенные сигналы считаются из существующих таблиц, миграций и новых таблиц нет. Склад у гостиницы
  тоже показан (бар объекта), хотя в задании его не было.

## Последствия

- Ответ `/owner-summary` получил поле `attention`; поле необязательное в типе web.
- Ссылки короткие (Журнал, Зал, Номера, Брони, Склад, Разобрать), тексты до ~30 знаков: в колонке 1280 строка влезает без многоточия.
- Строка в одну линию с многоточием (`.owner-todo span`), не больше 4 строк: Главная остаётся на одном экране 1280x720.
- Порог окна 2 ч, счёт дольше 2 ч и горизонт 7 дней заданы константами в домене; менять там.
