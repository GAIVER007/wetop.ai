# Безопасность: Node закреплён точной версией, уязвимые пакеты обновлены

Дата: 21.10.2026. Поручение владельца: проверить проект и сервер на уязвимости, затем «продолжай, делай, что надо».
Отчёт: `workspace-cleanup-control/reports/vuln-audit-2026-10-21.md` (вне репозитория).

## Проблема
- Образы сервера (`deploy/Dockerfile`, сторож и наблюдатель) собирались с плавающего тега `node:24-alpine`: точная
  версия Node на стойке не видна и меняется при каждой пересборке. В CI по `.nvmrc` = `24` оказалась 24.22.0;
  безопасный выпуск 24.22.1 (выпуск безопасности Node от 21.10.2026).
- `npm audit`: 7 high и 3 moderate в пакетах разработки и сборки (prisma CLI через deepmerge-ts и mysql2, vite,
  vitest, lodash, brace-expansion, fast-uri). В рабочих зависимостях (`--omit=dev`) уязвимостей не было.

## Решение
- `node:24.22.1-alpine` во всех трёх Dockerfile, `.nvmrc` = `24.22.1`. Сторож `tests/unit/runtime-pins.test.ts`:
  тег с точной версией, не ниже 24.22.1. Минимум поднимается в нём при следующем выпуске безопасности.
- `npm audit fix` без мажорных версий: prisma 7.10.1, vite 8.3.5, vitest 5.0.5, lodash 4.18.1, mysql2 3.24.4 и др.
  `@prisma/client` и `@prisma/adapter-pg` подняты до 7.10.1 вместе с CLI, чтобы клиент и генератор были одной
  версии. Итог `npm audit`: 0.

## Что не входит
Docker и containerd на сервере, libnss3, Node хоста и Caddy, закрепление тегов cloudflared/traefik/redis/pgvector:
вне репозитория или требуют перезапуска служб, только по отдельному поручению владельца, по одному пункту.

## Последствия
Пересборка образа даёт ту же версию Node. Новый выпуск безопасности: поднять тег, `.nvmrc` и минимум в стороже.
