# Код подтверждения почты при регистрации и подсказка надёжности пароля

Дата: 22.10.2026. Ветка: `feat/registration-email-code-20261022`.

## Проблема

После регистрации человек получал письмо только со ссылкой: нужно было уйти в почту, нажать ссылку и вернуться на сайт.
Владелец 22.10.2026 предложил код в письме, который вводится в том же окне.

## Варианты

1. Код при регистрации, ссылка остаётся в том же письме запасным путём.
2. Только код, ссылку убрать.
3. Код при каждом входе (пароль и код, настоящая двухфакторная проверка).

## Решение

Владелец выбрал вариант 1: «Только при регистрации: код вместо ссылки, ссылку оставить в том же письме как запасной
вариант». Обычный вход остаётся почтой и паролем: ADR-053 в силе, код только подтверждает почту.

- Письмо одно: шесть цифр (и в теме, чтобы видно в уведомлении телефона) и прежняя ссылка на 72 часа.
- Код действует 15 минут. Пять неверных попыток гасят код в базе (`used_at`), перезапуск API его не оживляет;
  ссылка из письма при этом остаётся. Повторное письмо выдаёт новый код и гасит прежний, не чаще раза в минуту
  (прежний предел). По адресу посетителя общий предел с переходом по ссылке: 30 в час.
- Ответ на неизвестную почту, уже подтверждённую, заблокированную и неверный код один: «Код не подошёл».
- В базе только отпечаток `sha256("email-code:<userId>:<code>")` в существующей таблице `email_verifications`.
  Новой миграции нет: код от ссылки отличает префикс отпечатка и срок 15 минут. Код заводится на миллисекунду
  раньше ссылки, чтобы окно повторного перехода по ссылке (ADR-095) по-прежнему смотрело на последнюю ссылку.
- Успешный код гасит и ссылку того же письма: подтверждение одно.
- Маршруты: API `POST /auth/email/verify-code` (публичный, ответ как у входа), окно сайта
  `POST /api/site-auth/verify-code` (кука сессии тем же ответом), экран стойки `/login/check-email` получил поле кода.
- Под полем нового пароля в окне регистрации подсказка надёжности: полоска из четырёх делений и список условий.
  Обязательные условия прежние и проверяет сервер (не короче 10 знаков, не только цифры). Остальные пункты только
  поднимают оценку. При входе подсказки нет.
- Образцы владельца были на Tailwind и `motion`. На сайте их нет, поэтому компоненты собраны на CSS-модулях без
  новых пакетов; при «уменьшить движение» анимаций нет.

## Причина

Короче путь до первого входа без нового риска: код короткий, но живёт 15 минут, гаснет после пяти ошибок, хранится
отпечатком и привязан к человеку. Схема данных не меняется, поэтому выпуск не ждёт миграций 132–137.

## Последствия

- Письмо подтверждения теперь с кодом в теме. Тексты окна сайта и экрана `/login/check-email` говорят про код.
- Форма оплаты картой, присланная владельцем тем же днём, сюда не входит: карту на своей странице собирать нельзя
  без PCI DSS, платёж идёт через страницу провайдера. Это отдельный вопрос.
