# UI-стенд убирает свою временную копию после прогона

Дата: 22.10.2026. Ветка `task/ui-runtime-cleanup-20261022`.

## Проблема
`tests/ui/isolated-workers.ts` на каждый прогон `tests/ui` создаёт рядом с деревом копию `.wetop-main-ui-*`
(тесты, apps/web, apps/site, apps/sites: около 56 МБ) и не удаляет её. На сервере к 22.10.2026 их набралось 20,
скрипт создания рабочих деревьев считает их деревьями проекта (у копии есть `apps/` и `package.json`), лимит 10
оказался занят, новое дерево не создать.

## Варианты
1. Чистить вручную после прогонов: забывается, копии копятся снова.
2. Класть копии в /tmp: проверка `UI_RUNTIME_PARENT must contain the repository checkout` это запрещает, Next.js
   (turbopack root) требует общего предка с деревом.
3. Удалять копию при завершении процесса, который её создал.

## Решение
Вариант 3. `removeOnExit`: `process.once('exit')` в процессе, создавшем копию (главный процесс Playwright).
Исполнители получают копию через `UI_ISOLATED_RUNTIME_ROOT` и её не удаляют. `rmSync` не идёт по символическим
ссылкам, поэтому node_modules, packages, scripts и tests/* исходного дерева не затрагиваются. Путь проверяется:
только `UI_RUNTIME_PARENT/.wetop-main-ui-*`. `UI_KEEP_RUNTIME=1` оставляет копию для разбора.

## Последствия
- Прогон, успешный или упавший, больше не оставляет копию. Проверено на сервере: зелёный и красный прогоны
  `settings-hub.spec.ts`, новых `.wetop-main-ui-*` нет.
- Отчёты Playwright (`test-results`) пишутся в исходное дерево, их это не касается.
- Уже накопленные копии убираются отдельно, по правилам уборки workspace.
- Сторож `tests/unit/ui-runtime-cleanup.test.ts`: красный до правки, зелёный после.
