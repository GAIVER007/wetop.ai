# Окно брони одного вида во всех направлениях (23.10.2026)

**Решение владельца:** вариант B из трёх эскизов («форма слева, свободные номера справа»), и тот же вид для салона и ресторана: «везде должно быть такое окно брони как единое».

Замечания владельца к эскизу:
- «Тариф» непонятен. При одном тарифе поле скрыто, цена считается по нему. При нескольких поле называется «Цена по тарифу».
- Сначала имя, потом телефон. Порядок одинаковый во всех трёх окнах.
- Салонное окно «Новая запись» выглядело криво (широкие пустые ряды, поиск клиента отдельно от выбора). Теперь оно в том же каркасе.

## Каркас

`apps/web/src/components/booking-shell.tsx` + `apps/web/src/app/booking-shell.css`:
- `BookingShell`: слева `form`, справа `pick` (`role=region` с именем), снизу липкий `footer`;
- `PickHeading`, `PickGroup` (группа: категория, специалист, зал; неподходящая серая с причиной), `PickButton` (номер, время, стол; `aria-pressed`, точка внимания), `BookingFooter`.

Ширина окна: новый токен `--overlay-w-xl` (1080 px, `design/tokens.json`), `Overlay size="xl"`. До 960 px одна колонка.

## Как подтягивается выбор справа

- **Гостиница:** свободные номера по категориям из той же проверки `reservationsApi.availability(arrival, departure)`, что и раньше (повтор при смене дат через 200 мс, «Проверяем свободные номера…»). Номера по порядку чисел (`reservations/new/room-choices.ts`). Категория меньше числа гостей серая («до 1 гостя»). Неубранный номер отмечен точкой (уборка из `api.inventoryUnits()`, новой проверки на сервере нет). Нажатие ставит категорию и номер в поля «Категория» и «Номер / койка» слева, отправка по-прежнему из полей. При группе (несколько мест или размещений) кнопок нет, номера назначает система. На телефоне кнопок нет, выбор полями.
- **Салон:** свободное время мастера первой услуги на выбранный день, шаг 30 минут, длительность всего визита (если все услуги у него), без пересечений с живыми записями и строками многоуслужных записей, прошедшее время сегодня не предлагается (`beauty/free-slots.ts`). Нажатие ставит время. Занятость окончательно проверяет сервер.
- **Ресторан:** подходящие свободные столы по залам (вместимость, брони дня на экране, как и раньше), кнопка выбирает стол. Полный список столов остался полем «Стол» (занятые и ручная посадка). Полоса шагов «Основное / Гость / Стол / Подтверждение» убрана: окно и так на одном экране.

Данные и API не менялись, миграций нет.
