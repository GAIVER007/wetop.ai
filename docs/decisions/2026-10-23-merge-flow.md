# 2026-10-23 Порядок слияния в main: без «свежести», автослияние, поезд

Статус: принято владельцем 23.10.2026 («хочу не быстро, хочу правильно и навсегда»; ответы на 3 вопроса).
Ветка `hermes/train-20261023`.

## Проблема

Защита `main` требовала, чтобы каждый PR был не старше `main` (`required_status_checks.strict = true`).
Полный `release-checks` идёт около 60 минут, а открытых PR было 13 от трёх авторов. Каждое слияние делало все
остальные PR «behind»: их проверки начинались заново, и очередь ходила по кругу. 22-23.10 поезд #766 перезапускался
так 7 раз. Параллельно ветки сами занимали номера миграций (142 дважды, 146 дважды), а на сервере агентов кончалось
место (104 брошенные копии стенда UI по 220 МБ), и тесты выкладки падали «меньше 6 ГБ».

## Варианты

1. Оставить «свежесть», сливать поездами раз в день.
2. Оставить как есть.
3. Убрать «свежесть», включить автослияние. Выкладка на сайт и так идёт только после зелёного `release-checks`
   на самой вершине `main` (`auto-release.yml`), поэтому проверка смеси на `main` сохраняется.

## Решение

Вариант 3.

- `main`: `strict = false`, шесть обязательных проверок прежние, `enforce_admins` прежний.
- В репозитории включены `allow_auto_merge` и кнопка «Update branch». Агент ставит автослияние на свой зелёный PR.
- Сайт обновляется только с вершины `main`, у которой зелёный `release-checks` (без изменений, ADR-139/152).
  Если смесь двух PR красная на `main`, сайт стоит на прежней версии, а починка идёт отдельным PR.
- Номер миграции занимается в `DATA_MODEL.md` до первой миграции в ветке, сторож `migration-ordinal-unique.test.ts`
  ловит повтор. Занято на 23.10: 142-144 (поезд #766, на проде), 145 голос #772, 146 черновики постов #787 (слит владельцем в main первым); голосу #772 нужно перенести свои 146 и 147 на следующие свободные номера.
- Открытые PR одного агента сводятся в один поезд, исходные закрываются с пометкой «вошло в #N».
- Брошенные копии стенда `~/.wetop-main-ui-*` старше двух часов агент удаляет до прогонов (на сервере агентов).

## Последствия

- PR больше не ждут друг друга, очередь GitHub не перезапускается.
- Риск: два по отдельности зелёных PR дают красный `main`. Он ловится прогоном на `main` до выкладки и не
  доходит до сайта; чинит тот, чей PR слит последним.
- Чужие PR (zapoinov13) агент не сливает в поезд без согласия автора: проверяет и пишет замечания в PR.
