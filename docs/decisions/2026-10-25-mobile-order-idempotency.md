# Серверный повтор создания заказа

25.10.2026, codex/wetop-mobile. Направление и точная модель приняты владельцем после предложения в DATA_MODEL.md, сообщением «че там давай продолжай».

Проблема: повтор после потерянного ответа createOrder мог создать дубль. Выбраны два nullable-поля на RestaurantOrder и уникальность ключа в филиале. Альтернатива без серверной защиты оставляла ручную сверку.

Используем существующий foodTransaction с FOR UPDATE филиала, поиск ключа внутри транзакции. Хэш v1 содержит нормализованный исходный запрос, пользователя и филиал; модификаторы сортируются. Replay проверяет актуальные права и waiterSelf, возвращает существующий orderView без перерасчёта цен. Другой запрос или пользователь с тем же ключом получает 409. Старая отправка без ключа совместима.

Миграция аддитивна, содержит CHECK пары полей и UNIQUE; откат запрещён при использованных ключах. Публичный gateway и рабочая база не изменяются. Мобильный клиент и долговременное сохранение попытки идут следующим срезом, до них отправка остаётся выключенной.
