# Сохранённая попытка отправки заказа

25.10.2026, продолжение утверждённого MOBILE-FOOD-1. Модель сервера не меняется.

Решение: перед сетевой отправкой сохранять неизменные payload и ключ в SecureStore. Одна незавершённая попытка на окружение, пользователя, организацию, бизнес и филиал. Namespace вычисляется UUID v5, ключ попытки UUID v4 через уже установленный Expo. Новых зависимостей нет. Session issuance не входит в namespace: после повторного входа того же пользователя попытка должна восстанавливаться.

Вместо одной большой записи: JSON делится по 400 Unicode code points (не более 1600 UTF-8 байт), затем последним записывается небольшой manifest. До успешной обратной проверки всей записи prepare не возвращает результат. Сбой до manifest не разрешает отправку. Сбой после manifest оставляет восстанавливаемую попытку. Отсутствующий chunk или некорректный manifest блокирует замену, а не удаляет сомнительную запись. Внутри процесса операции одного namespace сериализованы.

SecureStore использует WHEN_UNLOCKED_THIS_DEVICE_ONLY. Web preview не подменяет защищённое хранение памятью: создание такого store там отклоняется. Это ограничение надёжной нативной отправки, не запрет просмотра макетов.

Слот освобождается только acknowledge совпадающего ключа после валидного серверного подтверждения. Сначала удаляется и перепроверяется manifest, затем chunks; сбой удаления остаточных chunks не создаёт новую активную попытку. Незавершённые попытки не удаляются при logout и не читаются другим аккаунтом. Восстановление возможно только после подтверждения исходного контекста. Сетевых операций в store нет.

Ограничение JSON: 131072 UTF-16 единицы, чтобы ограничить объём локального хранения. Ошибка сохранения блокирует отправку. Частично записанные chunks без manifest могут остаться зашифрованными; автоматической очистки и offline-отправки нет. UI должен явно объяснить ошибку, не генерировать новый ключ поверх неопределённого результата.

Проверки: новые тесты сначала не собирались без модуля; после реализации mobile 57/57, mobile-types и lint прошли. Это модульные проверки и mock SecureStore, не доказательство реального iOS Keychain/Android Keystore. Store пока не подключён к экрану отправки. Следующий срез: контроллер сетевой попытки, повтор прежнего payload/key, восстановление в UI и проверки устройства.
