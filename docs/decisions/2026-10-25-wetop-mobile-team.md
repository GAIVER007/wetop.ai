# Мобильная команда ресторана

Дата: 25.10.2026. Статус: принято в рамках утверждённого мобильного плана.

Проблема: на телефоне нужен состав филиала и вклад людей за период. Сумма открытых или закрытых заказов не равна утверждённому показателю «Принёс».

Варианты: считать вклад на устройстве по заказам; показывать только график; читать существующий серверный staff-revenue и график смен. Выбран последний вариант.

Решение: мобильный шлюз отдельно запрашивает `/food-service/shifts` и `/food-service/staff-revenue?period=day|week|month`. Оба запроса передают подтверждённый scope и bearer, сервер применяет свои права и филиальную фильтрацию. Gateway возвращает только ID, имя, недельные интервалы и денежные строки. Контакты, ревизии профиля и служебные поля не передаются. Приложение связывает данные по ID. «Принёс» показывается как оплачено минус возвраты, в integer minor units и по отдельным валютам. Деньги без официанта и работников вне текущего состава показываются отдельными строками.

Причина: сохранить утверждённую финансовую формулу из `docs/decisions/2026-10-20-personnel-revenue.md`, не раскрывать личные контакты и не терять исторические оплаты.

Последствия: график является недельным шаблоном, а не фактом явки. При отсутствии права на финансовый отчёт список смен остаётся доступным с сообщением об отсутствии показателя. Количество закрытых заказов за тот же период читается из period-report. API-ответ расширен waiterId, gateway возвращает его, приложение соединяет показатели по ID. Если отчёт заказов недоступен, сумма оплат и график остаются видимыми, число заказов скрывается. Gateway остаётся выключенным в production до отдельного разрешения.
