# Окно записи салона и брони ресторана, вариант A (26.10.2026)

**Проблема:** владелец про прежние окна (вариант B, ADR 2026-10-23-booking-window): «так себе выглядит, много пустого
места». Карта фонда мелкими клетками отвергнута раньше («раньше же правая часть лучше была», PR №878 закрыт).

**Варианты:** эскизы A/B/C для салона и ресторана (`booking-form-sketch/v3.html`, вне репозитория). Выбран A для обоих
направлений (совет агента, владелец сказал «давай продолжай»).

**Решение:**
- **Салон, «Новая запись»:** слева клиент и услуги карточками (название, длительность, цена; фильтр по категориям,
  если их больше одной). Справа дата и время, мастера карточками («свободно N», выходной серый), ниже свободное время
  сеткой по утру, дню и вечеру, занятое серое; заметка под временем. При одной услуге поля «Услуга» и «Специалист»
  скрыты визуально (`sr-only`), остаются для отправки и читалки. Расчёт ячеек `beauty/master-map.ts` (та же
  `freeSlots`), тест 4/4, красный на заглушке.
- **Ресторан, «Новая бронь»:** слева гость, число гостей кнопками 1–10 и время кнопками по 30 минут выбранного
  периода (без прошедшего сегодня), поля даты, времени, периода и гостей остаются. Справа все столы залов плитками
  («Стол 3, 4 места»), занятые и маленькие серые с причиной; «Принял бронь» и заметка под столами.

**Последствия:** данные, API и проверки сервера без изменений, миграций нет. Окончательную занятость по-прежнему
проверяет сервер. UI: `tests/beauty-ui/beauty.spec.ts` «новая запись: свободное время…» и
`tests/food-ui/restaurant.spec.ts` «бронирования: шкала…» со снимками 1280×800
(`reports/booking-window-a-2026-10-26/`).
