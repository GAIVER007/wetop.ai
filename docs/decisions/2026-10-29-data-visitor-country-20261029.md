# Страна посетителя и раздел «Страны» в кабинете руководителя (29.10.2026)

## Проблема

Владелец 29.10.2026: «чтобы отображалось гео, с какой страны заходят: Казахстан столько-то посетителей, столько-то
регистраций; какая страна сколько оплачивает, с какой страны доход». Страна клиента уже есть
(`organizations.country_code`, страна телефона регистрации). Страны посетителя сайта нет.

## Варианты

1. Определять страну по IP своей базой GeoIP: новая зависимость, обновления базы, IP проходит через наш код.
2. Брать страну, которую Cloudflare уже определил на входе (`CF-IPCountry`), и хранить только двухбуквенный код.
3. Не показывать посетителей по странам, только клиентов и деньги.

## Решение

Вариант 2 («да» владельца 29.10.2026 на колонку). Миграция 169: `web_sessions.country VARCHAR(2) NULL` с проверкой
формы `web_sessions_country_iso2`. Приёмник `/a/hit` пишет код при создании визита (`countryFromHeader`: верхний
регистр, `XX`, `T1` и всё не по форме дают `null`). IP не хранится, как и раньше.

Раздел кабинета «Страны» (`/platform/cabinet/countries`, `GET /platform/countries`, только главный администратор):
по стране посетители wetop.ai (посетитель в стране первого визита месяца), новые клиенты месяца, первые оплаты,
платят сейчас, доход месяца, MRR, средний LTV и переходы; сортировка по доходу, итог; клиенты без страны строкой
«Страна не указана». В «Сайт wetop.ai» таблица «Страны посетителей» с числом подтвердивших почту.

## Причина

Без новых зависимостей и без персональных данных; страна точна ровно настолько, насколько её видит Cloudflare.

## Последствия

- Прошлые визиты без страны («Не определена»). Страна появляется с выкладки 169.
- Переход «посетитель → клиент» по стране приблизительный: страна посетителя по адресу входа, клиента по телефону.
- Если `api.wetop.ai` когда-нибудь пойдёт мимо Cloudflare, заголовка не будет и страна станет `null`, отчёты не
  ломаются.
- Откат: `down.sql` 169 снимает колонку; код без колонки не работает, поэтому откат вместе с прежним образом.
