# 2026-10-29 ui/owner-cabinet-20261029: кабинет руководителя, срез «главная и клиенты»

## Проблема

Владелец 29.10.2026: полностью проработать кабинет руководителя WETOP: деньги, подписки, клиенты, доступ, путь
посетитель → регистрация → пробный → оплата → продление, LTV, сколько клиент с нами. План
`docs/plans/2026-10-29-owner-cabinet-full.md`, владелец выбрал вариант «А» и вкладку «Клиенты» из «Б» («Да делай»).

## Решение

- Новый расчёт `apps/api/src/platform/growth.ts` (`buildGrowth`) и `GET /platform/growth?month=`: только главному
  администратору, служебной ролью базы, без новых таблиц. Деньги центами bigint, проценты целыми десятыми.
- Регистрация это учётка, которая завела организацию (владелец) или ещё никуда не вошла; приглашённые сотрудники
  клиентов не считаются. Пробный это новая организация месяца. Первая оплата и продление из `platform_payments`
  (отменённые не в счёт). MRR: подписки, у которых «оплачено до» не прошло. LTV: все оплаты клиента; средний по
  платившим. Конверсия продления: оплатили снова из тех, чей срок пришёлся на месяц.
- Посетителей wetop.ai пока никто не считает: `visitors: null`, на экране «счётчик не подключён» (срез 2 плана).
- Главная по варианту «А»: месяц ‹ ›, 4 цифры (MRR, клиенты, пробный, средний LTV), путь клиента с процентами,
  доход по месяцам, справа сроки. «Клиенты» стали страницей кабинета `/platform/cabinet/clients` с фильтрами и
  кнопкой «Доступ» (карточка организации платформы, где пробный, оплата и расширения).
- Стенд UI считает тем же `buildGrowth`.

## Последствия

Следующие срезы плана: счётчик на wetop.ai, окно «Доступ» с журналом в кабинете, ночная проверка подписок.
