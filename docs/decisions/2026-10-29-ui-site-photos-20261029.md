# 2026-10-29 ui/site-photos-20261029: фото первого экрана для сайтов без своих фото

## Проблема

Владелец: подбор фото, когда у клиента нет своих. Без фото все шаблоны начинались одинаковым текстовым первым
экраном. Хранилище картинок сайтов на сервере выключено (бакет в Казахстане не заведён), Unsplash закрыл
автоматический доступ, Openverse по нужным запросам пуст.

## Варианты

1. Ждать хранилище и копировать фото к себе.
2. Фото Pexels по ключу владельца, адрес `images.pexels.com` прямо в `<img>`.

## Решение

Вариант 2. Набор WETOP `packages/domain/src/marketing/stock-photos.ts`: по одному фото на каждый из 9 шаблонов
(лицензия Pexels: бесплатно, в том числе коммерчески, без указания автора; автор и страница сохранены в наборе).
- У фото набора постоянный id-UUID с префиксом `57c0f070-0000-4000-8000-`: схема SiteSpec не меняется.
- Шаблон ставит фото набора и раскладку первого экрана (тёмная роскошь на весь экран, остальные фото сбоку).
  Своё фото клиента главнее: шаблон его не трогает.
- API не ищет фото набора в библиотеке филиала (`withoutStockRefs`), рантайм отдаёт их адрес без хранилища
  (`stockAssetMap`), рендер знает адрес и без карты (превью, галерея шаблонов).
- CSP: `img-src` стойки разрешает `https://images.pexels.com`; рантайм сайтов добавляет origin из карты сам.
- Ключ Pexels только на сервере (`~/.config/wetop/pexels.env`), в коде его нет: подбор сделан один раз.

## Последствия

Фото грузятся с серверов Pexels. Если клиент загрузит своё, оно заменит фото набора. Набор расширяется добавлением
строки в `STOCK_PHOTOS`.
