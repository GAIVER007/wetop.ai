# Кабинет WETOP по умолчанию только у учётки компании (30.10.2026)

## Проблема

Владелец 30.10.2026: «почта zapoinov@bk.ru опять заходит вначале на страницу гостиницы, и только через настройки я вижу
кабинет WETOP… видит только кабинет WETOP по умолчанию и всё. А Вячеслав видит как сейчас».

Правка 29.10.2026 (#942) вела главного администратора в кабинет только в `/scope/resolve`, то есть сразу после входа
паролем. Открытие `app.wetop.ai` уже вошедшим (`/` и `startScreen`) по-прежнему вело на «Главную» гостиницы «Святой».
К тому же база не различает Юрия (учётка компании) и Вячеслава (владелец своего бизнеса): у обоих одна отметка
`platform_admins`, и правка 29.10 перевела бы в кабинет обоих.

## Варианты

1. Всем главным администраторам только кабинет: Вячеславу нужна его стойка Luxx, не подходит.
2. Различать по почте в коде: персональные данные в коде, запрещено.
3. Отметка в базе у главного администратора «Кабинет WETOP по умолчанию».

## Решение

Вариант 3 (владелец выбрал 30.10.2026). Миграция 171: `platform_admins.cabinet_home BOOLEAN NOT NULL DEFAULT false`;
миграция ставит `true` учётке компании `zapoinov@bk.ru` (решение кабинета 28.10.2026 называет её профилем компании),
если отметка главного администратора у неё действует. `wetop_app` читает колонку, как `user_id` и `revoked_at`.

API отдаёт `user.cabinetHome` (только при действующей отметке). Стойка ведёт в `/platform/cabinet`:
- после входа (`/scope/resolve`, как 29.10, теперь только при `cabinetHome`);
- при открытии приложения (`/` через `startScreen(..., { cabinetHome })`).

Свой адрес (`next`, ссылка из письма, закладка на раздел) открывается как раньше; стойки клиентов из кабинета через
«Доступ», как раньше. Вячеслав (`cabinet_home = false`) входит в свою стойку, кабинет у него в «Настройках».

## Последствия

- Отметку для другого человека ставит команда на сервере (как и саму `platform_admins`), маршрута API нет.
- Откат: `down.sql` 171 снимает колонку; код без неё не работает, откат вместе с прежним образом.
