# eQonaq (регистрация гостей, РК) — исследование

Статус: **документации нет** → интеграция не пишется (AGENTS §5). Код — только порт `packages/integrations/src/eqonaq`
(`EqonaqProvider`, заглушка `ManualEqonaqProvider` → статус MANUAL_REVIEW: администратор вносит гостя вручную).

Снято 10.09.2026 из открытых источников.

- eQonaq (eHotel) — модуль национального туристского портала Kazakhstan.travel для автоматизированного сбора,
  обработки и анализа сведений в туристской деятельности, в том числе учёта туристов и мест размещения
  (реестр ИС электронного правительства: <https://govarch.kz/en/infosys/info/2074>).
- Публичной документации API для PMS в открытом доступе не найдено: интеграция идёт через оператора портала
  (по опыту рынка — заявка от объекта размещения, выдача доступа/ключей интегратору).
- Письмо-запрос оператору подготовлено: `outbox/02-eqonaq.md` — **отправляет владелец**.

## Что нужно от владельца

1. Отправить письмо оператору eQonaq / Kazakhstan.travel (кто сейчас подаёт сведения за объект и как: вручную в портале?).
2. Полученную документацию (формат сообщений, авторизация, тестовый контур) положить в `docs/eqonaq/`.
3. До этого PMS печатает регистрационную карту (RU/KZ) и хранит документы гостей шифрованно; подача в eQonaq — вручную.
