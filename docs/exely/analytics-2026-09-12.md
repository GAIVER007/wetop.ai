# Раздел «Аналитика» в Exely: что там есть и откуда данные

Снято 12.09.2026 из кабинета объекта (владелец вошёл в своём Chrome), адрес
`secure.exely.com/app/analytics-v2/Extranet/`. Скриншоты на диск не сохранялись; персональных данных
на этих экранах нет. Основание для среза 8 — `plans/slice-8-web-analytics.md`.

## Главное

1. **Собственного счётчика посещений у Exely нет.** Подраздел «Эффективность сайта» — витрина
   Google Analytics 4: рядом с «Обновили данные 12 сентября» стоит значок Google, подсказка на нём —
   «Счётчик: G-XLJ63SQTJ4» (идентификатор потока GA4; не секрет — он стоит в HTML сайта). Exely читает
   отчёты GA4 и показывает пять чисел и три графика.
2. **Данных нет.** За сентябрь 2026 во всех виджетах «Данные не найдены» / «Отсутствуют данные за
   выбранный период». Либо счётчик на сайте не стоит, либо Exely не выдан доступ к GA4.
3. **Модуль бронирования Exely на объекте не подключён:** «Модуль бронирования → Настройки» открывает
   рекламную страницу Booking Engine с кнопкой «Отправить заявку». Поэтому «Календарь спроса» и
   воронка бронирования пустые. Аудит 07.09 (п. 10.5) записал модуль как подключённый с тремя
   источниками — по кабинету это не так, уточнить у владельца (Q-111).
4. Остальные подразделы («Ревенью метрики», «Оценка источников продаж», «Отчёты из Exely PMS»)
   считаются **по броням**, а не по сайту. Эти данные у нас уже есть; отчёты по ним — отдельная тема.

## Структура раздела

| Подраздел | Экран | Что показывает | Источник данных | У нас |
|---|---|---|---|---|
| Ревенью метрики | Темп и динамика загрузки | «Темп загрузки отеля»: прирост номероночей, дохода и средней цены за ночь по дням недели, текущий год против прошлого, сравнение с конкурентной группой. «Динамика загрузки»: в сравнении с прошлым периодом | Брони Exely + конкурентная группа Exely | Брони есть (утренний отчёт, сверка суток); конкурентная группа — вне scope (SPEC п. 7) |
| Ревенью метрики | Окно бронирования и отмены | За сколько дней до заезда бронируют и отменяют, по источникам продаж, текущий год против прошлого | Брони | `booked_at`, `arrival_date`, отмены в журнале — данные есть, отчёт не построен |
| Оценка источников продаж | Распределение продаж | Номероночи в разрезе источников (Channel Manager / Сайт), категорий и тарифов | Брони | `source` + `channel` на брони; отчёт не построен |
| Эффективность сайта | Сессии | Тайлы: Сессии, Уникальные посетители, Просмотры страниц, Страниц за сессию, Среднее время сессии. Графики: «Посещаемость сайта», «Посещения с мобильных устройств». Фильтр — месяц | **GA4** (счётчик G-XLJ63SQTJ4) | Срез 8 — свой счётчик |
| Эффективность сайта | Источники трафика | График «Источники трафика» по дням, «Распределение трафика по источникам» | **GA4** | Срез 8 |
| Эффективность сайта | Календарь спроса | «Даты, в которые хотят заехать посетители вашего сайта»: на дату заезда — запросов «нет номеров / есть номера / забронировано». «Посмотреть» ведёт в `/app/opportunity/#/opportunity/DemandCalendar` — страница пустая | Поиски дат в модуле бронирования Exely | Срез 8 — только если сайт шлёт событие поиска дат (Q-111) |
| Отчёты из Exely PMS | — | Ссылки: Доходность и загрузка (доход за проживание, номероночей, ADR, RevPAR, RevPAC, ALS, загрузка), Платежи, Заезды, Питание и сводная статистика | Брони и касса | Частично есть (`reports/`, утренний отчёт) |

Разделы «Маркетинг» (Email-рассылка, Анкетирование гостей), «Репутация», «Сравнение цен» к счётчику
отношения не имеют. Настройки счётчика в кабинете найти негде: у TravelLine/Exely идентификатор GA4
передают в поддержку письмом (см. ниже).

## Определения метрик — подсказки «?» на экране «Сессии», дословно

| Метрика | Подсказка Exely |
|---|---|
| Сессии | Количество сессий, которые начались на вашем сайте |
| Уникальные посетители | Количество уникальных посетителей, совершивших как минимум одно действие на сайте |
| Просмотры страниц | Суммарное количество просмотров страниц сайта (включая повторные просмотры страниц) |
| Страниц за сессию | Среднее количество просмотров страниц сайта посетителями в рамках одной сессии (включая повторные просмотры страниц в рамках одной сессии) |
| Среднее время сессии | Среднее время, которое проводит посетитель на сайте за одну сессию |

Это определения GA4 один в один (сессия рвётся после 30 минут бездействия). Наш модуль берёт их
как есть, чтобы цифры были сравнимы, если владелец параллельно оставит GA4.

## Как TravelLine/Exely подключает GA4 — из базы знаний TravelLine (Exely — бывший TravelLine)

- Отельер создаёт ресурс GA4 и **идентификатор потока данных отправляет в поддержку письмом**; поддержка
  ставит счётчик на форму бронирования; на сам сайт код GA4 отельер вставляет руками
  («Просмотр инструкций тега → Установить вручную»).
- Форма бронирования шлёт в GA4 четыре шага воронки: `step1_Выбор_номеров` (`/search`),
  `step2_Заказ_услуг` (`/preview`), `step3_Способ_оплаты` (`/payment`), `step4_Бронь_номера` (`/complete`).
- Компонент «TravelLine: Аналитика» показывал конверсию сайта (онлайн-брони к посетителям), посетителей
  по дням/неделям/месяцам, брони и отмены с сайта.

Источники: travelline.pro, база знаний, статьи «GA4: создание и настройка Google Analytics 4» и
«Как пользоваться компонентом TravelLine: Аналитика» (прочитаны 12.09.2026).

## Что это значит для нашего модуля

- Повторять у Exely нечего: там нет ни счётчика, ни приёмника — только чтение GA4. Свой счётчик
  (код на сайт + приёмник + отчёты) придётся написать в любом случае; альтернатива — читать GA4 по API,
  как Exely (развилка в ADR-025).
- Паритет по экрану «Сессии» и «Источники»: пять чисел, посещаемость по дням, доля мобильных,
  источники по дням и распределение. «Календарь спроса» — только при событии поиска дат с сайта.
- Определения метрик — GA4, сессия 30 минут.
