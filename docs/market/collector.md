# Сборщик загрузки конкурентов: служебный вход (M2a)

Решение: ADR-142, дополнение 03.10.2026 (Q-257, Q-260). Модель: DATA_MODEL §23.

Сборщик живёт вне API WETOP (ИИ-агент, задача по расписанию, скрипт). Платформа даёт ему ровно два адреса и
отдельный ключ. Откуда сборщик берёт числа, решает его подключение: площадки (Booking.com и другие) автоматически не
читаем, их условия это запрещают; допустимы обмен между отелями WETOP с согласия, договорный поставщик, опрос соседей.

## Ключ

| Где | Переменная | Что открывает |
|---|---|---|
| API платформы | `MARKET_COLLECT_KEY` | только два адреса ниже; не задан, сборщик не входит |
| Сборщик | то же значение в заголовке `x-wetop-service-key` | |

Ключ не открывает раздел стойки (`/market/occupancy`, ручной ввод, правку списка), брони, гостей и деньги: отказ 403.
Без ключа, 401. Значение вписывает владелец в `.env` сервера, в чат и репозиторий не копировать.

## Адреса

`GET /market/collector/competitors`

```json
{ "competitors": [
  { "id": "uuid", "name": "Отель Сосед", "url": "https://…", "distanceM": 300, "unitsTotal": 40,
    "propertyId": "uuid", "propertyName": "Гостиница", "timezone": "Asia/Almaty" } ] }
```

Только действующие конкуренты (убранные в архив не отдаются), всех объектов платформы.

`PUT /market/collector/competitors/:id/occupancy`

```json
{ "entries": [ { "date": "2026-10-04", "percent": 91 }, { "date": "2026-10-05", "percent": "64,5" } ] }
```

Ответ `200 { "saved": 1, "kept": 1, "observedOn": "2026-10-04" }`.

- День снимка: сегодня по поясу объекта конкурента. Объект и организацию API берёт из строки конкурента; поля
  `propertyId` и `organizationId` в теле игнорируются.
- Ночи: от 30 дней назад до года вперёд, не больше 62 за раз, без повторов. Процент 0…100, до десятых.
- Сборщик ничего не стирает: пустое значение, 400.
- Повтор за тот же день заменяет значение сборщика. Ночь, которую человек внёс сегодня вручную, не трогается
  (`kept`): человек сильнее сборщика.
- Неизвестный или убранный конкурент, 404. Каждая запись идёт в журнал `market.occupancy.collected`.

В таблице раздела такие снимки подписаны «ИИ».

## Сборщик WETOP (ИИ-агент), 09.10.2026

Решение владельца: ADR-142, дополнение 09.10.2026. Код: `scripts/market/collect.ts` (порядок шагов), `sources.ts`
(служебный вход, браузер, модель), `cli-collect.ts` (запуск).

```bash
MARKET_COLLECT_URL=https://api.wetop.ai MARKET_COLLECT_KEY=… ANTHROPIC_API_KEY=… npm run market:collect -- --dry-run
```

- `--dry-run` читает и оценивает, в WETOP ничего не пишет: так проверяют подключение. `--nights N` (1…62, по умолчанию 14).
- Сосед берётся, только если у него ссылка на Booking.com, Trip.com или Ostrovok и указано число номеров; иначе пропуск с
  причиной в выводе.
- Одна страница на ночь, пауза `MARKET_COLLECT_DELAY_MS` (по умолчанию 8000 мс) между страницами.
- Модель `MARKET_COLLECT_MODEL` (по умолчанию `claude-opus-5-5`); ответ проверяется схемой, отказ или непонятный
  ответ дают «не разобрано», такая ночь не пишется.
- Капчу и проверку площадки сборщик не обходит. Коды 202, 401, 403, 429 или страница-проверка, которую увидела
  модель: по этому соседу сборщик останавливается, уже оценённые ночи записывает.
- Проба 09.10.2026: Booking.com отдал безголовому браузеру 202 и пустую страницу. Пока так, данных Booking сборщик
  не получит; см. ADR-142 п. 12.
- Ключи вписывает владелец (SECURITY.md §3), в чат и репозиторий не копировать.

### Площадки: что видит сборщик (проба 09.10.2026)

| Площадка | Открывается | Что видно на дату |
|---|---|---|
| Booking.com | нет: поиск 202 и пустая оболочка, страница отеля без дат | наличия нет |
| Trip.com | 200, но выдача пуста («0 properties found») | наличия нет |
| Яндекс Путешествия | нет: капча, проба остановлена | ничего |
| Airbnb | да, 200 | объявления с ценой на ночь (квартиры, не отели) |
| Ostrovok | да, 200 | номера на дату, цена, «осталось N номеров» у части карточек |

Модели уходит только блок номеров страницы (`pageSection`): отзывы с именами гостей не уходят.

### Какая модель читает верно

Записанные страницы и ручная разметка: `tests/fixtures/market-pages/` (9 страниц: 7 Ostrovok, Booking, Яндекс).

```bash
ANTHROPIC_API_KEY=… npm run market:eval
```

Скрипт прогоняет разбор на `claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-opus-5-5`, печатает «модель, совпало из N,
стоимость» и записывает ответы в `recorded/`; по ним `scripts/market/pages.test.ts` проверяет разбор без сети.
По умолчанию ставится самая дешёвая модель со 100 % совпадений, если такой нет, `claude-sonnet-5-5`.

### Запуск по расписанию на Mac (не установлено)

```bash
scripts/ops/launchd/install.sh --dry market
```

`--dry` собирает и проверяет plist во временной папке, ничего не загружает; без `--dry` служба ставится. Служба
`kz.luxx.pms.market`: раз в сутки в 06:00 по часам Mac (`StartCalendarInterval`), `KeepAlive` и `RunAtLoad` выключены,
команда `node --import tsx scripts/market/cli-collect.ts`. Ключи в plist не пишутся: сборщик берёт их из `.env`
проекта. Без аргументов `install.sh` её не ставит, только по имени; видна в `status.sh`, снимается `uninstall.sh market`.
Память: один браузер на прогон, страницы по очереди; пик Chromium на странице Ostrovok около 844 МБ (сумма по
процессам, общая память посчитана несколько раз).
