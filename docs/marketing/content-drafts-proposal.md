# Контент: черновики постов с ИИ (предложение, 22.10.2026)

**Статус: УТВЕРЖДЕНО владельцем 23.10.2026** («Да давай наводи там делай что надо … что бы работало») вместе с
дополнениями §4.1 по разбору «Контент-завода» MarkVision. Q-CONTENT-1…6 закрыты предложениями агента. Миграция на
production только отдельным «да» с пакетом backup/rollback (AGENTS §14).

## 1. Зачем

Экран «Маркетинг → Контент» сейчас показывает только идеи и ссылку на медиатеку: «Создать контент» выключена,
вкладки «Генерация», «План публикаций», «Статистика» пустые. Владельцу салона, отеля или ресторана нужно быстро
получить текст поста на неделю и не забыть его опубликовать.

Первый срез: **ИИ пишет черновик текста поста, человек правит и ставит его на день недели.** В соцсети WETOP ничего
не публикует: человек копирует текст сам. Публикация, картинки и статистика охватов идут следующими срезами
отдельным решением.

## 2. Как это будет выглядеть

1. «Контент → Генерация»: поле «О чём пост» (до 500 знаков), канал (Instagram, Facebook, Telegram, WhatsApp-статус),
   тон (дружелюбный, деловой). Кнопка «Написать с ИИ».
2. Ответ: заголовок (необязательно), текст до 2 200 знаков, до 10 хештегов. Поле можно править. «Сохранить черновик».
3. «План публикаций»: неделя по дням филиала, в дне карточки черновиков с каналом. Перетаскивания нет: у черновика поле
   «День публикации». Кнопки «Скопировать текст» и «Отметить опубликованным».
4. Пустые состояния честные: нет ключа модели → «ИИ не подключён», исчерпан бюджет → «Лимит ИИ на месяц исчерпан».
   Черновик можно написать и без ИИ.

Одинаково для гостиницы, салона и ресторана; отличаются только примеры в подсказках (`verticalCopy`).

## 3. Модель данных (новый раздел DATA_MODEL, номер при слиянии)

Таблица `content_drafts`, одна строка на черновик поста филиала.

| Поле | Тип | Правило |
|---|---|---|
| `id` | UUID PK | |
| `location_id` | UUID FK locations | филиал из scope, не из тела запроса |
| `created_by` | UUID FK users | |
| `channel` | VARCHAR(20) CHECK | `INSTAGRAM`, `FACEBOOK`, `TELEGRAM`, `WHATSAPP_STATUS` |
| `cta` | VARCHAR(20) NULL CHECK | `BOOK_ONLINE`, `WHATSAPP`, `CALL`, `VISIT`, `NONE`; ссылку и номер подставляет домен из карточки |
| `topic` | VARCHAR(500) | что ввёл человек |
| `title` | VARCHAR(200) NULL | |
| `body` | TEXT, CHECK ≤ 2 200 | текст поста |
| `hashtags` | TEXT[] ≤ 10 | без `#`, каждый ≤ 50 |
| `origin` | VARCHAR(10) CHECK | `AI` или `MANUAL`; правка ИИ-текста origin не меняет |
| `planned_on` | DATE NULL | день публикации в поясе филиала (AGENTS §13) |
| `status` | VARCHAR(12) CHECK | `DRAFT` → `PUBLISHED` (отметил человек) или `ARCHIVED` |
| `published_at` | TIMESTAMPTZ NULL | когда отметили |
| `revision` | INT | защита от перезаписи, как у других форм (CAS) |
| `created_at`, `updated_at` | TIMESTAMPTZ | |

- RLS через филиал → бизнес → организацию, как §55/§57. Права: чтение и запись `marketing`; отдельного права нет.
- Индекс `(location_id, planned_on)` для недели.
- Удаления нет, только `ARCHIVED`. Журнал `audit_logs`: `content.draft.created|updated|published|archived`.
- Ни промпт, ни ответ модели, ни ключ не хранятся: только итоговый текст.
- Миграция `…_content_drafts` + `down.sql` (DROP только пустой таблицы), backup/restore/rollback по `docs/deploy.md`.
  На прод только отдельным «да» владельца.

## 4. Контракт ИИ `content-draft/0`

По образцу `ad-proposal/0` (платформенный ключ, каскад моделей, проверка остатка бюджета перед каждым вызовом,
`USAGE_UNAVAILABLE` при неизвестном расходе, в ответ не уходят промпт и ключ).

Запрос: `schemaVersion`, `requestId`, `topic`, `channel`, `tone`, `business {vertical, name, city, country, language}`,
`facts[]` (услуги, цены, адрес из карточки), `budgetRemainingTokens`. Ответ: `{ variants: [{ hook, title|null, body,
hashtags[], cta }] }`, 1–2 варианта (A/B). Домен обрезает и проверяет длины, убирает ссылки
и телефоны, которых нет в карточке филиала. Ответ модели только предложение: в базу попадает то, что сохранил человек.

### 4.1 Дополнения по разбору MarkVision (23.10.2026)

Источник: `markvision-analysis/CONTENT-FACTORY-REPORT.md` §8, выгрузка n8n «Clony AI MarkVision». Связку n8n не переносим:
логика в `apps/ai-seller` и `apps/api`, как у `ad-proposal/0`.

1. **Два варианта (A/B):** тот же смысл, разный хук. Сохраняется только выбранный человеком.
2. **CTA из закрытого списка;** ссылку брони и номер WhatsApp подставляет домен, модель их не пишет.
3. **Проверка фактов без второй модели:** домен ищет в тексте числа, цены, проценты и «лет», которых нет во входе
   (`facts[]`, тема), и возвращает `warnings[]` («2 цифры не из карточки»). Сохранение не блокируется. В БД не хранится.
4. **Одна повторная генерация** при невалидном ответе внутри того же бюджета, дальше честная ошибка.
5. **Расход** пишется в общий учёт бюджета ИИ, не в `content_drafts`; промпт не хранится.

## 5. API

| Метод | Путь | Право | Действие |
|---|---|---|---|
| POST | `/marketing/content/drafts/proposal` | marketing | текст от ИИ, ничего не сохраняет |
| GET | `/marketing/content/drafts?week=YYYY-MM-DD` | marketing | черновики недели филиала |
| POST | `/marketing/content/drafts` | marketing | создать (creationId, идемпотентно) |
| PATCH | `/marketing/content/drafts/:id` | marketing | правка с `expectedRevision` |
| POST | `/marketing/content/drafts/:id/published` | marketing | отметить опубликованным |
| POST | `/marketing/content/drafts/:id/archive` | marketing | в архив |

Без филиала 409, чужой филиал 403, чужой id 404. Read-only организация: только GET.

## 6. Проверки (RED → GREEN)

- api unit: права, 409/403/404, CAS, идемпотентность creationId, бот недоступен/бюджет исчерпан;
- integration на своём PostgreSQL: RLS, изоляция организаций, архив вместо удаления, журнал;
- ai-seller pytest: схема `content-draft/0`, бюджет, отсутствие ключа и промпта в ответе;
- UI (fixture): три вертикали, создание с ИИ и вручную, правка, план недели, reload, пустые и ошибочные состояния,
  390 и 1440, светлая и тёмная тема, axe.
