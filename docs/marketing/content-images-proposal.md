# Контент: картинки к постам с ИИ (предложение, 24.10.2026)

Статус: **ждёт решения владельца** по Q-CONTENT-5 (модель и месячный лимит) и Q-CONTENT-7 (шлюз картинок).
Продолжение `docs/marketing/content-drafts-proposal.md` (тексты постов, миграция 146, на проде).

## 1. Зачем

Черновик поста уже пишется с ИИ, но картинку владелец ищет сам. В MarkVision «Контент-завод» делал картинку и
карусель через n8n с открытым вебхуком и без лимита. В WETOP то же самое: внутри системы, с лимитом и учётом расхода.

## 2. Как будет выглядеть

- В редакторе черновика кнопка **«Картинка с ИИ»**: одна картинка за нажатие, по теме и тексту поста,
  формат по каналу (Instagram 4:5, Stories 9:16, Facebook и Telegram 1:1).
- Своя картинка: **«Выбрать из медиатеки»** (изображения сайта, MKT8) или «Загрузить».
- Под кнопкой счётчик: «Осталось 27 из 30 картинок в этом месяце». Лимит исчерпан: кнопка неактивна, объяснение
  словами, свои фото работают.
- В плане публикаций у карточки миниатюра; «Скачать картинку» рядом с «Скопировать».
- Карусель (до 10 картинок) и Stories отдельным следующим срезом (Q-CONTENT-6).

## 3. Модель данных (новый раздел DATA_MODEL при утверждении)

- `site_assets.source`: новое значение `AI_GENERATED` (картинка живёт там же, где изображения сайта: приватное
  хранилище, `storage_ref`, sha256, webp; повторно используется в медиатеке).
- `content_drafts.asset_id uuid null` → `site_assets.id` (одна картинка на черновик в этом срезе; карусель потом
  отдельной таблицей `content_draft_assets` с порядком).
- `content_image_usage`: филиал, месяц (DATE первого числа в часовом поясе филиала), счётчик, лимит на момент
  генерации; уникально (location_id, month); FORCE RLS; без DELETE. Списание в одной транзакции с записью картинки;
  сбой модели счётчик не тратит.
- Миграция с `down.sql`, backup и проверкой (AGENTS §14), на production только по отдельному «да».

## 4. Контракт бота `content-image/0`

`POST /internal/content-image` (служебный ключ, как `content-draft/0`): вход тема, текст поста, канал, факты
филиала (вид бизнеса, город, стиль бренда); выход PNG/WebP, размер, модель, стоимость по учёту расхода.
Правила подсказки: без текста на картинке (текст в подписи), без людей с узнаваемыми лицами и чужих логотипов,
без цен и цифр. Проверка размера и типа файла на стороне API до записи.

## 6. Проверки

RED → GREEN на каждом слое: домен (лимит, месяц в часовом поясе филиала, формат по каналу), бот (подсказка без
цифр и лиц, отказ модели), база (CHECK, RLS, уникальность месяца, гонка двух нажатий), API (лимит, чужой филиал,
повтор по `creationId`), UI (счётчик, исчерпанный лимит, миниатюра в плане, обе темы, 390 и 1440).
