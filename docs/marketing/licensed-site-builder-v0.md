# Лицензированный конструктор сайта v0 (MKT9.2)

08.10.2026, ТЗ владельца «WETOP MKT9.2: LICENSED LOVABLE SITE BUILDER». План
`plans/mkt9-2-licensed-lovable-builder-2026-10-08.md`, модель `DATA_MODEL.md` §29.12–§29.15, разбор Lovable
`plans/mkt-lovable-model-2026-10-07.md`. Снимки `reports/mkt9-2-licensed-lovable-builder-2026-10-08/`.

## 1. Главное правило

Проект конструктора это текущий филиал. **Один филиал, один сайт навсегда** (полный UNIQUE `marketing_sites.location_id`).
Нового проекта, копии, ремикса и второго черновика нет; пробовать можно только новыми версиями того же сайта, вернуть
любую версию можно из «Истории». Архивный сайт филиал не освобождает.

## 2. Лицензия

- Лицензия живёт на филиале (`site_builder_entitlements`), статусы `TRIAL` (со сроком), `ACTIVE` (срок не обязателен),
  `OFF`. Только филиалы гостиничного бизнеса.
- Выдаёт, продлевает и выключает **только главный администратор платформы**: «Платформа → Организации → Конструктор
  сайта», `GET /platform/organizations/:id/site-builder`, `PUT …/site-builder/:locationId`. Запись идёт служебной ролью,
  у `wetop_app` на лицензии только `SELECT`, поэтому ни партнёр, ни его администратор лицензию себе не включат даже в обход
  API. Каждая смена в журнале `site_builder.entitlement_updated` с «было» и «стало».
- Проверка в трёх местах, не в интерфейсе:
  1. ранняя проверка в API (`assertSiteBuilderWrite`) даёт 403 до остальных проверок;
  2. `siteTransaction` записи повторяет её в той же транзакции, что и сама запись;
  3. воркер ИИ проверяет лицензию и организацию перед каждым платным вызовом; без неё задача `FAILED`
     `LICENSE_UNAVAILABLE`, модель не зовётся.
- Коды: 403 `SITE_BUILDER_NOT_ENABLED` («Конструктор сайта не подключён для этого филиала»), 403
  `SITE_BUILDER_EXPIRED` («Срок конструктора сайта истёк»).
- Без лицензии закрыто: создание сайта, сохранение, восстановление версии, весь ИИ (сборка, чат, план, оформление),
  картинки, публикация, возобновление, откат, знания проекта, закладки. Открыто: чтение всего, пауза, архив, выбор
  сайта брони. **Опубликованный сайт продолжает работать** и после окончания лицензии.
- Миграция выдаёт `ACTIVE` без срока только тем филиалам, у которых сайт уже был: начатая работа не обрывается. Новых
  лицензий агент не выдаёт.

## 3. Маршруты (право `settings`, строгий scope филиала MKT3)

| Маршрут | Что делает |
|---|---|
| `GET /marketing/site` | сайт, имя филиала, `builder` (доступ, статус, срок, причина), знания проекта |
| `POST /marketing/site/bootstrap` `{}` | заводит сайт филиала: имя из филиала, адрес `suggestMarketingSlug` с детерминированным суффиксом; есть сайт 200, новый 201, архивный 409 `SITE_ARCHIVED`. Прежний `POST /marketing/site` снят |
| `GET/PATCH /marketing/site/context` | знания проекта `{ instructions }` до 5000 знаков; в журнале только длина |
| `POST /marketing/site/assistant` | `requestKey`, `mode` CHAT/PLAN/DESIGN, `text`, необязательные `answers`; ставит `site_ai_runs` |
| `GET /marketing/site/assistant/:id` | состояние и проверенный ответ |
| `POST /marketing/site/assistant/:id/approve` | по успешному плану ставит одну задачу сборки, `requestKey` = id плана; повтор отдаёт ту же задачу |
| `GET /marketing/site/conversation?limit=` | сборки и разговоры одним списком по времени, с текстом человека |
| `PUT/DELETE /marketing/site/versions/:id/bookmark` | закладка версии с подписью, до 20 на сайт |
| `POST /marketing/site/generations` | как в MKT9, INITIAL принимает `designRunId` и `designId` выбранного направления |

## 4. Режимы ИИ

- **Сборка**: прежние INITIAL, PATCH, SECTION (`docs/marketing/site-generation-v0.md`, `site-editor-v0.md`).
- **План**: ИИ отвечает либо до четырёх вопросов с вариантами, либо планом (что меняет, страницы, блоки, шаги, чем
  придётся пожертвовать, текст команды сборки). План можно поправить; «Собрать по плану» создаёт ровно одну сборку.
- **Чат**: ответ словами, без новой версии. Может предложить «Перейти в сборку»; на просьбу опубликовать показывает
  кнопку «Перейти к публикации». ИИ сам никогда не публикует.
- **Оформление**: ровно три направления только из перечислений SiteSpec (тема, вариант первого экрана, порядок блоков).
  У нового сайта выбор уходит в первую сборку и применяется после ответа модели детерминированно
  (`applyDesignDirection`); у готового применяется в редакторе без ИИ и сохраняется обычной версией.

Ответ бота разбирает и проверяет платформа (`parseAssistantResult`); неверный ответ даёт `FAILED`, а не мусор в ленте.
Разговорные задачи версий не создают никогда.

### 4.1 Память разговора (доводка 08.10.2026 по ревью владельца)

- **История для модели.** Перед каждым вызовом `site-assistant/0` воркер собирает из базы прошлые ходы ТОЛЬКО этого
  сайта (`site_id` задачи), созданные раньше текущей задачи: успешные разговоры (Чат, План с планом, Оформление) и
  успешные сборки (`BUILD`: текст человека и «Изменение применено к сайту»). Браузер историю не присылает. Упавшие ходы
  и упавшие сборки не берутся (лента в стойке их по-прежнему показывает). Промпты, сырые ответы модели, тексты ошибок,
  журнал, другие филиалы, организация, продавец и техподдержка в историю не попадают по построению.
- **Пределы:** не больше 12 ходов и 16 000 символов канонической записи (`JSON.stringify`, счёт по символам). Берутся
  самые новые целые ходы; первый не влезающий ход останавливает отбор, строки не режутся (`boundAssistantHistory`).
- **Контракт:** поле `history: [{ mode: CHAT|PLAN|DESIGN|BUILD, userText, assistantText, payload }]`, от старых к
  новым, текущий запрос отдельно в `userText` и в историю не входит. Бот кладёт историю отдельным блоком «ИСТОРИЯ
  РАЗГОВОРА» между знаниями проекта и запросом. Старшинство: правила системы, правила SiteSpec, данные гостиницы,
  знания проекта, история, текущий запрос. История это данные: старые «игнорируй правила» правил не меняют.
- **Ответ на вопросы плана:** браузер шлёт `{ requestKey, mode: "PLAN", replyToRunId, answers: [{ questionId, answer }] }`,
  `text` необязателен (дописывается «Дополнением»). Сервер находит родителя только в этом сайте (чужой или
  несуществующий id: нейтральный 404 без вопросов), требует `PLAN`, `SUCCEEDED` и `kind: QUESTIONS` (иначе 400), каждый
  вопрос родителя ровно один раз (незнакомый, повтор, пропуск: 400), ответ из вариантов или свой при `allowCustom`, до
  400 знаков. Модель не зовётся, задача не создаётся.
- **Один чистый контракт без повторов:** новая задача плана хранит самодостаточный запрос (исходная просьба, точные
  вопросы, ответы; `planFollowUpText`), поэтому ход плана с вопросами в историю не идёт. Связи с родителем в базе нет,
  миграции 068 и 069 не менялись: родитель нужен только при постановке.
- Расход токенов на историю учитывает провайдер вместе со всем запросом (Q-274, Q-279 без изменений).

## 5. Общие правила ИИ сайта (обе таблицы: `generation_runs` и `site_ai_runs`)

- одна активная задача ИИ на сайт (проверка под замком сайта), 409 `AI_RUN_ACTIVE`;
- платные вызовы одной организации по одному (воркер берёт задачи обеих таблиц одной очередью);
- один дневной пул 150 000 токенов на организацию (Q-274), кэш не считается дважды;
- неизвестный расход (Q-279) останавливает ИИ сайта организации до следующих суток UTC, и при постановке тоже
  (409 `USAGE_UNAVAILABLE`);
- 10 запросов в час на человека в организации на все режимы вместе.

## 6. Бот

`POST /internal/site-assistant` (`site-assistant/0`), только служебный ключ, только ключ модели платформы. Сообщение
разделено на правила системы, данные гостиницы, текущий документ, знания проекта и запрос человека; знания и запрос это
данные, а не правила. Промпт и сырой ответ модели не хранятся и не возвращаются.

## 7. Интерфейс

- Нет сайта: «Сайт для {филиал}», поле «Опишите, каким должен быть сайт», «Создать сайт» и «Показать варианты
  оформления», ниже тихий список «WETOP уже знает». Названия и адреса не спрашиваем.
- Есть сайт: полоса проекта (филиал, «Сайт филиала», состояние лицензии, черновик и опубликованная версия, «История»,
  «Изображения», «Публикация»), слева ИИ с режимами, блоки и сайт, справа живой сайт.
- Над живым сайтом «Выбор» (`S`) и «Текст» (`T`). В «Тексте» щелчок по разрешённому тексту даёт правку на месте, Enter
  применяет, Escape отменяет; сохранение даёт обычную ручную версию, ИИ не зовётся. Цены, даты, бронь, тарифы, коды
  категорий, картинки, ссылки и контакты так не правятся. Метки `data-editor-path` ставит только рендер черновика в стойке,
  в опубликованном сайте их нет.
- Разговор хранится на сервере и виден после обновления и с другого компьютера; в браузере остаётся только недописанный
  текст.
- Без лицензии всё видно, кнопки записи выключены, плашка «Конструктор сайта не активен для этого филиала».

свои домены (MKT10), ИИ-SEO (MKT11), ИИ-картинки, рисование и комментарии на сайте, выделение нескольких блоков.
