# Редактор сайта v0: ручная правка, ИИ-правки и история версий

Срез MKT9. План и решения: `plans/mkt9-site-editor-ai-edits-2026-10-07.md`. Модель данных не менялась, миграций нет:
всё ложится на `marketing_sites`, `marketing_site_versions`, `generation_runs`, `site_assets` (`DATA_MODEL.md` §29).
Публикация не меняется: это MKT7 (`site-publication-v0.md`).

## 1. Одна цепочка неизменяемых версий

```
голова rN ── ручное сохранение ───────────────► rN+1 (MANUAL, родитель rN)
          ── ИИ PATCH или SECTION от rN ───────► rN+1 (AI, родитель rN, задача)
          ── восстановление rK ───────────────► rN+1 (MANUAL, родитель rN, документ rK)
published_version_id меняет только MKT7 (публикация, откат, возобновление)
```

Ни одна операция редактора не делает `UPDATE` версии и не трогает `published_version_id`. Черновика «на сервере» нет:
несохранённый документ живёт только в браузере.

## 3. Маршруты управления (право `settings`, строгий scope филиала MKT3)

| Маршрут | Ответ |
|---|---|
| `POST /marketing/site/versions` `{ baseRevision, spec }` | 201 `{ version: { id, revision, … } }`; 400 с `errors[]` (путь, код, текст); 409 `VERSION_CONFLICT` при чужой ревизии; 409 `ASSET_UNAVAILABLE` с `paths[]` |
| `GET /marketing/site/versions` | до 100 последних, новые сверху: `id, revision, parentVersionId, source, generationRunId, createdById, createdAt, specHash, isLatest, isPublished`; документа нет |
| `GET /marketing/site/versions/:id` | метаданные и `spec`; версия другого сайта или филиала 404, как несуществующая |
| `GET /marketing/site/versions/:id/diff?against=<id>` | `{ from, to, changes }`: разница `against → :id`; обе версии этого сайта, иначе 404 |
| `POST /marketing/site/versions/:id/restore` `{ baseRevision }` | 201 новая версия от головы с документом `:id`, `source = MANUAL`; 409 `VERSION_CONFLICT`; 409 `ASSET_UNAVAILABLE`, если в версии есть картинка, удалённая из библиотеки |
| `POST /marketing/site/generations` | без `type` (или `INITIAL`) как в MKT6; `PATCH` и `SECTION` §6 |
| `GET /marketing/site/generations/:id` | плюс `type`, `baseVersionId`, у SECTION `target`; текста команды нет |

Рантайм (`/sites-runtime/*`) исторических версий не отдаёт: чтение версии по id есть только у управления
(таблица `route-access` держит это явным списком).

## 4. Восстановление против отката

| | Восстановление (MKT9) | Откат (MKT7) |
|---|---|---|
| Что меняется | голова черновика: новая версия | только опубликованная версия |
| Новая версия | да, `revision + 1` | нет |
| Публичный сайт | не меняется | меняется сразу |
| Картинка, удалённая из библиотеки | 409 `ASSET_UNAVAILABLE`: заменить | показывается (объект удержан, MKT8) |

## 5. Смысловая разница (`diffSiteSpecs`)

События, а не JSON: `area` (`site`, `page`, `section`, `asset`), `kind` (`added`, `removed`, `moved`, `changed`,
`variant`, `replaced`), плюс `field`, `pageId`, `sectionId`, `sectionType`, `label`, `from`, `to`, `slot`.

- Сайт: `displayName`, `tagline`, `locales` (с языком по умолчанию), `contacts`, `legal`, `seo`, `theme`,
  `integrations`, `navigation`.
- Страницы по `id`: добавлена, удалена, перемещена (наибольшая общая подпоследовательность, перестановка это одно
  `moved`, а не удаление и добавление), изменены `title`, `slug`, `seo`, `settings` (главная).
- Секции по `id` во всём документе: добавлена, удалена, перемещена (в том числе на другую страницу, `field: page`),
  `variant` с было и стало, `changed` содержимого (без ссылок на картинки).
- Картинки по месту (`logo`, `favicon`, `page:<id>:og`, `section:<id>:image`, `section:<id>:images`,
  `section:<id>:items`): у одиночного места `replaced`, у списков `added` и `removed`.
- Порядок вывода детерминирован: сайт, страницы в порядке новой версии и удалённые, секции, картинки по месту.

## 6. ИИ-правки

Постановка (тело строгое, лишнее поле 400):

```json
{ "requestKey": "uuid", "type": "PATCH", "baseVersionId": "uuid", "instruction": "Сделай первый экран короче" }
{ "requestKey": "uuid", "type": "SECTION", "baseVersionId": "uuid", "pageId": "page-home", "sectionId": "hero-main",
  "instruction": "необязательно" }
```

До постановки: сайт не в архиве, голова есть и равна `baseVersionId` (иначе 409 `BASE_VERSION_CHANGED`), у SECTION
цель есть на этой странице базы (иначе 409 `UNKNOWN_SECTION`), нет задачи в `QUEUED` или `RUNNING`, ИИ и бюджет
настроены, не больше 10 постановок в час на человека (общий счётчик всех видов, повтор ключа не считается). Хэш брифа
сервер собирает сам и пишет в задачу. Команда: обрезка краёв, без управляющих символов кроме перевода строки, PATCH
1–1800 знаков, SECTION 0–1500 (пусто значит «Пересобери эту секцию, сохранив её назначение.»).

Хранение команды: у PATCH `generation_runs.instruction` это текст; у SECTION конверт
`{"pageId":"…","sectionId":"…","v":1}` каноническим JSON, перевод строки и текст как есть (пусто, если текста нет).
Текст в конверте не экранируется, поэтому длина гарантирована: заголовок до 100 знаков плюс 1500 меньше 2000
(`VARCHAR(2000)`). Разбор только `encodeSectionInstruction` и `decodeSectionInstruction`.

Воркер один и ветвится по `run.type`; INITIAL как в MKT6. Перед моделью и перед каждым повтором: сайт не в архиве,
голова равна базе (иначе `BASE_VERSION_CHANGED` без модели), база этого сайта, бриф с тем же хэшем (иначе
`BRIEF_CHANGED`), конверт разбирается, база проходит текущий валидатор. Повторяются `SCHEMA_INVALID`,
`MODEL_UNAVAILABLE`, `TIMEOUT`, всего три попытки; в повтор уходят только пары «путь код».

Успех одной транзакцией под замком сайта: задача `RUNNING`, сайт не в архиве, голова всё ещё база (ручное сохранение,
сделанное за время работы ИИ, выигрывает: `BASE_VERSION_CHANGED`, версии от ИИ нет), документ проходит проверку
картинок MKT8, новая версия `base + 1`, родитель база, `source = AI`, задача, автор постановщик; публикация не
трогается. Журнал без текста команды: вид, база, у SECTION страница и секция, версия, модель, счётчики.

## 7. Бот: `POST /internal/site-edit` (`site-edit/0`)

Только служебный ключ (сессия панели, ключ виджета, неверный ключ 403). Ключ модели только платформы (Q-274; ключ
партнёра не читается), бюджет `SITE_GENERATION_DAILY_TOKEN_BUDGET` общий с генерацией (все виды задач в сутках UTC
организации), расход всех фактических вызовов, неизвестный расход `USAGE_UNAVAILABLE` и стоп каскада (Q-279).

```json
{ "schemaVersion": "site-edit/0", "requestId": "…", "mode": "PATCH",
  "siteSpecSchemaVersion": "site-spec/0", "briefInput": {}, "baseSpec": {}, "instruction": "…",
  "budgetRemainingTokens": 10000, "validationErrors": [] }
```

У `SECTION` ещё `target: { pageId, sectionId }`. Ответ как у генерации: `status`, `spec` (документ SiteSpec целиком,
не JSON Patch), `errorCode`, `model`, `usage { input, cached, output, complete, paidCalls }`. Системные правила в коде;
текущий документ, бриф и просьба владельца отдельными блоками данных; просьба в системное сообщение не попадает.

## 8. Что платформа проверяет у ответа ИИ (`checkEditedSpec`)

PATCH: валидатор SiteSpec v0; не меняются `site.vertical`, `displayName`, `locales`, `defaultLocale`, `contacts`,
`legal`, `site.seo` (в том числе разметка для поисковиков), `integrations`, у страниц число, порядок, `id`, `slug`,
`isHome`, `seo`; `emitStructuredData` у FAQ как в базе. Каждая картинка выхода есть в базе (ИИ может оставить или
убрать, но не добавить), каждый внешний адрес есть в базе, коды категорий из текущего брифа. Можно: тексты, слоган,
тема, состав, порядок и варианты секций, навигация.

SECTION: всё, кроме целевой секции, канонически равно базе; у цели тот же `id`, `type` и место, вариант того же типа;
картинки и внешние адреса только из базовой цели; категории из брифа.

Отказ любого правила: `SCHEMA_INVALID` с путями. Перед созданием версии ссылки на картинки ещё раз проверяются по
библиотеке (как при ручном сохранении).

## 9. Стойка `/marketing/site/editor`

Право `settings`, только гостиница. Раскладка MKT9.1 (07.10, по образцу конструкторов, план
`plans/mkt9-1-editor-live-preview-2026-10-07.md`):

- **Верхняя полоса**: «Черновик, версия N», «На сайте: версия M» (или «ещё не опубликован»), «Есть несохранённые
  изменения / Все изменения сохранены», «История», «Сохранить черновик». В шапке страницы «Публикация» и «Изображения».
- **Справа живой сайт**: тот же рендер, что Worker (`apps/sites/src/draft-preview.ts`), по документу на экране, то есть
  сразу после правки формы, без сохранения. Без ключа сайта, брони, счётчика, цен «от» и токена превью; стили внутри
  страницы; `noindex`. Рамка `srcdoc` с `sandbox="allow-same-origin"` без `allow-scripts`: скрипты сайта не выполняются,
  стойка сама слушает щелчки. Над сайтом: страница, язык (если языков больше одного), «Компьютер / Телефон», «Открыть в
  новой вкладке» (подписанное превью MKT7 сохранённой версии). Наведённый блок обведён пунктиром, выбранный рамкой.
- **Щелчок в блоке** выбирает секцию: её форма во вкладке «Блоки», рамка на сайте, блок становится целью ИИ. Ссылка меню
  или подвала на страницу сайта переключает страницу просмотра; наружу ничего не открывается. Документ, который рендер
  не может нарисовать, оставляет прошлый кадр с подсказкой.
- **Слева три вкладки**: «ИИ» (лента запросов сессии и строка ввода, см. ниже), «Блоки» (страницы и блоки открытой в
  просмотре страницы: добавить, ↑ ↓, копия, удалить; выбранный блок открывает форму с «Все страницы и блоки» и «Изменить
  этот блок с ИИ»), «Сайт» (настройки сайта).
- **Вкладка «ИИ»**: запрос с меткой «Блок «…»» уходит `SECTION` (текст необязателен), без метки `PATCH`; «Весь сайт»
  снимает метку. Несохранённые правки: кнопка «Сохранить и отправить» (сначала версия, потом запрос). Ctrl+Enter
  отправляет. В ленте: запрос человека, «В очереди / ИИ работает», «Готово: ИИ создал версию N» с «Что изменилось» и
  «Вернуть как было» (восстановление базовой версии запроса новой версией с вопросом), ошибка постоянным текстом по коду
  с «Повторить запрос». **С MKT9.2** лента хранится на сервере (`GET /marketing/site/conversation`: сборки и разговоры
  ИИ одним списком, с текстом человека, видна людям с `settings` этого филиала после обновления и с другого компьютера;
  решение владельца MKT9.2 отменяет §110 ТЗ MKT9 внутри сайта филиала, в журнал аудита текст по-прежнему не идёт);
  в `sessionStorage` остаётся только недописанный текст. Режимы «Чат», «План», «Сборка», варианты оформления, правка
  текста на сайте, закладки и лицензия: [`licensed-site-builder-v0.md`](licensed-site-builder-v0.md).
- **До 960 px** четыре вкладки «ИИ / Блоки / Сайт / Просмотр», переключатель ширины скрыт.

- Одно состояние: документ целиком; «изменено» значит, что каноническая запись отличается от загруженной версии.
- Без автосохранения, без JSON-редактора; формы по реестру секций домена (тест сверяет его с валидатором).
- Ошибка проверки, 409, отказ API и сбой связи ввод не стирают; ошибки встают у полей и сводкой со ссылкой к полю.
- 409: «Посмотреть новую версию», «Сравнить» (разница новой версии и ваших правок), «Продолжить с моими изменениями»
  (база становится новой головой, следующее сохранение пишет ваши правки поверх). Автослияния нет.
- Живой просмотр по документу на экране; «Открыть в новой вкладке» только для сохранённой головы (с правками «Сначала
  сохраните черновик»); ИИ правит сохранённую голову (с правками «Сохранить и отправить»).
- Уход со страницы с правками спрашивает.
- Картинки только из библиотеки MKT8 (готовые, этого филиала, нужного вида); ALT отдельно в документе, подсказка из
  библиотеки; адрес руками не вводится. Категории только из брифа; цены руками нет.
- Удаление страницы или секции, на которую ссылаются навигация, кнопки или политика, запрещено со списком ссылок.
- Язык снимается вместе со своими текстами; язык по умолчанию снять нельзя.
- Окно «Какой сайт сделать?» (слово владельца 07.10, по образцу конструкторов): нет сайта или нет версий, тогда
  вместо редактора одна крупная строка ввода и «Создать сайт» (Ctrl+Enter; готовых примеров нет, слово владельца
  07.10). Нет сайта: он заводится
  существующим `POST /marketing/site` с названием филиала и адресом из названия (`suggestMarketingSlug`, поле видно и
  правится; занятый адрес отказом у поля, молча не меняется). Затем первая версия ИИ потоком MKT6, текст человека уходит
  пожеланием (§6а). Шаги «Сайт заведён → Собираем данные гостиницы → ИИ пишет сайт → Открываем редактор»; ошибка
  словами по коду, текст на месте. Стартового документа «вручную» нет.

## 6а. Пожелания к первой версии (INITIAL)

`POST /marketing/site/generations` с телом MKT6 принимает необязательное `instruction` (до 1800 знаков, те же правила
текста, что у PATCH). Хранится в `generation_runs.instruction`, наружу и в журнал не идёт. Воркер передаёт его боту
полем `instruction` контракта `site-generation/0` (нет пожеланий, нет и поля: прежний контракт не меняется); бот кладёт
его блоком «ПОЖЕЛАНИЯ ВЛАДЕЛЬЦА» после данных, в правила не включает. Проверка ответа прежняя (`checkGeneratedSpec`):
пожелания не источник фактов, название, контакты и категории только из брифа.

## 10. Не входит

Автослияние, автосохранение, отмена задачи, ИИ-SEO (MKT11), свои домены (MKT10), генерация картинок, очистка старых
версий (Q-272), создание сайта из редактора.
