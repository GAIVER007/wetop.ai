# Заявки с управляемого сайта, контракт тела (SITE-2)

Статус: **контракт тела и разбор в домене с 15.10.2026**; приём на API вводят срезы SITE-4 (`/w/beauty/book`,
`/w/food/reserve`) и SITE-5 (`/w/lead`, `site_leads`), они требуют миграций (план `plans/site-seo-flow-2026-10-15.md`,
ADR-185 п. 3). Код: `packages/domain/src/marketing/site-lead.ts` (`parseSiteLead`, `SITE_LEAD_ENDPOINTS`); форма:
секция `leadForm` ([`sitespec-v1-verticals.md`](sitespec-v1-verticals.md) §4), скрипт `apps/sites/src/render/lead-script.ts`.

Бронь номера (`HOTEL_BOOKING`) идёт прежним виджетом и прежним телом `POST /w/book`; здесь её нет.

## 1. Адреса

| Режим | Адрес | Ответ при успехе |
|---|---|---|
| `BEAUTY_APPOINTMENT` | `POST /w/beauty/book` | 201, повтор того же `requestKey` 200 с той же записью |
| `TABLE_RESERVATION` | `POST /w/food/reserve` | то же |
| `CALLBACK` | `POST /w/lead` | то же |

Браузер посетителя шлёт JSON без cookies (`credentials: 'omit'`). Ошибка: код 4xx и `{ "message": "<текст для
посетителя>" }`, форма показывает текст как текст.

## 2. Общие поля

| Поле | Тип | Обязательно | Правило |
|---|---|---|---|
| `k` | строка | да | публичный ключ сайта счётчика `pms_` + 12 hex (как у `/w/book`): по нему API находит филиал |
| `name` | строка | да | до 120 знаков после обрезки, без управляющих символов |
| `phone` | строка | да | как ввёл посетитель, `^\+?[0-9 ()-]{7,32}$`; к E.164 приводит API |
| `comment` | строка | нет | до 1000 знаков, переводы строк допустимы |
| `requestKey` | UUID v4 | да | один на попытку отправки; повтор не создаёт вторую запись |
| `turnstileToken` | строка | нет | обязателен, когда проверка включена (`GET /w/config` отдаёт `turnstileSiteKey`); действие `booking` |
| `website` | строка | нет | ловушка для ботов: непустое значение API принимает молча и не записывает |
| `lang` | `ru`, `kk`, `en` | нет | язык страницы для ответа и уведомления |

Лишнее поле, в том числе поле другого режима, это отказ (`parseSiteLead` возвращает список полей).

## 3. Поля режимов

**Запись к мастеру** (`BEAUTY_APPOINTMENT`):

| Поле | Тип | Обязательно | Правило |
|---|---|---|---|
| `serviceCode` | строка | да | код услуги из секции `services` сайта (id услуги каталога WETOP) |
| `employeeId` | UUID | нет | мастер из секции `staff`; нет поля: «любой мастер» |
| `startsAt` | `YYYY-MM-DDTHH:mm` | да | начало по часам филиала, **без смещения**: пояс филиала знает API (`locations.timezone`, AGENTS.md §13) |

**Бронь стола** (`TABLE_RESERVATION`):

| Поле | Тип | Обязательно | Правило |
|---|---|---|---|
| `date` | `YYYY-MM-DD` | да | дата по календарю филиала, существующая |
| `time` | `HH:mm` | да | время по часам филиала |
| `partySize` | целое | да | 1–50 |

**Перезвоните** (`CALLBACK`): только общие поля.

## 4. Что решает API (не форма)

Свободно ли время (то же расписание, что у стойки), действует ли услуга и мастер в филиале, лимиты частоты, Turnstile,
статус созданной записи («Записан», «Забронирован», «Новая заявка»), источник «Сайт», уведомления. Форма ничего из
этого не проверяет и не обещает.
