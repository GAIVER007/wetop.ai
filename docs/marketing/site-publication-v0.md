# Публикация, превью и домены управляемого сайта, v0 (MKT7)

Статус: **07.10.2026, срез MKT7, в ветке, ждёт ревью владельца.** План: `plans/mkt7-publication-preview-domains-2026-10-07.md`.
Модель: `DATA_MODEL.md` §29.4, §29.6, §29.8, §29.11. Решения владельца: Q-271 и Q-275 (RESOLVED OWNER 07.10.2026,
`QUESTIONS.md`). Общая архитектура: [`README.md`](README.md).

Поток: версия → превью → публикация (платформенный поддомен, свой `TrackedSite`) → рантайм Worker → пауза и
возобновление → новая версия и публикация → откат → архив.

## 1. Адреса сайтов (Q-271)

- Сайты клиентов живут на отдельном registrable domain `SITES_BASE_DOMAIN`, не под `wetop.ai`. Значение задаёт
  инфраструктура (`.env` API, переменная Worker); конкретного apex в исходниках нет. `parseSitesBaseDomain` отвергает
  пустое значение, схему, порт, путь, IP и `wetop.ai` с поддоменами.
- Платформенный адрес `<slug>.<SITES_BASE_DOMAIN>`, превью `preview.<SITES_BASE_DOMAIN>`.
- Wildcard DNS и маршрут Worker `*.<SITES_BASE_DOMAIN>` заводятся заранее. Публикация API Cloudflare не вызывает: хост
  это строка `site_domains`.
- Нормализация хоста одна для API и Worker (`normalizeSiteHost`, `packages/domain/src/marketing/host.ts`): нижний
  регистр, без порта и точки в конце, IDN в punycode, не IP, до 253 знаков.
- Нет `SITES_BASE_DOMAIN` или оно неверное: публикация отвечает 503 `SITES_DOMAIN_UNCONFIGURED`, страница показывает
  «Адрес сайтов не настроен».
- Свои домены (`CUSTOM`) в MKT10 через Cloudflare for SaaS (Custom Hostnames); в MKT7 только схема, ни API, ни
  проверки, ни сертификатов.

## 2. Маршруты управления

Все под входом, право `settings`, строгий scope одного филиала гостиницы (как MKT3), лишние поля тела 400, хост в теле
не принимается никогда.

| Маршрут | Тело | Что делает |
|---|---|---|
| `POST /marketing/site/preview` | `{ versionId }` | ссылка превью `{ url, expiresAt }` для версии своего сайта; 503 `PREVIEW_DISABLED` без секрета |
| `POST /marketing/site/publish` | `{ expectedVersionId, bookingRatePlanId? }` | публикует только голову черновика (§3) |
| `POST /marketing/site/pause` | `{}` | `PUBLISHED → PAUSED`, `TrackedSite` на паузу |
| `POST /marketing/site/resume` | `{}` | `PAUSED → PUBLISHED` с повторной проверкой версии |
| `POST /marketing/site/rollback` | `{ versionId }` | откат на ранее опубликованную версию (§4) |
| `POST /marketing/site/archive` | `{}` | архив (§5) |
| `GET /marketing/site/publications` | | журнал, до 100 строк, без документа |
| `GET /marketing/site/booking-source` | | канонический сайт брони, подходящие сайты объекта, действующие тарифы |
| `PUT /marketing/site/booking-source` | `{ trackedSiteId: uuid \| null }` | выбор вручную; негодный сайт 409 `BOOKING_SOURCE_NOT_ELIGIBLE` |

Каждое действие пишет строку `marketing_site_publications` (кроме выбора источника брони) и запись `audit_logs`
`marketing.site.<действие>`.

## 3. Публикация

Одна транзакция под замком строки сайта:

1. `expectedVersionId` равен `latest_version_id`, иначе 409 `VERSION_CHANGED`. Повтор уже опубликованной головы:
   `changed: false`, ничего не пишется.
2. Повторная проверка версии: тот же валидатор, версия схемы и хэш (`SPEC_INVALID`), ни одной ссылки на медиа до MKT8
   (`MEDIA_NOT_READY`, Q-270 не решается), все категории документа есть у объекта филиала и активны
   (`CATEGORY_UNAVAILABLE`).
3. Тариф брони, если в документе `integrations.booking.mode = WETOP_WIDGET`: явный из запроса → тариф связанного
   управляемого сайта → тариф канонического сайта брони филиала → 409 `BOOKING_RATE_PLAN_REQUIRED`. Первый,
   самый дешёвый, «базовый» и тариф по умолчанию объекта не берутся. Заданный, но выключенный тариф даёт 409
   `BOOKING_RATE_PLAN_INVALID`, а не переход к следующему источнику. Без брони в документе тариф в теле 400.
4. Домен: строка `PLATFORM_SUBDOMAIN` `<slug>.<SITES_BASE_DOMAIN>`, `PENDING → ACTIVE`, основная. Хост занят живой
   строкой другого сайта: 409 `HOST_TAKEN`.
5. `TrackedSite` управляемого сайта: при первой публикации новый (новый публичный ключ `pms_…`), дальше тот же.
   Хосты сайта в `tracked_sites.hosts` синхронизируются с `ACTIVE`-доменами; родительский домен туда не кладётся.
6. Канонический сайт брони (Q-275): первая публикация ставит указатель на этот сайт, только если указатель пуст и
   других подходящих сайтов у объекта нет. Уже выбранный сайт, в том числе приостановленный, не заменяется.
7. Состояние: `DRAFT → PUBLISHED`; публикация на паузе меняет версию и остаётся `PAUSED`.

## 4. Пауза, возобновление, откат

- Пауза только из `PUBLISHED`. Рантайм отвечает 404 (сайт не в `PUBLISHED`), домены остаются за сайтом.
- Возобновление только из `PAUSED`, с той же проверкой версии и тарифа, что публикация; нет действующего основного
  домена: 409 `DOMAIN_MISSING`.
- Откат: версия своего сайта (`404` иначе), которая уже была опубликована (журнал `PUBLISH`, `ROLLBACK`, `RESUME`;
  иначе 409 `NEVER_PUBLISHED`), не текущая (`ALREADY_PUBLISHED`), с той же проверкой версии. Меняется только
  `published_version_id`: голова черновика не трогается, пауза остаётся паузой.

## 4а. Сайт счётчика управляемого сайта

`TrackedSite`, созданный публикацией, настраивает только публикация. Старый путь `/analytics/sites/:id` его читает
(карточка и отчёт, `managed: true`), но `PATCH` и `DELETE` отвечают 409 `MANAGED_SITE_READ_ONLY` («Управляемый сайт
настраивается в «Маркетинг → Сайт и SEO»»); репозиторий аналитики тоже не трогает строку, у которой есть
`marketing_sites`. Экран `/website` вместо формы показывает ссылку на публикацию. Хосты такого `TrackedSite` всегда
ровно `ACTIVE`-домены его `site_domains` (лишний хост, добавленный в обход, снимается при следующей синхронизации; после
архива список пуст). Внешние сайты работают как раньше.

## 5. Архив

Домены сайта `REMOVED` (хост освобождается), `TrackedSite` на паузу без хостов сайта, указатель брони филиала снят,
если стоял на этом сайте (на внешний сам не переключается), состояние `ARCHIVED`. Версии и журнал остаются. Архивный и
неизвестный хост рантайм не различает: одинаковый нейтральный 404 без имени сайта (выбран 404, а не 410: по 410 можно
было бы узнать, что сайт на этом адресе был).

## 6. Превью

- Токен: base64url JSON `{ v: 1, siteId, versionId, exp }` и HMAC-SHA256 секретом `SITE_PREVIEW_SECRET` (не короче 32
  байт). Срок 60 минут; токен со сроком дальше 24 часов отвергается. Сравнение подписи за постоянное время.
- Ссылка `https://preview.<SITES_BASE_DOMAIN>/?token=…`. Стойка открывает её сразу в новой вкладке, текстом не
  показывает и не хранит.
- `GET /sites-runtime/preview?token=` (ключ `SITES_RUNTIME_KEY` плюс токен): версия ровно из токена и только своего
  сайта, сайт не в архиве; просроченный токен 410, испорченный или чужой 404, без секрета 503.
- Ответ Worker: `X-Robots-Tag: noindex, nofollow`, `Cache-Control: private, no-store`, `Referrer-Policy: no-referrer`;
  нет брони, счётчика и цены «от»; `robots.txt` запрещает всё, `sitemap.xml` 404.
- Токен разрешает одну версию целиком, со всеми её страницами. Все внутренние переходы превью несут тот же токен
  (`/privacy?token=…`, секция другой страницы `/?token=…#rooms`): бренд, меню, подвал, ссылка на политику, кнопки
  `PAGE`, `SECTION`, `BOOK` и «На главную» на странице 404. Секция той же страницы остаётся фрагментом (`#faq`), браузер
  сам оставляет адрес с токеном. Внешние ссылки токена не получают. Токен не пишется ни в счётчик (его в превью нет), ни
  в куки или `localStorage`, ни в лог Worker; `no-referrer` не отдаёт его чужим сайтам.

- Хост превью Worker включает только при верном `SITES_BASE_DOMAIN` по тому же правилу, что API
  (`parseSitesBaseDomain`: не `wetop.ai` и не его поддомен, без схемы, порта и пути); неверное значение выключает превью.

## 7. Рантайм на боевых хостах

`GET /sites-runtime/current` находит сайт по `site_domains` в `ACTIVE` (карта dev и test остаётся только для стендов)
и отдаёт настоящий `primaryHost`. Worker уводит неосновной хост сайта 301 на основной с тем же путём и запросом;
неверный хост отвечает 404, не спрашивая API.

## 8. ИИ-продавец (Q-275)

`bookingSiteForAgent` берёт только `locations.booking_tracked_site_id` филиала агента и проверяет: тот же объект,
`ACTIVE`, бронь включена, тариф задан. Иначе котировки нет; запасного «самого раннего сайта» нет. Начальное
заполнение указателя в миграции 064 ставит его только при ровно одном подходящем сайте.

## 9. Чего в MKT7 нет

Своих доменов, TXT-проверки, сертификатов, API Cloudflare и проверочного cron (MKT10); медиа и хранилища (MKT8, Q-270);
редактора страниц (MKT9). Миграции на рабочей базе, выкладку API и Worker, DNS и зону делает владелец.
