# Лимит на краю Cloudflare для чата помощника (`assistant.wetop.ai/widget/*`)

Последний пункт аудита «шесть дыр» 30.09.2026 (`reports/security-vibe-audit-2026-09-30.md` §5, «за владельцем»).
Скрипт — `scripts/ops/cloudflare-widget-ratelimit.sh`, его тест — `tests/unit/cloudflare-widget-ratelimit.test.ts`.

## Зачем, если бот уже считает

Бот ограничивает реплики сам: 60 в час на посетителя и на IP (`widget_messages_per_hour`), счётчики в Redis, при
недоступном Redis — 503 без вызова модели (PR #194). Но считает он уже у себя: поток запросов с одного адреса проходит
туннель, доходит до контейнера и до Redis, и только там получает 429. Правило на краю Cloudflare отсекает такой поток
до туннеля — грубо (один IP, короткое окно) и бесплатно для сервера. Это второй слой, а не замена счётчикам бота.

## Правило

| Что | Значение | Почему так |
|---|---|---|
| Фаза | `http_ratelimit` зоны `wetop.ai` | только там живут правила rate limiting |
| Пути | `/widget/session`, `/widget/consent`, `/widget/message`, `/widget/attachment` | четыре записывающих пути виджета (`apps/ai-seller/src/channels/widget.py`); модель зовёт только `/widget/message`, остальные заводят посетителя и файлы |
| Не входят | `/widget/widget.js`, `/widget/demo`, `/widget/messages` (опрос) | их частоту задаёт сам виджет и кэш, человек их чаще не вызывает; ограничить опрос — сломать чат |
| Считаем по | IP (`ip.src`, `cf.colo.id`) | единственная характеристика на планах Free и Pro |
| Порог | 20 запросов за 10 с с одного IP | человек не пишет чаще одного сообщения в полсекунды; у офиса за одним NAT с десятком посетителей запас остаётся; скрипт на сотни запросов в секунду упирается сразу |
| Действие | блок на 10 с | план Free допускает только 10 с периода и 10 с блока |
| Хост | не указан | на Free в выражении доступен только путь; других хостов зоны с путями `/widget/*` нет (стойка — `/…`, API — `/w/*` и `/a/*`), поэтому правило по пути касается только `assistant.wetop.ai`. На Pro и выше задать `CF_RL_HOST=assistant.wetop.ai` |

Своё правило скрипт узнаёт по `ref = wetop-widget-ratelimit`: повторный `apply` заменяет его, а не добавляет второе;
чужие правила фазы (например, лимит на `/login`, который советовала комиссия 26.09) остаются как есть. На плане Free в
зоне помещается **одно** правило rate limiting: если оно уже занято под вход, Cloudflare отклонит второе — тогда
решать владельцу, какое важнее, или переходить на Pro (два правила).

## Как поставить (владелец, с Mac или с сервера)

1. Токен API в панели Cloudflare: «My Profile → API Tokens → Create Token → Custom», права **Zone → Zone WAF → Edit** и
   **Zone → Zone → Read**, ресурс — только зона `wetop.ai`. Значение — в `.env` клона строкой `CLOUDFLARE_API_TOKEN=…`
   (или в окружение на один вызов); в репозиторий, чат и журнал оно не попадает — скрипт передаёт его curl через
   stdin, а не аргументом.
2. Посмотреть, что стоит сейчас (только чтение):
   ```bash
   scripts/ops/cloudflare-widget-ratelimit.sh status
   ```
3. Поставить:
   ```bash
   scripts/ops/cloudflare-widget-ratelimit.sh apply
   ```
   Номер зоны скрипт находит сам по имени `wetop.ai`; при двух аккаунтах Cloudflare (`docs/deploy.md` §2, грабля
   23.09) токен должен быть выдан в том аккаунте, где зона.
4. Проверить живьём: 25 быстрых POST на `/widget/session` с одного адреса — первые проходят (ответ бота, 200 или 4xx
   по смыслу), затем Cloudflare отвечает **429** со своей страницей, и в журнале бота этих запросов нет:
   ```bash
   for i in $(seq 1 25); do curl -s -o /dev/null -w '%{http_code} ' -X POST https://assistant.wetop.ai/widget/session \
     -H 'Content-Type: application/json' -d '{}'; done; echo
   ```
   Через 10 с запросы снова проходят. Обычный чат на `wetop.ai` при этом работает: открыть виджет, отправить две
   реплики.
5. Записать результат в `SECURITY.md` §14 и `CLAUDE.md` §2 (как у остальных пунктов аудита).

## Откат

```bash
scripts/ops/cloudflare-widget-ratelimit.sh remove
```

Снимает только своё правило. Счётчики бота работают независимо от этого правила, снятие ничего в боте не меняет.

## Что подкрутить

`CF_RL_REQUESTS`, `CF_RL_PERIOD`, `CF_RL_TIMEOUT`, `CF_RL_PATHS`, `CF_RL_HOST` — переменные окружения перед `apply`
(шапка скрипта). На Free период и блок — только 10 с; другие значения Cloudflare отклонит, скрипт покажет ответ.
