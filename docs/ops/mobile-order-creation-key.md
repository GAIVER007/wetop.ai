# Выпуск защиты создания ресторанного заказа

Миграция 20261025000159_restaurant_order_creation_key подготовлена, не применена. Номер сверить с цепочкой main перед выпуском.

Порядок: зелёный гейт на точном SHA; отдельное разрешение владельца на миграцию; проверенный backup и восстановление на отдельном стенде; применение SQL владельцем; validation; совместимый API; только затем включение mobile POST. До миграции новый Prisma API не выкладывать: обычные SELECT RestaurantOrder ожидают новые колонки. Старый API совместим с расширенной схемой, но не даёт гарантий повтора с ключом. Смешанный rollout не должен принимать мобильные POST на старом сервере.

Backup: штатная процедура docs/deploy.md для целевой базы и схемы, фиксировать SHA, состояние миграций, checksum и результат restore drill. Не копировать production-данные в тестовые fixtures. SQL запускать с ON_ERROR_STOP, правильным search_path и только на отдельно согласованной базе.

Validation: обе колонки, unique index, CHECK; прежние заказы имеют NULL/NULL; число заказов и суммы неизменны. На изолированном PostgreSQL проверить два одновременных create с одинаковым ключом, один ID/номер и одно событие food.order.created; отличие payload даёт 409. Scoped доступ проверить отдельно под прикладной ролью с RLS. Тест с mock не доказывает блокировки и RLS.

Rollback: остановить мобильную отправку и новый API. down.sql берёт ACCESS EXCLUSIVE и отказывается работать при хотя бы одном сохранённом ключе. Если ключи использованы, схему и ключи сохранить, чинить вперёд. При пустых ключах отдельно согласованный down.sql, возврат прежнего API и проверка здоровья. Отмена заказа не удаляет ключ.

Локальная репетиция: PostgreSQL 16 в отдельном контейнере wetop-mobile-replay-20261025, только loopback. Миграции применены; replay integration 2/2; populated rollback отказал с Creation keys exist. Production backup/restore, RLS прикладной роли и разрешение применения этим не заменяются. Флаг MOBILE_ORDER_CREATE_ENABLED оставлять выключенным до подтверждения миграции и совместимой версии API.
