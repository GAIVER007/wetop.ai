# Хранилище изображений сайтов: подготовка и проверка в Казахстане (MKT8, Q-270)

Что делает владелец перед тем, как включить загрузку изображений управляемых сайтов на рабочем сервере. Код MKT8 этого
не делает: бакет не заводит, ключей не вписывает, миграций не применяет. Контракт: `docs/marketing/site-assets-v0.md`.

## 1. Решение (Q-270 RESOLVED OWNER 07.10.2026)

Приватный S3-совместимый бакет физически в Казахстане. Первый поставщик PS Cloud Object Storage; если он письменно не
подтверждает, что именно этот проект хранилища, его реплики и резервные копии остаются в Казахстане, рабочий поставщик
Cloud24 S3 (дата-центр в Алматы). Код и схема одинаковы для обоих: меняются только переменные из §4. Cloudflare R2,
Supabase Storage, AWS вне Казахстана, иностранный CDN как origin и диск сервера API не используются.

## 2. Ворота включения (все пункты сразу, иначе `SITE_ASSET_STORAGE=off`)

1. API рабочего контура работает на сервере в Казахстане.
2. Бакет физически в Казахстане.
3. Поставщик письменно подтвердил: страна проекта хранилища, страна репликации и страна резервных копий (если они есть)
   это Казахстан.
4. Ключи бакета есть только в `.env` сервера API (не в стойке, не в Worker, не в браузере, не в git).

Переменная окружения сама по себе residency не доказывает: доказательство это письмо поставщика (§3).

## 3. Что спросить у поставщика письменно (PS Cloud; то же для Cloud24)

- страна размещения именно этого экземпляра объектного хранилища (проекта, а не бренда: в открытых материалах у PS Cloud
  площадки в Алматы, Астане и Ташкенте);
- страна репликации данных;
- страна резервных копий поставщика, если они делаются;
- адрес (endpoint) и регион для S3 API;
- совместимость с S3: подписанные GET (SigV4), `PutObject`, `DeleteObject`, `HeadObject`, стиль пути;
- приватный бакет: без анонимного чтения и листинга, без публичного веб-хостинга бакета;
- ключ доступа только к одному бакету и только на чтение, запись и удаление объектов (без управления бакетом);
- порядок смены ключей.

Ответ (номер письма, дату, кто подтвердил) записать сюда ссылкой на документ, без секретов. Шифрование на стороне
поставщика не заявлять, пока оно не включено и не подтверждено для этого аккаунта: MKT8 опирается на приватный бакет,
узкие ключи, HTTPS и то, что сырой файл не хранится.

## 4. Настройка сервера API

```
SITE_ASSET_STORAGE=s3
SITE_ASSET_S3_ENDPOINT=https://<адрес S3 поставщика>
SITE_ASSET_S3_REGION=<регион поставщика>
SITE_ASSET_S3_BUCKET=<бакет>
SITE_ASSET_S3_ACCESS_KEY_ID=<ключ>
SITE_ASSET_S3_SECRET_ACCESS_KEY=<секрет>
SITE_ASSET_S3_FORCE_PATH_STYLE=1        # если поставщик не поддерживает виртуальные хосты бакетов
SITE_ASSET_SIGNED_URL_TTL_SECONDS=3600
```

Неполная или неверная настройка (адрес не `https:`, пустой бакет и т. п.) выключает хранилище целиком с одной строкой
`site_assets.storage_misconfigured` в логе, без значений.

## 5. Порядок выкладки

1. Копия базы, затем миграции `20261007000066_site_assets` и `20261007000067_site_asset_grants` (`mig deploy`), затем
   выкладка API (`docs/deploy.md` §1д). До ворот §2 `SITE_ASSET_STORAGE` не задаётся: библиотека пустая, загрузка 503,
   опубликованные сайты без картинок работают как раньше.
2. Бакет и ключи по §3, письмо поставщика по §3.
3. Переменные §4 в `.env` сервера, перезапуск API.
4. Проверка: `npx tsx scripts/ops/site-assets-storage-check.ts` на сервере API (кладёт и читает крошечную картинку,
   проверяет, что без подписи объект не читается, удаляет; бакет с `prod` в имени только с `--production`). Вывод без
   ключей и адресов.
5. Выкладка Worker не нужна: адреса картинок он берёт из контракта рантайма.

## 6. Переезд PS Cloud → Cloud24

Новые переменные §4, перенос объектов с теми же ключами (`site-assets/…`, например `rclone copy` между бакетами), затем
проверка §5 п. 4. Схема и строки базы не меняются.

## 7. Правовое

Публичные сайты отдают опубликованные картинки посетителям по всему интернету: это распространение публичного
содержимого сайта, а не выбор места хранения. Origin, оригиналы и копии остаются в Казахстане; сырые загрузки не
хранятся нигде. Перед рабочим включением юрист подтверждает формулировки политики конфиденциальности (фото гостиницы,
отсутствие персональных данных на снимках, удаление геометки).
