# Разрешение на публикацию общей главной WETOP

В текущем поручении владелец явно разрешил довести утверждённую общую главную до рабочего состояния, слить в main и выложить на домен. Повторно подтвердил необходимость доступа к публикации в main/на сайт. Это разрешение на данный выпуск после проверок, не разрешение обходить гейт, переписывать release или публиковать незавершённые срезы.

## Проверенные возможности

- Реальный origin проекта: GAIVER007/wetop.ai. GitHub API подтверждает push=true и admin=true для действующей авторизации. Никаких новых токенов или широких серверных прав для push/PR merge не требуется.
- В main нет технической защиты ветки (protected=false); поэтому агент обязан соблюдать проектный гейт самостоятельно. Не выполнять пробный push в main ради проверки доступа.
- Workflows release-checks и auto-release включены. Текущие чужие/существующие прогоны не отменять.
- Обычная выкладка: проверенный код → main → release-checks → auto-release fast-forward release → серверный auto-deploy. Успешный merge не равен доказанной выкладке.
- Root-installed wetop-migrate-approved разрешён только без аргументов. Его установка не включает approval, не предоставляет shell/Docker sudo и не разрешает запуск произвольного пакета.

## Что ещё не настроено для релиза с миграциями

Нужны owner-provisioned approval точного immutable image/commit и доверенный backup+restore runner. После успешной миграции существующая автоматика дополнительно требует wetop-auto-deploy --migrations-applied <точный release SHA>. Текущий sudo не предоставляет этот вызов. Не выдавать наличия migration helper за полный автоматический cutover и не использовать этот флаг без реально подтверждённой миграции.

На момент проверки у рабочих образов нет org.opencontainers.image.revision label. Clone/deployed markers не подтверждают полный состав образа. Итоговый выпуск должен иметь проверяемое соответствие версии и реальный authenticated smoke/reconciliation на app.wetop.ai.

## Граница полномочий

Разработка продолжается в feat/unified-owner-data-20261016. Все внесённые в ней изменения текущей задачи принадлежат этой работе. Не создавать дубликат модулей и не отклонять их как неизвестные dirty-файлы. Наличие GitHub ADMIN не отменяет тесты, review, миграционный порядок и сохранение чужих изменений.
