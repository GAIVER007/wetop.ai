# ТЗ: установка счётчика и виджета бронирования PMS на сайт Luxx Aparts

Дата: 12.09.2026. Сайт в PMS: «Сайт Luxx Aparts», ключ `pms_5724b8e298e4`, тариф виджета «Базовый тариф».
Готовый код — `docs/site/snippet-luxx-aparts.html`. Актуальный код всегда на странице PMS
«Продажи → Сайт и онлайн-бронирование → Настройки» (`/website/settings`, карточка сайта; до 27.09 — `/analytics/setup`,
старый адрес ведёт туда же): если адрес API поменяется, там будут правильные строки.

---

## 1. Что получаете

| Что | Где видно |
|---|---|
| Посещения сайта: сессии, уникальные посетители, просмотры, время, доля мобильных, отказы | PMS → «Сайт и онлайн-бронирование → Аналитика» (`/website/analytics`) |
| Источники: поиск (Google, Яндекс), соцсети (Instagram, TikTok…), реклама (utm/gclid), рассылки, переходы с сайтов, прямые | там же, таблица «Источники трафика» |
| Устройства, браузеры, ОС, страницы | там же |
| События: поиск дат, шаг бронирования, клики по телефону и WhatsApp | там же, «События с сайта» |
| Календарь спроса: на какие даты заезда гости искали номера | там же |
| **Брони с сайта** — сколько и из какого источника | тайл «Брони с сайта» и колонка «Брони» |
| Бронь гостя из виджета | шахматка, «Сегодня», карточка брони с источником «сайт», счёт на проживание, остаток в Channex |

Что **не** собирается: IP-адреса, полный User-Agent, cookies, имена и телефоны посетителей. Данные гостя
попадают в PMS только когда он сам заполнил форму брони.

## 2. Что нужно сделать до установки (5 минут)

1. **Вписать домен сайта в PMS.** Откройте `/website/settings`, карточка «Сайт Luxx Aparts», поле «Домены
   сайта»: замените заглушку `luxx-aparts.example` на настоящий адрес (например `luxxaparts.kz`; `www` и
   поддомены подходят сами). Пока стоит заглушка, приёмник и виджет **отбрасывают** запросы с сайта.
2. **Сайт должен быть на https.** Если сайт на `http://`, виджет и счётчик всё равно работают, но браузер
   покажет «небезопасно» на форме с телефоном гостя.
3. **Адрес API.** В коде ниже стоит **постоянный** адрес `https://api.wetop.ai` (с 15.09.2026, ADR-045).
   Он не меняется при перезапуске туннеля и переживает перезагрузку Mac: туннель держит служба launchd
   `domain`. Условие запуска из раздела 6 (Q-112) закрыто. Остаётся Q-111: адрес настоящего сайта отеля
   и форма поиска дат не подтверждены, поэтому на боевой сайт код пока не ставится.

## 3. Код

### Блок 1 — счётчик. В `<head>` каждой страницы сайта

```html
<!-- PMS: счётчик посещений -->
<script async src="https://api.wetop.ai/a/pms.js" data-site="pms_5724b8e298e4"></script>
```

### Блок 2 — виджет бронирования. Один раз, там, где должна быть форма

```html
<!-- PMS: виджет бронирования -->
<div id="pms-booking"></div>
<script async src="https://api.wetop.ai/w/widget.js" data-site="pms_5724b8e298e4"></script>
```

Виджет рисуется внутри `<div id="pms-booking">`. Нужен другой контейнер — добавьте атрибут
`data-target="#мой-блок"`. Ширина — до 680 px, растягивается по контейнеру; стили свои, с сайтом не
конфликтуют (все правила под классом `.pmsw`), гарнитуру виджет не подгружает — берёт системный шрифт.
На узком экране поля и кнопки встают в одну колонку, высота полей и кнопок 44 px — под палец.

**Если цвета виджета не совпадают с сайтом**, их можно переопределить своим CSS — вставить после блока 2:

```html
<style>
  .pmsw {
    --pmsw-accent: #1f4bd8;      /* кнопки и ссылки */
    --pmsw-accent-dark: #17399f; /* наведение */
    --pmsw-ink: #16213a;         /* заголовки и цены */
    --pmsw-ink-2: #3d4656;       /* подписи полей */
    --pmsw-muted: #6b7280;       /* пояснения */
    --pmsw-line: #e3e5e8;        /* рамки */
    --pmsw-radius: 12px;         /* скругление */
  }
</style>
```

Менять имеет смысл только акцент и скругление — остальное подобрано под читаемость.

## 4. Куда вставлять — по платформам

| Платформа | Блок 1 (счётчик) | Блок 2 (виджет) |
|---|---|---|
| **Tilda** | Настройки сайта → «Ещё» → «HTML-код для вставки внутрь head» → вставить, «Сохранить», **опубликовать все страницы** | На нужной странице добавить блок **T123 «HTML-код»** (категория «Другое»), вставить блок 2, опубликовать |
| **WordPress** | Плагин «WPCode» (бывший Insert Headers and Footers) → Header → вставить; либо `header.php` темы перед `</head>` | В редакторе страницы добавить блок «HTML» (Custom HTML) и вставить блок 2 |
| **Самописный сайт** | В шаблон страницы перед `</head>` | В разметку нужной страницы |
| **Wix, uKit, Craftum и т. п.** | Настройки → «Пользовательский код / Код в head» | Элемент «HTML-код / Embed» на странице |

Проверка, что вставили правильно: открыть сайт, в браузере «Просмотр кода страницы» — строка с `pms.js`
должна быть внутри `<head>`, а `<div id="pms-booking">` — там, где ожидаете форму.

## 5. Как это работает для гостя и стойки

1. Гость выбирает заезд, выезд, число гостей → «Показать цены». Виджет спрашивает PMS: свободные места по
   категориям (считаются так же, как для каналов) и цену за весь период по тарифу «Базовый тариф» из
   календаря цен. Закрытые продажи и категории без мест показываются серым.
2. «Забронировать» → имя, фамилия, телефон (обязательно), почта, комментарий → «Подтвердить бронь».
3. PMS создаёт бронь **тем же путём, что стойка**: источник «сайт», статус «подтверждена», первая свободная
   ячейка категории, счёт на проживание с начислением по цене, запись в журнале, остаток уходит в Channex.
4. Гость видит номер брони вида `20260912-8FJBFT` и текст «оплата при заселении, заезд с 14:00».
5. Стойка видит бронь на шахматке и в «Сегодня»; комментарий гостя — в заметках брони.

Умолчания (можно поменять, вопросы Q-114…Q-116 в `QUESTIONS.md`): предоплаты нет, бронь подтверждается
сразу; уведомление гостю не отправляется — номер только на экране; язык виджета русский; заезд не раньше
сегодня и не позже чем через 365 дней, не больше 30 ночей, гостей 1–8; лимит 5 броней в час с одного
адреса и 30 в час на сайт (защита от спама).

## 6. Постоянный адрес API (обязательно до боевой установки)

Почему: код на сайте содержит адрес API. Быстрый туннель Cloudflare выдаёт новый адрес при каждом
перезапуске, и код на сайте начнёт указывать в пустоту; кроме того, быстрый туннель пробрасывает **весь** API.

Что сделать (владелец, один раз, ~20 минут; нужен домен в аккаунте Cloudflare, бесплатный план подходит):
готовый рецепт и пример конфигурации — `scripts/ops/cloudflared-named.example.yml`. Итог: адрес вида
`https://pms.<ваш-домен>`, наружу выходят только `/a/*` (счётчик), `/w/*` (виджет) и webhook Channex.
Альтернатива — хостинг API у провайдера в Казахстане (там же, где будет production-БД, ADR-018).

После переключения: вписать `PUBLIC_API_URL=https://pms.<домен>` в `.env`, перезапустить API, на
`/website/settings` скопировать обновлённый код и заменить на сайте **две строки** (хост в `src`). Ключ
`pms_5724b8e298e4` не меняется.

## 7. Проверка после установки

**Прямо сейчас, без сайта** (демо-страницы доступны только из локальной сети, наружу они закрыты):
с компьютера, на котором работает PMS, откройте
- `https://api.wetop.ai/a/demo?k=pms_5724b8e298e4` — страница со счётчиком, нажмите кнопки;
- `https://api.wetop.ai/w/demo?k=pms_5724b8e298e4` — страница с виджетом, сделайте тестовую бронь.

Затем в PMS: `/website/settings` → «Проверить счётчик» (покажет время последнего события); `/website/analytics`
→ отчёт за сегодня; тестовую бронь найти по номеру и **отменить** с карточки.

**После установки на сайт:**
1. Открыть сайт с телефона через LTE (не через Wi-Fi объекта), пройти 2–3 страницы.
2. В PMS `/website/settings` → «Проверить счётчик» → «Счётчик жив…».
3. На сайте сделать тестовую бронь с комментарием «тест» → в PMS открыть карточку по номеру → отменить.
4. В `/website/analytics` за сегодня: сессия есть, источник «прямые заходы», «Брони с сайта» 1, в календаре спроса — дата.
5. Поставить ссылку из Instagram с utm (`?utm_source=instagram&utm_medium=social`) и зайти по ней — в
   источниках появится «соцсети / instagram».

## 8. Если не работает

| Симптом | Причина | Что делать |
|---|---|---|
| «Проверить счётчик» → «Событий ещё не было» | Домен сайта в PMS не совпадает с настоящим | Вписать домен на `/website/settings` (раздел 2, п. 1) |
| То же, сайт на https | Адрес API в коде на `http://` | Нужен https-адрес API (раздел 6) |
| Виджет показывает «Ошибка 404» | Бронирование с сайта выключено или ключ не тот | `/website/booking` → «Принимать брони с сайта», ключ в коде должен совпадать |
| Виджет показывает «запрос не с домена сайта» | То же, что первая строка | Вписать домен |
| Скрипт не грузится, в консоли браузера `ERR_NAME_NOT_RESOLVED` | Быстрый туннель перезапустился, адрес сменился | Раздел 6; временно — взять новый адрес на `/website/settings` |
| Скрипт не грузится у части посетителей | Блокировщик рекламы | Так у всех счётчиков; после переезда на `pms.<свой-домен>` блокировки реже |
| «На выбранные даты свободных мест нет» | Категории заняты или закрыты ограничением | Проверить шахматку и ограничения в `/rates` |
| «слишком много броней…» (429) | Лимит защиты от спама: 5 в час с одного адреса | Подождать час или проверять с другого адреса |
| Бронь не пришла в Channex | Остаток уходит очередью | `/channels` → очередь; при необходимости «Отправить очередь сейчас» |

- [ ] Постоянный адрес API настроен, `PUBLIC_API_URL` вписан, код на сайте с новым адресом (раздел 6)
- [ ] Проверка с телефона через LTE: счётчик жив, тестовая бронь дошла и отменена
- [ ] Ссылки в Instagram и рекламе размечены utm
- [ ] Кнопки «Позвонить» / «WhatsApp» вызывают `pms('event', …)` (необязательно, см. `snippet-luxx-aparts.html`)
