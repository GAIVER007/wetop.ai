# 15.10.2026: CORE-SECURITY-FIX, закрытие подтверждённых дыр CORE-01 (ADR-183)

Ветка `claude/core-security-fix-20261015` поверх `claude/core-01-20261014` (PR #529, NO-GO-отчёт) со
слиянием `main` `80f18f303`. Решения: ADR-183. Миграций нет, модель не менялась. Red → green: шесть
красных (`…05-42-14Z-integration-167c`) → зелёные (`…05-46-39Z`, повтор после lint-правки `…05-52-55Z`).

## Закрыто

- **U2-1 (P1, кросс-организация).** `resetExternalEventAttempts` привязан к объекту интеграционного
  скоупа: повтор события каналов больше не сбрасывает `external_events` чужой организации; без скоупа
  отказ. Репродукция CORE-01 переведена из `it.fails` в постоянного стража. Строки эпохи до backfill
  (`property_id IS NULL`) повтором не сбрасываются (ADR-183, честный отказ).
- **U2-2 (P1).** Витринное правило закрыл параллельный CORE-SECURITY-FIX-01 (PR #535, O3=A: гости
  организационные, ограниченному сотруднику контроллер закрыт целиком). Этот пакет добавляет второй
  эшелон на уровне данных: `guests.repository.visible()` для пользователя с назначениями отдаёт лишь
  гостя, связанного бронью или проживанием с Property его мест, либо гостя без единой брони.
  Совместимость пакетов доказана совместным прогоном (94/94).
- **U2-3 и U2-4** оказались закрыты параллельным PR #535 тоньше (сохранение чужих привязок мастера
  вместо отказа; roleAt до выборки филиала): при слиянии взят канон `main`, мои варианты сняты; мои
  red → green тесты обоих пунктов остались и зелёные против их реализации.
- **U1-C.** Первый объект (и с ним HOSPITALITY-бизнес) из гостиничного онбординга создаёт только
  владелец, как owner-only `POST /branches`; менеджер с существующим отелем работает как раньше.
  Прежние сценарии «с нуля» в тестах приведены к владельцу (`onboarding.test.ts`,
  `onboarding-without-property`, `onboarding-concurrency`).
- **U1-D.** «Ранний» Property выбирается только среди живых (архивные филиалы и бизнесы исключены в
  `organizationPropertyRef`), `HotelService.property()` получил тот же порядок `createdAt asc`
  (детерминизм настроек против шахматки).

## Не входило (по ADR-183)

Нормализация телефона Customer (решение владельца о бэкфилле), EXCLUDE для назначений столов,
организационный охват диалогов ИИ-продавца (сверка с ADR-ами мультивертикали), полный запрет тихого
ORGANIZATION-fallback (вопрос CORE-02), P3-мелочи CORE-01.
