# Голосовая бронь, срез 2 (ресторан) (23.10.2026)

Ветка `claude/voice-booking-restaurant-20261023` на ветке салона (PR 793). Решения владельца: `docs/decisions/2026-10-23-voice-booking-salon-restaurant.md`.

## Что сделано
- **Формы сайта**: из `writeReservation` вынесен общий расчёт `planFood` (период обслуживания и правила брони филиала, поведение формы сайта то же, `site-forms` integration 25/25).
  Для голоса добавлена проверка свободного стола `assertSpareTable`: активные столы активных зон нужной вместимости без пересечения по времени (с буфером) минус брони на это время
  без назначенного стола. Условие осторожное: лучше отказать, чем пообещать. Стол не называется и не назначается. Входы `voiceFoodCheck` и `voiceFoodReserve`, источник брони `VOICE`.
- **API**: `GET /voice/food-availability` (ответ да/нет с причиной словами платформы), `POST /voice/booking-quotes` и `/confirm` направляются по направлению (ресторан добавлен в роутер).
  Котировка 30 минут (таблица `voice_booking_quotes`, вид `TABLE`), подтверждение один раз, стол заняли в момент подтверждения -> котировка отклонена, лимит 3 брони за звонок, данные гостя: имя, телефон, комментарий.
  Общие проверки салона и ресторана вынесены в `voice-gate.ts`.
- **Воркер**: `check_table`, `quote_table`, `confirm_table`; бронь только на время, которое проверка показала свободным.

## Проверки
- Red до кода: сервис (10), Python `test_booking_food.py` (6 красных).
- Интеграция на одноразовом Postgres 16 в мире ресторана FL1 (7 сценариев): бронь BOOKED/VOICE без стола с комментарием и аудитом, повтор, вместимость и буфер, непосаженные брони занимают места, правила (предел гостей, вне периода, закрытый день, прошлое), гонка за последний стол, чужой звонок, выключатель, лимит 3.
- Python 226 с SDK; `site-forms`, `voice-beauty-booking` зелёные.

## Что учесть
- Суточный лимит по телефону не действует (Q-VOICE-10). Сквозной звонок не прогонялся.
- Меню и цены агент по телефону не называет.
