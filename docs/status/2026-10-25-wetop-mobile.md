# WETOP mobile, 25.10.2026 UTC

Ветка codex/wetop-mobile, отдельный worktree. Подготовлен read-only обзор ресторана для владельца и управляющего: выручка закрытых заказов, средний чек, поступления по способам, текущая работа, периоды сегодня/неделя/месяц, недели месяца, топ-3 кухни и бара, сотрудники. Доступ и контекст проверяются мобильным шлюзом и сервером.

Проверка: синтетический браузерный сценарий на ширине 375 px, без горизонтальной прокрутки и ошибок консоли; целевые тесты API и шлюза 17/17, мобильные тесты 43/43. Нативный iOS/Android запуск и публичный gateway пока не проверены. Создание заказа остаётся без отправки до решения MOBILE-FOOD-1 в QUESTIONS.md, чтобы исключить дубли после таймаута.

Следующий read-only срез: команда ресторана. График филиала и показатель «Принёс» за день, неделю, месяц соединены по ID. Контакты и ревизии не отдаются в приложение; суммы без официанта и вне текущего состава не теряются. Синтетический экран 375 px проверен. Создание и расчёт заказа всё ещё требуют отдельного решения по MOBILE-FOOD-1 и проверок денежного сценария.

Проверки команды: mobile 45/45, gateway 17/17, mobile-types и web typecheck, lint, Expo export iOS/Android/Web. Серверный код этого среза не меняет модель данных и не использует общую dev-базу.

Подготовлена read-only карта салонных API в `plans/mobile-salon-api-audit-2026-10-25.md`. По стоп-меню зафиксирован MOBILE-FOOD-2: значение `active=false` и временный стоп-лист не отождествляются без решения владельца.
