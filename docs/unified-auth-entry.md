# Единый вход WETOP — ADR-131

Публичный вход и регистрация открываются на главной продукта: `/#login`, `/#register`.
`app.wetop.ai/login` и `/register` — совместимые переходы, а не второй лендинг.
Серверный мост `/api/site-auth/*` сохраняется: пароль передаётся POST-запросом,
сессия — только HttpOnly-cookie приложения, никогда в адресе или JSON ответа.
После входа окно проверяет `/api/site-auth/session` и только затем переходит в приложение.

Управление сотрудниками, приглашениями и активными сессиями находится в `/profile/access`.
Права API не меняются. `/login/verify`, `/login/reset`, `/login/set-password`,
`/login/check-email` и `/invite/*` остаются рабочими техническими страницами.
При отключённом JavaScript или запрете cookies доступна компактная резервная форма
`/auth/fallback`, связанная с главной через `noscript` и сообщение ошибки сети.

## Локальная конфигурация

Использовать один hostname для обеих частей, например `127.0.0.1`, не смешивать его с `localhost`.

- Главная, порт 3002: `WETOP_SITE_URL=http://127.0.0.1:3002`,
  `WETOP_APP_URL=http://127.0.0.1:3000`, `npm run dev -w apps/site`.
- Приложение, порт 3000: `WETOP_SITE_URL=http://127.0.0.1:3002`,
  `APP_URL=http://127.0.0.1:3000`, `APP_AUTH_REQUIRED=1`; `APP_API_URL` — явный адрес нужного API.
- В dev источники 3002 разрешены CORS. Для локального `next start` дополнительно задать
  `SITE_ORIGINS=http://127.0.0.1:3002`. Не добавлять wildcard и не отключать защиту cookies.

Без этих переопределений адреса production: `https://wetop.ai`, `https://app.wetop.ai`.
Главная статическая: её переменные задаются при сборке. Не выкладывать сборку с локальными адресами.

## Проверка и выкладка

Изолированный браузерный набор: `npm run test:record -- e2e --config tests/ui/playwright.auth.config.ts --workers=1`.
Он поднимает главную 3002, приложение 3102 и синтетический API 4313, без базы и отправки писем.
Проверки публичного сайта: `npm run test:record -- e2e --config tests/site/playwright.config.ts`.

Выкладывать сначала приложение с совместимым мостом, затем production-сборку главной;
проверять оба домена по `docs/deploy.md`. Откат — согласованная предыдущая пара сборок.
Изменений схемы, миграций, фондов и внешних интеграций в этом срезе нет.
Зелёный локальный стенд не подтверждает отправку настоящей почты или публикацию на домене.
