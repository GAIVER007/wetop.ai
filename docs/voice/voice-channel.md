# Голосовой агент: канал «телефонный звонок» (ИИ-колл-центр)

Статус: этап 0 (проект) и этап 1 (воркер) от 22.10.2026. Интеграция только по `videosdk-telephony.md` (AGENTS.md §5).
Решение: `docs/decisions/2026-10-22-voice-agent.md`. Открытые вопросы: `QUESTIONS.md`, раздел Q-VOICE.

## Что строим

Звонок клиента на номер объекта принимает ИИ-голос. Он здоровается и называет себя ИИ-помощником, отвечает по базе
объекта, собирает контакт, при просьбе или сомнении переключает на человека. Каждый звонок остаётся в журнале.

Голос это четвёртый канал ИИ-продавца рядом с виджетом, Telegram и WhatsApp. Текстовый движок
`apps/ai-seller/src/ai/engine.py` не меняется: у голоса другая модель (Gemini Live принимает и отдаёт звук) и свой
рантайм, поэтому код живёт отдельным пакетом `apps/ai-seller/voice/`. Общее только данные: справочники объекта
через те же адреса WETOP `/bot/*` и те же правила «чего боту нельзя» (`apps/ai-seller/AGENTS.md`).

## Решения по умолчанию (подтверждены владельцем 22.10.2026)

| # | Вопрос | Решение |
|---|---|---|
| 1 | SIP-провайдер | Twilio для теста, боевой выбор позже (Q-VOICE-1) |
| 2 | Запись и согласие | Записывать, ИИ представляется в начале (Q-VOICE-2) |
| 3 | Модель | Gemini Live из демо (Q-VOICE-3) |
| 4 | Вертикаль | Салон первым: он первый в выпуске (AGENTS.md §28) |
| 5 | Что умеет агент | Отвечать, собирать контакт, переключать на человека. Создание записи НЕ в первом срезе |

Пункт 5 уточнён по коду. У текстового продавца в салоне нет создания записей: он видит только каталог услуг, а
запись и оплату «уточняет администратор» (`src/ai/vertical_tools.py`). Адреса WETOP для заявки есть только у
гостиницы (`/bot/booking-intents`). Голос не может обещать то, чего не умеет текстовый бот, поэтому запись по
телефону это отдельная развилка (Q-VOICE-5), а не умолчание.

## Что агент может и чего нельзя

Можно: назвать услуги и цены из каталога (`/bot/beauty-services`), часы работы, адрес; принять имя, телефон и
пожелание; записать «просьба перезвонить»; перевести на человека.

Нельзя (правила `apps/ai-seller/AGENTS.md`, «Чего боту нельзя»): считать итоговую сумму; обещать запись, скидку,
время мастера; ставить диагнозы и давать медицинские советы; называть остатки числом; зачитывать текст ошибки.
Нет данных или сбой справочника: «администратор уточнит и перезвонит», и просьба о звонке записывается.

Начало разговора, всегда: «Здравствуйте, это ИИ-помощник <объект>. Разговор записывается.» Это текст из профиля,
владелец может его изменить, но не убрать (Q-VOICE-2).

## Идентичность звонка

Маршрут (`organization_id`, `agent_id`) берётся из `metadata` правила маршрутизации, которое задаёт владелец в панели
VideoSDK (SDK передаёт её в `JobContext.metadata`; значение может прийти словарём или JSON-строкой). Правила закрыты по
умолчанию (`voice/numbers.py`, `decide_route`):

- metadata нет: берётся единственный маршрут из `VOICE_NUMBER_MAP` (однообъектный режим);
- metadata есть, но битая или её пары нет в `VOICE_NUMBER_MAP`: отказ (вежливо прощаемся, `REJECTED` в журнале),
  запасного пути нет, чужой звонок не достаётся первому объекту;
- `VOICE_NUMBER_MAP` необязательна (срез 3): пустая не режет, непустая работает как список разрешённых пар. Профиль объекта
  (имя бизнеса, голос, номер администратора, хвост приветствия) воркер читает с платформы по `agent_id`
  (`GET /voice/profile`), и платформа же подтверждает, что агент существует, действующий (`active`) и принадлежит этой
  организации. Совпадение `agentId` и `organizationId` в ответе воркер проверяет сам;
- платформа недоступна: профиль из окружения (`VOICE_OBJECT_NAME` и др.) используется ТОЛЬКО если воркер настроен ровно на
  один маршрут и звонок идёт на него. Иначе звонок получает вежливый отказ без перевода: чужой объект не должен услышать
  чужое имя и попасть к чужому администратору;
- доверенный корень маршрута это правило маршрутизации в панели VideoSDK (metadata); платформа проверяет пару
  организация и агент, но ключ воркера общий для всех объектов.

## Устройство пакета `apps/ai-seller/voice/`

| Файл | Роль |
|---|---|
| `profile.py` | `VoiceProfile` (объект, приветствие, голос, номер человека), сборка инструкций из профиля и каталога |
| `phone.py` | Нормализация номера в E.164, маска для журнала (в журнал номер целиком не пишется) |
| `numbers.py` | Таблица «номер -> организация и агент», проверка |
| `journal.py` | `CallJournal`: события звонка, JSONL на томе, идемпотентность по `call_id`, маска телефона |
| `wetop_client.py` | Чтение каталога и контекста агента из WETOP, ключ только заголовком `x-wetop-service-key` |
| `tools.py` | Инструменты агента: `get_services`, `request_callback`, `transfer_to_human` |
| `agent.py` | `MyVoiceAgent`: хуки входа и выхода, подключение инструментов (единственное место с `videosdk`) |
| `worker.py` | Точка входа: `WorkerJob`, `Options`, чтение окружения, `python -m voice.worker` |
| `tests/` | Тесты без сети и без `videosdk` (его импортирует только `agent.py`) |

Чистая логика не импортирует SDK, поэтому тесты идут на любой машине. SDK подключается в `agent.py` и
`worker.py`, они проверяются пробным звонком (этап 3).

## Журнал звонков

Просьбы о звонке: полный номер клиента лежит только в `<журнал>.callbacks.jsonl` (права 0600), в основном журнале
только маска и хэш ключа. Не более 3 просьб за звонок. Куда их показывать администратору, решает Q-VOICE-6.

Событие внешнее, значит по AGENTS.md §11 у него есть внешний ID (`call_id`), `received_at` (UTC), состояние,
ошибка, повтор и след аудита. Состояния: `RECEIVED -> ANSWERED -> ENDED` или `REJECTED` (неизвестный номер),
`FAILED`. Запись идемпотентна по `call_id`: повтор того же события не плодит строки. Время ставит приложение, а не
база. Телефон в журнале маскирован (последние 4 цифры). Содержимое разговора в журнал не пишется до решения по
записи (Q-VOICE-2).

Первый срез держит журнал файлом JSONL на смонтированном томе (как требует `AGENTS.md` ai-seller: журнал не только
в контейнере). Таблица в базе это изменение модели данных: предложение в `DATA_MODEL.md`, раздел VOICE-20261022,
статус «ожидает утверждения». Миграцию без утверждения не пишем (AGENTS.md §2, §14).

## Что делает человек, а что агент

Делает владелец: заводит аккаунт VideoSDK, ключи (`VIDEOSDK_AUTH_TOKEN` или пару `VIDEOSDK_API_KEY` и
`VIDEOSDK_SECRET_KEY`, `GOOGLE_API_KEY`), SIP-транк и номер у провайдера, шлюзы и правило маршрутизации в панели
по README демо, значения ключей вписывает сам (`SECURITY.md`). Агент пишет код и тесты, ключи не видит.

## План проверки (этап 3)

1. Unit: профиль, номера, журнал, инструменты (этап 1, красные до кода).
2. Воркер стартует и регистрируется (`register=True`) с тестовыми ключами владельца.
3. Пробный входящий звонок: приветствие с «ИИ-помощник», ответ по каталогу, «просьба перезвонить» в журнале,
   перевод на человека, неизвестный номер.
4. Результат записать в `docs/status/`; без него задача не закрыта (AGENTS.md §10).

## Раздел «Голосовой агент» в стойке (срез 4, готов 22.10.2026)

Страница `/marketing/voice` (`apps/web/src/app/marketing/voice/`), право `marketing`, только салон (`features.ts`): итоги месяца
(звонков, принято агентом, просьб, переводов, средний разговор, отклонено; без звонков «Нет данных»), вкладки «Просьбы
перезвонить» (полный номер со ссылкой `tel:`, пожелание, время по поясу филиала, кнопка «Отметить обработанной»), «Журнал
звонков» (номер звонившего маской, состояние, длительность, итог) и «Подключение» (памятка без полей для ключей). Месяц
переключается как в «Бюджете». Карточка «Голосовой агент» в хабе «Продвижение» и пункт меню видны салону; остальным направлениям нет.
Готовые компоненты из `DESIGN.md` (`Page`, `Tabs`, `Table`, `Badge`, `EmptyState`); новых компонентов нет.
Решение владельца 22.10.2026 (`docs/decisions/2026-10-22-voice-card-visible.md`): карточка, пункт меню и экран остаются видимыми всем салонам, выключатель по AGENTS.md §28 не строится. Видимость не означает готовность к боевым звонкам: они ждут подключения номера и ответов на Q-VOICE-1, Q-VOICE-2.

Запуск на сервере и пробный звонок: `docs/ops/voice-release.md`.

## API платформы (этап 2, срез 2)

Код: `apps/api/src/marketing-voice/`. Контракт на 22.10.2026.

**Приём событий воркера:** `POST /voice/events`, только узкий ключ `VOICE_INGEST_KEY` в заголовке `x-wetop-service-key`
(общий служебный и чужие узкие ключи получают 403, без ключа 401). Значение ключа вписывает владелец в `.env` API и воркера;
строку `VOICE_INGEST_KEY=` без значения надо добавить в `.env.example` (файл закрыт для агента правилами проекта).
Тело (лишние поля отвергаются):

| Поле | Тип | Правило |
|---|---|---|
| `agentId` | UUID | агент ИИ-продавца; организацию, бизнес и филиал определяет сервер |
| `externalCallId` | строка | 1-128 видимых знаков без пробелов (идентификатор комнаты звонка) |
| `state` | enum | `RECEIVED`, `ANSWERED`, `ENDED`, `REJECTED`, `FAILED` |
| `occurredAt` | ISO с поясом | не из будущего (допуск 5 минут) и не старше 30 суток |
| `direction`, `dialedNumber`, `callerMasked`, `endReason`, `errorCode`, `transferRequested`, `consentAnnounced` | необязательные | `callerMasked` только вида `***1234` |
| `callback` | необязательный `{phone, name, note}` | телефон приводится к E.164, имя до 100, заметка до 500 |

Ответ `201 {ok, callId, state, duplicate}`. Идемпотентно по (агент, `externalCallId`): состояние идёт только вперёд, конечные
`ENDED`, `REJECTED`, `FAILED` не меняются, запоздалое событие меньшего ранга ничего не откатывает (`duplicate: true`).
Длительность считает сервер по `answeredAt` и `endedAt`. Просьба о звонке уникальна по (звонок, телефон). Ошибки: 400 (тело),
404 (агента нет), 422 (у агента не выбран филиал); значения полей в тексте ошибок не повторяются.

**Чтение для стойки** (право `marketing`, филиал строго из указателя, без филиала 409 «Выберите филиал»):

- `GET /marketing/voice/summary?month=ГГГГ-ММ`: звонки, отвеченные, завершённые, отклонённые, сбои, просьбы, переводы,
  средняя длительность (`null`, если нечего усреднять); месяц считается по поясу филиала;
- `GET /marketing/voice/calls?month=&limit=&offset=`: журнал (limit до 100, по умолчанию 50), номер только маской;
- `GET /marketing/voice/callbacks?status=NEW|DONE&limit=`: очередь просьб, полный номер виден;
- `PATCH /marketing/voice/callbacks/:id` с `{"status": "DONE"}`: закрыть просьбу (организация должна быть доступна для записи);
  повтор возвращает ту же закрытую просьбу.


## Воркер отправляет события (срез 3)

Код: `apps/ai-seller/voice/` (`outbox.py`, `flusher.py`, `platform.py`, `session_plan.py`, `flush.py`). Схема:

```
звонок -> события (RECEIVED, ANSWERED, просьба, перевод, ENDED/FAILED) -> файл в очереди на томе -> POST /voice/events
```

- Событие сначала пишется на диск (`VOICE_OUTBOX_DIR`, по умолчанию `<журнал>.outbox`, права 0600), потом уходит. Воркеров
  по процессу на звонок, каталог общий: событие занимается атомарным переименованием. Доставка по меньшей мере один раз,
  безопасно: платформа принимает повтор идемпотентно.
- Ответы платформы: 200/201 подтверждено; 400 отвергнуто сразу (в `rejected/`); 401, 403, 408, 429, 5xx и нет связи
  повторяется без предела с паузой 5 с, 10 с, 20 с ... до 15 минут; 404 и 422 (выкладка без маршрута, неверный адрес, агент без
  филиала) повторяются 10 раз, затем откладываются. Отложенное не удаляется и не теряется.
- Во время звонка очередь отправляется в фоне каждые 5 секунд, при выходе догоняется до 10 секунд и не дольше удачных проходов.
  Что не ушло, уйдёт со следующим звонком или командой `python -m voice.flush` (из `apps/ai-seller`; код выхода 2, если
  осталось). `python -m voice.flush --requeue-rejected` возвращает отложенное в очередь после исправления причины.
- Сигнал: каждая отложенная запись пишет в лог `ERROR` с причиной и именем файла (без данных клиента); `voice.flush`
  печатает число отложенных. Расписание запуска `voice.flush` и оповещение владельцу настраивает владелец сервера.
- Порядок событий одного звонка не гарантирован: сервер состояние только двигает вперёд и позднее событие меньшего ранга
  принимает без отката.
- Профиль: `GET /voice/profile?agent=<uuid>` тем же ключом `VOICE_INGEST_KEY`; ответ минимален (`agentId`, `organizationId`,
  `objectName`, `greetingTail`, `voiceName`, `handoffPhone`), агент должен быть `active`.

Новые переменные воркера: `VOICE_INGEST_KEY` (обязательна), `VOICE_OUTBOX_DIR` (необязательна). `VOICE_NUMBER_MAP` стала необязательной.
