# PREPARED ordinary136, former HELD 134, Beauty positions and permissions

Подготовка одобрена18.10.2026; в production НЕ применено. Точные десять SQL SHA и отдельные обязательные cutover-допуски: `packages/database/prisma/beauty-release-preparation.json`, `docs/ops/beauty-zapis-release.md`.

Модели BEAUTY-ACCESS-20261018 и BEAUTY-ACCESS-REVOCATION-20261018 утверждены владельцем 18.10.2026. Миграция аддитивная, существующим участникам должности автоматически не назначает. Пока у участника нет ни одной строки назначения, сервер сохраняет прежнюю совместимость. После первой строки, включая отозванную, сервер применяет только новые назначения.

Зависит от обычных migrations accounts 013, access extensions 020 и membership scopes 073. Для текущей вершины предварительное release-имя: `20261018000136_beauty_positions`. Итоговый порядок фиксируется в `docs/ops/beauty-zapis-release.md`.

Перед применением владелец делает свежую резервную копию и проверяет восстановление. Beauty traffic и writers останавливаются. `migration.sql` выполняется в собственной транзакции на старом совместимом API. Только после validation запускается новый API, потому что новый non-OWNER auth projection читает `beauty_position_assignments` без fallback отсутствующей таблицы.

Проверки после применения:

1. Таблицы, индексы, FK, CHECK, три trigger-функции и их закреплённый search_path существуют в целевой схеме.
2. Должность принимается только для BEAUTY-бизнеса. Назначение проверяет организацию членства, бизнес, филиал, должность и существующие membership_scopes; OWNER не получает назначение.
3. OWN разрешается только для view в journal, appointments, payroll и reviews. Refund разрешается только как finance/refund/BUSINESS.
4. `wetop_app` видит SELECT только своей организации и не пишет. `wetop_service` читает и пишет; физическое удаление назначения блокируется, отзыв выполняется через `revoked_at` и revision.
5. Активное назначение не даёт архивировать должность. Отозванное назначение сохраняется, но не активируется снова, пока должность архивна. Отозванная строка продолжает занимать уникальную область назначения.
6. Наличие любой строки назначения включает строгий режим и не возвращает старую coarse role после отзыва последнего назначения.

Rollback empty-only. `down.sql` допустим только до создания первой должности, permission или assignment. Retain trigger намеренно блокирует DELETE assignments, поэтому документ не предлагает очищать историю для принудительного down. После использования модели выполняют совместимый forward repair или восстанавливают проверенную резервную копию вместе со старым приложением в отдельно согласованное окно.
