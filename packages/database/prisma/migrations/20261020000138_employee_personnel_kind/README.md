# 138 Employee personnel kind: назначение «специалист / другой сотрудник / оба»

Модель: DATA_MODEL.md, раздел «Решение владельца 18.10.2026: назначение сотрудника в «Персонале»». Выпуск в обычной
цепочке разрешён владельцем 20.10.2026: `docs/decisions/2026-10-20-personnel-kind-release.md`. Прежний вариант
`migrations-hold/20261018000001_employee_personnel_kind` из PR #648 в main не входил и заменён этой миграцией.

Миграция аддитивная: одна nullable колонка `employees.personnel_kind` text и CHECK на три значения `SPECIALIST`,
`OTHER_EMPLOYEE`, `BOTH`. Умолчания и заполнения нет: старые записи остаются NULL («Не назначено»), назначение ставит
руководитель. Роли доступа, членство, связь с `users`, услуги, записи и выплаты не меняются. Новых таблиц, политик RLS
и прав нет: колонка живёт под существующими политиками `employees`.

## Применение (production)

1. Свежая резервная копия и проверка восстановления по docs/ops/backups.md.
2. `migration.sql` выполняется в своей транзакции с `ON_ERROR_STOP`; старый API колонку не читает и не ломается.
3. Проверка: колонка есть, NULL у всех строк, CHECK `employees_personnel_kind_check` отвергает другое значение.
4. После проверки выкладывается API/UI, который читает и пишет назначение.

## Откат

`down.sql` берёт ACCESS EXCLUSIVE на `employees` и отказывает, если есть хотя бы одно назначение. Назначения не
очищаются ради отката: сначала их выгружают и согласуют восстановление или совместимый forward repair. Без CASCADE.
