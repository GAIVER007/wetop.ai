# 139 Уровни доступа сотрудника

Решение владельца 20.10.2026: `docs/decisions/2026-10-20-staff-access-levels.md`. В форме «Новый сотрудник» блок
«Доступ в WETOP»: без входа, личный кабинет, администратор, управляющий.

Миграция аддитивная:

- значение `EMPLOYEE` в `MembershipRole` («Личный кабинет»: права только `self`, таблица прав в
  `packages/domain/src/accounts/permissions.ts`);
- nullable `invites.employee_id` (FK на `employees`, `ON DELETE SET NULL`) и индекс: приглашение, выданное при
  добавлении сотрудника, после принятия ставит `employees.user_id`.

Существующие люди, приглашения и назначения не меняются. Новых таблиц, политик RLS и прав базы нет.

## Применение (production)

1. Свежая резервная копия и проверка восстановления по docs/ops/backups.md.
2. `migration.sql` (`ALTER TYPE … ADD VALUE` идёт отдельной командой; в одной транзакции новое значение до COMMIT
   не используется, миграция его и не использует).
3. Проверка: `SELECT enum_range(NULL::"MembershipRole")` содержит EMPLOYEE; столбец `invites.employee_id` есть.
4. После проверки выкладываются API и UI.

## Откат

`down.sql` отказывает, если роль EMPLOYEE у кого-то есть (членство, назначение или приглашение). Иначе снимает столбец
и пересоздаёт тип без EMPLOYEE. Без CASCADE.
