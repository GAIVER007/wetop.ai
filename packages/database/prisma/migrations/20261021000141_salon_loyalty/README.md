# 141 Бонусы и подарочные сертификаты салона

Решение: `docs/decisions/2026-10-21-salon-reminders-loyalty.md`, §2-3. В production НЕ применено.

Что добавляет:

- значения `BONUS` и `GIFT_CERTIFICATE` в `PaymentMethod`. Это не деньги в кассе: CHECK пускает их только в оплату и
  возврат записи салона (`restaurant_cash_operations` с `appointment_id`, вид INCOME или EXPENSE); в гостиничных
  платежах, кассе гостиницы, платежах ресторана, сверках и настройках способов их нет;
- `bonus_programs` (одна на бизнес салона, выключена по умолчанию, 5% начисления, 30% чека бонусами, без срока);
- `customer_bonus_entries`: журнал движений бонусов (ACCRUAL, REDEEM, REVERSAL, ADJUSTMENT), только дописывается;
  одно движение каждого вида на операцию кассы (`UNIQUE(payment_id, kind)`), баланс = сумма движений;
- `gift_certificates` (код 8 знаков без 0 O 1 I L, уникален в бизнесе; остаток не меньше нуля и не больше
  номинала; удалять нельзя) и `gift_certificate_entries` (SALE, REDEEM, REVERSAL), только дописывается;
- триггеры принадлежности: бизнес салона своей организации, клиент своей организации, запись и операция кассы
  своего бизнеса;
- RLS: ENABLE + FORCE на всех четырёх таблицах; `wetop_app` читает и вставляет строки своей организации (движения
  пишутся в транзакции оплаты), программу бонусов пишет `wetop_service`.

## Применение

1. Свежая резервная копия (`pg_dump -Fc`) с проверенным восстановлением.
2. `/root/wetop-mig.sh status`, затем `/root/wetop-mig.sh deploy` (после 140).
3. Проверка: `SELECT enum_range(NULL::"PaymentMethod");` содержит BONUS и GIFT_CERTIFICATE; четыре новые таблицы
   пусты; `relforcerowsecurity = t` у всех четырёх.
4. Выкладка совместимого API. Отчёты по кассе считают только живые деньги: способы бонусов и сертификата в остатках
   кассы не показываются (`foodCashBalances` знает только денежные способы).

## Откат

`down.sql` откатывает только пока бонусами и сертификатами не пользовались: есть движения, сертификаты, программа
или оплата способом BONUS/GIFT_CERTIFICATE, откат отказывает. Перечисление `PaymentMethod` пересоздаётся без двух
значений, CHECK на столбцах способа снимаются и ставятся обратно теми же определениями. После первого использования:
выгрузить данные и решать правкой вперёд или восстановлением резервной копии в согласованное окно.
