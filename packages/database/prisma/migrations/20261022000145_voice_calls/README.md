# 145 Журнал голосовых звонков

Решение: `docs/decisions/2026-10-22-voice-stage2-storage.md`, модель: `DATA_MODEL.md` VOICE-OWNER-APPROVAL-20261022. В production НЕ применено.

Что добавляет:

- `voice_calls`: звонок голосового агента. Уникален по (агент, внешний ID звонка), повтор события обновляет ту же строку.
  Телефон звонящего только маской. Состояние идёт вперёд, конечные ENDED, REJECTED, FAILED не меняются.
- `voice_callbacks`: просьбы перезвонить. Единственное место полного номера (E.164). После создания меняются только
  статус и отметка закрытия; закрытая просьба не открывается заново.
- `voice_profiles`: профиль голоса по агенту (хвост приветствия, голос, номер администратора).
- триггеры принадлежности: бизнес, филиал, агент и звонок одной организации.
- RLS: ENABLE + FORCE на всех трёх. `wetop_app` читает свои строки и закрывает просьбы (UPDATE только трёх столбцов),
  события и профиль пишет `wetop_service`.

## Применение

1. Свежая резервная копия (`pg_dump -Fc`) с проверенным восстановлением.
2. `/root/wetop-mig.sh status`, затем `/root/wetop-mig.sh deploy` (после 141).
3. Проверка: три таблицы пусты; `relforcerowsecurity = t` у всех трёх; `\dT` показывает три новых типа.
4. Выкладка API приёма событий (срез 2) только после миграции.

## Откат

`down.sql` откатывает, пока журналом не пользовались; есть строки, откат отказывает. После первого использования:
выгрузить данные и решать правкой вперёд или восстановлением резервной копии в согласованное окно.
