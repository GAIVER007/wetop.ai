# 146 Черновики постов «Контента»

Решение: `docs/decisions/2026-10-23-content-drafts.md`, модель `docs/marketing/content-drafts-proposal.md` §3.
В production НЕ применено.

Что добавляет: таблицу `content_drafts` (черновик поста филиала: канал, тема, текст, хештеги, кнопка действия,
происхождение AI/MANUAL, день публикации DATE, статус DRAFT/PUBLISHED/ARCHIVED, revision), CHECK на словари и длины,
триггер неизменности места/автора/происхождения и архива, RLS ENABLE + FORCE через филиал → организацию, права
`SELECT, INSERT, UPDATE` без `DELETE`. Существующие таблицы не меняются, данных не переносит.

## Применение

1. Свежая резервная копия (`pg_dump -Fc`) с проверенным восстановлением.
2. `/root/wetop-mig.sh status`, затем `/root/wetop-mig.sh deploy`.
3. Проверка: таблица `content_drafts` пуста, `relforcerowsecurity = t`, `has_table_privilege('wetop_app',
   'content_drafts', 'DELETE') = false`.
4. Выкладка совместимого API (экран «Контент» читает таблицу; без миграции API отвечает ошибкой только на этом экране).

## Откат

`down.sql`: останавливается, если в таблице есть строки (сначала выгрузить черновики). Иначе снимает политику,
триггер, функцию и таблицу. Другие таблицы не затрагиваются.
