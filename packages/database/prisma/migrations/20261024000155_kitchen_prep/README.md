# 155 Заготовки для всех направлений

Решение: план `plans/2026-10-24-kitchen-for-all-verticals.md`, DATA_MODEL §62; «Да» владельца 24.10.2026 на
рекомендации (заготовки списывают ингредиенты в момент «Приготовили»). В production НЕ применено: миграция
останавливает автовыкладку, применяет владелец.

Что добавляет:

- `kitchen_products.kind` (`RAW | PREP`, по умолчанию `RAW`): у всех существующих продуктов `RAW`, данные не
  меняются. Вид нельзя сменить, когда по продукту есть партии или техкарта.
- `kitchen_prep_recipes` (выход партии) и `kitchen_prep_recipe_lines` (ингредиенты на выход): только у `PREP`,
  ингредиент того же бизнеса, циклы запрещены триггером (рекурсивная проверка).
- `KitchenMovementKind` += `PRODUCTION_OUT`, `PRODUCTION_IN`; `kitchen_stock_movements.production_lot_id`: расход
  ингредиента ссылается на партию заготовки, ради которой списан (для сторно).
- Страж `kitchen_stock_guard` пускает и гостиницу (`HOSPITALITY`): склад кухни в API и на экране у неё с 21.10.2026
  (ADR-STOCK-ALL), а база отказывала («Food or Beauty business required»).
- RLS ENABLE + FORCE и права как у склада кухни.

## Применение

1. Свежая резервная копия с проверенным восстановлением.
2. `mig status`, `mig deploy` по `docs/deploy.md`, одна транзакция.
3. Проверка: `SELECT kind, count(*) FROM kitchen_products GROUP BY 1;` только `RAW`;
   `SELECT count(*) FROM kitchen_prep_recipes;` = 0.

## Откат

`down.sql`. До отката снять партии заготовок и движения `PRODUCTION_*` (перечисление пересоздаётся без них).
После отката гостиница снова не сможет заводить продукты кухни.
