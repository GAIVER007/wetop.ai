# 157 «Меню бара» у гостиницы и салона

Решение: план `plans/2026-10-24-kitchen-for-all-verticals.md` (срез K3), DATA_MODEL §62.3, «Да» владельца
24.10.2026 (Q-KITCHEN-ALL-1 «а»: продажа через бар, без экрана кухни). В production НЕ применено: применяет
владелец, после 155 и 156.

Что меняет:

- Стражи меню (`restaurant_module_guard`, `restaurant_modifier_guard`, `menu_item_photo_guard`) пускают категории,
  позиции, фото и группы добавок гостиницы и салона. Заказы (`restaurant_orders`) по-прежнему только у ресторана.
- `bar_sale_lines`: `product_id` NULL, новые `menu_item_id` (FK `menu_items`) и `note` (снимок добавок текстом);
  CHECK «ровно одно из двух»; себестоимость позиции меню может быть 0 (нет техкарты), у товара бара как прежде > 0.
  `bar_sales.total_cost >= 0`. Страж строки продажи проверяет позицию меню бизнеса филиала.
- `kitchen_stock_movements.bar_sale_id` (FK `bar_sales`): расход склада кухни по продаже бара; страж
  `kitchen_link_guard` проверяет филиал продажи.
- Данные не меняются: у существующих строк `product_id` заполнен.

## Применение

1. Свежая резервная копия с проверенным восстановлением.
2. `mig status`, `mig deploy` по `docs/deploy.md` (вместе с 154–156).
3. Проверка: `SELECT count(*) FROM bar_sale_lines WHERE product_id IS NULL;` = 0.

## Откат

`down.sql` отказывает, если уже есть продажи позиций меню или меню у гостиницы и салона; иначе возвращает стражи
и ограничения как в 081/091/112/135/144.
