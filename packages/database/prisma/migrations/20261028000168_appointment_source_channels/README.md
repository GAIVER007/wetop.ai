# 168 Источник записи салона

Решение владельца 28.10.2026 (DATA_MODEL `APPOINTMENT-SOURCE-20261028`): в окне новой записи администратор отмечает,
откуда клиент: Instagram, WhatsApp, звонок, пришёл сам или просто администратор.

Аддитивно: четыре значения `AppointmentSource` (`INSTAGRAM`, `WHATSAPP`, `PHONE`, `WALK_IN`). Существующие записи
не меняются (остаются `DESK`, `WEBSITE`, `VOICE`).

## Применение (production)

1. Свежая резервная копия и проверка восстановления по docs/ops/backups.md.
2. `migration.sql` (без транзакции не нужно: `ADD VALUE IF NOT EXISTS` и новые значения в той же миграции не читаются).
3. Проверка: `SELECT unnest(enum_range(NULL::"AppointmentSource"))` показывает 7 значений.
4. Новый код пишет новые значения, поэтому выкладка идёт после миграции (сервер сам ждёт её применения).

## Откат

`down.sql` в одной транзакции: записи с новыми источниками становятся `DESK` (теряется только отметка источника,
запись остаётся), тип `AppointmentSource` пересоздаётся с прежними `DESK`, `WEBSITE`, `VOICE` (как откат 139).
Схема после отката совпадает с состоянием до 168 (проверка `scripts/ops/check-migrations.sh`).
