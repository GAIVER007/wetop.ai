# Конкуренты у всех направлений: загрузка соседей с площадок (уточнение владельца 23.10.2026)

23.10.2026. Владелец: «конкурентов мы будем отслеживать через Booking и т. д., где будем видеть их загруженность».
Значит, главное не цены вручную, а **загрузка соседей с площадок бронирования**, как уже сделано у гостиницы
(ADR-142, п. 10–16). Ручной ввод остаётся запасным путём. Статус: **план, ждёт «да» на модель данных и миграцию**
(AGENTS.md §1, §2, §15). До «да» код и схема не меняются; у салона и ресторана карточка «Конкуренты» пока «Скоро»
(PR #801).

## Что уже есть у гостиницы (ADR-142)
- Экран `/market`: ваша загрузка против соседей по ночам, подсказки к цене, календарь сигналов.
- ИИ-сборщик `scripts/market/` (`npm run market:collect`): открывает страницу соседа на площадке как гость, без
  обхода капчи и защиты, и пишет уровень «Нет мест / Мало мест / Есть места» (§23.1).
- Факты проб 09.10.2026: **Booking.com** обычному браузеру отдаёт пустую страницу (защита), данных нет;
  **Ostrovok** отдаёт номера на дату и «осталось N», сборщик читает его; Trip.com пусто; Яндекс — капча.
  Законный путь к Booking: партнёрский API (Booking.com Demand API) или поставщик рыночных данных — решение
  владельца (ADR-142 п. 12).

## Как пятикласснику
- **Зачем:** видеть, когда у соседей всё занято. Тогда у тебя можно поднять цену; когда у них пусто — дать акцию.
- **Боль:** сейчас смотришь соседей руками на сайтах по одному, каждый день.
- **Как:** добавляешь соседей со ссылкой на их страницу записи или брони. ИИ раз в день открывает страницы на
  ближайшие дни и пишет, сколько у них свободно. Экран показывает «вы и рынок» по дням.
- **Аналогия:** смотреть, сколько машин на парковке у соседнего магазина.

## Салон и ресторан: где видно загрузку
Booking и Ostrovok салоны и рестораны не продают. Аналог «свободных номеров» у них — **свободные окна записи** и
**свободные столы** на страницах онлайн-записи. Площадки для пробы (как пробы гостиницы 09.10, одна страница на
площадку, тем же браузером, без обхода защиты):
- салон: страницы онлайн-записи (Dikidi, YCLIENTS, Booksy, 2ГИС «Записаться»): число свободных окон на день;
- ресторан: онлайн-бронь столов (Restoplace, 2ГИС/Chocolife, сайт ресторана): есть ли столы на вечер.
Что площадка реально показывает, решает проба; ничего не выдумываем. Где страница закрыта защитой — «закрыто
проверкой», как у гостиницы.

Шкала та же, что у гостиницы (§23.1): **Нет мест / Мало мест / Есть места** на день; процента нет, площадки его не
показывают.

## Модель данных (предложение DATA_MODEL §60, переписано под загрузку)
Только добавление; гостиничные `competitors*` (§23) не меняются.
1. `location_competitors` — сосед филиала: `business_id`, `location_id`, `name`, `address?`, `distance_m?`, `url?`
   (страница записи/брони), `note?`, `active`, `created_by_id?`, время.
2. `location_competitor_snapshots` — снимок дня: `competitor_id`, `day DATE` (на какой день смотрели),
   `observed_on DATE` (когда смотрели), `level` (`SOLD_OUT` / `FEW_LEFT` / `AVAILABLE`, тип §23.1), `free_slots INT?`
   (сколько окон/столов видно, если площадка показывает), `source` (`MANUAL` / `AI_AGENT`), `created_by_id?`,
   `observed_at`. Уникально `(competitor_id, day, observed_on)`; ручной ввод того же дня сильнее сборщика
   (как у гостиницы).
- Тенант: составные FK по филиалу, триггер «тот же бизнес». `down.sql`: DROP двух таблиц.
- Цены соседей вручную (прежний вариант А) — вторым шагом, если понадобится, отдельной таблицей.

## Срезы
0. **Проба площадок** салона и ресторана (без кода в продукте): по 1–2 страницы на площадку, отчёт в `reports/`,
   какие из них показывают свободные окна/столы. Без этого схему не утверждаем.
1. Миграция + домен (уровень дня, «рынок почти полон» при половине соседей с данными, как §23.1).
2. API для B/F и служебный вход сборщика (тот же узкий ключ `MARKET_COLLECT_KEY`, только снимки).
3. Сборщик: чтение площадок, прошедших пробу.
   **Сделано 23.10.2026 для Dikidi:** служебный вход `business-market/collector`, `npm run market:collect-business`
   (`docs/market/collector.md`). YCLIENTS и Restoplace — следующий срез.
4. Экран `/market` для салона и ресторана: «вы и рынок» по дням (ваша загрузка из журнала записей / броней столов),
   карточка «Конкуренты» из «Скоро» в «Доступно».

## Решения владельца, нужные до кода
1. «Да» на модель и миграцию выше.
2. Booking для гостиницы: подключать партнёрский API / поставщика данных или остаться на Ostrovok (ADR-142 п. 12).

## Не входит
Обход капчи и защиты площадок, маскировка под человека, автоматическая смена цен.
