## 2. Что стоит на сервере — команды для веб-терминала Hostinger (от root)

```bash
cd /root/wetop
git log -1 --format='%h %ci %s'                 # коммит клона
git reflog -5 --date=iso                        # когда клон двигали
git status --porcelain                          # ждём только deploy/compose.hostinger.yml
cd deploy
C="docker compose -f compose.yml -f compose.hostinger.yml"
$C ps                                           # контейнеры, healthy
$C images                                       # ID образов
docker inspect -f '{{.Name}} {{.Created}}' pms-lux-api-1 pms-lux-web-1
$C exec -T web cat apps/web/.next/BUILD_ID     # сборка стойки
```

Коммит клона ещё не доказывает, что внутри образа: клон могли подтянуть без пересборки. Что реально работает — по
меткам коммитов в коде самого контейнера:

```bash
$C exec -T api sh -c 'for s in \
  VERIFY_HOURS:packages/domain/src/accounts/email-verification.ts \
  assertPropertyVisible:apps/api/src/database/property-ref.ts \
  organizationPropertyRef:apps/api/src/database/property-ref.ts \
  housekeepingRefusal:packages/domain/src/housekeeping/flow.ts \
  unitHousekeepingStatus:apps/api/src/reservations/reservation-card.ts; do
  m=${s%%:*}; f=${s#*:}; n=$(grep -c "$m" "$f" 2>/dev/null); echo "$m ${n:-0}"; done'
```

| Метка | Коммит, время (UTC) | Если 0 |

| `VERIFY_HOURS` | `da300029`, 20.09 18:10 | подтверждения почты нет: зарегистрировавшийся сразу входит |
| `assertPropertyVisible` | `4dbfc0c1`, 20.09 18:15 (PR #42) | замка ADR-061 нет: вошедший видит объект Luxx |

## 3. Регистрация на проде — решение владельца (Q-157)

- **Закрыть:** в `/root/wetop/.env` поставить `REGISTRATION_OPEN=0`, затем `$C up -d --no-deps --force-recreate api`
  и повторить `/auth/options` — ждём `"registrationEnabled":false`. Стойку пересоздавать не нужно: настройку она
  берёт у API (ADR-055).
- **Оставить открытой:** записать в Q-157, что открыто осознанно. Что видит новичок, скажут метки §2: при
  `assertPropertyVisible` = 1 — «Объект не настроен для вашей организации», при `organizationPropertyRef` = 1 — свой
  пустой объект и онбординг. Войти он сможет только после подтверждения почты, а оно работает, только если задан
  ключ почты.

ADR-060: пока нет разделения данных в самой базе, на боевом сервере регистрация должна быть закрыта.

## 4. База Supabase открыта наружу через Data API — срочно

**Что найдено 22.09.2026** (советник безопасности Supabase и запрос прав, только чтение):

- уровень ERROR «RLS Disabled in Public» на **всех 41 таблице** схемы `public`, в том числе `users` (хеши паролей),
  `sessions`, `password_resets`, `email_verifications`, `guests`, `guest_documents`, `payments`;
- роли `anon` и `authenticated` имеют права на эти таблицы: `SELECT` на `users`, `sessions`, `guests`, `INSERT` на
  `payments` — проверено `has_table_privilege`;
- схема `public` у Supabase по умолчанию открыта через Data API (PostgREST). Тогда любой, у кого есть публичный ключ
  проекта (anon / publishable — Supabase считает его несекретным и сам предлагает вставлять в браузер), читает и
  пишет эти таблицы по HTTPS в обход приложения. Включён ли Data API у проекта, из базы не видно — смотреть в панели.

WETOP Data API не пользуется: приложение ходит в базу напрямую через Prisma (`DATABASE_URL`), пакетов `@supabase/*`
в коде нет. PMS работает ролью-владельцем таблиц, поэтому запрет для `anon` её не заденет.

**Варианты (решает владелец — это права и настройки боевой базы):**

- **А — выключить Data API** в панели Supabase: Project Settings → Data API — выключить Data API или убрать `public`
  из списка открытых схем. Минута, без кода, обратимо. Перед этим убедиться, что ничто стороннее (например, сценарии
  n8n) не читает эту базу по REST. **Рекомендация агента.**
- **Б — отобрать права** у `anon` и `authenticated` на схему `public`, включая права по умолчанию для будущих таблиц, —
  миграцией с `down.sql`. Закрывает и при включённом Data API.
- **В — включить RLS на всех таблицах без политик** — миграцией. Приложение не заденет, `anon` не получит ни строки.
  Это же фундамент для разделения организаций в базе (ADR-061, путь Б), но политики — отдельный срез.

**Критерий готовности:** Data API выключен (снимок настроек в `reports/`) или
`select has_table_privilege('anon', 'public.users', 'SELECT')` возвращает `false`; дата — в `SECURITY.md` §12.

После переезда базы на ps.kz (A1) Data API там нет, и вопрос снимается сам. До этого в Supabase лежат учётные записи
сотрудников, а если живой день пройдёт до A1 — и данные гостей.
