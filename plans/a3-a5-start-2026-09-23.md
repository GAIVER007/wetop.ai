## A3 · Проверенный откат на канале + ночной дежурный (Q-123)

**Уже готово.** Откат разделён на два сценария в `CUTOVER.md` (ADR-041): **откат одного канала** (шаги 2–6, ARI не останавливать) и **полный откат** (шаг 1 → 2 для всех → 3–6). Выключатель `CHANNEX_ARI=off` проверяется в шлюзе (`apps/api/src/channels/ari-switch.ts`) — очередь, полная выгрузка и сторож его уважают. Шаг 6 (сверка окна переезда) проверен: `cli-rollback-window.ts`, 10 тестов (red→green).

**Осталось — только на живом канале.** Шаги 2–5 (отключить канал в Channex `deactivate` → вернуть Exely провайдером в экстранете OTA → вернуть остатки/цены → подтвердить) проверяются на первом настоящем канале — Hostelworld. На staging их проверить нечем (это ограничение staging, не пробел).

**Ночной сторож.** После A1 решается сам: PMS уедет на ps.kz, внешний сторож `pms-lux-watch` останется на Hostinger (сейчас обе на одной машине `187.77.145.152` — при падении сервера сообщения не будет). Дежурный агент — на сервер (`pms-lux-guard`, ADR-067).

- **Критерий готовности:** откат Hostelworld проверен по шагам живьём и записан в таблицу ROLLBACK (кем, дата); назван **человек, который читает группу дежурных ночью**.
- **Файлы:** `CUTOVER.md` (ROLLBACK, таблица по каналам), `plans/plan-2026-09-13-rollback-drill.md`, Q-123.
- **Кто:** владелец (экстранет OTA, Exely) + агент (сверка). Проверяется вместе с A5-Hostelworld.

## A4 · Channex — живая проверка сертификации

**Что.** Анкета отправлена; осталась живая проверка — **запись видео** (Channex принимает вместо созвона, срока нет). Показать действия именно через PMS: цена на дату, диапазон+две категории, остатки, ограничения, приём брони — 8 шагов.

**Порядок съёмки.** Владелец ставит экран на запись и входит сам (пароль руками, сессия 12 ч — войти в день записи, панель Claude открыта Cmd+Shift+B); агент выполняет 8 шагов в браузерной панели; владелец смотрит готовое и **отправляет сам**.

**Перед записью — агент сверяет стенд с листом:** цены на 15–17.12 равны таблице (тариф «ОТА +35 %»), ограничений 0 строк, броней на эти даты нет, очередь ARI пуста. После записи — снять всё поставленное.

- **Открыто:** Q-031 — что Channex требует для включения production (он платный).
- **Критерий готовности:** Channex подтвердил прохождение и открыл боевой (production) доступ.
- **Файлы:** `plans/channex-demo-recording-2026-09-21.md` (сценарий, даты, значения); task ID — `reports/channex-certification-tasks.json`.
- **Кто:** владелец (запись/отправка) + агент (прогон сценариев).

## A5 · Переключение каналов по одному (Gate 9–10)

**Порядок (строго по одному, следующий — после reconciliation прежнего в ноль):**
Hostelworld → Ostrovok → Expedia → Agoda → Trip.com → **Booking.com (последним)**. OneTwoTrip и Bronevik — адаптеров в Channex нет (Q-096).

**⚠ Проверка маппинга перед первым каналом.** `GET /channels/channex/mapping`: на каждую категорию **ровно одна пара**, тариф `exely-10158310` («для ОТА +35 %»). Ошибка тарифа = цены в OTA уедут на 35 %. Сейчас у каждой категории **две пары** (ОТА с 09.09 + базовый с 13.09) — решить, остаётся ли базовый. Настройка объекта на боевой базе: `POST /channels/channex/setup` **без параметра**.

**Блокеры A5:** A1 + приоритет B (дефекты приёма ревизий) + переходные работы Q-167 вариант А (ADR-064) — `plans/transition-exely-sync-2026-09-23.md`: шаги 1–8 (код и тесты на локальной базе, без РК), шаги 9–12 (после A1).

**Данные при переключении.** 157 будущих броней (Booking/Trip/Expedia) Channex подтянет сам; **25 броней (Agoda 19, Hostelworld 2, Ostrovok 4) переносятся вручную** из нашей БД и сверяются с кабинетом канала. Перенесённым **оплату повторно не просить** (96,5 % «не оплачено», но площадка уже взяла — Q-086).

**Переходный период (вариант А).** Стойка работает в Exely; Exely→PMS — досинхронизация только на чтение, каждые 5 мин; брони переключённых каналов смена заводит в Exely руками с меткой `WETOP <номер брони PMS>` в комментарии (импорт такие пропускает). Настоящие данные гостей и досинхронизация — только на базе в РК, после A1. Конец перехода — после Booking.com: досинхронизацию снять, ADR-052 действует полностью.

- **Критерий готовности на канал:** чеклист канала из `CUTOVER.md` закрыт целиком; `npm run cutover:channel -- <канал>` даёт расхождение 0; тестовое событие получено; мониторинг включён.
- **Файлы:** `CUTOVER.md` (migration matrix, порядок, чеклист, маппинг 5 категорий/тарифов), `plans/transition-exely-sync-2026-09-23.md`.
- **Кто:** владелец (экстранеты) + агент (отчёты, маппинг, сверка).

## Что агент НЕ трогает (границы)
Exely / OTA / Channex production не менять до момента, описанного в плане канала. Ключи только в `.env` руками; чтение `.env` и реальных выгрузок агенту закрыто; ключ в чат не диктуется. Реальные ПДн — не в Claude/ChatGPT/Codex; в тестах только вымышленные гости. Развилки — в `QUESTIONS.md`/`DECISIONS.md` с датой. Деньги — integer minor units, без float.
