ТЗ: Онбординг «Создайте ИИ-продажника за 3 минуты»

Гостевой мастер создания ИИ-бота продаж без регистрации: сайт → автоанализ → проверка данных → генерация промпта и базы знаний → тест-чат → регистрация → бот сохраняется в аккаунт.

0. Общие правила

Адрес страницы: /create (можно с параметром ?ref=<источник>, например ?ref=landing_hero).
Весь мастер — одна страница, шаги меняются без перезагрузки, с анимацией (сдвиг вправо/влево, 200 мс).
Раскладка: слева — карточка текущего шага, справа (только на десктопе) — «живое превью» бота. На шаге теста справа — чат.
Шапка: слева логотип + название платформы, справа — индикатор прогресса из 4 точек: Источник → Проверка → Тест → Регистрация (пройденные — длинные тёмные, будущие — маленькие серые).
На всех шагах кроме «Старт» и «Источник» — плавающая кнопка слева снизу «← В начало» (возвращает на Старт, данные не стираются).
Все данные гостя хранятся на сервере в черновике, привязанном к гостевой сессии. Если пользователь закрыл вкладку и вернулся — поля восстанавливаются.
Все ошибки показываются всплывающими уведомлениями (toast), мастер никогда не «застревает».
На каждом ключевом действии отправляется аналитическое событие (список в разделе 4).
1. Гостевая сессия (при открытии страницы)

При первом открытии страницы один раз вызывается POST /wizard/session с { ref } (если есть в URL, обрезать до 200 символов).
Сервер:
если у браузера уже есть гостевой токен (заголовок X-Wizard-Token) — возвращает существующую сессию;
иначе создаёт новую сессию + пустой черновик, генерирует токен формата wz_ + 64 hex-символа, пишет событие wizard_started.
Ответ: guestSessionId, guestToken (только при создании), lastStep, draft { businessName, niche, description, wizardData, hasGenerated, testMessagesUsed }.
Клиент сохраняет guestToken в localStorage и дальше шлёт его в заголовке X-Wizard-Token во всех запросах мастера.
Если в черновике есть название или ниша — подставить все поля в форму. Счётчик тест-сообщений = testMessagesUsed.
Все последующие запросы без валидной сессии → 401.
2. Шаги мастера (по кнопкам)

Шаг 1. «Старт» (intro)

Заголовок: «Создайте ИИ-продажника за 3 минуты».
Подзаголовок: «Введите сайт — мы обучим бота на вашем бизнесе. Протестируйте прямо здесь, без регистрации.»
Кнопка «Начать создание →»:
событие wizard_started;
переход на шаг «Источник».
Справа — пустое живое превью.
Шаг 2. «Источник» (source)

Заголовок «Начнём с ссылки», текст «Адрес вашего сайта — мы извлечём всё о бизнесе автоматически».
Поле URL сайта (placeholder https://вашсайт.kz).
Переключатель «Сценарий» (2 кнопки, одна активна): ИИ-продажник (по умолчанию, sales) / Техподдержка (support).
Кнопка «Начать обучение →»:
неактивна, пока поле пустое;
если URL не начинается с http:// или https:// → toast «Введите корректный адрес сайта», остаёмся;
иначе: событие source_submitted { hasUrl: true, botType } → шаг «Сканирование» → запрос скана.
Ссылка «или настроить вручную без сайта» → сразу на шаг «Проверка» с пустыми полями.
Шаг 2а. «Сканирование» (scanning) — экран ожидания

Заголовок «Обучаю бота…», текст «Сканирую ваш сайт и анализирую бизнес».
Чек-лист из 3 пунктов: Сканирование сайта → Извлечение информации → Анализ бизнес-модели. Каждые 2,2 с подсвечивается следующий пункт (не дальше 3-го, пока не пришёл ответ).
Запрос POST /wizard/scan { url, botType }. Сервер:
проверяет URL (иначе 400);
скачивает сайт и достаёт текст (безопасно: запрет внутренних/локальных адресов, лимиты размера и времени);
отправляет текст в ИИ → получает businessName, niche, description, (опц.) faqCandidates;
сохраняет в черновик: название/нишу/описание (если ИИ вернул пусто — оставляет старое), источник данных { type: 'website', label: url, content: текст до 100 000 символов }, botType;
событие scan_completed (или scan_failed при ошибке → 502).
Успех: все пункты отмечены, поля заполнены, «Имя ассистента» = «Ассистент», если не задано; через 0,5 с → шаг «Проверка».
Ошибка: toast «Не удалось просканировать сайт — заполните данные вручную» → шаг «Проверка».
Шаг 3. «Проверка» (review)

Заголовок «Проверьте информацию», текст «Поля заполнены из вашего сайта — поправьте при необходимости».
Поля (сетка 2 колонки):
Поле	Тип	По умолчанию
Имя ассистента	текст, placeholder «например, Алина»	«Ассистент» после скана
Название компании*	текст	из скана
Ниша*	текст	из скана
Основная цель	текст, placeholder «Записать на консультацию»	—
Описание	многострочное (на всю ширину)	из скана
Ключевые преимущества (через запятую)	многострочное	—
Валюта	список: KZT, USD, EUR, RUB, GBP	KZT
Часовой пояс	список: UTC+5 (Алматы), UTC+5 (Астана), UTC+3 (Москва), UTC+0, UTC+4	UTC+5 (Алматы)
Скрытые значения по умолчанию: стиль письма friendly, обращение «Вы», стиль бота human.
Справа живое превью обновляется на каждое нажатие клавиши: имя, компания, цель, преимущества (чипами), валюта, часовой пояс.
Кнопка «Сгенерировать бота →»:
неактивна, пока пусто Название или Ниша (и toast «Заполните название и нишу»);
PATCH /wizard/config со всеми полями (ошибку игнорируем). Сервер обновляет только переданные поля, доп. поля кладёт в wizardData, событие review_edited;
переход на шаг «Генерация», сброс опроса;
в фоне запускается POST /wizard/generate (не ждём его, пользователь идёт в опрос).
Шаг 4. «Генерация» (generating)

Генерация идёт в фоне, а пользователь в это время отвечает на опрос.

4а. Опрос «Пока мы собираем бота» (5 вопросов, по одному на экран, счётчик «n/5»):

«Чего хотите достичь с ботом?» — свободный текст.
«Размер вашей команды?» — Только я / 2-10 / 11-50 / 51+.
«Сколько лидов в день?» — Менее 10 / 10-50 / 50-200 / 200-1000 / 1000+.
«Откуда узнали о нас?» — Instagram / Google / Реклама / Рекомендация / Другое.
«Чем вы занимаетесь?» — E-commerce / Обучение / Бьюти / Медицина / Услуги / Недвижимость / Другое.
Кнопка «Далее» (на 5-м — «Готово»). Ответы необязательны.
После «Готово» → POST /wizard/survey (upsert по сессии, событие survey_answered, ошибки игнорируются).
Сверху маленький индикатор «⟳ Идёт настройка бота…».
4б. «Финальная сборка»:

Пока не готово: «Осталось примерно 45 сек» (обратный отсчёт); когда готово — «Готово!».
Чек-лист: Анализирую бизнес → Психология продаж → Создаю базу знаний → Финальные штрихи, каждые 3,5 с следующий пункт; по завершении запроса — все отмечены.
Кнопка «Протестировать бота →»: пока идёт генерация — неактивна с текстом «⟳ Собираем…».
Серверная логика POST /wizard/generate:

Если в черновике нет названия или ниши → 400.
Двухпроходная генерация через ИИ на основе: название, ниша, описание, стиль бота + все источники данных (текст сайта):
проход 1 — системный промпт продажника (роль, цель, тон, этапы продаж, работа с возражениями, призыв к цели);
проход 2 — база знаний, разбитая на разделы (услуги, цены, FAQ, условия и т.д.).
Сохраняет в черновик: generatedPrompt, generatedKnowledge, generatedKnowledgeSections. Событие generate_completed { sections }.
Ответ { ok, preview: { sectionsCount } }.
Ошибка → клиент показывает toast «Ошибка генерации, пробуем ещё раз позже», но всё равно разблокирует кнопку.
Шаг 5. «Тест бота» (testbot)

При входе — GET /wizard/quota → { usedCount, limit } (лимит = 5 сообщений).
Заголовок «Протестируйте вашего бота», текст «Спросите что угодно — бот отвечает на основе вашего сайта».
Чат справа (на мобильном — внутри карточки): история, поле ввода, кнопка отправки, счётчик «использовано N из 5», индикатор «печатает…».
Отправка сообщения:
сообщение пользователя сразу появляется в чате;
POST /wizard/message { text, history } (history — последние реплики вида «Пользователь: …»/«Ассистент: …», сервер берёт максимум 10);
сервер: нет сгенерированного промпта → 400; лимит исчерпан → 402 limit_reached (+ событие testbot_limit_reached); пустой текст → 400; иначе ИИ отвечает (системный промпт = сгенерированный промпт + «БАЗА ЗНАНИЙ» целиком), счётчик +1, событие testbot_message_sent;
ответ бота добавляется в чат, счётчик обновляется;
402 → поле блокируется, toast «Лимит тестовых сообщений исчерпан — зарегистрируйтесь, чтобы продолжить»;
другая ошибка → в чате сообщение бота «Упс, не получилось ответить — попробуйте ещё раз 🙏».
Лимит считается только на сервере (анти-абуз).
Когда лимит исчерпан — под кнопкой текст «Лимит тестов исчерпан — сохраните бота, чтобы общаться без ограничений».
Кнопка «🔒 Зарегистрироваться и сохранить бота» → событие testbot_cta → шаг «Апсейл».
Шаг 6. «Апсейл» (upsell)

Заголовок «Усильте вашего бота», текст «Можно включить позже в кабинете».
3 карточки с галочкой:
Повторные касания — автодожим замолчавших лидов;
Человеческая задержка — паузы перед ответами, как живой менеджер;
Разделение сообщений — длинные ответы бьются на части.
Кнопки «Продолжить →» и «Пропустить» — обе ведут на «Регистрацию».
Шаг 7. «Регистрация» (signup)

Плашка «🎁 Получите 7 дней бесплатно».
Заголовок «Почти готово!», текст «Зарегистрируйтесь — и бот сохранится в вашем аккаунте».
Фаза «Форма»: Email, Пароль (мин. 6), чекбокс «Принимаю Пользовательское соглашение и Политику конфиденциальности».
Кнопка «Зарегистрироваться →»:
нет email или пароль < 6 → toast «Email и пароль (мин. 6 символов)»;
не отмечен чекбокс → toast «Подтвердите согласие»;
нет гостевого токена → ошибка «Сессия Wizard истекла. Начните заново»;
иначе регистрация: имя пользователя = имя ассистента или название компании; гостевой токен кладётся в метаданные пользователя (pending_wizard_token), чтобы завершить мастер даже если письмо откроют на другом устройстве; путь возврата = /dashboard.
Если подтверждение email не нужно: сразу вход → завершение мастера (см. раздел 3) → toast «Готово! Бот сохранён в вашем аккаунте» → переход в /dashboard. Если завершение не удалось → ошибка «Не удалось сохранить бота. Войдите в аккаунт и повторите».
Если нужно подтверждение: переход в фазу «Подтверждение», toast «Ссылка подтверждения отправлена на почту».
Фаза «Подтверждение»: текст «Мы отправили ссылку на {email}. Откройте её — бот сохранится автоматически», кнопки «Отправить письмо повторно» и «Изменить email» (назад к форме).
Всегда внизу: «Уже есть аккаунт? Войти» → запоминает возврат /dashboard → страница входа. После входа мастер завершается автоматически.
3. Завершение мастера (создание реального бота)

Срабатывает после: регистрации без подтверждения, перехода по ссылке из письма, или обычного входа.
Клиент берёт гостевой токен из localStorage, а если его нет — из метаданных пользователя.
POST /wizard/complete с токеном пользователя + гостевым токеном.
Сервер одной транзакцией (с блокировкой черновика, защита от двойного нажатия):
проверяет, что черновик принадлежит этой гостевой сессии и ещё не превращён в бота (если бот уже создан — возвращает его, не создаёт второй);
создаёт бота у пользователя: имя, описание, системный промпт = generatedPrompt, настройки из wizardData (имя ассистента, цель, преимущества, валюта, часовой пояс, стиль, обращение, тип sales/support);
создаёт базу знаний из generatedKnowledgeSections и ставит её в очередь индексации (поиск по смыслу);
привязывает опрос и события к пользователю, записывает botId в черновик;
выдаёт пробный период 7 дней.
После успеха клиент удаляет гостевой токен из localStorage и из метаданных. При ошибке — токен не удаляется, попытка повторяется при следующем входе.
Пользователь попадает в /dashboard, бот виден в списке.
4. Аналитические события

wizard_started, source_submitted, scan_completed, scan_failed, review_edited, generate_completed, survey_answered, testbot_message_sent, testbot_limit_reached, testbot_cta. Произвольные события — POST /wizard/event { type (≤60 симв.), payload }, ошибки на клиенте игнорируются. Хранить с guestSessionId, ref, временем → воронка «открыл → скан → генерация → тест → регистрация».

5. Данные (минимальная модель)

GuestSession: id, tokenHash, ref, lastStep, createdAt, expiresAt.
OnboardingDraft: id, guestSessionId / userId, businessName, niche, description, botStyle, wizardData (JSON), dataSources (JSON), generatedPrompt, generatedKnowledge, generatedKnowledgeSections (JSON), testMessagesUsed (int, 0), botId (null до завершения).
WizardSurvey: guestSessionId (unique), goal, teamSize, leadsPerDay, source, industry.
WizardEvent: guestSessionId, type, payload (JSON), createdAt.
6. Безопасность и лимиты

Гостевой токен хранить на сервере только в виде хеша; формат проверять регуляркой ^wz_[a-f0-9]{64}$.
Скан сайта — защита от SSRF (нельзя localhost/внутренние IP), таймаут, лимит размера.
Лимит 5 тест-сообщений и rate-limit на скан/генерацию по сессии и IP.
Все ИИ-запросы гостя — на счёт платформы, быстрая стабильная модель.
Таблицы гостя недоступны напрямую из браузера — только через серверные функции.
7. Критерии приёмки

 Путь «сайт → проверка → генерация → тест → регистрация» проходится без ошибок за ≤3 минуты.
 Путь «вручную без сайта» работает.
 Ошибка скана не блокирует мастер.
 Перезагрузка страницы восстанавливает введённые данные.
 6-е тестовое сообщение блокируется сервером (402).
 После регистрации (с подтверждением email или без) и после входа существующим аккаунтом бот появляется в кабинете ровно один раз.
 Письмо, открытое на другом устройстве, тоже сохраняет бота.
 Все события пишутся в аналитику.
