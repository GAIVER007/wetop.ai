# Аналитика v2 — срез AN2: вкладка «Загрузка» v2 (28.09.2026)

**Основание:** сообщение владельца от 28.09.2026 — «AN1 принимаю. Визуальный гейт закрыт — можно переходить к AN2»,
в том же сообщении решения по Q-208 и Q-209 и перенаправление `/management/dashboard`. Решение — дополнение к
**ADR-114**. После AN2 снова **стоп и снимки**; AN3–AN6 без отдельного подтверждения не начинаются.

Прежний экран «Загрузка» (бывшая «Статистика») не удаляется, а переходит на систему модуля: та же полоса периода,
тот же расчёт, что у «Обзора», тот же тип фонда. Отвечает на вопрос смены «сколько мест занято, свободно и закрыто»
— за день, как раньше, и теперь за период.

---

## 1. Что просил владелец и где это на экране

| Пункт поручения | Как сделано |
|---|---|
| дата / период | Полоса «Обзора» с отрезком по умолчанию «Сегодня»; «7 дней», «Этот месяц», «Прошлый месяц», свой период. У одного дня — стрелки «‹ ›» на соседние дни. Старые `?date=` и `/management/statistics?date=` открывают этот день |
| `Все / Номера / Койки` | Переключатель полосы; тип переходит между вкладками «Обзор» и «Загрузка» |
| занято, свободно, заблокировано, без размещения | Пять плиток: Загрузка, Занято, Свободно, Заблокировано, Без размещения (ссылка «разместить» → брони без места). За день — места, за период — ночи (место × ночь) |
| загрузка по категориям | Таблица: Мест (за период — ночей фонда), Занято, Свободно, Блок, Без места, Загрузка, «К прошлому» (п.п.) |
| deep link «Открыть шахматку» | Кнопка под таблицей — на тот же день или период (до 62 дней, потолок шахматки) с типом фонда; название категории — шахматка этой категории |
| сравнение категорий | Полосы по загрузке сверху вниз, черта — средняя по выбранному фонду, справа — отличие от неё в п.п. Одна категория — панели нет |
| знаменатель прежний | Заблокированное место в фонде: занято + свободно + блок = фонд, загрузка = занято / фонд |

## 2. Решения владельца, которые вошли в срез

- **Q-208.** Достоверной разбивки выручки по ночам нет (начисление одно на проживание, датировано заездом;
  `ReservationItem.price` — сумма, `DailyRate` — прайс, а не проданная цена). Сумма не делится, расчёт прежний,
  график «Обзора» называется **«Выручка по заездам»**.
- **Q-209.** Одна `Reservation` — одна бронь. Брони, отмены, незаезды, средний чек и источники «Обзора» считаются
  по броням с заездом в периоде; размещения — отдельным числом в подписи плитки «Брони». «Новые брони» по дате
  создания — AN3.
- **`/management/dashboard`** перенаправляет на «Обзор» с тем же периодом; пункт реестра меню и компоненты
  `management/period/*` убраны; ссылки Главной ведут в «Аналитику» и на «Загрузку» дня.

## 3. Что меняется в коде

- `packages/domain/src/dashboard/metrics.ts`: у проживания — `reservationId` и `reservationStatus`; брони и
  источники — по броням; у категории — `freeNights`, `blockedNights`, `unassigned`; `bookings.stays`.
- `apps/api/src/dashboard/dashboard.repository.ts`: проживание несёт id и статус брони; проживания без места
  групповой брони считаются каждое (раньше одинаковые схлопывались в одно).
- `apps/web/src/app/management/analytics/`: `params.ts` (вкладка, отрезок по умолчанию, `?date=`, соседний день),
  `toolbar.tsx` (стрелки дня), `tiles.tsx` (плитка и честное сравнение — общие для вкладок), `overview.tsx`
  (Q-208, Q-209, на одном дне без двойной загрузки категорий), `occupancy/*` (вкладка v2), `analytics.css`.
- `apps/web/src/app/chessboard/board-grid.tsx`: тип места из адреса `?kind=ROOM|BED`.
- `apps/web/src/app/today/dashboard.css`: на телефоне полоса категорий не схлопывается.
- Модель данных, финансовая логика, команды, миграции — не тронуты.
