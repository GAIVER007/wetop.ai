# Салон красоты по ТЗ «Модуль для салонов красоты» v1.0 от 09.10.2026

Поручение владельца: два изображения, макет WETOP.AI «Для индустрии красоты» (9 экранов) и ТЗ
с 13 разделами, «перенести точь в точь дизайн и всю логику». Ветка `claude/beauty-salon-module-tz`.

## Что уже есть (аудит 09.10.2026)

Срезы B1–B5 (план `beauty-phase3-2026-10-03.md`) дали: модель §19.1 целиком (10 таблиц,
миграции 044–045), журнал дня по мастерам (`/calendar` → `beauty/journal.tsx`), записи списком
(`/appointments`), каталог услуг с ценой филиала (`/services`), мастеров с drawer «Основное /
Услуги / Филиалы / График / Отсутствия» (`/employees`), «Сегодня» салона (MV8, `beauty-today.tsx`),
клиентов плоским списком (`/customers`), аналитику статусов и выручки DONE за период
(`/management/analytics`). Статусы: BOOKED, CONFIRMED, DONE, NO_SHOW, CANCELLED.
Деньги записи: снимок `price`/`currency` в записи, Folio не используется (Q-252), выручка = сумма DONE.

## Чего нет и почему это важно

| Из ТЗ | Статус | Препятствие |
|---|---|---|
| Зарплата мастеров (§5 ТЗ: фикс, % услуг, % товаров, бонусы, штрафы, итог) | нет совсем | модель данных + финансовая логика, AGENTS §2/§15 → Q-BS-1 |
| Статус «В процессе» | нет | правка enum = миграция → Q-BS-2 |
| Сегменты клиентов новый/постоянный/VIP | нет | производные выводимы; VIP = ручная пометка, поля нет → Q-BS-3 |
| Карточка клиента с историей, тратами, средним чеком | нет (срез B6) | выводимо из `appointments`, нужен read-only агрегат в API |
| Загрузка мастеров, средний чек, повторные визиты, топ услуг | нет | выводимо из утверждённой модели |
| Drag-and-drop переноса в шахматке | нет (перенос формой) | UI поверх существующего `PATCH /beauty/appointments/:id` |
| Вид «Неделя» и «Месяц» шахматки | нет | UI поверх `GET /beauty/appointments?date=` |
| Продажа товаров, % от продаж товаров | нет | товаров в модели салона нет → Q-BS-5 |
| Экспорт Excel/PDF | нет | в проекте принят CSV → Q-BS-6 |
| Фото мастеров | нет поля | модель → Q-BS-4, пока инициалы |

## Отклонения от макета, намеренные

- Левое боковое меню макета не переносится: оболочкой стойки владеет линия DS2
  (`plans/mv8-5-ds2-shell-navigation-2026-10-09.md`), меню остаётся верхним. Прецедент:
  «Настройки объекта» 09.10.
- Валюта в макете ₽, в продукте валюта филиала (тиын, integer minor units, ADR-008).
- «Тариф Профи до 1 дек. 2026» в сайдбаре макета: тарифов подписки в модели нет, не рисуем.
- Числа макета (24 записи, 125 430 ₽) не имитируются: только живые данные, пустые состояния честные.

## Стадии

- **S1 «Главная» салона** (этот срез): `/today` салона доводится до макета. Плитки: Записи сегодня,
  Выручка сегодня (сумма DONE, валюта филиала), Клиентов (уникальные за день), Мастера на смене
  X из Y. Ближайшие записи со статусом словом. Блок «Мастера на смене» со счётом записей каждого.
  Быстрые действия: Новая запись (`/calendar`), Добавить мастера (`/employees`), Услуги (`/services`).
  Данных хватает в `GET /beauty/appointments` (колонки несут интервалы, записи несут цены).
- **S2 «Мастера» карточками** (этот срез): `/employees` по макету, сетка карточек: инициалы-аватар,
  имя, специализация (из умений), чип «На смене / Выходной / В архиве», записей сегодня, часы смены.
  Drawer правки прежний. Таблица остаётся на телефоне? Нет: карточки адаптивны сами.
- **S3 «Клиенты»** по макету: телефон, последний визит, всего визитов, средний чек, сегмент
  (производный: Новый < 2 визитов, Постоянный ≥ 2; VIP не выдумываем до Q-BS-3). Нужен read-only
  агрегат: `GET /beauty/customers` расширяется полями `visits`, `lastVisit`, `avgCheckMinor`
  (считаются по DONE). Правка API без правки модели.
- **S4 «Услуги»**: колонка «Популярность» = доля записей услуги за 30 дней, read-only агрегат.
- **S5 «Шахматка»**: цвета плашек по статусу с легендой, переключатель День | Неделя,
  drag-and-drop поверх `PATCH` (перенос формой остаётся как доступная альтернатива).
- **S6 «Финансы / Зарплата»**: ждёт решения Q-BS-1 по модели §19.2 (предложение записано).
- **S7 «Аналитика»**: загрузка мастеров, средний чек, повторные визиты, топ услуг, из тех же данных.
- **S8 Экспорт**: CSV по образцу гостиницы (Q-BS-6).

В этой сессии делаются S1 и S2, дальше по порядку сколько успею; S6 заблокирован вопросом.
Каждая стадия: red → green, `npm run test:record`, axe в двух темах, телефон 390 px.
