# BOOK-SEC1: Cloudflare Turnstile перед бронью с сайта (аудит 29.09.2026)

Решение — ADR-129, открытый вопрос — Q-224. Модель данных, статусы броней и правила бронирования не меняются.

## Проблема

Публичный `POST /w/book` сразу создаёт подтверждённую бронь, которая занимает инвентарь и уходит в каналы. Ключ сайта публичен, домен
проверяется по `Origin`, который вне браузера подделывается. Лимиты (5 в час с адреса, 30 в час на сайт, журнальный предел) ограничивают
поток, но не отличают гостя от бота: шести адресов хватает, чтобы забить инвентарь и заблокировать настоящих гостей.

## Что делаем (этап 1 из двух)

Turnstile — защита от массового автоматического спама, а не гарантия валидности брони. Сильная защита (подтверждение почтой,
статус `TENTATIVE`) — отдельный этап после оценки и продуктового решения.

- **Сервер.** `TurnstileService` проверяет токен у Cloudflare (`siteverify`) непосредственно перед созданием брони. Секрет только на
  сервере (`TURNSTILE_SECRET_KEY`). Нет токена, токен неверный, устарел или уже использован — брони нет. Cloudflare недоступен,
  ответ непонятен или секрет отвергнут — тоже брони нет (fail-closed). Проверка идёт до занятия слота лимита сайта: неудачные
  попытки не расходуют его. Имя хоста в ответе Cloudflare сверяется с доменами сайта, действие — с `booking`.
- **Не затрагивается.** Поиск цен и мест (`GET /w/availability`) идёт без проверки. Прежние лимиты остаются вторым слоем.
- **Виджет.** Получает публичный ключ `TURNSTILE_SITE_KEY` из `GET /w/config`, показывает Turnstile в форме гостя, отправляет токен
  в `POST /w/book`, после каждой попытки сбрасывает виджет (токен одноразовый). Кнопка «Подтвердить бронь» активна, когда токен есть.
- **Включение (уточнено 30.09.2026, решение владельца).** Режим задаётся явно: `WEB_BOOKING_TURNSTILE_REQUIRED=1` — обязательна
  (без `TURNSTILE_SITE_KEY` или `TURNSTILE_SECRET_KEY` API не стартует), `=0` — выключена осознанно (предупреждение при старте).
  Вне production не задан: включена, если есть секрет. В production режим обязан быть задан явно: не задан или непонятное значение —
  отказ старта, даже при обоих ключах (решение владельца 30.09.2026). Проверка при непонятном значении остаётся включённой. Так две потерянные переменные не открывают `/w/book` тихо.

## Тесты

- `turnstile.test.ts` — токен: нет / неверный / устарел / повтор / слишком длинный; отказ Cloudflare; сеть, не-200, не JSON,
  таймаут; неверный секрет; хост и действие; стартовая проверка настроек.
- `web-booking.controller.test.ts` — через HTTP: без секрета как раньше; с секретом бронь без токена не создаётся; успех;
  неверный, устаревший, повторный токен; Cloudflare недоступен; поиск цен без токена; `GET /w/config` без утечки секрета.
- `tests/ui/booking-widget-turnstile.spec.ts` — браузер, запросы и Cloudflare подменены: кнопка выключена до токена, токен уходит
  в `/w/book`, после попытки виджет сбрасывается; без ключа форма как раньше.

## Выкладка (владелец)

1. В Cloudflare → Turnstile создать виджет: домены — домены сайтов гостиниц и хост API (демо-страница), режим Managed.
2. В серверный `.env`: `TURNSTILE_SITE_KEY` (публичный), `TURNSTILE_SECRET_KEY` (секретный) и `WEB_BOOKING_TURNSTILE_REQUIRED=1`, пересоздать API. Сначала env, потом код: на новом коде без них production не стартует.
3. Проверить демо `/w/demo?k=…`: бронь без прохождения проверки не отправляется; после — создаётся.
4. Если у сайта гостиницы строгая CSP — разрешить `https://challenges.cloudflare.com` в `script-src` и `frame-src`.
5. Откат — `WEB_BOOKING_TURNSTILE_REQUIRED=0`: проверка выключится, виджет вернётся к прежней форме.

## Не входит

Подтверждение почтой и `TENTATIVE` (этап 2; Q-224 закрыт вариантом (а) 30.09.2026 — не делаем, пока нет реальных случаев); проверка на `/a/hit` (счётчик) и на регистрации.
