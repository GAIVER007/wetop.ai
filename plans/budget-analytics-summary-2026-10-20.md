# «Бюджет и аналитика»: сводка в одном экране (20.10.2026)

**Статус: одобрен владельцем 20.10.2026** («Сводка в одном экране: расход ручной + расход кабинета Meta, заявки, цена
заявки, ROMI по каналам; один пункт меню вместо двух»). Решение: `docs/decisions/2026-10-20-budget-analytics-summary.md`.
Ветка `hermes/budget-20261020` от `main` `ce4b623e2`.

## 1. Что есть сейчас

- Меню «Продвижение»: два пункта «Бюджет» (`/marketing/budget`) и «Аналитика маркетинга» (`/marketing/analytics`).
- Бюджет: обзор месяца (план, факт, прогноз, план по каналам), журнал расходов. Данные `GET /marketing/budget`.
- Аналитика: воронка «Расходы → Обращения → Брони → Выручка» по каналам (`GET /marketing/results`, только гостиница),
  календарь по дням, CSV.
- Расход кабинета Meta (§55, ADR-MKT-META) лежит в статистике кампаний (`marketing_campaign_stats.spend_minor` в валюте
  кабинета) и отдаётся `GET /marketing/campaigns` полями `cabinetSpend` / `cabinetCurrency`. Журнал расходов ведётся
  вручную (развилка Д = А): расход кабинета в журнал не попадает.

## 2. Что делаем

1. **Один пункт меню «Бюджет и аналитика»** (`/marketing/budget`) вместо двух. Внутри вкладки маршрутами:
   **Сводка** (`/marketing/budget`, открывается первой), **План** (`/marketing/budget/plan`, бывший обзор),
   **Расходы** (`/marketing/budget/expenses`), **Аналитика** (`/marketing/analytics`, адрес прежний и рабочий).
   `/marketing/analytics` подсвечивает тот же пункт меню; права и реестр страниц не меняются (право `marketing`).
2. **Сводка месяца** чистой функцией `marketing/budget/summary.ts` поверх трёх настоящих ответов API
   (`/marketing/budget`, `/marketing/campaigns`, `/marketing/results`), без своих запросов:
   - **расход вручную**: учтённые строки журнала в валюте отчётности;
   - **расход кабинета Meta**: сумма дней кампаний кабинета в валюте кабинета, по валютам раздельно;
   - **заявки**: обращения каналов из `/marketing/results` (термин по направлению из `vertical-copy.ts`);
   - **цена заявки**: ручной расход / заявки, целыми minor units с округлением к ближайшему;
   - **ROMI по каналам**: (выручка канала − ручной расход канала) / ручной расход канала, только у каналов с выручкой
     (сайт, WhatsApp, Instagram, телефон) и только в одной валюте; итог по этим каналам;
   - у строки Meta: заявки площадки и цена заявки по кабинету (расход кабинета / лиды площадки, DATA_MODEL §53
     «CPL площадки»), в валюте кабинета.
3. **Не считаем дважды:** ручной расход и расход кабинета показываются раздельно и не складываются (правила сложения
   в §55 и плане Meta нет: журнал может содержать оплату того же счёта Meta). Вопрос владельцу: `QUESTIONS.md`
   Q-MKT-SUM.
4. **Чего нет, того нет:** нет выручки по каналу (Meta, Google, салон и ресторан без `/marketing/results`) →
   «нет данных» с причиной; разные валюты не складываются и не сравниваются; деление на ноль → «нет данных».

## 3. Без изменений

Схема базы, миграции, API (кроме подставного стенда: засев кампаний кабинета), право раздела, журнал расходов.
Старая идея `marketing_expenses.source = META` не переносится.
