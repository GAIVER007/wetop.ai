## C · SaaS-трек

### C1 · Мультитенантность до конца (Q-152)
**Готово (с 21.09, `main`).** Регистрация заводит свой объект; вошедший видит только объект своей организации — замок в приложении (ADR-061), модульные тесты `apps/api/src/database/property-ref.test.ts`.
**Осталось.** Row Level Security; тест изоляции на настоящем PostgreSQL; ключи Channex и почты сейчас на установку, а не на организацию; служебные пути (webhook, виджет, сторож) берут объект по имени Luxx. Спор ADR-055/061 ↔ ADR-056 — Q-157.
- **Критерий:** данные одной организации не видны другой; тест изоляции.

### C2 · Онбординг доделать
**Готово.** Сервис, экран и тесты есть (`apps/api/src/hotel/onboarding.ts`, `packages/domain/src/onboarding`, `tests/ui/onboarding.spec.ts`).
**Осталось.** Сквозной путь «регистрация → подтверждение почты → онбординг → бронь → заселение» на настоящей базе.
- **Критерий:** новичок из пустого кабинета за один экран доходит до «можно поселить гостя» (категория + места + тариф + цены на горизонт); e2e.

### C3 · Подписки, пробный период, биллинг, статус оплат — НЕ построено
В коде модулей подписок/биллинга нет. Нужны: организации-арендаторы, пробный период (после 7 дней — только чтение, ADR-046), тарифные планы, приём оплаты, экран «статус оплат» для владельца платформы. Сейчас статус TRIAL и срок ставятся, но **перехода в «только чтение» нет**.
**Сначала модель, потом код** — модель платформы v2 в `DATA_MODEL.md` (ADR-019 отложен). До модели нужны ответы владельца: **Q-141** (чем платят партнёры), **Q-143** (тарифы WETOP), **Q-144** (пробный период), **Q-145** (где ПД сотрудников).
- **Критерий:** организация регистрируется сама, живёт в пробном периоде, платит, статус оплаты виден владельцу платформы; тесты.

### C4 · Q-153 — продление смены по паролю
Уже всплыло в A2. Решение владельца → срез (`shouldRenewSession` в домене цел, включение — одна строка).
