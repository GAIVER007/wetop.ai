# CH1 — «Каналы продаж»: обзор вместо отчёта; отчёт — в «Аналитика → Источники продаж» (27.09.2026)

Первый этап ТЗ «Каналы продаж v2» (`plans/tz-channels-2026-09-27.md` §15, ADR-107). Владелец
подтвердил продолжение 27.09.2026 («Давай продолжай») после сведения ТЗ. По правилу ветки сессии
CH1 идёт тем же PR #110, что и ТЗ (отдельную ветку сессия открывать не вправе); после CH1 — стоп
и dark/light скриншоты состояний (§15.1 ТЗ).

## Состав

**`/channel-manager` становится обзором** (заголовок «Каналы продаж»; адрес не меняется — на нём
сидят ссылки и меню, слияние меню — CH5):

- полоса здоровья (`StateBar`, как на `/channels`): спокойно «Все каналы работают», предупреждение
  или тревога по той же градации, что `queueTone` на `/channels` (ошибки отправки или застой
  ≥ 10 мин — тревога; ожидание, несопоставленные категории, события FAILED, webhook — внимание);
- счётчики: в очереди · ошибок отправки · требуют разбора (события FAILED, `events.total`) ·
  без сопоставления (категории объекта минус сопоставленные) · последняя синхронизация;
- «Требует внимания» — строки-проблемы со ссылкой на место исправления (`/channels`,
  `/channels?queue=FAILED`, `/channels?status=FAILED`, `/connections`). Кнопок действий на обзоре
  нет: действия живут на `/channels`, их `data-testid` заморожены сертификацией Channex;
- карточка подключения Channex (`Panel` + `Badge` + `Grid`/`Fact`, композиция как на
  `/connections`): состояние, среда, сопоставлено M из N категорий и тарифы, последний
  webhook/импорт по Алматы, [Открыть] → `/channels`; property id не показывается;
- компактные источники за 30 дней **по числу броней** (валюты в одну долю не складываются —
  правило плана 20.09): существующий `GET /hotel/channel-report` за окно [сегодня−29, сегодня],
  статус ALL; ссылка «Подробнее в аналитике» (без стрелки — DESIGN.md §14);
- аналитического фильтра периода на обзоре нет (ТЗ §3);
- отказы API по D4: каждый блок падает отдельно (`LoadError`/`Alert`), экран остаётся; сбой не
  выдаётся за пустоту. «Объект в Channex не создан» — по загруженным данным, не по ошибке.

**Отчёт по источникам переезжает на `/analytics/sources`** («Источники продаж») без изменения
поведения: форма периода/статуса, счётчики, таблица, пустое состояние, `Help`, загрузка. Это
вынужденная часть CH5, взятая в CH1: убрать фильтр с обзора, не потеряв функциональность, можно
только дав отчёту новый адрес (правило ADR-105/ADR-107 «функциональность не удалять»). Ссылка
«Фактические оплаты за период» и параметры `?from&to&status` сохраняются.

**Навигация**: карточка каталога `/channel-manager` получает описание про состояние подключений;
в каталог добавляется «Источники продаж» (`/analytics` → children). Пункты сайдбара не меняются —
это CH5.

**API и расчёты не меняются** (правило CH1). Задеваемые файлы: два `page.tsx` + `loading.tsx`,
`lib/navigation.ts`, `channels/actions.ts` (revalidate + `/analytics/sources`), DESIGN.md §8
(строка «Сводка „Менеджера каналов“» описывает старый экран — переписать на обзор и отметить
переезд отчёта), спеки UI и списки маршрутов, сценарии стенда
(`cli-ui-walkthrough`, `cli-ui-smoke`, `cli-channex-wetop-cycle` — сверка отчёта по новому адресу).

## Доказательства

- red-before-green: новый спек обзора записывается красным на текущем коде, затем зелёным;
- отчётные тесты `channex-screens` / `workspace` / `empty-base` переезжают на `/analytics/sources`
  и остаются зелёными (поведение отчёта не менялось);
- `typecheck`, `lint`, полный UI-набор стойки `--workers=1` — через `npm run test:record`;
- dark/light скриншоты состояний обзора (всё в порядке · очередь и ошибки · не сопоставлено ·
  пусто/отказ) — `reports/channels-overview-2026-09-27/`; стоп до CH2.

## Чего в CH1 нет

Вкладок и слияния меню (CH5), мастера подключения, изменений `/channels` и его кнопок, новых
порогов и бизнес-правил, изменений API, модели данных и прав.
