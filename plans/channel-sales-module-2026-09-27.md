# Модуль «Каналы продаж»: один вход вместо двух пунктов меню (27.09.2026)

**Поручение владельца 27.09.2026** (разбор экрана синхронизации по снимкам): экран Channex нужен,
но это технический пульт интеграции, а не рабочий экран администратора. Он отвечает на вопрос
«обмен WETOP с OTA сейчас вообще работает или нет», а не «сколько броней пришло с Booking».
Два пункта меню — «Менеджер каналов» и «Синхронизация каналов» — для пользователя непонятны.

Решение владельца (цитаты из поручения):

- объединить в один модуль **«Каналы продаж»** со структурой: Обзор, Подключения, Сопоставление,
  Синхронизация, События;
- группа «Продажи» в меню: Тарифы, Каналы продаж, ИИ-продавец, Сайт и онлайн-бронирование;
- отдельного пункта «Синхронизация каналов» в меню не оставлять;
- «страшные таблицы» (UUID событий, JSON, payload, попытки, внутренние ID) обычному сотруднику
  не показывать — спрятать за «Технические детали»;
- ручные опасные кнопки («Создать объект и категории», «Зарегистрировать webhook»,
  «Проверить webhook», «Полная выгрузка 500 дней») перенести в «Настройки подключения»
  и показывать OWNER / техническому специалисту;
- функциональность сохранить полностью.

Решение записано как **ADR-107** (при записи — ADR-106, см. «Нумерация»).

## Что делаем

### 1. Маршруты

| Было | Стало |
|---|---|
| `/channel-manager` — отчёт по источникам | redirect на `/channels` (параметры периода сохраняются) |
| `/channels` — весь пульт одной страницей | `/channels` — модуль с вкладками (`[[...section]]`, как у «Настроек гостиницы» и «ИИ-продавца») |
| — | `/channels` — Обзор |
| — | `/channels/connections` — Подключения |
| — | `/channels/mapping` — Сопоставление |
| — | `/channels/sync` — Синхронизация |
| — | `/channels/events` — События |
| `/channels/events/[revisionId]` — приём брони | без изменений (статический сегмент побеждает catch-all) |

Старые адреса с параметрами старого пульта: `/channels?queue=…` → `/channels/sync?queue=…`,
`/channels?status=…|type=…|q=…` → `/channels/events?…` (redirect в корне модуля).

### 2. Вкладки

- **Обзор** — для управляющего: полоса состояния обмена (`StateBar`: соединение Channex, webhook,
  последний обмен, очередь, ошибки), тревога овербукинга, кнопки ежедневного обмена
  («Отправить очередь сейчас», «Забрать брони из Channex») и отчёт по источникам броней за период
  (бывший «Менеджер каналов» без изменений расчёта). Технические значения (задача Channex, id
  объекта, адрес webhook) — в свёрнутом `<details>` «Технические детали».
- **Подключения** — состояние подключения Channex (среда, объект, сопоставлено, последние
  webhook/импорт) + группа «Настройка подключения» (те же четыре кнопки с теми же `data-testid`
  и в том же порядке) — только роли OWNER; сотруднику вместо кнопок строка
  «Настройку подключения меняет владелец организации.» (образец — «ИИ-продавец», ADR-083).
- **Сопоставление** — таблица «категория WETOP ↔ категория/тариф Channex» (существующая).
- **Синхронизация** — упрощённый экран: строки «Остатки», «Цены и ограничения» (по видам очереди
  `AVAILABILITY`/`RESTRICTIONS`: актуально / в очереди / ошибка), «Брони» (по входящим событиям);
  последний обмен, очередь, ошибки. Таблица строк очереди с фильтрами — в «Технические детали».
  Отдельной строки «Цены» не выдумываем: в очереди Channex цены едут внутри сообщений
  RESTRICTIONS, и врать про отдельный статус нечем.
- **События** — существующий журнал входящих событий с фильтрами и постраничностью; ссылки на
  страницу приёма ревизии сохраняются.

### 3. Меню (`lib/navigation.ts`)

Группа «Продажи»: Тарифы → **Каналы продаж** (`/channels`) → ИИ-продавец →
**Сайт и онлайн-бронирование** (`/analytics`, переименование пункта — страница «Аналитика»
не меняется). Пункты «Менеджер каналов» и «Синхронизация каналов» уходят. Дочерние ссылки
вкладок — в реестре для поиска. Маршруты, API и расчёты не меняются.

### 4. Чего не трогаем

- API, модель данных, домен, `packages/integrations` — без изменений.
- `data-testid` кнопок и значений (`channel-flush`, `channel-pull`, `channel-setup`,
  `channel-webhook-register`, `channel-webhook-test`, `channel-sync`, `channel-result`,
  `outbox-pending`, `outbox-last-task` и таблицы) — те же, порядок команд тот же:
  на них стоит запись показа для сертификации Channex
  (`tests/e2e/channex-certification.spec.ts` ходит на `/channels` и жмёт `channel-flush` —
  корень модуля это покрывает, спек не меняется).
- Страница «Интеграции» (`/connections`) остаётся: это общий экран подключений
  (база, сайт, Channex); её ссылка «Настроить Channex» ведёт на `/channels/connections`.

### 5. Тесты

Обновляются наборы стойки на подставном API: `channex-screens`, `workspace` (разделы каналов),
`navigation`, `requests`, `accessibility`, `premium`, `empty-base`, `manager-actions` — новые
адреса вкладок, разнесённые кнопки, роль STAFF для «Настройки подключения». Прогоны — только
через `npm run test:record` (typecheck, lint, unit, UI-набор в один поток).

## Q-199 — закрыт владельцем 27.09 (дополнение к ADR-107)

«Per-channel health не выдумываем»: «Работает / Ошибка / Устарело» — только у Channex; OTA внутри
Channex — наблюдаемые источники фактами (последняя входящая активность, события с ошибкой, полнота
сопоставления), формулировка «Booking.com — работает» запрещена, пока backend её не подтверждает.
Сделано на «Обзоре»: таблица «Каналы» по последним 50 событиям + заметка о сопоставлении
(«категорий N из M», предупреждение при неполном). Отдельный per-channel health — только когда
Channex/API даст достоверные данные, отдельным решением.
