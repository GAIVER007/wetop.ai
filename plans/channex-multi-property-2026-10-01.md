# Channex для нескольких организаций и филиалов

Утверждено владельцем 01.10.2026: один служебный аккаунт Channex WETOP, отдельный объект Channex
и сопоставления у каждой гостиницы, доступ сотрудника только к своему объекту. Рабочие OTA не
активировать автоматически; подключение после настройки фонда и тарифов.

1. Проверить текущие данные и критические пути. Нынешняя интеграция берёт первый объект по имени
   Luxx Aparts или `INTEGRATION_PROPERTY_ID`; это безопасно для одной гостиницы, но не для нескольких.
   Записать красные тесты: два объекта с одинаковыми кодами категорий; вебхук другого объекта;
   отсутствие сопоставления; фоновая очередь двух объектов; пользователь другой организации.
2. Перевести внутренние команды на явный `property_id` WETOP и `provider_property_id` Channex.
   Выбор филиала из проверенного контекста входа; фоновый процесс перечисляет подключённые объекты.
   Запретить первый найденный объект, имя Luxx и глобальный `INTEGRATION_PROPERTY_ID` как замену
   выбранного объекта в многопользовательских путях.
3. Подключение: владелец выбирает объект и тариф, система проверяет фонд и цены, затем создаёт
   недостающие записи в Channex staging и сопоставления WETOP. Повтор не создаёт дубли;
   существующий объект можно связать после проверки ID. Секрет ключа не появляется в браузере.
4. Входящие: webhook проверяет общий секрет и `property_id`, сопоставляет объект, сохраняет событие
   до обработки; лента опрашивается по каждому подключённому объекту, подтверждение только после
   записи брони в нужную гостиницу. Чужой ID и неизвестная ревизия остаются без подтверждения и
   видны как ошибка. Изменение и отмена также идут в тот же объект.
5. Исходящие: дельты, очередь, full sync и чтение результата группируются по объекту, без смеси
   категорий/тарифов. Вебхук можно сделать общим для аккаунта Channex или пообъектным, но только
   при той же проверке секретов и маршрутизации. Статус и журнал видны в контексте филиала.
6. Доказательства: изолированные тесты на два объекта, отказ чужому пользователю, сквозной
   sandbox-цикл на втором вымышленном объекте, сверка цен/остатков, повтор события, сбой и retry.
   После проверок commit/push и deploy по `docs/deploy.md`, readback SHA и health.

Модель: `DATA_MODEL.md` §7. Документация API: `docs/channex/site/guides/pms-integration-guide.md`,
`docs/channex/site/api-v.1-documentation/webhook-collection.md` и коллекции объектов, тарифов,
остатков, бронирований. Без отдельного решения не меняются правила цены/брони и не отправляется
ARI в Channex production.

Открытый Q-218: поведение для активной категории без продажного тарифа/мест. До решения такое
подключение следует отклонять понятной ошибкой и не публиковать неполные данные.

Дополнение владельца 01.10.2026: в модель `Property` добавить страну, город и тип размещения
Channex, показать их в «Настройках объекта». Для Luxx backfill по уже подтверждённым данным,
остальные филиалы заполняют сами. Production migration только с backup, validation и rollback.
