## Почему старые команды не запускаются

`cli-e2e-cleanup.ts` отменяет брони, может обходить API прямой записью и инициировать Channex sync.
`cli-purge-test-data.ts` сохраняет витрину, считает некоторые OTA без Exely тестовыми и опирается
на предположение, что старые события уборки созданы только проверками. Он отказывается удалять
активные назначения. Эти предположения нельзя автоматически переносить на текущую базу.
`GUARD_PROPERTY_LIVE=false` и CANCELLED не доказывают тестовое происхождение конкретной записи.
Ни один из скриптов очистки/восстановления в этом аудите не запускался, даже без --apply.

## Препятствия публикации

- Локальный HEAD `ca4d478`, после fetch `origin/main=eb6752b`: локальная main отстаёт на 4 коммита.
- Серверный checkout `/root/wetop`: `claude/trusting-ramanujan-gi6uzl`, HEAD `5bd5056`.
  От текущей origin/main: 87 уникальных коммитов main против 84 серверной ветки.
  Наличие HEAD в checkout ещё не доказывает точную ревизию запущенного Docker-образа.
- В текущей main нет `deploy/`; сервер использует `deploy/compose.yml` и локальный
  `deploy/compose.hostinger.yml` (последний untracked). Их нельзя затереть переключением ветки.
- В серверной ветке есть отличия авторизации, API, UI, миграций и запуска контейнеров.
  Нельзя копировать только CSS на сервер или заменять весь серверный код main без согласованного merge.
- В локальном дереве остаётся чужой `.git/HEAD.lock` от 18:04:37 UTC; открыт процессом виртуализации.
  Замок не удалялся, индекс не менялся в этом аудите. Другой писатель должен освободить дерево (§17).

## Что отдельно необходимо для боевой готовности

По `CUTOVER.md`, `SECURITY.md` и последнему отчёту о переносе база с настоящими ПД должна быть в РК.
Текущий режим — псевдонимы; перенос приложения на Hostinger сам по себе этот гейт не закрывает.
Выбор production-БД (Q-070а), регламент backup (Q-073), живая смена двойного ввода, ответственный
дежурный, сертификация и поэтапное подключение каналов остаются самостоятельными критериями.
Этот запрос не трактуется как разрешение обойти их, переключить PII_STORAGE или выполнить cutover.
