# Как начать план дизайн-системы на другом компьютере (14.09.2026)

К плану [design-system-2026-09-14.md](design-system-2026-09-14.md). Инструкция написана для Mac. На Windows шаги
те же, отличаются только команды установки.

---

## 1. На основном Mac — до перехода

1. Отправить последние коммиты на GitHub. Команду запускает владелец, агенту отправку блокирует фильтр
   безопасности.

   ```bash
   git -C "/Users/vyacheslav/Desktop/Проекты/Pms Lux" push origin main
   ```

2. Перенести на второй компьютер файл документа ментора `~/Downloads/Вячеслав-план-и-дизайн-система.pdf`
   (AirDrop, флешка или «Избранное» в Telegram). В git его нет.
3. Скриншоты Exely из `project-input/exely-screens/` тоже не в git. Они понадобятся на шаге 1 плана: закрасить
   фамилии гостей и перенести.

## 2. Что поставить на втором компьютере

| Что | Зачем | Проверка |
|---|---|---|
| Git и вход в GitHub-аккаунт владельца — GitHub Desktop или `gh auth login` | Репозиторий `GAIVER007/wetop.ai` приватный. Вход делает владелец, токены в чат не вставлять | `git ls-remote https://github.com/GAIVER007/wetop.ai.git` отвечает без ошибки |
| Node.js 24 (файл `.nvmrc`) | Сборка и тесты | `node -v` → v24 |
| Google Chrome | UI-тесты Playwright запускают установленный Chrome (`tests/ui/playwright.config.ts`) | Chrome открывается |
| Приложение Claude (вкладка Code) или Claude Code в терминале, вход тем же аккаунтом claude.ai | Модель Fable 5.1 и Claude Design привязаны к тарифу аккаунта | В выборе модели есть Fable 5.1 |
| poppler — по желанию: `brew install poppler` | Чтобы Claude мог читать PDF ментора по страницам. Всё нужное из документа уже есть в плане | `pdftoppm -v` |

## 3. Получить проект

```bash
git clone https://github.com/GAIVER007/wetop.ai.git
```

```bash
cd wetop.ai && npm install
```

## 4. Ключи

- **Шаги 0–6 плана ключей не требуют.** Скриншоты, страница компонентов и UI-тесты работают на синтетическом
  API (`tests/ui`) без базы и без Channex. `.env` на втором компьютере для них не нужен. Запись тестов
  (`npm run test:record`) без `.env` тоже работает: файл нужен ей только для того, чтобы вычеркнуть секреты из
  лога.
- **Шаг 5 (Claude Design)** — нужен только вход в claude.ai.
- **Шаг 7 (API и e2e на базе `pms_test`)** — нужен `.env`. Ключи вписывает владелец руками по `.env.example`.
  Через git, чат и мессенджеры ключи не передаются (`SECURITY.md`).

## 5. Что на втором компьютере НЕ запускать

Службы объекта работают только на основном Mac. Вторая копия сломает живую работу:

- `scripts/ops/launchd/install.sh` — API, стойка, туннель, синхронизация Exely, сторож;
- `scripts/ops/channex-tunnel.sh` — второй туннель перерегистрирует webhook Channex на себя, и брони пойдут на
  второй компьютер;
- `scripts/imports/*`, `cli-sync-day.ts` — вторая синхронизация Exely;
- `E2E_CHANNEX_LIVE=1`, `npm run dev -w apps/api` с настоящим `.env`.

Для плана дизайна ничего из этого не нужно.

## 6. Как запустить план — первое сообщение новой сессии

1. В Claude открыть папку `wetop.ai`. `CLAUDE.md` подхватится сам: в нём уже записано, что план ждёт решений
   владельца.
2. Выбрать модель Fable 5.1 и усилие high. Так советует документ ментора для шагов 2 и 6; для мелких правок
   хватит medium.
3. Отправить сообщение ниже. Строку 2 поправить, если какое-то решение не совпадает с рекомендацией плана.

```
Продолжаем план дизайн-системы: plans/design-system-2026-09-14.md.
Я на втором компьютере. Службы launchd, туннель Channex и синхронизация Exely работают только на основном Mac —
здесь их не запускай и не устанавливай. .env здесь нет: шаги 0–6 идут на синтетическом API.

1. Прочитай CLAUDE.md, AGENTS.md, TESTING.md и план целиком. Документ ментора лежит здесь: <путь к PDF>.
2. Мои решения по разделу 11 плана: Д1 да, Д2 да, Д3 да, Д4 вариант (а), Д5 да, Д6 Claude Design, Д7 да.
3. Сделай шаг 0 (номера ADR и вопросов сверь с main), потом шаг 1. Перед загрузкой спецификации DTCG спроси
   разрешения. Скриншоты Exely с закрашенными фамилиями я положу сам.
4. Коммить только свои файлы явным списком. git push запускаю я.
5. После каждого шага — коротко: что сделано, доказательство, что нужно от меня.
```

Память Claude с основного Mac (заметки о ваших привычках) на второй компьютер не переезжает. Правила проекта
лежат в `CLAUDE.md` и `AGENTS.md` и едут вместе с git — их достаточно.

## 7. Как не разъехаться между компьютерами

- Перед каждым заходом, на том компьютере, где работаете:

  ```bash
  git pull --no-rebase origin main
  ```

- В конце захода агент коммитит свои файлы, отправку запускает владелец:

  ```bash
  git push origin main
  ```

- Вернувшись на основной Mac — сначала `git pull --no-rebase origin main`. На нём продолжают работать и
  коммитить другие сессии.
- План дизайна вести в одном месте за раз. Две сессии на двух компьютерах будут править одни и те же файлы
  (`tokens.css`, `components/`).
