# Финансы за период — срез F2: операции, переход к деталям, выгрузка (28.09.2026)

**Основание:** ТЗ владельца «Финансы / Деньги за период» от 27.09.2026, §7 Phase F2; «давай» владельца
28.09 на снимки F1 (стоп-гейт ADR-107). F1 — `plans/finance-f1-2026-09-27.md`. Решение — дополнение F2 к
**ADR-107**.

ТЗ перечисляет в F2 четыре пункта: (1) последние оплаты и возвраты, (2) drill-down по карточкам,
(3) фильтры по способам оплаты, (4) экспорт / сверка / касса. Первые три и экспорт делаются на данных,
которые уже есть. **Сверка и касса не делаются:** «проверка наличных» и закрытие кассовой смены в модели
не существуют — это Q-200, и, скорее всего, правка `DATA_MODEL.md`.

---

## 1. Что есть в данных

- `payments`: способ, сумма, статус (`COMPLETED` / `VOIDED`), `paid_at`, распределения по счетам
  (`payment_allocations`) — через них платёж связан с бронью (одна оплата может лечь на счета нескольких
  броней — редко, но бывает).
- `refunds`: сумма, `created_at`, платёж, с которого вернули (от него — способ), счёт (от него — бронь).
- «Оплачено» и «Возвращено» в итогах F1 считают проведённые платежи по `paid_at` и возвраты по
  `created_at` в границах суток пояса объекта (С-13). Список операций берёт ту же выборку, поэтому
  «Итого» по списку без отборов сходится с плитками.

## 2. Что входит в F2

1. **`GET /finance/operations?from&to[&type][&method][&limit]`** — только чтение, одним SQL:
   оплаты за период (проведённые и аннулированные) и возвраты за период; у строки — время по часам объекта,
   тип, способ, сумма, статус, бронь (первая по номеру и число броней, если их несколько), гость брони.
   Ответ: строки новыми первыми (`limit` по умолчанию 50, не больше 20 000), `total` по отбору,
   суммы по отбору (оплачено — только проведённые, возвращено), числа по способам для чипов.
   `type` — `PAYMENT` / `REFUND`, `method` — один из 9 способов; неверное — 400.
2. **Раздел «Оплаты и возвраты»** (`#operations`) после списка долгов: отбор по типу («Все / Оплаты /
   Возвраты» с числами) и по способу (чипы только тех способов, что были в периоде), строка «N операций:
   оплачено X, возвращено Y», таблица Дата и время / Тип / Бронь / Гость / Способ / Сумма / Статус.
   Возврат — сумма с минусом «−» (DESIGN.md §14); аннулированная оплата — приглушена, «аннулирована»,
   в суммы не входит. Первые 20 строк и «Показать все N».
3. **Переход к деталям:** все четыре плитки — ссылки: «Начислено» → «По видам начислений»,
   «Оплачено» → операции с отбором «Оплаты», «Возвращено» → «Возвраты», «К сбору» → долги (было в F1).
   Способ в таблице «Оплаты по способам» — ссылка на операции этого способа. Строка возвратов в
   «Требует внимания» ведёт к списку возвратов.
4. **Выгрузка CSV** `/finance/export?from&to[&type][&method]` — те же операции и те же отборы, что на
   экране: `;`, UTF-8 с BOM (открывается в Excel), суммы в тенге с запятой, время по часам объекта.
   **Без имён гостей:** файл уходит из системы, бронь по номеру находится в стойке. Если операций больше
   20 000 — отказ со словами «укоротите период», а не обрезанный файл.
