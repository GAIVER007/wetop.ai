# «Обзор бизнеса»: вид единого раздела «Финансы» по макету владельца

Дата: 09.10.2026. Основание: макет владельца («там смотри вот как должен выглядеть раздел финансов
это у нас как главная типа») поверх слияния ADR-152. Макет = утверждённый визуальный концепт
(как «да давай норм» 05.10); числа с макета вымышленные и в приложение не переносятся, все значения
считаются из существующих API.

## Состав экрана (сверху вниз)

1. Заголовок «Обзор бизнеса», подзаголовок «Ключевые показатели, деньги, загрузка и задачи в одном
   месте»; справа период: отрезок датами («01.10.2026 → 31.10.2026»), ссылки «Сегодня / 7 дней /
   Месяц» (7 дней = прежняя «Неделя»: последние семь дней) и «Обновить данные». Свои даты и
   «Вчера / Прошлый месяц» остаются в фильтрах ниже.
2. Семь плиток `Stat`: Выручка за период (= Поступления кассы: `paidMinor + incomeMinor`), Чистая
   прибыль (= Поступления − Расходы, подсказка «поступления минус расходы»), Загрузка сегодня
   (к вчера, п.п.), Заезды сегодня (к вчера), Выезды сегодня (к вчера), К оплате / Долги
   (= остаток по броням периода, `/finance/debts`), Свободно мест (из всего фонда). Сравнения:
   суммы к прошлому отрезку той же длины (второй вызов `/finance/operations`, только итоги),
   день к вчера (`/desk/dashboard` за вчера). «нет базы для сравнения» остаётся честным состоянием.
3. «Загрузка и операционные показатели»: кольцо «Загрузка сегодня», Занято / Свободно / Всего мест,
   «Прогноз загрузки на 7 дней» столбиками с процентами (прежний блок владельца), «Подробнее» в
   аналитику загрузки.
4. «Финансовый обзор» (прежние testid сводки кассы сохраняются): Поступления и Расходы за период с
   дельтами, «Движение денег по дням» двумя рядами столбиков из строк `/finance/operations`
   (лимит 500; если лента обрезана, под графиком честная приписка), «Остаток на счетах»
   (`cash.totalMinor`) со списком способов.
5. «Поступления по способам оплаты»: `ShareBar` по `paymentsByMethod` из `/finance/report`
   (оплаты броней, как в «Обзоре»).
6. «Сегодня»: дата; плитки Заезды, Выезды, Ожидают заселения, Ожидают выезда (`/desk/today`);
   строка «Брони без оплаты N · сумма» (долги периода) и «К оплате у выезжающих» (прежний долг дня).
7. «Что требует внимания»: строки с числами — Брони без оплаты, Просроченные платежи, Низкая
   загрузка (дни прогноза ниже 40 %), Задачи (`tasksOpen`); кнопка «Все задачи» открывает прежнюю
   очередь «Требуют внимания» панелью (логика A3 сохраняется целиком).
8. «Последние операции»: последние строки общей ленты (дата, тип, описание, сумма со знаком, способ,
   статус), «Все операции» ведёт к прежней ленте с фильтрами. Колонки «Источник» из макета нет:
   в ответе операций источника нет, добавлять API этим планом не разрешено.
9. Ниже без изменений: фильтры операций и свёрнутые «Отчёты и управление» (вкладки, касса, CSV).

## Умолчания

- Надписи по-русски и по DESIGN.md: без «vs.» (пишем «к прошлому периоду», «к вчера»), без стрелок
  в конце ссылок («Подробнее», «Все операции» словами).
- Плитки — примитив `Stat` с необязательной иконкой в углу (дополнение DS1c, строка в DESIGN.md
  §8.2); заливки и градиенты не появляются.
- Цвета графиков из токенов: прогноз `--chart-1`, деньги `--success` / `--danger` (как у сумм
  кассы); точки способов - декоративный цикл токенов, смысл держат подписи.
- Бюджет `requests.spec` для `/finance`: 15 путей (+ прошлый период операций, + вчерашний день
  dashboard); повторных GET нет.
- Высота: раздел прокручивается на компьютере намеренно, как «Отчёты» (уже решено в ADR-152 для
  раскрытых вкладок; теперь и свёрнутый вид длиннее экрана).

## Чего не делаем

API, модель, миграции, права, финансовые формулы сервера; салон и ресторан; `release`. Меню не
меняется (вкладка так и называется «Финансы», первая; экран внутри называется «Обзор бизнеса»).

## Проверка

Контракт `tests/ui/finance-home-merge.spec.ts` расширяется под макет и сначала красный; правка
затронутых спеков (заголовок, имена областей, плитки); наборы ui (частями, стенд в одно окно весь
набор не держит), unit, typecheck, lint через `test:record`; суммы и счётчики сверяются с fixture
API. Коммит своих файлов, push, PR #321 обновляется.
