# Срез 5: фискальный чек по запросу гостя (K2; DATA_MODEL §25, ADR-141)

## Решение владельца
03.10.2026: «фискальный чек выдаём по запросу». Значит, чек не пробивается автоматически на каждую оплату. Его пробивает касса объекта, когда гость попросил.

## Что сделано
- Таблица `fiscal_receipts` (миграция `20261003000046_fiscal_receipts` с `down.sql`, RLS по объекту): платёж, номер чека из кассы, когда, кто. Один чек на платёж.
- `POST /finance/payments/:id/receipt` (право `desk`): номер 1–64 знака одной строкой (`parseReceiptNumber`), только проведённый платёж своего объекта. Повтор даёт 409 под блокировкой строки платежа, уникальный индекс страхует. Пишется в журнал `finance.receipt.issued`.
- «Счета» брони: колонка «Чек» у платежа: номер или форма «номер чека · чек выдан».

## Чего нет и почему
- Облачная касса (Webkassa, re:Kassa и т. п.) не подключена: нет документации оператора в `/docs` (Q-259, AGENTS.md §5). Адаптер добавит внешний id и состояние отправки к той же строке.
- Чек возврата пробивается в кассе; отметки возврата в этой версии нет.
