# Срез 1 плана развития: письмо гостю с подтверждением и языки виджета (03.10.2026)

Основание: ADR-144, план `plans/wetop-unified-roadmap-2026-10-03.md` (H1, H6). Модель данных не меняется.

## Что делается

1. **Язык гостя в брони с сайта.** `parseBookingRequest` принимает `lang` (ru, kk, en, zh; «kz» → kk, «EN-us» → en,
   незнакомый → ru, отказа нет: бронь важнее языка письма).
2. **Письмо с подтверждением** `mail.bookingConfirmationLetter` (`packages/integrations/src/mail/booking-letter.ts`):
   простой текст без ссылок на четырёх языках, номер, даты и время заезда и выезда, категория, гости, ночи, сумма и
   «оплата при заселении». Казахский и китайский тексты проверяет носитель языка до выкладки.
3. **Отправка из брони с сайта.** `WebBookingService.book` после записи брони шлёт письмо на адрес из формы через
   отправитель `BOOKING_MAILER` (тот же сервис писем, что у приглашений; без настроенной почты письма нет).
   Адрес не сохраняется: в бронь пишется псевдоним (ADR-018), в журнале сайта только `confirmationEmail`
   (`sent`, `none`, `failed`). Сбой письма бронь не роняет (аудит 26.09, С-33).
4. **Языки виджета.** Словарь ru, kk, en, zh в `widget.js`, кнопки RU, KZ, EN, 中文 над формой, язык по умолчанию
   из `data-lang` (иначе русский: язык браузера не угадываем), смена языка пересобирает форму с сохранением дат,
   гостей и промокода; язык уходит в `POST /w/book`. Подсказка у поля почты о письме. Ответы сервера об ошибках
   остаются на русском.
5. **ИИ-продавец.** Языки по умолчанию у нового профиля: русский, казахский, английский, китайский (домен и бот).
6. **Стойка.** Вкладка «Бронирование» и окно установки виджета говорят о языках, `data-lang` и письме.
