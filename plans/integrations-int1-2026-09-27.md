# «Интеграции» v2 — срез INT1: Integration Hub (27.09.2026)

**Основание:** ТЗ владельца «Интеграции v2» от 27.09.2026 (29 пунктов, передано облачной сессии задачей,
ветка `claude/integrations-screen-restructure-e51aay`). ТЗ задаёт порядок: INT1 — только представление,
после него стоп и снимки; INT2 (настройки Channex: переподключить, отключить) — только после отдельного «да».

Решение записано как **ADR-107**.

## 1. Аудит перед правкой (§27 ТЗ)

| Вопрос | Ответ по коду |
|---|---|
| Что сегодня считается интеграцией | Экран `/connections` показывал три разных вещи: панель «Данные проекта» (`/system/connection`: источник данных, Supabase, число мест, категорий, броней, тарифов, услуг, сайтов), Channex (`/channels/channex/connection` + `/webhook/status`) и «Сайт и бронирования» (`/analytics/sites`) |
| Откуда здоровье Channex | `ChannelConnectionService.status()` (`apps/api/src/channels/connection.ts`): живой `GET` объекта в Channex при каждом открытии (без синхронизации и импорта), состояния `READY / NO_KEY / NO_MAPPING / MAPPING_MISMATCH / DENIED / NOT_FOUND / RATE_LIMITED / UNREACHABLE`; время последнего webhook и импорта; число сопоставленных категорий и тарифов. Отдельно — статус webhook (включён, отвечает ли адрес) и сводка очереди в каналы |
| Ключи — на установку или на объект | На установку: `CHANNEX_API_KEY`, `CHANNEX_PROPERTY_ID`, `CHANNEX_API_BASE_URL` в env сервера. Раздел открыт только организации подключённого объекта и главному администратору (`IntegrationOwnerGuard`, `ChannelOperatorInterceptor`, ADR-095); остальным API отвечает 403 |
| Что такое `site` в базе | Таблица `sites` (DATA_MODEL §11): счётчик посещений и виджет бронирования на сайте объекта — собственный модуль WETOP (ADR-025, ADR-026), не внешний сервис. Настраивается в «Настройки → Сайт» (`/analytics/setup`), отчёт — «Продажи → Аналитика сайта» |
| eQonaq в рабочем пути | Нет. `packages/integrations/src/eqonaq` — порт без реализации (документации нет, AGENTS.md §5); владелец отложил eQonaq 11.09 (Q-122). В коде только требование гражданства при заселении |
| Где Exely | Код клиента Exely удалён из рабочего пути (ADR-073); интеграцией не является |
| Какие действия с соединением есть | Только на «Каналах продаж» (`/channels`, группа «Настройка подключения»): создать объект в Channex, зарегистрировать и проверить webhook, полная выгрузка. Переподключить и отключить — эндпоинтов нет |
| Какие ключи пользователь может менять | Никакие: ключ задаётся на сервере, поля в интерфейсе нет и не будет в INT1 |
| Что считается успешным соединением | `state = READY` — объект в Channex прочитан этим ключом только что |
| Что только для поддержки | Среда Channex, ID объекта в Channex, время последнего webhook и импорта, время проверки |

## 2. Что входит в INT1

- Экран `/connections` («Настройки → Интеграции»): заголовок «Интеграции», подзаголовок «Подключения внешних
  сервисов для {объект}.», вкладки «Подключённые N / Доступные N» (`?tab=available`, `.settings-tabs`).
- Панель «Данные проекта» с экрана убрана. Диагностика базы переехала в «Платформа → Организации», раздел
  «Состояние системы» — только главному администратору (§1, §13 ТЗ). Часовой пояс и валюта и так видны в
  «Настройки → Гостиница».
- «Сайт и бронирования» убран: это модуль WETOP (§12, §26 ТЗ; аудит выше).
- Глобальная «Проверить соединение» из шапки убрана; проверка — кнопкой на карточке (§9).
- Карточка Channex (подключённая): название, «Менеджер каналов», состояние, назначение одной строкой, причины
  «требует внимания» со ссылкой к месту исправления, объект, последний обмен словами, сколько сопоставлено;
  действия «Проверить соединение», «Настройки» (группа «Настройка подключения» на `/channels`), «Каналы продаж».
  Очередь, события и сопоставления построчно не повторяются (§6).
- «Технические детали» свёрнуты и видны только владельцу организации и главному администратору (§23).
- Карточка Channex в «Доступных» — когда интеграция установки не у этой организации (403) или ключа нет:
  «Не подключено» и как подключить (поддержка WETOP), без кнопки, которая ничего не делает (§10). В «только
  чтении» — «Подключение — после оплаты подписки» (§20).
- Пустые состояния обеих вкладок (§19).

## 3. Правила состояния (§14–16 ТЗ) — `apps/web/src/lib/integrations.ts`

| Сигнал | Состояние |
|---|---|
| API ответил 403 или `NO_KEY` | не подключено |
| Запрос не прошёл (сеть, 5xx) | неизвестно, «Не удалось проверить Channex» |
| `NO_MAPPING` | требует внимания, «Объект в Channex не создан» → настройка |
| другое состояние не `READY` | требует внимания, причина словами API |
| `READY`, но ни одной сопоставленной категории | требует внимания → сопоставление |
| webhook не зарегистрирован или выключен / адрес не отвечает | требует внимания |
| ошибки отправки в очереди / очередь стоит ≥ 10 мин (порог «Каналов продаж») | требует внимания → очередь |
| webhook или очередь не проверены | неизвестно (если нет проблем) |
| всё остальное | работает, без перечня зелёных пунктов |

Окна свежести «по времени последнего обмена» нет: у гостиницы бывают тихие часы без броней и без изменений
цен, и старое время обмена само по себе не неисправность. Состояние держится на живых сигналах.

## 4. Чего INT1 не делает

- Не вводит таблицу `IntegrationConnection`, не переносит ключи (§18).
- Не добавляет переподключение, отключение, изменение ключей, аудит этих действий — это INT2.
- Не рисует eQonaq, WhatsApp, платежи и прочие карточки: в рабочем пути их нет (§10).
- API и модель данных не меняются. Подставной API UI-тестов получил режимы Channex (`channex: ok / attention /
  foreign / no-key`).

## 5. Открыто для владельца

- «Несколько интеграций» на снимке показать нечем: реальная интеграция одна. Сетка карточек под несколько готова.
- Показывать ли eQonaq в «Доступных» как «Скоро» — решение владельца (Q-122: отложен без срока).
- Scope «Объект: {имя}» берётся из настроек объекта вошедшего. Главный администратор чужой организации увидит
  имя своего объекта, а не Luxx (интеграция одна на установку) — поправится в INT4 вместе с владением.
