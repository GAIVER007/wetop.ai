# «Интеграции» v2 — срез INT2: страница настроек Channex (28.09.2026)

**Основание:** ответ владельца 28.09.2026 на снимки INT1: «INT1 принимаю. Начинай INT2 — настройки Channex. Слияние
INT1 в `main` считаю подтверждением текущего визуального направления». Там же Q-122 закрыт: eQonaq в «Доступных» не
показывать даже с пометкой «Скоро». Решение — **ADR-120**. После INT2 — стоп и снимки; INT3 только после отдельного «да».

## 1. Аудит перед правкой

| Вопрос | Ответ по коду |
|---|---|
| Что уже показывает соединение Channex | Карточка на «Интеграциях» (INT1, ADR-116) и вкладка «Каналы продаж → Подключения» (ADR-112): состояние объекта, webhook, среда, ID объекта, кнопки настройки для владельца |
| Какие действия с соединением есть в API | `GET /channels/channex/connection` — живая проверка объекта, только чтение. `POST …/setup` (создать объект и категории), `POST …/webhook/register`, `POST …/webhook/test` — на «Каналах продаж → Подключения», только владельцу (ADR-112). `POST …/sync` (полная выгрузка) — массовая синхронизация, остаётся в «Каналах продаж» |
| Переподключить, отключить, сменить ключ | Эндпоинтов нет. Ключ — `CHANNEX_API_KEY` в env сервера установки, меняет поддержка WETOP. **Разрыв зафиксирован, кнопок не рисуем** |
| Дата подключения | В ответе API нет (строки сопоставления без `createdAt`). Не показываем: добавлять поле ради подписи — правка API, а дата первого сопоставления у Luxx — дата переезда каналов, а не подключения |
| Последняя успешная проверка | Не хранится: проверка идёт при открытии страницы. Показываем «проверено только что, в 14:22» при `READY` и «проверка не прошла» с причиной иначе |
| Последний обмен | Самое позднее из последнего webhook, последнего импорта и последней отправки в каналы — всё в ответах API |
| Категории N из M | Сопоставленные категории — строки `/channels/channex/mapping` с `providerRoomTypeId`; все категории — сводка фонда `/inventory/summary`. Оба ответа есть, «из M» подтверждено |
| Тарифы N из M | Знаменателя нет: сопоставление тарифа — пара «категория × тариф», а тарифы без продаж сопоставлять не нужно. Показываем только «сопоставлено N» |
| Webhook | `registered && active`, проба адреса `callbackReachable`, время пробы `callbackCheckedAt` |

## 2. Что входит в INT2

- Страница `/connections/channex`: заголовок «Channex», хлебная крошка «Интеграции», под заголовком «Менеджер каналов
  для {объект}» и бейдж состояния (тот же расчёт, что у карточки).
- Причины «требует внимания» — сверху, со ссылкой к месту исправления.
- «Соединение»: состояние, объект, ключ доступа (задан на сервере / не задан — без значения), проверка, последний обмен.
- «Состояние»: webhook (включён и отвечает / не отвечает / не включён / не проверен), категории N из M, тарифы
  «сопоставлено N», последний обмен.
- Действия: «Проверить соединение» (только чтение, доступно и в «только чтении») и «Каналы продаж».
- «Управление подключением» внизу: переподключение, смена ключа и отключение — через поддержку WETOP; настройка
  webhook и объекта в Channex — ссылкой на «Каналы продаж → Подключения» (кнопки там, у владельца).
- «Технические детали» — свёрнуты, владельцу и главному администратору: среда, ID объекта, время последнего webhook,
  импорта, отправки в каналы, пробы webhook.
- Не подключено (403 / нет ключа): бейдж «Не подключено» и как подключить, без ссылки в «Каналы продаж».
- Новое правило состояния: сопоставлены не все категории — «требует внимания», «Не сопоставлено категорий: K из M» →
  «Каналы продаж → Сопоставление» (пункт «mapping incomplete» из ТЗ INT1 §14). Карточка на «Интеграциях» считает так же:
  один загрузчик на обе страницы.
- Кнопка «Настройки» на карточке ведёт на `/connections/channex`.

## 3. Чего INT2 не делает

- Не переносит очередь, брони из каналов, редактор сопоставлений, события, массовую выгрузку и отчёт по источникам.
- Не переносит кнопки настройки webhook и объекта с «Каналов продаж → Подключения»: их место задано ADR-112.
  Вопрос, где им жить, — **Q-213**.
- Не показывает ключи, секреты, адрес webhook и сырые ответы Channex.
- Не меняет API, модель данных, хранение ключей и владение интеграцией. Новой логики «только чтения» нет: на странице нет
  изменений, а проверка — чтение.
