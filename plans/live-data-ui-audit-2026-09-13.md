# Реальные данные и проверка интерфейса

Поручение владельца: убрать демонстрационные цифры, связать интерфейс с реальными данными
Channex, проверить каждый раздел и кнопки, сократить текст и выровнять блоки.

1. Удалить тестовый API из обычного запуска; запретить случайное использование fixture-сервера
   вне явно включённых UI-тестов. Проверить чтение и команды, ошибки и пустые ответы.
2. Показать проверяемое состояние соединения: PMS/БД, доступ Channex, сопоставление объекта,
   webhook, входящие события. Проверка только чтением; не запускать production ARI/тестовые брони.
3. Сократить пояснения и повторяющиеся подписи; справочную информацию поместить в раскрываемые
   блоки. Сохранить смысл денежных показателей, ошибки и обязательные поля. Выровнять формы,
   действия, сводки и страницы разделов на desktop/mobile.
4. Проверить переходы, поиск, фильтры, команды, состояния ожидания, ошибки и повторные действия
   по всем реализованным разделам. Зафиксировать отсутствующие возможности отдельно от ошибок.
5. Выполнить записанные unit/typecheck/lint/UI-проверки и сборку, push в текущий PR.

Начальное состояние проверено: localhost:3000 работал с `tests/ui/fixture-api.ts` на 4311.
В этой копии нет .env, DATABASE_URL, CHANNEX_API_KEY или рабочего API на 3001. Запрошен адрес
рабочего backend либо путь к настроенной копии. Секреты не запрашиваются в чат и не выводятся.
До предоставления подключения не заявлять live-проверку Channex. Не удалять реальные данные:
«обнулить» относится к демонстрационным показателям, а не к броням/счетам объекта.

Результат: [аудит и границы](../reports/hostel-frontend/live-data-audit-2026-09-13.md).
Код, проверки и сборка завершены. Реальное подключение остаётся за отсутствующим адресом
backend/окружением; никаких production-команд или удаления рабочих данных не выполнялось.
