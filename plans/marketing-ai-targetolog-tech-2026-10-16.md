# ИИ-таргетолог: технический проект (16.10.2026)

**Статус: модель §3 (3.1–3.5) утверждена владельцем 16.10.2026 (DATA_MODEL §57, ADR-MKT-LAUNCH), предел бюджета
«остаток плана / дни»; 3.6 и WhatsApp (§8) решаются позже.**
Продолжение `plans/marketing-ai-targetolog-wetop-2026-10-16.md` (разбор связки n8n `AI-targetolog1` и ТЗ владельца,
решения: запуск сразу `ACTIVE`, модель WETOP, вход с экрана WETOP). Здесь: как это устроено в коде, по слоям, с
моделью, маршрутами, отказами, тестами и порядком PR.

## 1. Принципы

1. **Один путь запуска.** Экран, позже Telegram и авторежим зовут один сервис API; второго «упрощённого» пути нет.
2. **Код Meta только в `packages/integrations/src/meta`** (ADR-004), только по выжимкам `docs/meta/*.md` (AGENTS.md §5).
   Домен не знает слов `adset`, `act_`, `image_hash`.
3. **Правила (что можно запускать, что делать по KPI) в домене**, чистыми функциями без сети и базы: их проверяют unit
   тесты, а не живой кабинет.
4. **Каждый шаг в Meta оставляет след** (ADR-007): что создано, номер в Meta, попытка, ошибка. Сбой на середине не
   оставляет работающей рекламы, о которой WETOP не знает.
5. **Один ключ на кабинет.** Перебора чужих ключей и общего ключа из окружения нет (см. разбор ТЗ §3).
6. **ИИ советует, код решает.** Ответ модели проходит схему и правила домена; бюджет, город, возраст, цель после
   проверки, а не «как сказала модель».

## 3. Модель данных: предложение §57 (нужно «да» владельца)

Новый раздел `DATA_MODEL.md` §57, версия v2.40. Миграции 126/127 (+ `down.sql`), права отдельной миграцией, RLS через

### 3.1 Активы по умолчанию у подключения (поправка §55)

`marketing_ad_connections`: `page_id` varchar(40) NULL, `instagram_user_id` varchar(40) NULL, `pixel_id` varchar(40)
NULL. Это выбор по умолчанию для мастера, не ключи и не секреты; меняются в мастере («запомнить»).

### 3.2 `marketing_ad_creatives`: файл креатива

`id`, `location_id` FK, `kind` `MarketingCreativeKind` (`IMAGE` | `VIDEO`), `storage_key` varchar(300), `mime`
varchar(60), `size_bytes` int, `sha256` char(64), `width`, `height` int NULL, `duration_ms` int NULL,
`uploaded_by_id` FK users SET NULL, `created_at`. UNIQUE (`location_id`, `sha256`): тот же файл второй раз не грузится.
Файл в закрытом хранилище `SITE_ASSET_STORAGE`, как чеки §51; наружу только через API с правом. Пределы: фото JPEG,
PNG, WebP до 8 МБ; видео MP4/MOV до 200 МБ (точные пределы Meta из `docs/meta/create.md`).

Номер картинки или видео в Meta здесь не хранится: он свой у каждого кабинета и лежит в шаге запуска (3.4).

## 5. Запуск: порядок, отказы, компенсация

```
POST /launches
 1. домен: проверка настроек (цель ↔ куда ↔ активы, бюджет > 0 и ≤ плана канала Meta на месяц / дней, город в стране)
 2. INSERT launch (RUNNING, MEDIA); при повторе request_key вернуть прежний id
 3. ответ 202 { id }; дальше в фоне, под замком подключения (один запуск кабинета за раз)
 4. MEDIA     фото → adimages (hash);   видео → advideos, ждать готовности (опрос, предел 10 мин)
 5. CAMPAIGN  campaigns   objective по цели, special_ad_categories [], status ACTIVE
 6. ADSET     adsets      daily_budget, optimization_goal, destination_type, promoted_object, targeting, ACTIVE
 7. CREATIVE  adcreatives object_story_spec, CTA, url_tags (UTM с {{ad.id}})
 8. AD        ads         adset_id, creative_id, ACTIVE
 9. DONE      marketing_campaigns (external_id, источник META) ← связь; SUCCEEDED
```

- **Повтор шага:** коды Meta 1, 2, 4, 17, 613 повторяются до 3 раз с паузой 2, 8, 30 с; 190, 10, 200–299 и ошибки
  содержания сразу `FAILED` словами Meta (`error_user_msg`, иначе `message`).
- **Компенсация:** если упал шаг после `CAMPAIGN`, созданная кампания переводится в `PAUSED` (шаг `ROLLED_BACK` в
  журнале). Удалять не нужно: в Ads Manager остаётся видно, что пытались создать. Кампания `ACTIVE` без объявления денег
  не тратит, но `PAUSED` убирает и это сомнение.
- **Обрыв процесса:** при старте API запуски `RUNNING` старше 15 минут закрываются `FAILED` «прервано перезапуском»
  с той же компенсацией по известным номерам.
- **Почему фон, а не один долгий запрос:** видео в Meta обрабатывается минутами; запрос из браузера столько не живёт.
  Отдельной очереди не заводим: запуски редкие (единицы в день), хватает фоновой задачи процесса и строки в базе.
  `ponytail:` один процесс API; при нескольких экземплярах замок подключения переходит в `pg_advisory_lock`.
- **Сразу `ACTIVE`** (решение владельца). Перед кнопкой экран показывает сумму «до N ₸ в день, до M ₸ за месяц» и
  кнопку «Остановить» после запуска.

### 5.1 Что показала документация (`docs/meta/create.md`, `docs/meta/whatsapp-ads.md`)

То, на чём обычно падают самодельные запуски; код делает так с первого PR:

- кампания: `special_ad_categories: []` и с v24.0 `is_adset_budget_sharing_enabled: false` (бюджет на группе), иначе
  ошибка 4834011;
- группа: возраст и пол не по умолчанию требуют `targeting_automation.advantage_audience`; при `1` нельзя `age_max`,
  а `age_min` только 18–25. Поэтому ИИ предлагает возраст, а человек выбирает «Широко (Advantage+)» или «Точно»;
- `promoted_object` после создания не меняется; для пикселя нужен `conversion_domain`;
- креатив: `instagram_user_id` (старое `instagram_actor_id` закрыто), Messenger кнопкой `MESSAGE_PAGE`; отказ от
  улучшений Advantage+ по каждой функции, спорные места проверяются `validate_only` до настоящего вызова;
- бюджет группы меняется не чаще 4 раз в час (613/1487632): авторежим этап 5 укладывается с запасом;
- реклама в WhatsApp: в `promoted_object` только `page_id`, номер берётся привязанный к странице;
- **тенге:** в таблице единиц Meta KZT нет, ошибка в 100 раз возможна. До ответа (Q-MKT-KZT) кабинет в тенге получает
  отказ словами, кабинеты в USD и других валютах из таблицы запускаются.

## 6. Предложение ИИ: контракт `ad-proposal/0`

По образцу `bar-receipt-scan/0` (`docs/bar/receipt-scan-v0.md`): платформа зовёт бота `POST /internal/ad-proposal`
служебным ключом, без организации и агента, ключ модели только платформы, без состояния.

Запрос:

```json
{
  "schemaVersion": "ad-proposal/0",
  "requestId": "uuid",
  "creative": { "kind": "IMAGE", "mediaType": "image/jpeg", "dataBase64": "..." },
  "frames": [],
  "offer": "до 500 знаков от человека",
  "goal": "MESSAGES",
  "destination": "WHATSAPP",
  "business": { "vertical": "HOTEL", "name": "...", "city": "Алматы", "country": "KZ", "language": "ru" },
  "history": [{ "goal": "MESSAGES", "spend": "12000", "leads": 9, "ageMin": 25, "ageMax": 45, "text": "..." }],
  "budgetRemainingTokens": 60000
}
```

`frames`: для видео 3–4 кадра JPEG, снятые в браузере (как в ТЗ §4), само видео модели не уходит.
`history`: до 10 прошлых запусков филиала с результатами из §53/§55; это данные, не инструкции.

Ответ `spec`:

```json
{
  "headline": "до 40 знаков",
  "primaryText": "до 500 знаков",
  "description": "до 30 знаков",
  "cta": "WHATSAPP_MESSAGE",
  "ageMin": 25, "ageMax": 54,
  "genders": [],
  "interests": ["до 5 слов"],
  "welcomeMessage": "до 200 знаков",
  "iceBreakers": ["до 2 вопросов"],
  "notes": ["почему так"]
}
```

Что делает платформа (`domain/marketing/ad-proposal.ts`): обрезает и чистит длины; возраст в 18–65 и `ageMin ≤ ageMax`;
`cta` только из списка, допустимого для `destination`; интересы пока только показываются человеку (подбор по каталогу
Meta отдельным шагом); город и бюджет ИИ не выбирает: город из филиала или поиска, бюджет из плана. Правила «Креатора»
и «Таргетолога» из связки (прямой отклик, фильтр платёжеспособности, широкая аудитория, приветствие и две подсказки)
переносятся в промпт бота словами, без чисел денег.

Ошибки как у скана: бот недоступен, `MODEL_UNAVAILABLE`, `TIMEOUT` → 503 «ИИ сейчас недоступен, заполните сами»;
`SCHEMA_INVALID` → 422. Мастер работает и без ИИ: поля можно заполнить руками.

## 7. Мастер на экране

1. **Кабинет и куда вести**: подключённый кабинет; цель плитками (Сообщения в WhatsApp, Instagram Direct, Messenger;
   Заявки через форму; Сайт); страница, Instagram, форма или адрес сайта из активов; чего не хватает, сказано словами
   и ссылкой на Meta (ТЗ §14).
2. **Креатив**: фото или видео (кадры видео снимаются в браузере для ИИ); пара фраз об оффере; «Подготовить с ИИ».
3. **Предложение**: текст, заголовок, призыв, возраст, пол, город, бюджет в день и предел из плана; всё правится;
   превью объявления.
4. **Запуск**: сводка «до N ₸ в день», кнопка «Запустить кампанию», затем экран шагов с опросом и «Остановить».

## 8. WhatsApp: как связывать (решение позже)

| Вариант | Как | За | Против |
|---|---|---|---|
| **А. Свой WhatsApp WETOP** (рекомендую) | реклама «в WhatsApp» ведёт на номер, уже подключённый к ИИ-продавцу через официальный API Meta (С3). Первое сообщение из рекламы несёт `referral` с номером объявления; бот передаёт его платформе вместе с обращением | атрибуция до объявления без кодовых слов; ИИ-продавец отвечает сразу и доводит до брони; один номер, официальный канал, без риска блокировки | номер должен быть привязан к странице Facebook; у организации должен быть подключён WhatsApp в WETOP |
| Б. Green API (как в ТЗ §9) | сторонний шлюз к обычному WhatsApp, вебхук в WETOP | быстро, любой номер | неофициальный доступ, риск блокировки номера; переписка через третью сторону (персональные данные, ADR-009); второй канал рядом с ботом |
| В. Кодовое слово (как в n8n) | ссылка `wa.me` с текстом-кодом, человек вручную видит код | ничего подключать | атрибуция ломается, если человек стёр текст; ИИ-продавец не участвует |

Выжимка `docs/meta/whatsapp-ads.md` подтверждает вариант А: в сообщении из рекламы приходит `referral` с
`source_id` (номер объявления, при `source_type = ad`) и `ctwa_clid`; повторится ли он в следующих сообщениях, не
обещано, поэтому бот сохраняет его при первом приёме и закрепляет за перепиской. Отправка событий обратно в Meta
(Conversions API) требует права `whatsapp_business_manage_events`. Для варианта А нужно: чтение `referral` в
`apps/ai-seller/src/channels/whatsapp.py` (сейчас бот берёт только текст), передача номера объявления в платформу и
поле у обращения. Решение владельца нужно до этапа 4; этапы 1–3 от него не зависят: реклама в WhatsApp запускается
на номер, привязанный к странице, при любом варианте.

## 9. Авторежим по KPI (этап 5)

- **Когда:** после ночной сверки (§55), раз в сутки; по кнопке «Оценить сейчас».
- **Данные:** расход и заявки за 3 дня по группам и объявлениям (отчёт `level=adset` и `level=ad`, выжимка есть).
- **Правила** (`domain/marketing/ad-kpi.ts`, чистая функция): CPL < целевого и заявок не меньше 3 → бюджет группы +20%
  (не выше предела); между целевым и максимальным → ничего; > максимального → бюджет −30% или пауза объявления;
  расход без заявок больше 1,5 × максимального CPL → пауза объявления. Все числа: настройки, а не константы.
- **Режимы:** `ADVISE` (только список советов на экране, человек жмёт «Применить») по умолчанию; `AUTO` выполняет сам.
  Каждое действие в журнале, откат кнопкой (обратное действие со ссылкой на исходное).
- **Ограничители:** не больше одного изменения бюджета группы в сутки; суммарный дневной бюджет кабинета не выше
  плана канала (§52).

## 10. Безопасность

- Ключ кабинета только в API, шифром (§55); в ответах и журнале его нет; ошибки Meta очищаются от адресов с ключом.
- Запуск и остановка: право `ads_launch` и филиал вошедшего (RLS); кабинет того же филиала (триггер).
- Бюджет проверяется сервером до Meta, а не только экраном.
- Текст оффера и подпись креатива: данные для модели, инструкции из них не исполняются (слой защиты бота).
- Файл креатива: проверка типа по содержимому, предел размера, закрытое хранилище.
- Вебхуки (этап 4, WhatsApp и заявки форм): подпись `X-Hub-Signature-256` секретом приложения, без подписи 403
  (бот уже так делает для WhatsApp).
