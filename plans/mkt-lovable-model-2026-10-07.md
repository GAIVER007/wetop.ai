# Как работает Lovable и какую модель взять для WETOP

07.10.2026, поручение владельца: «внимательно разберись, как Lovable создаёт сайты, возьми оттуда механику и пойми,
как сделать такую же модель». Это разбор и предложение, не код. Источники: публичная документация и блог Lovable,
руководства пользователей (список в конце). Сам сайт lovable.dev из облачной сессии закрыт политикой сети, поэтому
разбор по документации и описаниям, без собственного прохода по интерфейсу.

## 1. Механика Lovable по шагам

| Шаг | Что видит человек | Что происходит внутри |
|---|---|---|
| 1. Идея | Большое поле «Got an idea?» на главной, кнопка отправки, выбор режима, вложения (картинка, макет) | Создаётся проект; текст становится первым сообщением чата |
| 2. Первая сборка | Слева чат с ходом работы ИИ, справа живой превью, который появляется по мере сборки | Агент пишет код: React + Vite + Tailwind + shadcn/ui, TypeScript; каждое действие ИИ сохраняется снимком версии |
| 3. Правка словами | Пишет в тот же чат «сделай шапку темнее» | Режим Build: агент меняет код и проверяет результат; новый снимок версии |
| 4. Правка с прицелом | В превью «Select» (клавиша S): тычет в элемент, пишет, что поменять; можно выбрать несколько | Запрос ИИ ограничен выбранным элементом: меньше «поверхность правки», меньше поломок |
| 5. Правка без ИИ | «Visual edits»: выбрал элемент, меняет текст, цвет, отступы, шрифт в боковой панели (как в Figma); правка текста прямо на странице (T) | Меняется код напрямую, без вызова модели (дешевле и точнее) |
| 6. Режимы | Chat (обсудить, ничего не меняет), Plan (ИИ пишет план, человек правит его и утверждает), Build (делает) | Один разговор на все режимы; Plan перед большими изменениями |
| 7. Знания | «Knowledge»: постоянные правила проекта и рабочего пространства | Подмешиваются к каждому запросу агента |
| 8. История | История версий: посмотреть любую, вернуться, «закладка» на удачной версии | Снимок после каждого действия ИИ; откат это новое состояние, а не удаление истории |
| 9. Публикация | «Publish»: адрес на поддомене Lovable, свой домен (автоматически или DNS вручную, нужен платный план) | Сборка и выкладка отдельно от правок: правки не попадают наружу до повторной публикации |
| 10. Лимиты | Кредиты на сообщения; часть правок бесплатна (текст на странице, Chat) | Дорогое (ИИ) отделено от дешёвого (прямые правки) |

Главные принципы: (1) один экран «чат слева, живой сайт справа»; (2) каждое действие ИИ даёт версию, к которой можно
вернуться; (3) чем уже правка (выбранный элемент), тем надёжнее; (4) прямые правки без ИИ для мелочей; (5) публикация
отдельным явным шагом.

## 2. Что из этого уже есть в WETOP (MKT3–MKT9)

| Механика Lovable | WETOP сейчас |
|---|---|
| Поле «опишите идею» | Окно «Какой сайт сделать?» (MKT9): текст, примеры, «Создать сайт», шаги создания |
| Первая сборка ИИ | Первая версия по брифу филиала (MKT6) плюс пожелания из окна |
| Правка словами (Build) | «Что изменить с помощью ИИ?» → `PATCH`, новая версия |
| Select элемента + просьба | «Изменить эту секцию с ИИ» → `SECTION`: меняется только выбранная секция, платформа это доказывает |
| Visual edits без ИИ | Формы редактора по каждой секции (текст, вид, кнопки, картинки, порядок), без ИИ и без расхода |
| Снимок после каждого действия ИИ | Каждое сохранение и каждая правка ИИ это неизменяемая версия |
| История и возврат | «История»: предпросмотр, сравнение словами, «Восстановить как черновик» |
| Knowledge | Бриф филиала (данные гостиницы) подмешивается к каждому запросу; правила в коде |
| Publish, свой домен | Публикация, пауза, откат (MKT7); свой домен в MKT10 |
| Кредиты | Дневной бюджет токенов организации (Q-274) |

## 3. Чем WETOP намеренно отличается

Lovable генерирует **код**. WETOP генерирует **документ сайта** (`SiteSpec`), который показывает общий рантайм из
проверенных блоков (ADR-149, вариант B). Это не недостаток, а условие продукта для гостиницы:
- бронь, цены «от», свободные места и аналитика это живые блоки WETOP, а не код, который ИИ может сломать;
- ИИ не может вставить чужой скрипт, форму сбора карт или выдуманный телефон: платформа проверяет каждую версию;
- сайт работает быстро и одинаково у всех клиентов, обновления блоков доходят до всех сразу.

Поэтому «правка кода» у нас заменена «правкой документа», а всё остальное поведение Lovable повторяется.

## 4. Чего не хватает до ощущения Lovable (предложение, по порядку пользы)

| # | Что | Как сделать у нас | Нужна миграция или решение |
|---|---|---|---|
| L1 | **Один экран: чат слева, живой сайт справа** | Редактор получает вкладку «Сайт»: справа превью сохранённой головы (ссылка превью MKT7 в рамке), обновляется после каждого сохранения и правки ИИ; слева лента: команды и ответы («ИИ создал версию 5», «Посмотреть изменения», «Вернуть») | Нет. Рамка превью требует разрешить стойку в `frame-ancestors` хоста превью (Worker) |
| L2 | **Лента разговора** | Показывать прошлые команды человека из `generation_runs` этого сайта и итог каждой (версия или ошибка) | Нет миграции; решение владельца: сейчас текст команды наружу не отдаётся (ТЗ MKT9 §110). Предлагаю отдавать его только автору и `settings` в своём филиале |
| L3 | **Тычок в секцию на превью** | В режиме «Выбрать» щелчок по секции в превью открывает её форму и поле «Изменить эту секцию с ИИ» | Нет; рантайм уже ставит секциям `id`, нужен только скрипт превью, сообщающий стойке id секции |
| L4 | **Правка текста прямо на превью** | Двойной щелчок по заголовку в превью меняет поле формы | После L3; без ИИ |
| L5 | **Закладки версий** | «Отметить удачной» в истории | Да: колонка или таблица закладок, решение владельца |
| L6 | **Режим «План»** | ИИ сначала отвечает списком изменений, человек утверждает, потом правка | Да или новый вид задачи; решение владельца |
| L7 | **Обсудить без изменений (Chat)** | Ответ ИИ текстом про сайт без новой версии | Новый вход бота и учёт расхода; решение владельца |

Рекомендация: **L1 + L2 + L3** одним следующим срезом. Они дают главное ощущение Lovable (пишу слева, вижу сайт справа,
тычу в блок), не требуют миграций и не трогают публикацию. L5–L7 по отдельному решению.
