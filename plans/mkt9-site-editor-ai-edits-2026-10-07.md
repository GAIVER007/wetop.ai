# MKT9: редактор сайта, ИИ-правки и история версий

Дата: 07.10.2026. Ветка `claude/sharp-dirac-6s46fw` заново от `main` `791adad0` (PR #285 MKT8 влит, merge
`791adad02a5955102f32ffa9c6533a29bc4f3757`). ТЗ владельца «WETOP MKT9 — SITE EDITOR + AI EDITS» (164 пункта).
Контракт: `docs/marketing/site-editor-v0.md`. После черновика PR: STOP, MKT10 и MKT11 не начинаются.

## 1. Что строим

```
latest MarketingSiteVersion → правка формами → новая неизменяемая версия (MANUAL)
                            → ИИ PATCH / SECTION → новая версия (AI)
                            → смысловая разница версий → восстановление старой как нового черновика
                            → предпросмотр и публикация существующим MKT7
```

Публикация не меняется: ни сохранение, ни ИИ-правка, ни восстановление не трогают `published_version_id`.

## 2. База: миграций нет

Всё ложится на существующие `marketing_sites`, `marketing_site_versions`, `generation_runs`, `site_assets`.
`GenerationRunType` уже знает `PATCH` и `SECTION`, у задачи есть `base_version_id` и `instruction VARCHAR(2000)`,
триггер `generation_run_guard` уже держит «база только своего сайта», «команда и база не меняются». Словарь кодов
ошибок в CHECK уже содержит `BASE_VERSION_CHANGED` и `BRIEF_CHANGED`; новых кодов не вводим (их нет в CHECK).

- `PATCH`: `instruction` хранит текст человека (обрезан, без управляющих символов кроме перевода строки, до 1800).
- `SECTION`: `instruction` хранит версионированный конверт `{"v":1,"pageId":…,"sectionId":…,"text":…}`
  каноническим JSON; текст человека до 1500 знаков, конверт гарантированно не длиннее 2000 (тест на худшем случае).
  Разбор только `encodeSectionInstruction` / `decodeSectionInstruction` в домене.

## 3. Домен (`packages/domain/src/marketing/`)

| Модуль | Что |
|---|---|
| `site-spec.ts` | наружу `SITE_SPEC_ICONS`, `SITE_SPEC_THEME`, `SITE_SPEC_SOCIAL_NETWORKS`, `siteSpecSectionFields(type)`; валидатор берёт значения из них же |
| `editor.ts` | реестр редактора 11 секций (`SITE_EDITOR_SECTIONS`: подписи, варианты, поля), шаблон новой секции и страницы, новый id, ссылки на страницу и секцию (запрет удаления), снятие языка, разбор пути ошибки, перестановка |
| `diff.ts` | `diffSiteSpecs(from, to)`: уровни сайт, страница, секция, изображение; перестановка как `moved` (по LCS), детерминированный порядок |
| `edit.ts` | правила ИИ-правки: разбор команды, конверт SECTION, `checkEditedSpec(spec, base, brief, mode, target)` отдельно от `checkGeneratedSpec` (INITIAL не меняется) |

`checkEditedSpec`, PATCH: `validateSiteSpec`; неизменны относительно базы `site.vertical`, `displayName`, `locales`,
`defaultLocale`, `contacts`, `legal`, `site.seo`, `integrations`; страницы (число, порядок, `id`, `slug`, `isHome`,
`seo`) не меняются, меняется `title` и секции; `emitStructuredData` у FAQ как в базе (новая FAQ без него); каждая
картинка выхода есть в базе; каждый внешний адрес выхода есть в базе; коды категорий из текущего брифа. Можно:
тексты, слоган, тема, состав, порядок и варианты секций, навигация (подписи и структура).
SECTION: всё, кроме целевой секции, канонически равно базе (сайт, тема, навигация, интеграции, страницы, их порядок и
свойства, остальные секции, позиция цели); у цели тот же `id` и `type`, вариант того же типа, картинки и внешние
адреса только из базовой цели, категории из брифа.

## 4. API (`apps/api/src/marketing-site/`, право `settings`, строгий scope MKT3)

| Маршрут | Что |
|---|---|
| `POST /marketing/site/versions` | как в MKT3; ответ дополнен `id`; 409 с `code: VERSION_CONFLICT` |
| `GET /marketing/site/versions` | до 100 последних, метаданные без документа: `id, revision, parentVersionId, source, generationRunId, createdById, createdAt, specHash, isLatest, isPublished` |
| `GET /marketing/site/versions/:id` | метаданные и документ; чужая версия 404 |
| `GET /marketing/site/versions/:id/diff?against=` | `against → :id` той же смысловой разницей; чужая 404 |
| `POST /marketing/site/versions/:id/restore` | `{ baseRevision }` → новая версия `revision+1`, родитель голова, источник `MANUAL`, документ из `:id`; ассеты по правилам черновика (удалённый → 409 `ASSET_UNAVAILABLE`) |
| `POST /marketing/site/generations` | без `type` и с `INITIAL` как в MKT6; `PATCH` `{requestKey, type, baseVersionId, instruction}`; `SECTION` `{requestKey, type, baseVersionId, pageId, sectionId, instruction?}` |
| `GET /marketing/site/generations/:id` | плюс `type`, `baseVersionId`, `target` у SECTION; текста команды нет |

Рантайм не меняется: `/sites-runtime/*` исторических версий не отдаёт. Маршрутов `cancel` нет.

Воркер один, ветвится по `run.type`. INITIAL без изменений. PATCH и SECTION до модели: сайт не в архиве, голова равна
базе (иначе `BASE_VERSION_CHANGED`), база этого сайта, бриф с тем же хэшем (иначе `BRIEF_CHANGED`), конверт
разбирается, база проходит текущий валидатор. Бот `/internal/site-edit` (`site-edit/0`), тот же бюджет дня,
тот же учёт расхода (Q-274, Q-279), повторы те же (перед повтором снова «голова равна базе»). Успех одной транзакцией
под замком сайта: голова всё ещё база, проверка ассетов MKT8, версия `base+1`, родитель база, `AI`, задача, автор.
Журнал без текста команды.

## 5. Бот (`apps/ai-seller`)

`src/ai/site_edit.py`, вход `POST /internal/site-edit` рядом с генерацией, только служебный ключ. Ключ модели только
платформы (`api_key=None`), бюджет перед каждым вызовом, неизвестный расход останавливает каскад. Системные правила в
коде; база, бриф и просьба человека отдельными блоками данных; просьба не попадает в системное сообщение.
Ответ: полный SiteSpec (не JSON Patch), платформа доказывает границы своей проверкой.

## 6. Стойка (`/marketing/site/editor`)

Компьютер: слева структура (страницы, секции, добавить, ↑ ↓, копия, удалить), в центре форма выбранного, справа
состояние и действия (ревизии, сохранено или нет, Сохранить черновик, Предпросмотр, История, ИИ, Публикация,
Изображения). Телефон 390: вкладки «Структура / Редактор / Настройки», снизу кнопка сохранения.
Одно состояние: документ SiteSpec целиком; «изменено» = канонический JSON отличается от загруженного. Без автосохранения,
без JSON-редактора. Ошибка любого вида не стирает ввод; 409 предлагает посмотреть новую версию, сравнить и продолжить
со своими правками. Уход со страницы с правками спрашивает. Картинки только из библиотеки MKT8 нужного вида, URL
руками не вводится. Категории только из брифа. Цены руками нет.

## 7. Что не делаем (по ТЗ)

Автослияние при 409, автосохранение, JSON-редактор, ИИ-SEO (MKT11), свои домены (MKT10), генерация картинок, отмена
задачи, очистка старых версий (Q-272), стартовый документ «Создать вручную» (§121 разрешает опустить: только
«Создать первую версию с ИИ»), создание сайта из редактора.
