# Mobile access: состояния и приёмка

Дата: 24.10.2026. Подготовка документации, не реализация и не доказательство прохождения тестов.

Источники в ветке codex/wetop-mobile: apps/web/src/lib/scope-resolve.ts, apps/api/src/auth/auth.controller.ts, SPEC-mobile-access.md. Перед реализацией сверить с актуальной основной веткой.

## Последовательность экранов

Запуск → проверка хранилища → вход или проверка серверной сессии → разрешённый контекст → кабинет. На любом промежуточном этапе защищённое содержимое скрыто.

| Состояние | Что видно | Действие |
|---|---|---|
| Проверка сессии | Индикатор и текст «Проверяем вход» | Дождаться ответа, без рабочего меню |
| Нет сессии | Почта, пароль, показать пароль, вход, восстановление | Отправить форму один раз |
| Вход выполняется | Заполненная форма, индикатор | Повторная отправка заблокирована |
| Неверные данные | Сообщение возле формы | Исправить и повторить |
| Сеть недоступна | Понятная ошибка связи | Ручной повтор, без фиктивного успеха |
| Доступ ограничен по частоте | Сообщение об ограничении | Не запускать автоматические повторы |
| Ошибка сохранения токена | Сообщение о невозможности завершить вход | Не открывать кабинет, не сохранять пароль |
| Выбор контекста | Только бизнесы и филиалы из серверного ответа | Выбрать доступный контекст |
| Нет доступного рабочего контекста | Объяснение, выход | Не выдавать завершённый кабинет или права владельца |
| Контекст подтверждён | Имя, бизнес, филиал и разрешённая навигация | Открыть доступный раздел |
| Смена контекста | Загрузка без старых данных | Повторно проверить серверный контекст |
| Сессия истекла | Вход с пояснением | Очистить локальную сессию |
| Выход без сети | Экран входа, сообщение о локальном выходе | Не заявлять об успешном серверном отзыве |

Тексты являются предложением для реализации. Пароль не помещать в URL, логи, аналитику, сохранённое состояние или сообщения ошибок.

## Выбор филиала: уточнение существующего поведения

Обычный кабинет: один филиал выбирается автоматически; при нескольких используется только валидный сохранённый выбор, иначе выбор человеком. Нулевой список не превращается в рабочий кабинет.

Исключение текущей веб-реализации: decideScope(..., {personal:true}) при нескольких назначениях выбирает сохранённое доступное назначение либо первое из списка, уже ограниченного сервером, и ведёт в /my-work. Это обнаруженный контракт веб-кода, а не новое правило мобильного продукта. Не применять его ко всем сотрудникам по названию роли и не переносить общий запрет первого филиала на personal без сверки. До реализации проверить, как сервер и вызывающий код определяют personal. При противоречии с новой моделью задать отдельный вопрос вместо самостоятельной смены правила.

/auth/me может вернуть user:null; отсутствие HTTP 401 само по себе не доказывает вход. Неподтверждённый scope возвращается без businessId/locationId. Сессию и выбранный филиал проверять отдельно.

## Матрица будущих тестов

Все сценарии ниже запланированы, не запущены.

| ID | Условие | Ожидаемый результат |
|---|---|---|
| A01 | Хранилище пусто | Форма входа, кабинет закрыт |
| A02 | Токен есть, me ещё выполняется | Защищённые данные не отображаются |
| A03 | me возвращает user:null | Очистка и форма входа |
| A04 | me возвращает 401 | Очистка и форма входа |
| A05 | me недоступен по сети | Повтор проверки, кабинет закрыт |
| A06 | Успешный вход, запись storage не удалась | Нет готовой сессии и ложного успеха |
| A07 | Два нажатия Войти | Один запрос |
| A08 | Неверный пароль | Ошибка без раскрытия токена или ответа upstream |
| A09 | 429 | Нет автоматического цикла повторов |
| A10 | Один доступный филиал | Выбран и подтверждён me со scope |
| A11 | Несколько филиалов, сохранённый выбор удалён | Обычный кабинет просит выбор |
| A12 | Personal с несколькими назначениями | Поведение сверено с действующим серверным сценарием |
| A13 | Филиалов нет | Отдельное состояние, без придуманных прав |
| A14 | me отклонил scope | Старый филиал не открывается |
| A15 | Поздний ответ после смены организации | Ответ игнорируется |
| A16 | Ответ приходит после выхода | Сессия не восстанавливается |
| A17 | Deep link в кабинет без входа | Закрытый доступ |
| A18 | Назад после выхода | Защищённый экран не возвращается |
| A19 | Выход без сети | Локальная очистка, серверный отзыв не подтверждён |
| A20 | Cookie без Bearer к шлюзу | Нет доступа к защищённому действию |
| A21 | Неизвестные action/method, service-key, произвольный URL | Запрос отклонён |
| A22 | Ошибка upstream содержит чувствительные поля | Очищенная ошибка, без секретов |
| A23 | Некорректный scope или слишком большое тело | Отклонение до upstream |
| A24 | Восстановление для существующей и отсутствующей почты | Одинаковое публичное подтверждение |

## Обязательные уровни доказательств

1. Red/green компонентных и транспортных тестов на вымышленных fixtures.
2. Проверки типов, lint и сборка Expo. Это не проверка native runtime.
3. Проверка клавиатуры, autofill, SecureStore, возврата из фона и deep links на iOS/Android.
4. Вход на согласованном окружении с разрешённой тестовой учётной записью; не использовать реальные данные из файлов проекта.
5. Публикация только после проверки текущего SHA и штатного процесса. Push ветки не равен deploy.

## Передача в реализацию

Не писать код и не запускать тесты до подтверждённого завершения другой сессии. Далее проверить свежесть контракта, разрешение на шлюз и SecureStore, реализовать по SPEC-mobile-access.md. Ролевой HTML-макет служит визуальным ориентиром, не источником правил авторизации или расчётов.
