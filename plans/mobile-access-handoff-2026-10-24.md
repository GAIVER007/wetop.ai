# Mobile access: следующий этап

24.10.2026. Ветка codex/wetop-mobile. Основание: SPEC-mobile-access.md.

Владелец поручил продолжить и подтвердил, что в основном репозитории ещё работает другая сессия. По AGENTS.md §17 кодовые работы и тесты ждут её завершения. Отдельный worktree не снимает ограничение. Подготовлена только документация.

## План

1. После завершения соседней сессии проверить замки, ветки и актуальные auth/scope контракты. Чужие изменения не переносить.
2. Утвердить техническую часть SPEC-mobile-access.md: ограниченный шлюз /api/mobile/v1 и SecureStore для токена. Публикация отдельно от локальной реализации.
3. Красные тесты шлюза: методы и allowlist, Bearer, запрет cookie-only доступа, проверка тела/scope, таймаут, безопасные ошибки. Затем реализация на существующих API без изменения ролей и модели данных.
4. Клиентская сессия: запуск, вход, проверка me, выбор организации/филиала, выход. Пароль не сохранять. Не открывать кабинет по одному локальному токену.
5. Экраны входа, восстановления, выбора контекста и защищённого кабинета. Права серверные; демонстрационные суммы в настоящий кабинет не переносить.
6. Проверки сети, storage, 401/429, двойного нажатия, поздних ответов, deep links и очистки данных после выхода.
7. Mobile tests, typecheck, gateway tests, lint, Expo export. Native runtime и реальный вход проверять отдельно на устройстве и доступном окружении.

## Критерии

Серверный вход ведёт в разрешённый кабинет; истёкшая сессия закрывает доступ; смена бизнеса скрывает старые данные; выход очищает локальную сессию и сообщает результат серверного отзыва.

Шлюз, SecureStore и настоящий вход пока не реализованы. HTML остаётся макетом, Expo содержит foundation. Код и тесты в этом этапе не изменялись и не запускались.
