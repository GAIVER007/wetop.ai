## Решения

- Expo + React Native + TypeScript, Expo Router. Использовать development builds. EAS, платные сервисы и учётные записи магазинов на данном этапе не нужны.
- Приложение живёт в apps/mobile. Оно не импортирует apps/web или серверные модули. Переиспользование возможно только для чистых типов и функций после проверки зависимостей.
- Согласованные версии Expo/RN/React выбираются одним совместимым набором при установке. Корневой React существующих приложений не обновляется ради mobile.
- Корневой tsconfig не включает apps/mobile, поэтому нужна отдельная проверка TypeScript. Корневой lint охватывает новый код; проверка учитывает native environment без отключения правил проекта целиком.
- Тесты компонентов: jest-expo и React Native Testing Library. Связь с общей dev-базой отсутствует. Изменения test:record для mobile оформляются отдельным узким шагом, чтобы сохранить воспроизводимость прогонов.
- SecureStore применяется в следующем mobile-access, вместе с проверкой серверного контракта сессии. В foundation токенов и сетевого входа нет.
- Нижняя навигация разрешена утверждённой native-спецификацией только для apps/mobile. Она не возвращается в веб-стойку вопреки DESIGN.md/UI3.1.

Граф: F1 → F2 → F3 → F4 → F5 → F6. Работы последовательные, без параллельных изменений общей конфигурации.

## Проверенные ограничения среды

24.10.2026: xcodebuild сообщает, что активен /Library/Developer/CommandLineTools; simctl недоступен. Xcode и Android Studio не найдены в /Applications и ~/Applications. Стандартный ~/Library/Android/sdk отсутствует, adb в PATH не найден. Поэтому локальная проверка native binary пока заблокирована. Наличие /usr/bin/java не доказывает наличие JDK.

Разработка исходников, component tests, typecheck и JavaScript bundle проверки возможны без симуляторов. Отчёт должен явно говорить, что native runtime не проверен, если SDK останутся недоступны. Установка многогигабайтных IDE и принятие их лицензий не подразумеваются этим этапом.

## Риски и границы

- Не распространять разрешение на Expo на произвольные новые библиотеки. До дополнительной необходимости не добавлять UI kit, state manager или аналитический SDK.
- Не переносить .env из грязной папки. Не включать SERVICE_API_KEY в public config.
- Не запускать integration/e2e с общей базой.
- Не называть foundation законченным приложением. Вход, организация/филиал, настоящая сводка и выход остаются следующими модулями.
- Если задача меняет бизнес-модель, остановить зависимый шаг и записать вопрос; продолжить независимые проверки.

Реализация уточнена: мобильный пакет имеет отдельный package-lock.json, команды используют --prefix вместо workspace. Для локальных development-сборок зафиксированы ios.bundleIdentifier и android.package: ai.wetop.mobile.dev. Идентификаторы публикации в магазинах этим не утверждаются.
