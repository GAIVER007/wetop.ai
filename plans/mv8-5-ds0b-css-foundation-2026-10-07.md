# MV8.5 DS0b: каскад CSS по договору слоёв

**Основание.** ТЗ владельца 07.10.2026 («MV8.5 DS0b — CSS foundation consolidation»), DS0a влит
(PR #267, `50f04c5c`), финальный `release-checks` 37631054628 зелёный целиком. Ветка
`claude/mv8-5-ds0b-css-foundation` от `main` `50f04c5c`.

**Чего нет в срезе.** Нового вида экранов, новых компонентов, реестров статусов, правки навигации,
API, схемы и миграций. Срез визуально нейтральный: меняется устройство каскада, а не внешний вид.

## 1. Как доказываем нейтральность

Снимков мало: они не ловят сдвиг в 2 px на соседнем экране. Поэтому два инструмента:

- `tests/ui/ds0b-capture.spec.ts` (только с `DS0B_CAPTURE=before|after`): снимки 4 экранов гостиницы
  (1440 и 390, светлая и тёмная) и выгрузка вычисленных стилей каждого элемента 23 маршрутов гостиницы
  (43 свойства, ключ: путь в DOM). Разметка в срезе не меняется, путь один и тот же до и после.
- `scripts/design/ds0b-style-diff.ts`: сравнение выгрузок, расхождения сгруппированы по классу и
  свойству. Шум измерен вторым проходом «до» на том же коде.
- Салон и ресторан: снимки своих наборов (`tests/beauty-ui`, `tests/food-ui`, `tests/branches-ui`),
  попиксельно через `npm run design:diff`.

Каждое расхождение: ожидаемая уборка, утверждённая каноника или случайная поломка. Поломка
исправляется до PR.

## 2. Устройство после среза

| Слой | Файл | Что |
|---|---|---|
| объявление порядка | `globals.css`, первой строкой | `@layer reset, tokens, base, components, sections, utilities;` |
| `reset`, `base`, `utilities` | `globals.css` | сброс, элементы, помощники с `!important` |
| `tokens` | `tokens.css` | генератор оборачивает вывод в слой |
| `components` | `components.css` (новый) | примитивы ровно по одному определению и общие компоненты (`components/*.tsx`) |
| `sections` | `workspace.css`, остаток `premium.css`, оболочка, файлы разделов | экранный CSS |

`glass.css` удаляется: его правила разложены по владельцам. Пять экранных файлов из `layout.tsx`
(`today/desk.css`, `today/dashboard.css`, `management/hotel.css`, `hotel-settings/settings.css`,
`control.css`) разобраны по правилам: правило одного раздела уходит к его маршруту, общее (вкладки
настроек, карточки разделов, `context-help`, полосы дней) в `components.css`, мёртвое с доказательством
удаляется.

## 3. Порядок работ (каждый шаг: сравнение стилей и точечные UI-тесты)

1. Слои: объявление порядка, обёртки файлов без перестановки правил.
2. Примитивы `.btn`, `.panel`, `.stat`, `.tbl`, `.page__title`, `.seg`, `.badge`, `.inp`, `.field` в
   `components.css`, одно определение на селектор; значения из действующего каскада, а не на глаз.
3. `glass.css` по владельцам и удаление.
4. Пять экранных файлов по маршрутам.
5. Мёртвый CSS и токены только с доказательством на свежем `main`.
6. `!important` до 5 и меньше, долг `space-off-scale` ниже 315 без слепой замены.
7. Сторож: каждый канонический примитив определён один раз.
