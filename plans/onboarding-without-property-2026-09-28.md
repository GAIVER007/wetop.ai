# План: онбординг организации без объекта (28.09.2026)

> Основание: поручение владельца «делай сам» (28.09.2026) и находка `reports/platform-p1-cleanup-2026-09-28.md`
> §5а: после сброса платформы (ADR-118) у существующей организации нет объекта, а онбординг ждёт готовый объект.
> Модель данных не меняется: объект создаётся в цепочке той же функцией `createPropertyInChain`
> (DATA_MODEL v2.6 §18.4), что и при регистрации. Бизнес-правил бронирования и денег правка не касается.

## Что сломано

ADR-118 оставляет после очистки только владельца, организацию и членство; объекты, Business и Location удаляются,
«чтобы следующий вход начинался с onboarding». Но:

1. `GET /hotel/onboarding` без объекта отвечает 404 «У вашей организации ещё нет объекта» — форма онбординга не
   открывается;
2. `POST /hotel/onboarding` тоже начинает с поиска объекта — 404;
3. `GET /hotel/settings` без объекта — 404, гейт стойки (`onboarding-gate.tsx`) глотает ошибку и на онбординг не
   ведёт: владелец видит отказ на каждом экране.

Объект создаёт только регистрация. Войти после сброса можно, начать работу — нельзя.

## Что делаем

- **API, `OnboardingService`.** Нет объекта у организации вошедшего:
  - `status()` — `{ needed: true, name: <имя организации>, currency: 'KZT' }` вместо 404; объект не создаётся (GET
    ничего не пишет);
  - `provision()` — в той же транзакции, где заводятся номера, сначала `createPropertyInChain` с умолчаниями
    регистрации (имя — организации, `Asia/Almaty`, валюта — из формы или KZT, заезд 14:00, выезд 12:00), дальше как
    сейчас. Журнал — та же строка `hotel.onboarding` (объект новый — `entityId` нового объекта).
  - Умолчания нового объекта — одна константа `NEW_PROPERTY_DEFAULTS` в `packages/database/src/property-chain.ts`;
    регистрация берёт её же, чтобы два места не разошлись.
- **Стойка, гейт.** 404 от `/hotel/settings` («объекта нет») ведёт на `/onboarding` — и при «Заполнить позже»:
  без объекта рабочие экраны всё равно пусты. Остальные отказы гейт по-прежнему не трогает.

## Не делаем

Не создаём объект при входе или на GET; не трогаем три выборки по `properties.organization_id` (настройки, онбординг,
брони) — это P2; не меняем онбординг организации, у которой объект есть.

## Доказательства (`npm run test:record`)

- unit `apps/api/src/hotel/onboarding.test.ts`: прежний тест «нет объекта — 404» заменяется двумя — status без
  объекта просит онбординг именем организации; provision без объекта создаёт объект в цепочке и заводит номера под
  ним. Красные до кода.
- unit гейта: решение «404 объекта → /onboarding, даже при отложенном» — `apps/web/src/lib/onboarding-later.test.ts`.
- integration: организация без объекта (как после сброса) → `provision` → объект с `location_id`, Business
  HOSPITALITY, категории созданы.
- typecheck, lint, unit, integration целиком; живые e2e на пересобранной сборке.
