# Раздел «Организации и филиалы»: страница и окно «Создать организацию» по макетам владельца

Статус: решения владельца получены 09.10.2026 (ADR-153), срезы ORG1 (API), ORG2 (страница), ORG3 (окно создания) сделаны. Отличия от первоначального плана: триала нет вовсе, черновика нет, владелец это роль на введённую почту, ресторан считается как остальные направления.
Поручение владельца 09.10.2026: «сделай ровно как на скриншоте», «настрой сразу, чтобы всё работало и всё считалось, не просто картинка».

## Что на макетах

1. **Список** (макет 1): заголовок «Организации», четыре плитки итогов (организации, филиалы, объекты, доход за месяц), вкладки по направлениям с числом, сортировка и переключатель «карточки / список», карточки организаций с картинкой, адресом, доходом, загрузкой или числом клиентов, списком филиалов с процентом, кнопками «Открыть» и «⋯»; ниже «Динамика по всем филиалам» (Доход / Загрузка / Гости), «Распределение по типам бизнеса», «Последние действия».
2. **Окно «Создать организацию»** (макет 2): три шага (организация, первый филиал, подтверждение), форма с названием, брендом, направлением (отель, салон, ресторан, другое), владельцем, телефоном, почтой, страной, городом, часовым поясом, валютой, БИН, сайтом, переключателями «что создать сразу», справа панель «Что будет создано», «Сохранить как черновик», «Продолжить».
3. Меню на макете 1 боковое, на макете 2 верхнее. Стойка живёт на верхнем меню (ADR-134), поэтому оболочка остаётся текущей: страница `/platform` с заголовком «Организации и филиалы», как на макете 2. Боковое меню не возвращаем.

## Что уже есть в коде (проверено)

- `/platform` (право главного администратора): `BranchWorkspace` показывает филиалы **только текущей организации**, форма добавления филиала, сводка по гостиничным филиалам, таблица организаций с подпиской и расширениями.
- Цепочка `Organization → Business → Location → Property` и `createPropertyInChain`, `createBeautyLocationInChain` (`packages/database/src/property-chain.ts`). Регистрация (`apps/api/src/auth/auth.service.ts` около строки 369) уже создаёт организацию, бизнес, филиал и членство владельца одной транзакцией. Схема для этого не меняется.
- `GET /platform/organizations` отдаёт организации без филиалов и без цифр; `PUT /platform/organizations/:id/status` меняет доступ.
- Цифры по филиалам: `GET /branches/overview` считает загрузку, доход, поступления и возвраты **только гостиничных филиалов текущей организации**.
- `AuditLog` (`organization_id`) есть, по нему можно строить «Последние действия».

## Чего нет и что для этого сделать

| Блок макета | Источник сейчас | Что делаю |
|---|---|---|
| Создание организации | нет API | `POST /platform/organizations`: организация, бизнес выбранного направления, первый филиал, членство владельца (существующая учётная запись по почте), всё в одной транзакции, повтор по `id` не создаёт дубль, запись в `AuditLog`. Только главный администратор. Схема не меняется |
| Статус новой организации | `TRIAL` по умолчанию | Как в Q-ORG-20261001: создаётся с явным статусом доступа, без автоматического списания и без нового бесплатного периода (предлагаю `READ_ONLY` до «оплата получена»; **вопрос владельцу ниже**) |
| «Сохранить как черновик» | нет | Черновик хранится в браузере (localStorage), на сервере ничего не создаётся. Серверный черновик требует новой таблицы, то есть правки `DATA_MODEL.md` |
| Плитки итогов, список организаций с филиалами | нет сквозного запроса | `GET /platform/overview`: организации, бизнесы, филиалы, число объектов, одной выборкой служебной ролью базы (как `organizations`), без броней и гостей |
| Загрузка и доход за месяц | только текущая организация, только отели | Те же формулы (общий числитель и знаменатель, не среднее процентов), по каждому филиалу за календарный месяц в поясе филиала. Салон: записи и суммы из снимка цены записи. Ресторан: загрузки и дохода в модели нет, показываю «нет данных», не ноль |
| Деньги разных валют | Q-197 | Итог по организациям считается в `reportingCurrency` только если у всех филиалов она совпадает, иначе итоги раздельно по валютам. Конвертации нет |
| «Динамика по всем филиалам» | нет | Помесячный ряд за 12 месяцев на тех же формулах. Переключатель Доход / Загрузка / Гости. Месяцы без источника пустые, не нули |
| «Распределение по типам бизнеса» | нет | Доли дохода по направлению бизнеса, из тех же сумм |
| «Последние действия» | `AuditLog` | Последние события по всем организациям: понятные подписи для известных действий, остальные скрываю |
| Картинка карточки | нет поля | Нейтральный значок направления, фото в модели нет; загрузка картинок отдельным срезом |
| Экспорт, «Настройки структуры» (макет 2) | нет | Экспорт CSV списка организаций и филиалов; «Настройки структуры» ведёт на существующие настройки |
| Подписка, ИИ-продавец, лицензии сайта, состояние системы | есть на странице | Остаются, переезжают в «⋯» карточки и в раскрываемую панель, ничего не теряется |

## Срезы и проверки

1. **ORG1, API.** `POST /platform/organizations`, `GET /platform/overview`, права, тесты (red → green): только главный администратор, повтор не плодит дубль, транзакция откатывается целиком, чужой владелец и несуществующая почта дают понятный отказ, два филиала разных валют не суммируются, ресторан без дохода даёт «нет данных».
2. **ORG2, список.** Плитки, вкладки, сортировка, карточки и список, диаграммы, «Последние действия», по токенам и компонентам из `/design-system` (`DESIGN.md` §8, §8.1, §8.2); новый компонент только после строки в §8. Телефон и тёмная тема.
3. **ORG3, окно создания.** Три шага на примитиве окна, проверка полей, «Что будет создано» считается из введённого, черновик в браузере, ошибки сервера на месте.
4. Каждый срез: `npm run test:record`, typecheck, lint, UI-спек, снимки в `reports/`. Запись в `docs/history.md` и этот файл.

## Что записываю в документы

- `DECISIONS.md`: новый ADR «Платформа: создание организации и сквозной обзор» (основание: поручение владельца, без смены схемы).
- `QUESTIONS.md`: статус новой организации; серверный черновик; фото организации; цифры ресторана.
- `DATA_MODEL.md`: не меняется, пока не выбран серверный черновик или поле фото.

## Решения, которые нужны от владельца до кода

1. **Статус новой организации:** `READ_ONLY` до оплаты (рекомендую, как в Q-ORG-20261001) или `TRIAL` на 14 дней?
2. **Владелец:** только существующая учётная запись по почте (рекомендую) или приглашение внешнему человеку (отдельный срез)?
3. **Черновик:** в браузере (рекомендую) или на сервере с новой таблицей и миграцией, которую применяет владелец?
4. **Ресторан:** в доходе и загрузке «нет данных» (рекомендую), пока в модели нет этих числителей?

Производственных миграций план не требует. Выкладка по ADR-152 после зелёного гейта.
