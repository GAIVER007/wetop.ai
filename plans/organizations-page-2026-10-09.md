# Страница «Организации»: одна страница, управление организациями

**Дата:** 09.10.2026. **Статус:** часть 1 и срез ORG1 (название, архив, возврат) сделаны и проверены, создание организации ждёт ответа владельца (Q-283). Q-282, Q-284, Q-285 закрыты предложенными умолчаниями (ADR-154).
**Поручение владельца 09.10.2026:** перенести «Платформу» в «Настройки»; на странице «Организации» убрать непонятные
названия и ID, собрать всё на одну страницу: добавить организацию, удалить её, редактировать, видеть статистику по
филиалам.

## 1. Что было

Вкладка «Платформа» с одним пунктом «Организации» (только главный администратор, `/platform`). Внутри склеены два
экрана: филиалы текущей организации (с ID организации и филиала, «Реквизиты организации», «Добавить объект / филиал»,
«Сводка по гостиничным филиалам») и спрятанная раскрывашка «Подписки и администрирование» с таблицей всех организаций.
Статистика жила отдельной таблицей внизу, не рядом с филиалом.

## 2. Часть 1: сделано (только интерфейс, API и модель данных не менялись)

| Что | Как |
|---|---|
| Вкладка «Платформа» | Снята. «Организации» лежат в «Настройках», последним пунктом, видны только главному администратору. Адрес `/platform` прежний |
| Одна страница | Сверху своя организация: название, период, итоги (загрузка, гости, начислено, поступило с возвратами), карточки филиалов. Ниже таблица всех организаций платформы (всегда раскрыта) с карточкой выбранной. В самом низу «Состояние системы» |
| Статистика по филиалам | Загрузка, гости в заездах, начислено и поступило стоят прямо в карточке филиала |
| Названия | Нет ID организации и филиала, нет «Реквизитов организации», «Один аккаунт, отдельный номерной фонд…», «объект / филиал», «Сводка по гостиничным филиалам». Кнопка называется «Добавить филиал» |
| Не тронуто | `/branches` (выбор филиала после входа, там остаётся прежний вид), все формы подписки, «ИИ-продавца» и конструктора сайта |

Доказательства: `apps/web/src/lib/navigation-roles.test.ts` (красный 1 из 19, затем зелёный), UI-спеки
`tests/ui/branches.spec.ts` и `tests/ui/platform-access.spec.ts`, снимки в `reports/organizations-page-2026-10-09/`.

## 3. Часть 2: чего нет и почему

В API есть только: список организаций, смена статуса подписки, расширение «ИИ-продавец», лицензия конструктора сайта,
создание филиала. Нет создания организации, правки её данных, удаления, правки и удаления филиала. Каждое из этого
меняет данные или деньги и упирается в решение, которое агент не придумывает (AGENTS.md §4, §15):

| Что просят | Где упирается | Вопрос |
|---|---|---|
| Удалить организацию | `plans/slice-13-accounts-2026-09-15.md`: «удаление организации не предусмотрено, статус вместо удаления». Журнал только дописывается (v1.7), у организации брони, гости, счета, платежи | Q-282 |
| Добавить организацию | Сейчас организация появляется только самостоятельной регистрацией на wetop.ai вместе с владельцем | Q-283 |
| Редактировать организацию | Полей «реквизиты», «БИН», «договор» в модели нет (DATA_MODEL §13, §16); переименование филиала открыто как Q-239 | Q-284 |
| Статистика по филиалам других организаций | ADR-083: главному администратору чужие брони, гости и счета не видны по построению | Q-285 |

## 4. Часть 2: предлагаемый срез ORG1 (после ответов)

Предлагаю по умолчанию, владелец может выбрать иначе в Q-282…Q-285:

1. **API (только главный администратор, право `platform`):** `POST /platform/organizations` (название и почта владельца,
   статус `TRIAL`, владельцу уходит приглашение существующим механизмом), `PATCH /platform/organizations/:id`
   (название), архив и возврат из архива через уже существующий статус (`SUSPENDED` и обратно), запись в журнал на
   каждое действие. Новые маршруты попадают в `route-access.test.ts` с правом `platform`, чужих организаций касается
   только главный администратор.
2. **Интерфейс на этой же странице:** кнопка «Добавить организацию» над таблицей (форма раскрывается на месте), в
   строке таблицы «Изменить» и «В архив», подтверждение вводом названия, архивные организации скрыты фильтром
   «Показать архивные».
3. **Тесты:** сначала красные (AGENTS.md §6): API (права, валидация, дубли, журнал), `tests/integration` (изоляция
   организаций, RLS, архив не удаляет данные), UI (форма, подтверждение, возврат из архива).
4. **Модель данных:** если Q-282 решится «удалять насовсем» или Q-284 потребует реквизитов, сначала правка
   `DATA_MODEL.md` и миграция с откатом (AGENTS.md §2, §14). Для варианта «архив» схема не меняется.

## 5. Что не делаем

Окончательное удаление данных организации без выгрузки и срока хранения; показ чужих броней, гостей и счетов; перенос
филиала между организациями; правку и удаление филиала (Q-239).

## 6. Что сделано в ORG1 (09.10.2026, ADR-154)

Поручение «давай делай продолжай» принято как согласие с предложенными ответами (как «делай сам» 10.09.2026).

| Что | Как | Доказательство |
|---|---|---|
| Название | `PATCH /platform/organizations/:id`, форма «Название» в карточке организации | API: `platform.controller.test.ts`; БД: `tests/integration/platform-extensions.test.ts`; UI: `tests/ui/organizations-manage.spec.ts` |
| Удалить, то есть архив | `POST …/archive`: `SUSPENDED`, люди не входят, данные целы; кнопка с окном подтверждения; архивные скрыты, «Показать архивные (N)» | те же три набора |
| Вернуть | `POST …/restore`: прежний статус из журнала, иначе «только чтение»; платный доступ сам не появляется | те же три набора |
| Своя организация | в архив не убирается (409 и отключённая кнопка), в таблице помечена «Ваша» | те же три набора |
| Добавить организацию | кнопка раскрывает ссылку на регистрацию: организация регистрируется сама | `organizations-manage.spec.ts` |
| Статистика по чужим организациям | не показывается (Q-285 А, ADR-083) | без изменений |

**Не сделано: создание организации главным администратором (Q-283).** Приглашением нельзя (`invites_role_not_owner`, ADR-107), а восстановления пароля в проекте нет, поэтому завести человека без пароля нельзя. Нужен новый сценарий «владелец задаёт пароль по ссылке из письма»: письмо, токен, срок жизни, правка модели. Это решение владельца (Q-283, вариант А).
