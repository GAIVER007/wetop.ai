# Срез 2 плана развития: запросы оплаты в брони, Kaspi и ссылка банка (03.10.2026)

Основание: ADR-141 (Р4: Kaspi и Halyk у объекта есть, привязка разрешена), план
`plans/wetop-unified-roadmap-2026-10-03.md` (H3, K3, K4, X2), модель `DATA_MODEL.md` §23.

## Почему так

У Kaspi нет официального API оплаты для внешнего софта: счёт по номеру телефона выставляется в Kaspi Pay вручную.
Ссылки Halyk ePay и других банков создаются в кабинете банка; API банков подключаются только по документации в
`/docs` (Q-258). Поэтому первый шаг: запрос оплаты как запись в WETOP, который связывает выставленный счёт со счётом
проживания, даёт администратору готовый текст гостю на четырёх языках и одним нажатием превращается в обычный платёж.
Когда появится документация банка, адаптер будет создавать ссылку и отмечать оплату сам, таблица не меняется.

## Что сделано

1. **Модель** `payment_requests` (§23) и миграция `20261003000044_payment_requests` с `down.sql`: способ только
   KASPI, HALYK, BANK_TRANSFER_PERSON, CARD_TERMINAL; ссылка только `https://`; CHECK «оплачен ⇔ есть платёж»,
   «закрыт ⇔ есть время закрытия»; RLS `rls_tenant` по объекту, таблица в `RLS_TENANT_TABLES`.
2. **Домен** `packages/domain/src/finance/payment-request.ts`: разбор формы (сумма в тенге с пробелами и запятой) и
   `paymentRequestMessage` (ru, kk, en, zh; Kaspi, ссылка, перевод, терминал).
3. **API** (`@Access('desk')`): `GET/POST /finance/reservations/:number/payment-requests`,
   `POST /finance/payment-requests/:id/paid`, `POST /finance/payment-requests/:id/cancel`. «Оплачено» создаёт платёж
   и закрывает запрос одной транзакцией под блокировкой строки запроса и счёта; повтор 409. Ссылка банка в журнал не
   пишется (в ней бывает одноразовый токен), только `hasLink`.
4. **Стойка**: блок «Запросы оплаты» над счетами в карточке брони (`payment-requests.tsx`): форма с остатком по
   умолчанию, список со статусом, «Оплачено» и «Отменить» с подтверждением, текст гостю с выбором языка и кнопкой
   «Скопировать текст для гостя».
5. **Попутно**: на телефоне 390 px раздел «Счета» был шире экрана на 44 px (сетка `.folio-form` росла по самой
   широкой строке полей); у колонки теперь `minmax(0, 1fr)`. Найдено тестом этого среза, воспроизведено без него.
