# Супер-админка платформы: обзорный дашборд владельца WETOP.AI

**Дата:** 10.10.2026. **Поручение владельца:** ТЗ «Супер-админка платформы / Кабинет владельца
платформы WETOP.AI» (20 разделов) и макет «Дашборд платформы» (скриншот в поручении).
**Ветка:** `claude/platform-superadmin`.

## 1. Что уже есть (аудит 10.10)

- Раздел `/platform` «Организации» (ADR-083, ADR-ORG-PAGE): своя организация с филиалами,
  таблица всех организаций, создание (ADR-ORG2), архив и возврат (ADR-ORG1), статус оплаты
  «ACTIVE / READ_ONLY» вручную (ADR-102), расширение «ИИ-продавец», лицензии конструктора,
  техподдержка `/platform/support`, «Состояние системы» (ADR-116).
- Право: отметка `platform_admins`, ставится только командой на сервере (ADR-083);
  маршруты `@Access('platform')`, читают служебной ролью базы в обход RLS.
- Графики стойки: `DayBars`, `DonutShare`, `LineChart`, плитки `Stats`/`Stat` с дельтой и иконкой.
- Целевая структура раздела записана в `ARCHITECTURE.md` §17 (Обзор · Партнёры ·
  Тарифы/подписки · Расширения · Платежи WETOP · Поддержка · Состояние системы · Журнал).

## 3. Срез P1 (этот PR): обзорный дашборд без правки модели данных

Всё из существующих таблиц, миграций нет, модель не меняется.

### API
- `GET /platform/overview` (право `platform`, служебная роль):
  - организации: всего, по статусам (TRIAL / ACTIVE / READ_ONLY / SUSPENDED), новые за 30 дней;
  - рост: организации по месяцам за последние 12 (новые и накопительно), месяцы по UTC;
  - направления: организации по направлению старейшего бизнеса (HOSPITALITY / BEAUTY / FOOD_SERVICE);
  - люди: всего пользователей с членством, активных за 30 дней (`users.last_login_at`).
- `GET /platform/organizations`: к ответу добавляются `verticals` (направления бизнесов)
  и `locations` (число филиалов) — для таблицы. Внутренние показатели чужих организаций
  (брони, выручка гостей) по-прежнему не отдаются (Q-285, ADR-083).
- Маршрут в реестр `route-access.test.ts` с правом `platform`.

### Стойка (страница `/platform`, по макету)
- Ряд KPI-плиток `Stats`: Всего клиентов, Активные (оплата получена), Пробный период,
  Только чтение, Активные пользователи (30 дней), Новые подключения (30 дней).
- «Рост количества клиентов»: `DayBars` по месяцам (12 столбиков, накопительно, подробности месяца).
- «Клиенты по направлениям»: `DonutShare`.
- «Статус клиентов»: `DonutShare`.
- Блок «Подписки и выручка»: честные слова, что платежи платформе в системе не ведутся
  (тариф Core по ADR-102, оплата счётом), со ссылкой на Q-PA-1/Q-PA-2. Чисел нет.
- Таблица организаций: + колонки «Направление», «Филиалы», «Подключена»; поиск по названию
  и почте владельца; отбор по статусу и направлению (на клиенте, организаций немного).
- Существующие блоки (своя организация, создание, карточка, состояние системы) не трогаются.

### Отличия от макета, названные прямо
- Левого бокового меню нет: оболочка стойки с верхним меню общая (DS2 ведёт навигацию),
  как записано в ADR-157/ADR-158 для других экранов по макетам.
- Плиток MRR и «Просроченные оплаты» нет: данных нет (см. §2), вместо них блок «Подписки и выручка».
- Валюта ₽ из макета не используется: валюта платформы — тенге (Q-143).
- Рекламная карточка «Развиваем бизнесы вместе» не делается (декорация без данных).

### Проверки (red → green)
- unit: чистая функция сборки обзора (месяцы, статусы, направления, границы месяца);
- API: `platform.controller.test.ts` — overview, 403 без отметки;
- реестр маршрутов `route-access.test.ts`;
- UI: фикстура `/platform/overview` + спек `tests/ui/platform-overview.spec.ts`
  (плитки, графики, поиск и отборы таблицы, пустые состояния, axe в двух темах);
- typecheck, lint.
