# Справочники объекта: способы оплаты и статьи кассы в «Настройках» (07.10.2026)

Поручение владельца 07.10.2026 (утро): «где у нас раздел, где можно добавлять справочник: расходы, приходы,
способы оплаты: как оплатит гость, наличной, картой и т.д.». Разбор утром показал: статьи кассы есть
(`CashCategory`, §21), но спрятаны за призрачной кнопкой «Статьи» в «Финансы → Касса»; способов оплаты
на объект нет вовсе, это жёсткий список `PaymentMethod` в схеме. Владелец вечером: «да давай делай дальше сам».
Решение: ADR-152. Модель: `DATA_MODEL.md` §21.6 (v2.13). Ветка `claude/youthful-wozniak-vin0pp`, PR #271.

## 1. Что есть сегодня (аудит по коду)

- `PaymentMethod` в `schema.prisma`: девять значений, из них `EXTERNAL` ставят каналы. Список повторён
  примерно в двенадцати местах: домен (`cash.ts`, `payment-request.ts`), API (`finance.repository.ts`
  `PAYMENT_METHODS`, бар), стойка (`finance/labels.ts` `METHOD_RU`, `finance-panel.tsx` `METHODS`,
  `payment-requests.tsx`, `cash.tsx` `CASH_METHOD_OPTIONS`, формы бара), подставной API, скрипты сверки.
  Одного источника подписей нет.
- Настроек «какие способы принимает объект» нет: любая форма предлагает все восемь (без `EXTERNAL`).
- Статьи кассы: `GET /finance/cash` (вместе с остатками), `POST`/`PATCH /finance/cash/categories` (право
  `settings`), стартовый набор из одиннадцати статей при первом чтении; панель «Статьи кассы» в «Кассе»
  умеет добавить и выключить, переименования в интерфейсе нет (API `name` принимает).
- «Настройки объекта» (`/hotel-settings`): вкладки «Основное», «Проживание», «Услуги» (SET1…SET4);
  образец справочника с панелью справа: каталог услуг `hotel-settings/catalogs.tsx`.

## 2. Решения и умолчания (владелец: «делай сам»)

| № | Развилка | Принято |
|---|---|---|
| У1 | Свободный справочник способов (вариант Б) или настройка системного списка (вариант А) | **Вариант А.** Способы остаются системными кодами: на них завязаны отчёты, сверка кассы, CHECK в базе и запросы оплаты. Объект включает, выключает и упорядочивает. Вариант Б и свои подписи: Q-279 |
| У2 | `EXTERNAL` | Не настраивается: платёж площадки, его ставят каналы. В настройках его нет, формы стойки его не предлагают (как сегодня) |
| У3 | Умолчания без строк | Все восемь включены, порядок: наличные, терминал, Kaspi, Halyk, перевод от физлица, перевод от юрлица, депозит, гарантия картой. Существующие объекты не меняют поведения |
| У4 | Минимум | Хотя бы один способ включён, иначе принять деньги нечем (правило домена и формы) |
| У5 | Что делает выключение | Способ не предлагается в формах приёма оплаты, замены платежа, групповой оплаты, операций и переводов кассы, запросов оплаты; API отказывает словами «Способ оплаты «Kaspi» выключен в настройках объекта». История не трогается: отчёты, отбор операций, возвраты по старым платежам и сверка работают по любому способу |
| У6 | Плитки кассы (Q-246) | Правило прежнее: четыре плитки по умолчанию плюс способы с движениями; выключенный способ без движений плитки не получает; порядок плиток по настройке |
| У7 | Хранение | Таблица `payment_method_settings` (объект, способ, включён, порядок), строки пишутся только при сохранении настроек, все восемь одной транзакцией; чтение без строк отдаёт умолчания, ленивой записи при чтении нет; журнал `hotel.payment_methods.updated` (было и стало) |
| У8 | Права | Читать включённые способы может стойка (они приходят в ответах `/finance/reservations/:number` и `/finance/cash`), править владелец и управляющий (`settings`), как остальные «Настройки объекта» |
| У9 | Где статьи кассы | В «Настройки объекта → Справочники» вместе со способами: добавить, переименовать, выключить. В «Кассе» вместо призрачной кнопки ссылка в настройки; редактор один |
| У10 | Подписи способов | Один источник в домене (`PAYMENT_METHOD_RU`), `finance/labels.ts` берёт оттуда; остальные копии не трогаются в этом срезе (по одной при следующих правках) |

## 3. Что делаем

1. Домен `packages/domain/src/finance/payment-methods.ts`: `CONFIGURABLE_PAYMENT_METHODS`, умолчания,
   `resolvePaymentMethodSettings(rows)`, `enabledPaymentMethods`, `parsePaymentMethodSettings(raw)`,
   `assertPaymentMethodEnabled(method, enabled)`, `PAYMENT_METHOD_RU`.
2. Модель §21.6 и миграция `20261007000062_payment_method_settings` (+`down.sql`, RLS `rls_tenant`,
   CHECK `method <> 'EXTERNAL'`), таблица в `RLS_TENANT_TABLES`.
3. API: `GET`/`PUT /hotel/payment-methods` (`settings`), `GET /finance/cash/categories` (`settings`);
   `ReservationFinanceView.paymentMethods` и `CashView.paymentMethods` (включённые, по порядку);
   отказ выключенного способа в приёме оплаты, замене платежа, операциях и переводах кассы, запросах оплаты;
   кэш настроек объекта сбрасывается при сохранении.
4. Стойка: вкладка «Справочники» `/hotel-settings/directories` (способы оплаты: включить, порядок,
   одна кнопка сохранения; статьи кассы: список, добавить, переименовать, выключить); формы денег
   берут список включённых способов из ответа API; в «Кассе» ссылка «Статьи кассы: в настройках объекта».
5. Подставной API учит всё то же; журнал стойки знает `hotel.payment_methods.updated`.
6. Реестры: навигация, `route-access`, списки адресов в тестах и скриптах, DESIGN.md §8, CLAUDE.md §2.

## 4. Чего не делаем

- Свои названия способов и новые способы (вариант Б): Q-279.
- Формы бара (`bar/sale-form.tsx`, поставщики): свои списки, отдельной правкой.
- Сведение всех копий списка способов к одному источнику: только подписи (У10).
- Переезд существующих значений: строк нет, умолчания равны сегодняшнему поведению.

## 5. Проверки (red → green)

- Домен: разбор, умолчания, слияние со строками, запрет пустого набора, отказ выключенного способа.
- API: таблица прав (три новых строки), `finance.controller` (400 при выключенном способе в оплате и замене),
  `hotel` (сохранение, журнал, роли).
- Integration (локальная база): сохранение восьми строк одной транзакцией, чтение с умолчаниями,
  RLS-список совпадает с базой, `check-migrations` с откатом.
- UI `tests/ui/settings-directories.spec.ts`: вкладка, выключение Kaspi и порядок, отсутствие Kaspi
  в форме оплаты, запросах оплаты и кассе; статьи: добавить, переименовать, выключить; администратор
  без права не видит вкладку; axe в двух темах на 1440 и 390; снимки `reports/property-directories-2026-10-07/`.
- typecheck, lint, полный unit; integration на `db:local`.
