# «Настройки объекта» v2 — срезы SET2 (проживание) и SET3 (услуги) (28.09.2026)

**Основание:** ТЗ владельца «WETOP Hospitality — „Настройки объекта“ v2» (27.09.2026), §6–7, §11–17, §35; «да» владельца
по снимкам SET1 28.09.2026 — сигнал начинать SET2 и SET3 (ТЗ: «SET2/SET3 без отдельного подтверждения не начинать»).
SET1 слит в `main` (PR #116, решение ADR-115 после перенумерации 28.09). Этот план — дополнение к ADR-115.

**После SET2 и SET3 — стоп и снимки. SET4 (правила отмены в тарифах) и SET5 (Location-скоуп) — только после «да».**

---

## 1. Аудит перед правкой

| Вопрос ТЗ | Что в коде на 28.09 |
|---|---|
| Поля часов | `type="time"`: формат рисует браузер по своему языку — на стенде «02:00 PM», в русском «14:00». DESIGN §14 требует 24 часа всегда |
| Проверка часов | Только в API (`parseHotelSettingsPatch`: `HH:MM`, иначе «Время заезда — в виде 14:00»); ошибка показывается над формой, поле не подсвечено |
| Каталог услуг | `Service`: `code`, `nameRu`, `nameKz`, `price` (тиын), `tax`, `group`, `active`. Чтение — `GET /finance/services`, **только активные** (их же берёт начисление в счёт). Записи из стойки нет |
| История при правке | Начисление хранит свои `description`, `unitPriceMinor`, `amountMinor` на момент начисления — правка цены или названия в каталоге прошлые счета не меняет. Удалить услугу нельзя (на неё ссылаются начисления) — только `active = false` |
| Архив | Поле `active` уже есть — нового поля не нужно (ТЗ §16: «не изобретать archive field, если его пока нет») |
| Код услуги | Нужен только системе (уникален в объекте, начисление ищет по нему). Пользователю не показывается; новой услуге код даёт API |
| Права | Право `settings` (DATA_MODEL §16.5, ADR-107 о ролях) прямо включает «услуги»: владелец и управляющий. Администратору раздел закрыт целиком. «Только чтение» пробного периода (ADR-102) — общий механизм |
| Журнал | Правки настроек пишутся (`hotel.settings.updated`); для каталога — тем же способом, «было/стало» |

Модель данных не меняется: все поля есть. Меняется API — три новых пути каталога (см. §3).

## 2. SET2 — «Проживание»

1. **Время всегда в 24 часах.** Поле `type="time"` заменяется текстовым полем с цифровой клавиатурой (`inputMode="numeric"`,
   подсказка «14:00»). Ввод «9:00», «0900», «9.00» приводится к «09:00» одной функцией домена (`normalizeClockTime`) —
   ею же пользуется разбор API, так что стойка и API понимают время одинаково.
2. **Ошибка у поля.** Неверное время — `aria-invalid` и текст под полем (приём страницы компонентов: `Field` → `Input` →
   `Alert`), проверка при уходе с поля и при сохранении; с ошибкой форма не уходит.
3. Сохранение — как в SET1 (шапка, «есть изменения» / «сохранено»). Новых полей (ранний заезд, поздний выезд, возраст
   детей) нет — ТЗ §7 прямо запрещает поля «ради красивого Settings».

## 3. SET3 — «Услуги»

**API** (модуль гостиницы, рядом с `/hotel/settings`; право `settings`, запись закрыта и «только чтением»):
- `GET /hotel/services` — весь каталог, с архивными: `code`, `name`, `group`, `priceMinor`, `active`;
- `POST /hotel/services` — новая услуга: название, группа, цена, статус; код генерирует API (`svc-…`);
- `PATCH /hotel/services/:code` — правка тех же полей; архив и возврат из архива — `active`.
Разбор входа — в домене (`parseServiceInput`): название обязательно (до 200 знаков), группа — до 100, цена — через
`parseMoney` (больше нуля, до двух знаков после запятой). Журнал: `hotel.service.created` / `hotel.service.updated`,
«было/стало» только по изменённым полям. `GET /finance/services` (выбор услуги в счёте) не меняется: только активные.

**Экран:**
- подзаголовок раздела «Дополнительные товары и услуги, которые можно добавить в счёт гостя»; в шапке «Добавить услугу»
  (только с правом и вне «только чтения»);
- отбор: поиск, «Группа» (все + группы каталога), «Статус» (активные — по умолчанию, в архиве, все), число строк;
- таблица: Услуга | Группа | Цена | Статус; название обычным весом, код не показывается; статус словом в `Badge`
  («активна» — `ok`, «в архиве» — `neutral`);
- клик по названию (кнопка, доступна с клавиатуры) открывает панель справа (`Overlay drawer`): название, группа
  (с подсказками из существующих групп), цена в ₸, статус; «Сохранить» / «Создать»; ошибки — у полей и `Alert`;
- у кого нет права или организация в «только чтении» — таблица без кнопок, панель не открывается;
- подсказка «Начислить услугу гостю» остаётся под таблицей; строка «Каталог доступен только для просмотра» снимается.

## 4. Что не входит

Группы услуг отдельным справочником (ТЗ §17: «сложный CRUD групп пока не нужен» — группа остаётся текстом услуги),
казахское название и налог (в модели есть, в ТЗ нет — не трогаются), удаление, правила отмены (SET4), Location-скоуп и
переключатель объектов (SET5).
