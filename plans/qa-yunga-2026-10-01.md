## 2. WET-01: критерии приёмки ТЗ против текущего экрана

| Критерий ТЗ | Экран `channels/[[...section]]/page.tsx`, функция `Sync` |
| --- | --- |
| Без подключения нет успешных статусов | `notConnected` → полоса «Каналы не подключены. Обмен с OTA не подтверждён», строки «Не подключено» |
| После подключения, до первой отправки успех не показан | `s.lastSent` пуст → «Не отправлялось»; входящие без событий → «Событий ещё нет» |
| После подтверждённого обмена видны время и результат | «Отправлено в менеджер» и `eventTime(lastSent)`; «События получены» и время |
| Ошибка или разрыв меняют статус | `outbox.failed` → «ошибка», `failedEvents` → «требуют разбора: N» |
| Повторное открытие не возвращает ложный успех | Состояние считается на каждый запрос из `connection`, `outbox`, `events` |
| Тестовый контур | `environment !== 'production'` → «Тестовый контур. Ожидающих заданий нет; обмен с рабочими OTA не подтверждён» |

Оговорка: слово «актуально» для цен и остатков экран больше не употребляет; подтверждения провайдера по текущему
объекту в API нет, поэтому статус «актуально» не показывается вовсе, а не выводится из пустой очереди.

## 3. WET-02: сводка групповой брони

Смысл поля закрепляем тот, что уже у API: `adults` относится к одному размещению, `quantity` размножает
размещение на N мест. Итого гостей в размещении = `quantity × adults`. Правила API, схема и цены не меняются.

Правки (только `apps/web`):
1. `summarize` вынесена из `form.tsx` в `reservations/new/summary.ts` (чистая функция, без React), чтобы доказать
   правку модульным тестом: при 3 местах и 1 госте на место строка сводки «3 места, ячейки назначит система,
   3 гостя»; при 2 номерах по 2 гостя «2 места, …, 4 гостя»; при одном месте как раньше.
2. В групповом режиме поле подписано «Гостей на место», подсказка под группой говорит «всего N гостей».
3. Липкая строка сути (`booking-digest`) и блок «Проверить детали брони» берут ту же строку.

Red → green: `apps/web/src/app/reservations/new/summary.test.ts` (красный на перенесённой без изменений функции),
`tests/ui/booking-group-guests.spec.ts` (красный на прежней подписи и сводке; стенд: подставной API).

## 4. WET-04: выключить и включить тариф

Модель не меняется: `RatePlan.active` уже есть, его читают форма брони (`GET /rate-plans`), предложения цен
(`activeRatePlans`), создание брони (отказ по недействующему тарифу), список «Тарифных планов» (строка «не
действует» внизу). Не хватало только команды и кнопки.

API (`apps/api/src/rates/rate-plans.ts`, право `rates`, то есть владелец и управляющий):
- `PATCH /rates/plans/:code` принимает либо `{ cancellationPenalty }` (как раньше), либо `{ active: boolean }`;
  оба поля сразу или неизвестное поле: 400 словами.
- Выключение запрещено (409, причины словами, все сразу), пока:
  - тариф сопоставлен с менеджером каналов (`channel_mappings.local_rate_plan_id`): сначала снять сопоставление;
  - по тарифу бронирует сайт (`tracked_sites.rate_plan_id`): сначала выбрать другой тариф сайта;
  - у тарифа есть действующие производные тарифы: сначала выключить их;
  - впереди есть брони по тарифу (те же «брони впереди», что в списке): умолчание ТЗ «по умолчанию блокировать
    до явного разрешения», развилка записана как **Q-238**.
- Включение обратно: без условий (тариф возвращается со своими категориями, ценами и правилом отмены).
- Журнал: `rate_plan.active.updated`, было / стало, число броней впереди. То же значение: без записи и журнала.
- Список `GET /rates/plans` отдаёт у каждого тарифа `offBlockers: string[]`: причины, почему выключить нельзя
  (пусто: можно). Стойка показывает их до нажатия, сервер проверяет сам.
- `POST /rates/plans/derived`: родителем может быть только действующий тариф (раньше проверялось только стойкой).

Стойка (`apps/web/src/app/rates/plans-table.tsx`, `actions.ts`, `lib/api.ts`):
- В панели тарифа под правилом отмены блок «Статус тарифа»: словами, что значит «действует» и «выключен»,
  кнопка «Выключить тариф» / «Включить тариф»; при причинах кнопка выключена и причины перечислены
  (`Alert tone="warning"`); отказ API словами в панели; успех: уведомление «Тариф «…» выключен / включён».
- «Только чтение» и без права: таблица без кнопок, как раньше. Новых компонентов нет (DESIGN.md §8).

Подставной API (`scripts/preview/fixture-api.ts`): тот же разбор `PATCH /rates/plans/:code`, `offBlockers`
по броням впереди и производным, состояние живёт до `reset`.

Red → green: `apps/api/src/rates/rate-plans.test.ts` (новые сценарии: выключить без помех, причины 409, включить,
400 на оба поля), `tests/ui/rate-plans.spec.ts` (новый тест: кнопка, причина у тарифа с бронями, выключение
тарифа без броней, строка «не действует», в форме брони тарифа нет; красный на прежней панели).
