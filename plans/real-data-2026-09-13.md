# Подключение frontend к данным проекта

Запрос владельца: весь интерфейс должен читать реальные данные существующего backend/Supabase.

## Установлено

- Текущий preview запущен через `dev:demo`, источник — изолированный API на 4312.
- В этой рабочей копии нет `.env`, `apps/web/.env.local` и переменной `DATABASE_URL` в процессе. Backend на 3001 не запущен. Доступ к базе пока не подтверждён.
- Страницы и server actions используют общий клиент NestJS API, backend уже работает с PostgreSQL/Supabase через Prisma. Перенос запросов в браузер не требуется.
- Учётные данные этой копии проекта не передаются через Git. У владельца запрошен адрес настроенного backend или настройка `.env` без передачи секретов в чат.

## Выполнение

1. Проверка существующей базы: endpoint только для чтения, агрегаты выбранного объекта, явные состояния ошибки базы и отсутствия объекта. Никаких миграций, импорта или тестовых записей.
2. Экран «Подключения»: отдельно источник данных PMS, доступность базы, объект и количество записей; статус Channex остаётся самостоятельным.
3. Название гостиницы в каркасе и обзоре — из backend; отсутствие связи не подменяется названием из макета.
4. Единый запуск обычного frontend/backend; корневая конфигурация передаётся программе. Демо включается только отдельной командой. При просмотре реальных данных фоновые синхронизации и автоматические исправления не запускаются без отдельного выбора оператора.
5. Проверить все пути данных и команды, записать матрицу реализованных API и отсутствующих возможностей. Проверки записи — только на изолированных fixtures.
6. Unit/controller проверки ошибок и изоляции источников, browser-проверки новой панели и регрессий, typecheck/lint/build. Подтверждение реальной базы — только после предоставления подключения.
7. Отправить проверенные изменения в репозиторий, оставить обычный frontend доступным локально.

## Границы

Схема, финансовые правила, авторизация и OTA cutover не меняются. Акции, переписки, роли, фото и удобства не имеют утверждённых реализованных моделей/API: подключение базы само по себе их не создаёт. Секреты, данные гостей и строки подключения не выводятся и не коммитятся. Не выдавать изолированные тесты за доказательство живого подключения.

## Приёмка

- Обычный запуск не принимает источники demo/synthetic.
- Проверка соединения не пишет в БД и не вызывает провайдеров; ошибка не превращается в нулевую статистику.
- Название объекта совпадает с ответом backend; при отказе показано отсутствие данных.
- Если нет конфигурации, команда сообщает, что именно отсутствует, не печатая значения.
- На настроенном backend frontend читает данные по существующим контрактам и сохраняет существующие действия.
