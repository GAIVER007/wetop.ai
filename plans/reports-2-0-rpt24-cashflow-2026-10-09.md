# RPT2.4a: «Деньги за период» во вкладке «Финансы» отчётов (план, 09.10.2026)

Основа: `docs/metrics.md` §2 (четыре разных показателя), ADR-155. Миграций нет, модель данных и финансовая логика не меняются:
показатели собираются из уже существующей общей ленты денег (`GET /finance/operations`, оплаты, возвраты и операции кассы).

## Что строим
- Домен `packages/domain/src/finance/cashflow.ts`, `buildCashFlow(rows, from, to)`: по дням и за период
  - **Поступления** (проведённые оплаты) с делением «в кассе» (живые способы) и «вне кассы» (EXTERNAL, DEPOSIT, CARD_GUARANTEE);
  - **Возвраты** (так же с делением);
  - **Чистые поступления** = поступления минус возвраты;
  - **Приход кассы** и **Расходы** кассы, расходы по статьям; переводы между кассами в потоке не участвуют;
  - **Денежный поток** (по кассе) = поступления в кассу − возвраты из кассы + приход кассы − расходы.
  Аннулированные строки не входят. Начисления, долг и прибыль сюда не примешиваются.
- API `GET /finance/cashflow?from&to` (право `reports`, период до 366 дней): тот же отбор, что у `/finance/operations`, читает
  все строки периода; если строк больше предела выгрузки (20 000), ответ честно помечен `truncated`.
- Экран `/reports/finance`: шесть плиток (Поступления, Возвраты, Чистые поступления, Расходы, Приход кассы, Денежный поток),
  таблица по дням с итогом, расходы по статьям, подпись базы каждого числа; вкладка «Финансы» в оболочке «Отчёты».

## Что не входит (следующие срезы)
Остаток кассы на дату, долг на дату с возрастной разбивкой (нужна дата аннулирования начисления, Q-292), сравнение с прошлым
периодом, выгрузка CSV этого отчёта.

## Проверки
Домен: красные тесты на каждое правило (способы, аннулирование, переводы, границы суток, статьи, сумма дней равна итогу).
API: контроллер, замок прав (`route-access`), период и предел. UI на подставном API: плитки равны ответу API, итог таблицы равен
плиткам, axe в двух темах, телефон 390 px.
