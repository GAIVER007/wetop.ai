# Брони v2 — срез R3: быстрый просмотр брони справа (28.09.2026)

**Основание:** «да» владельца по снимкам R2 (28.09.2026) и ТЗ «Брони v2» §18–19, §21, §23, §46, §59, §65
(R3 — quick preview drawer). Решение — продолжение **ADR-106**. По AGENTS.md §1 код начинается только
после подтверждения этого плана. После R3 — визуальный стоп, R4 (действия по статусу) отдельным «да».

## 1. Что есть сейчас (аудит)

- Клик по ячейке «Бронь / гость» открывает справа панель 480 px: перехватывающий маршрут
  `app/@drawer/(.)reservations/[number]` рендерит **целиком** страницу `reservations/[number]/page.tsx`.
  В ней полоса фактов (гость, даты, место, гостей, стоимость, к оплате), вкладки «Обзор / Счета /
  Действия / История», формы оплаты, продления, переселения, отмены.
- Кликабельна только первая ячейка строки. Двойного клика нет. «Назад» закрывает панель и
  возвращает тот же список (router.back).
- Данных для просмотра хватает: `GET /chessboard/reservations/:number` (проживания с ячейкой,
  категорией, гостями, уборкой) и `GET /finance/reservations/:number` (начислено, оплачено,
  возвращено, остаток). Оба уже ограничены объектом организации (ADR-061, RLS ADR-103).

ТЗ §21 прямо просит не держать всю бронь в панели. Сейчас там именно вся бронь.

## 2. Что делает R3

**Панель открывается с короткого просмотра по §19**, а полная карточка уходит на свою страницу.

Первый экран панели, сверху вниз:

| Блок | Содержимое | Откуда |
|---|---|---|
| Шапка | номер брони моноширинным, статус словом о брони (как в списке, Q-135) | карточка |
| Гость | имя; телефон со скрытыми цифрами `+7 *** *** ** 12` (§11, §19); кнопки «Позвонить» и «WhatsApp» без показа цифр; «Открыть гостя» (§59) | карточка |
| Проживание | `24 → 27 сент.`, число ночей, пометки «заезд / выезд сегодня» | карточка |
| Размещение | одиночная: ячейка и категория или «⚠ без ячейки»; групповая: «N размещений» и список по проживаниям — ячейка или «⚠ без размещения», категория, гостей, даты, если отличаются от брони (§23) | карточка |
| Финансы | Итого, Оплачено, Возвращено и одной строкой состояние — теми же словами, что колонка «Финансы» (`finance-state.ts`); сбой счетов — «Финансы временно недоступны», остальное на месте (§46) | финансы брони |
| Источник | стойка / сайт / канал | карточка |
| Внизу | «Открыть бронь» — полная страница | — |

**Действия в R3 не теряются.** Сегодня смена оплачивает и переселяет прямо из панели, и отнимать
это до R4 нельзя. Поэтому под просмотром остаются прежние вкладки «Счета», «Действия», «История» с
теми же формами, без изменений. В R4 их место займут действия по статусу (§20), а невозможные
действия пропадут.

**Строка списка:**
- щелчок по любой ячейке открывает просмотр; щелчок по ссылке внутри строки работает как ссылка;
- двойной щелчок открывает полную страницу брони (§21);
- клавиатура: фокус по-прежнему на ссылке первой ячейки, Enter открывает просмотр;
- при наведении строка слегка подсвечивается (§36, без кнопок — они в R4);
- «Назад» и Esc закрывают панель, список, отбор из адреса и прокрутка остаются (§66.21).

**Телефон:** та же панель во всю ширину экрана, как сейчас (`.ui-drawer`, `min(480px, 100vw)`).

## 3. Чего R3 не трогает

API, схему, команды, формы действий (`actions-panel.tsx`, `finance-panel.tsx`), полную страницу брони
(перестройка — R5), «Показать на шахматке» и контекстное меню (R4/R7), поиск по Enter (§31, отдельно).
Разделение данных не меняется: новых путей по id нет, панель читает те же ограниченные эндпоинты.
«Только чтение» (ADR-102) работает общим механизмом: просмотр читается целиком, запись закрыта API.

## 4. Как сделано

- DESIGN.md §8: строка «Быстрый просмотр брони» до кода (правило §18).
- `reservations/[number]/preview.tsx`: серверный компонент просмотра; чистые функции (маска телефона,
  сводка размещений, строки финансов) — отдельным модулем с юнит-тестами.
- Маршрут `@drawer/(.)reservations/[number]`: просмотр + прежние вкладки «Счета / Действия /
  История» из страницы брони (выносятся в общий компонент без изменения разметки форм).
- Строки списка: маленький клиентский компонент на `tbody` — делегирует щелчок и двойной щелчок
  ссылке строки, пропуская щелчки по ссылкам и кнопкам.
- Подставной API UI-стенда: без изменений, если данных хватит; иначе — только витринные карточки.

## 5. Проверки и стоп

- Юнит: маска телефона (короткий, пустой, с «+»), сводка групп, строки финансов для всех состояний
  `financeState`, red → green.
- UI: щелчок по ячейке «Финансы» открывает просмотр, а не полную карточку; двойной щелчок — полная
  страница; «Назад» — тот же адрес с отбором; групповая бронь раскрыта; отменённая с возвратом;
  сбой счетов; «только чтение»; телефон 390.
- Регрессия: unit, typecheck, lint, integration, живые e2e, весь UI-набор `--workers=1`.
- Снимки стоп-гейта, светлая и тёмная тема: просмотр подтверждённой с долгом, проживающей,
  отменённой с «к возврату», групповой с частичным размещением, «только чтение», телефон 390;
  `reports/reservations-v2-r3-2026-09-28/`.

## 6. Решения владельца (28.09) и уточнение после аудита

Владелец: «давай делай как надо» — оба вопроса решены по рекомендации: прежние вкладки действий
остаются в панели до R4; телефон в панели скрытыми цифрами, кнопки «Позвонить», WhatsApp, Telegram
остаются.

Уточнение: панель, которую открывает строка, — это одобренная карточка **B3 (19–20.09, DESIGN.md §8)**:
полоса фактов над вкладками, следующее действие первым, проживания карточками, печать внизу; её
держит `manager-actions.spec.ts`. Поэтому R3 не заменяет её новым экраном, а доводит до §19 тем,
чего в ней нет:

1. **Строка списка** открывает панель щелчком по любой ячейке; двойной щелчок — полная страница;
   подсветка при наведении. Первая ячейка остаётся ссылкой — клавиатура и фокус как были.
2. **«Открыть бронь»** в шапке панели — полная страница вместо панели. Сначала шаг назад в документе
   списка, потом переход: в истории «список → бронь», «Назад» с полной страницы ведёт в список.
3. **Телефон в панели** скрытыми цифрами `+7 *** *** ** 12` и кнопки «Позвонить» / WhatsApp /
   Telegram. На полной странице номер целиком, как был.
4. **Полоса фактов: «Оплата»** вместо «К оплате» — теми же словами, что колонка «Финансы» списка
   (`finance-state.ts`): у отменённой брони больше нет «оплачено» при деньгах к возврату. Сбой счетов —
   «Финансы временно недоступны» (§46). Групповая бронь — «⚠ K без размещения», как в списке.
5. **«Финансы» в «Обзоре» панели:** итого начислено, оплачено, возвращено (§19).

Пункты 4 — на полосе и в панели, и на полной странице (одна полоса, один смысл слов); 1–3 и 5 —
только список и панель.
