# Срез «Хвосты P0 паритета с zapis.kz», 19.10.2026

Основание: карта `plans/zapis-parity-2026-10-19.md` (сверка 56 задач отчёта zapis.kz с кодом main b19e9e90),
поручение владельца: «Начинай с хвостов P0 из карты: мелкие дыры карточки записи, клиентов, мастеров,
плюс дешёвые C2/J1/B4».

Диагноз по каждому пункту - в карте паритета (ссылки file:line там). Этот срез берёт то, что не требует
правки модели данных. Поля клиента (пол, источник, второй телефон) и контакты филиала требуют миграций,
они идут следующим срезом после записи в DATA_MODEL.md.

## Состав среза (без изменений схемы и миграций)

| # | Пункт карты | Что делаем | Как проверяем (red → green) |
|---|---|---|---|
| 1 | N2 | Текст ИИ-продавца «подбор размещения» зависит от направления | unit на текст по вертикали |
| 2 | J1 | Пункт плоского меню для салона: «Склад», не «Бар» | unit навигации по вертикали |
| 3 | A3 | Итоговая длительность визита в форме записи (сумма строк) | unit формы: 3 строки → «Итого: 1 ч 45 мин» |
| 4 | C2 | Реестр: колонки «Автор» и «Источник» (createdBy уже в БД, source уже в БД); выгрузка CSV за период | unit API view (+2 поля), spec реестра, unit CSV |
| 5 | A5 | Выбор клиента: автодополнение по мере ввода; кнопки «Гость» и «Последний клиент» | unit формы + beauty-ui spec |
| 6 | A4 | Список платежей в карточке записи (операции кассы по appointmentId) | unit API (+payments list), spec карточки |
| 7 | H1 | Касса: у операции с записью ссылка на запись; карточка записи ссылается на кассу | unit API кассы (+appointmentId наружу), spec |
| 8 | B4 | Границы сетки журнала от часов салона (137), а не жёстких 08-20 | unit api bounds: салон 10-22 → сетка 10-22 |
| 9 | E5 | «В архив / Вернуть» из карточки мастера; подпись «Активен» в форме создания | unit + beauty-ui spec |

Не входит (следующие срезы): D1/M1 (миграции полей клиента и филиала), D2 XLSX полным путём,
E1 одна поверхность мастера, E4 приглашение из карточки, F2 расчёт салона в портале (политика ЗП),
все крупные НЕТ (K1 сообщения, G3 акции, H2-H4 счета и P&L, D5 баланс).

Права, API-контракты и деньги не меняются; новые поля ответов API - только чтение уже хранимых колонок.
