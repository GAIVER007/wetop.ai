# SEC-1a: production не стартует без роли с RLS (аудит 29.09.2026)

Первая часть SEC-1 из решения владельца (порядок SEC-4 → SEC-2 → SEC-1). Часть SEC-1b (гранты `wetop_app` на `users`,
`platform_admins` и служебные таблицы) — отдельным планом после разбора обращений к этим таблицам.

## Проблема

`createPrismaClient` (`packages/database/src/index.ts:57`): без `DATABASE_APP_URL` запросы организации молча идут в
пул служебной роли, для которой политики RLS не действуют. Проверки при старте нет. Ошибка в `.env` при выкладке
превращает изоляцию между организациями в прикладные фильтры, и любой пропущенный `propertyId` — IDOR между организациями.

Второй способ сломаться молча: в `DATABASE_APP_URL` попала строка не той роли (копия `DATABASE_URL`).

## Что проверено на production (владелец, 29.09.2026)

- API держит 5 соединений ролью `wetop_app` (`pg_stat_activity`).
- `wetop_app`: вход включён, `rolbypassrls = false`; `wetop_service`: без входа, `BYPASSRLS`.
- Политик `rls_tenant` 43. Проверка при старте на этом состоянии проходит.

## Что делаем

`assertRlsAtStartup(env)` в `@pms/database`, вызывается из `apps/api/src/main.ts` до `NestFactory.create`.

| Условие | Результат |
|---|---|
| `NODE_ENV` не `production` | проверки нет: разработка и тесты работают как раньше |
| `RLS_DISABLED=1` | проверки нет, предупреждение в журнал API |
| production, `DATABASE_APP_URL` пуст | отказ старта |
| production, роль соединения не `wetop_app` | отказ старта |
| production, у роли `BYPASSRLS` или суперпользователь | отказ старта |
| production, роль проверить не удалось | отказ старта (сообщение с кодом ошибки, без адреса и пароля) |
| production, `wetop_app` без `BYPASSRLS` | старт |

Роль определяется запросом `current_user` через одно разовое соединение по `DATABASE_APP_URL`, а не по имени в адресе:
адрес пулера содержит `wetop_app.<ref проекта>`, база называет роль `wetop_app`.

## Порядок выкладки

Production уже соответствует условиям (см. выше), поэтому новая версия API стартует. Перед выкладкой владелец может
проверить те же условия запросом из `docs/ops/rls.md`. Откат — прежний образ; либо `RLS_DISABLED=1` в `.env` на время разбора.

## Не делаем здесь

Гранты `wetop_app` и миграции (SEC-1b), правки выборок, смена ролей.
