## Что вышло иначе, чем в аудите

- **UUID в гостях и финансах не сделан.** Тесты этих контроллеров ходят с фиктивными идентификаторами `g1`, `f1`, `nope`:
  `ParseUUIDPipe` сломал бы все. Форму ошибки базы на неверный UUID без живой базы не воспроизвести, поэтому общий
  фильтр по коду Prisma писать вслепую не стал. Нужен отдельный шаг: интеграционный тест на `pms_test`, чтобы увидеть
  настоящую ошибку, затем либо фильтр, либо замена фиктивных id в тестах на UUID.
- **Лимит смены пароля** — по адресу (20 в час) и по сессии (10 в час, ключ окна — отпечаток ключа сессии), без счётчика
  на учётной записи: блокировка учётки чужими попытками из украденной сессии — отдельное решение.

## Сознательно не делаем здесь

- **HSTS** — включается в Cloudflare (зона), в коде остаётся липкий след в браузерах; решает владелец.
- **Обновление `@nestjs/platform-express`, `cryptography`** — отдельный PR зависимостей.
- **Токены в query-строке, регистрация без перечисления почт, куки `__Host-`** — меняют пользовательские сценарии, отдельное решение.
- **`bodySizeLimit: '11mb'` у server actions** — нужен для загрузки знаний ИИ-продавца, per-action Next не задаёт.
- **Отчёты CSP** — приёмника нарушений пока нет: report-only показывает их только в консоли браузера. Приёмник — следующий шаг.

## Порядок и правила

Сначала красный тест, потом правка (AGENTS.md §6). Прогоны — `npm run test:record`. Коммит — явным списком файлов.
Миграций нет, выкладку делает владелец по `docs/deploy.md`.
