# Срез 3 плана развития: ИИ-продавец оформляет бронь в чате (03.10.2026)

Основание: сценарий владельца 30.09.2026 (бронь `CONFIRMED` сразу после явного согласия, без предоплаты, место занято,
ответ с номером в исходный канал, повтор без дубля, телефон из канала), срок котировки 30 минут (01.10.2026),
ADR-143, план `plans/wetop-unified-roadmap-2026-10-03.md` (X1), модель `DATA_MODEL.md` §24. Предыдущий план
`plans/whatsapp-booking-2026-09-30.md` выполнен этим срезом.

## Платформа

1. Миграция `20261003000046_seller_booking_intents` с `down.sql`: таблица намерений, CHECK канала (`whatsapp`,
   `widget`), дат, гостей, суммы и «подтверждено ⇔ есть бронь», UNIQUE(agent, сообщение согласия), RLS по организации.
2. Узкий ключ записи `SELLER_BOOK_KEY` (`serviceKeyKind` → `seller-book`): только `POST /bot/booking-intents` и
   `POST /bot/booking-intents/confirm`; ключ котировки туда не пускается.
3. `BookingIntentsService`: котировка тем же расчётом, что у виджета (`quoteForAgent`): категория должна вмещать гостей,
   быть открыта и свободна; организация, объект и тариф сайта из строки агента. Подтверждение: своё, не истекшее,
   ключ согласия не занят другим сообщением; бронь через `ReservationsService.create` с `creationKey = id намерения` и
   `expectedTotalMinor`: повтор возвращает ту же бронь, изменившаяся цена или занятые места закрывают намерение
   (`REJECTED`) и требуют новой котировки. Гость псевдонимом, пока база вне РК (ADR-018). Источник WHATSAPP или WEBSITE.

## Бот

1. `src/ai/seller_booking.py`: инструменты `book_quote` (предложение, Redis на 30 минут, модель обязана спросить «да»)
   и `book_confirm` (бронь только при явном «да» гостя в сообщении этого хода, проверяет сервер бота по закрытому
   списку фраз на ru, kk, en, zh; телефон WhatsApp из канала, в чате сайта гость даёт телефон; Telegram без брони).
2. Клиент `WetopProviders.create_booking_intent` и `confirm_booking_intent` с ключом `INTEGRATION_BOOK_KEY`.
3. Сообщение хода передаётся инструментам через `incoming_var` из обвязки канала (`widget_runner.py`); ядро
   `engine.py` не тронуто. Ограничение то же, что у подтверждения действий помощника (S6): сообщение, разобранное из
   очереди занятого диалога, видит текст сообщения, которое держало замок.
4. Роль в системном промпте продавца: «помогаешь забронировать», бронь только после явного «да».
