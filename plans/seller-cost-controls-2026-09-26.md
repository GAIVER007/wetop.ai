## Решения владельца до кода

- **Р1. Дневной предел.** Рекомендую 150 000 токенов в сутки на гостиницу на ключе платформы (порядка 50–100 ходов);
  при ключе партнёра предел платформы не действует — это его расход. Превышен — продавец не зовёт модель, гостю
  отвечает «передам администратору», владельцу — один алерт в сутки.
- **Р2. Колонки в базе бота** для точной цены: у ответа — модель, входные, кэшированные и выходные токены
  (миграция бота + `down`). Без них отчёт — только по сумме токенов.
- **Р3. Второй путь.** Аварийная ступень — через отдельный адрес и ключ поставщика напрямую
  (`LLM_EMERGENCY_BASE_URL`, `LLM_EMERGENCY_API_KEY`, только ключ платформы). Для гостиниц с ключом партнёра второго
  пути нет (Q-186).
- **Р4. Отчёт** — сначала командой бота; в «Платформа → Организации» — следующим шагом (это правка контракта бота).

## 1. Дневной предел на гостиницу

- **Что:** перед вызовом модели — расход гостиницы за сегодня (сутки по Алматы) из `messages.tokens_used`; выше
  предела — модель не зовём, ответ-передача, алерт один раз в сутки.
- **Почему:** сейчас предела нет, бюджет платформы ничем не защищён.
- **Файлы:** `src/config.py` (`LLM_DAILY_TOKENS_PER_ORG`, 0 — выключен), `src/ai/budget.py` (новый: расход за сутки),
  `src/ai/engine.py` (проверка до каскада), `src/alerts/raise_alert.py` (вид алерта), `tests/test_budget_daily_cap.py`.
- **Чего не трогаем:** помощника (`organization_id IS NULL`), каскад, защиту, маскировку, гостиницы с ключом партнёра.
- **Готово, когда:** тесты красные на нынешнем коде → зелёные: ниже предела — ответ модели; выше — модель не вызвана,
  ответ-передача, алерт ровно один; с ключом партнёра — предел платформы не срабатывает.

## 2. Второй путь к модели

- **Что:** аварийная ступень может идти своим адресом и ключом, если заданы `LLM_EMERGENCY_BASE_URL` и
  `LLM_EMERGENCY_API_KEY`.
- **Почему:** все три ступени сейчас зависят от одного шлюза.
- **Файлы:** `src/config.py`, `src/ai/llm.py` (второй клиент только для аварийной ступени),
  `tests/test_llm_emergency_route.py`. Имена переменных — владельцу вписать в `env.example`.
- **Чего не трогаем:** основную и запасную ступени; ход с ключом партнёра.
- **Готово, когда:** тест: основной шлюз не отвечает → аварийная модель отвечает через второй адрес; без переменных
  поведение прежнее (старые тесты каскада зелёные).

## 3. Отчёт о расходе за месяц

- **Что:** `python -m src.jobs.usage_report --month 2026-09` — по гостиницам: диалогов, ответов, токенов (с Р2 — вход,
  кэш, выход и оценка стоимости по ценам моделей из настроек).
- **Почему:** цена ИИ-продавца — от расхода на гостиницу (ментор).
- **Файлы:** `src/jobs/usage_report.py` (новый), `tests/test_usage_report.py`.
- **Чего не трогаем:** контракт с платформой (Р4).
- **Готово, когда:** тест на двух гостиницах и помощнике: суммы раздельно, помощник в отчёт не попадает.

## 4. Кэш входа (после Р2)

- **Что:** писать модель и разбивку токенов из ответа поставщика; для моделей Claude через шлюз — метка кэша на
  первом системном сообщении.
- **Почему:** проверить совет ментора цифрами — какая доля входа идёт по цене кэша.
- **Файлы:** миграция бота (`migrations/`), `src/db/models.py`, `src/ai/llm.py`, `src/ai/engine.py`, тесты.
- **Чего не трогаем:** порядок частей промпта (он уже правильный).
- **Готово, когда:** тест на подделке ответа: поля пишутся в сообщение; в отчёте видна доля кэша.
