# Настройки: только рабочие разделы

Запрос владельца 20.09.2026: пройти настройки, упростить структуру и убрать
лишние страницы фотографий и удобств, которыми управляют в каналах.

## План реализации

1. В боковом меню оставить три входа: «Гостиница», «Интеграции», «Сайт».
2. Вместо страницы с шестью одинаковыми ссылками показать сведения PMS
   и расчётные часы. Внутри гостиницы оставить «Общие», «Услуги»,
   «Правила отмены». Последнее название соответствует сохранённой
   политике тарифов, а не начисленным штрафам гостей.
3. Убрать зеркала фото, удобств и гостевого описания Channex из настроек.
   Старые photo/amenities URL ведут в блок Channex на «Интеграциях»;
   description/check-in ведут к соответствующей области общих настроек.
   Не удалять данные или API контента, не записывать ничего в каналы.
4. Услуги: поиск по названию/коду/группе, аккуратный каталог цен,
   понятный переход к начислению в карточке гостя. Правила отмены:
   фильтры тарифов и статуса; существующие определения и деньги сохраняются.
5. Интеграции: единая структура состояния базы/Channex/сайта, рабочие
   кнопки проверки и переходов; локальный сбой не скрывает остальные блоки.
6. Сайт: понятные настройки доменов и бронирования; технические ключи,
   код установки и инструкции раскрываются при необходимости.
   Сохранить существующие server actions, подтверждения удаления,
   проверку счётчика, паузу/возобновление и ошибки форм.
7. RED/GREEN для навигации, redirect, фильтров и отказа независимого API.
   Проверить mobile/desktop, темы, клавиатуру, сохранение существующих
   настроек сайта на синтетическом API, обращения к реальному API только чтением.
8. Typecheck, lint, build, релевантные тесты, commit/push/PR и попытка
   штатного deploy с отдельным доказательством версии сервера.

## Границы

Модель и API записи не расширяются. Сведения гостиницы, расчётные часы,
каталог услуг и политики отмены сейчас доступны API только для чтения.
Не рисовать кнопки сохранения там, где нет утверждённого API. Сайт остаётся
редактируемым через существующие действия. Миграции и внешние записи не входят.

## Проверка рабочего дерева

До начала реализации проверены tests/runs/.locks/ (пусто), git status и
список активных задач приложения. Другой активной задачи WETOP не обнаружено.
Все девять файлов с суффиксом ` 2.ts` в apps/, packages/, scripts/ побайтово
совпали с закоммиченными версиями истории Git, включая отличавшийся от HEAD
sessions.controller.test (версия 7bdd0e78). Это сохранённые копии прежнего
кода, а не обнаруженная новая незакоммиченная реализация. Их не менять,
не удалять, не включать в тестовый набор и коммит. Прежние планы и Q-154
остаются отдельной незавершённой работой.
