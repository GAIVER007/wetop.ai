# Вход и регистрация окном на wetop.ai, «Заполнить позже» в онбординге, обучение в стойке (27.09.2026)

Поручение владельца 27.09.2026 (сессия, скриншоты `wetop.ai/#start` и `app.wetop.ai/login`):

1. «Войти» на wetop.ai перекидывает на `app.wetop.ai/login`. Надо: окно входа поверх той же страницы, почта и пароль,
   после входа — сразу в систему.
2. «Оставить заявку» переименовать («Создать аккаунт» / «Получить доступ») и открывать не раздел «Как начать», а
   регистрацию нового аккаунта со стандартными полями. Письмо подтверждения через Resend, после подтверждения аккаунт
   активен и открывается онбординг — с кнопкой «Пропустить, заполнить позже».
3. После первого входа — путь обучения: «тут эта кнопка, там это».

План утверждён самим поручением («распиши полноценный план и иди по нему»).

## Что уже есть в `main` (не делаем заново)

| Что | Где | Решение |
|---|---|---|
| Регистрация: почта, имя, название гостиницы, пароль | `apps/web/src/app/register`, `POST /auth/register` | ADR-046, 053, 060, 098 |
| Письмо «подтвердите почту» через Resend, ссылка → сессия | `email-verification.service.ts`, `/login/verify` | ADR-046, Q-137 |
| Онбординг «Настройте отель» и гейт, пока нет номеров | `app/onboarding`, `onboarding-gate.tsx` | plans/onboarding-2026-09-21.md |
| Панель «Первые шаги» на Главной до первой брони | `today/first-steps.tsx` | ADR-098 |
| На сайте «Регистрация» вместо «Оставить заявку» | `apps/site` | ADR-098 |

**Почему на живом сайте всё ещё «Оставить заявку»:** сайт на Cloudflare Pages не перевыкладывался после ADR-098
(`npm run site:deploy` за владельцем, ADR-098 «Порядок включения»). Эта правка сайта выйдет той же выкладкой.

## Развилки и выбор

**Д1. Как сделать окно входа на статическом сайте.** Сайт — статический экспорт без сервера; кука сессии живёт на
`app.wetop.ai` (`HttpOnly`, ставит стойка).

- (а) `<iframe>` страницы входа стойки в окне сайта. Просто, но окно чужого вида, двойная тема, `postMessage`.
- (б) Своё окно на сайте, форма шлёт `fetch` на стойку: `POST https://app.wetop.ai/api/site-auth/login` с
  `credentials: 'include'`. Стойка зовёт тот же `authApi.login`, ставит ту же куку и отвечает `{ next: '/today' }`;
  сайт переводит браузер туда. wetop.ai и app.wetop.ai — один сайт (same-site), кука `SameSite=Lax` ставится.
- **Выбрано (б).** Окно в дизайне сайта, ошибки словами API, те же пределы попыток (адрес посетителя уходит
  заголовком, как у серверного действия).

Защита: CORS только для списка источников (`SITE_ORIGINS`, по умолчанию `https://wetop.ai`, `https://www.wetop.ai`);
чужой `Origin` → 403 без обращения к API. Тело — только `application/json` (браузер делает предварительный запрос,
простую форму с чужого сайта не пошлёт). Ключ сессии в ответ не отдаётся — только кука.

Запасной путь: без JavaScript или при сбое связи кнопки остаются обычными ссылками на `app.wetop.ai/login` и
`/register`; в окне при сбое — ссылка «Открыть вход на отдельной странице».

**Д2. Название кнопки.** «Создать аккаунт» (владелец предложил его и «Получить доступ»). Подпись под кнопкой прежняя:
«7 дней бесплатно. Карта не нужна.»

**Д3. «Заполнить позже» в онбординге.** Гейт уводит на `/onboarding`, пока у объекта нет категорий. Отметка «позже»
в базе — правка модели (AGENTS §2), поэтому храним её кукой браузера `wetop_onboarding_later` (30 дней). Гейт её
уважает; на Главной «Первые шаги» первым пунктом ставят «Настройте номера и цены» со ссылкой на `/onboarding`,
пока номеров нет. Новый браузер снова предложит онбординг — это честно: номеров-то нет.

**Д4. Обучение.** ТЗ `plans/ux-retention-2026-09-26.md` §8 отказалось от тура с всплывающими шагами в пользу
«Первых шагов». Владелец 27.09 прямо попросил тур — решение владельца отменяет этот пункт (ADR-100). «Первые шаги»
остаются: тур показывает, где что, панель ведёт к первой брони.

- Тур сам стартует один раз на Главной у вошедшего, если объект уже настроен или онбординг отложен.
- Шаги привязаны к элементам через `data-tour`: поиск, «Работа с гостями» (Главная, Шахматка, Брони, Гости),
  «Номерной фонд», «Продажи» (тарифы, каналы, ИИ-продавец), «Финансы и отчёты», «Настройки», пробный период,
  профиль, чат помощника. Элемента нет на экране (закрыт по доступу, телефон) — шаг показывается окном по центру
  без подсветки или пропускается.
- «Далее», «Назад», «Пропустить», Esc, стрелки; фокус в окне; `role="dialog"`, счётчик «3 из 9».
- Отметка «пройдено» — `localStorage` на пользователя (`wetop.tour.v1:<id>`); без базы (правка модели не нужна).
- Повторить: пункт «Обучение: как устроена стойка» в меню профиля.

## Шаги

1. **Стойка — вход и регистрация для сайта.** `apps/web/src/app/api/site-auth/{options,login,register,resend}/route.ts`
   и чистый модуль `lib/site-auth.ts` (разбор источника, заголовки CORS, проверка тела). Тесты — сначала красные.
2. **Сайт — окно.** `components/auth-dialog.tsx` (клиентский, нативный `<dialog>`): вкладки «Вход» / «Создать аккаунт»,
   экран «Проверьте почту» с «Выслать ещё раз», «Регистрация временно закрыта», «Забыли пароль?» — ссылкой на
   стойку. Кнопки шапки, первого экрана, мобильного меню и «Как начать» открывают окно; `#login` и `#register` в
   адресе — тоже. Тексты в `i18n/ru.ts`, стили — токенами сайта (DESIGN.md §19), блок — в реестр §19.5.
3. **Онбординг.** Кнопка «Заполнить позже» (серверное действие ставит куку и ведёт на Главную), гейт её уважает,
   «Первые шаги» получают пункт «Настройте номера и цены». Подпись-шаги в шапке онбординга: «Шаг 1 из 2 — номера и
   цены», «дальше — короткое знакомство со стойкой».
4. **Тур.** `components/shell/product-tour.tsx` + `tour-steps.ts` (чистый список и выбор доступных шагов, тест),
   `data-tour` в меню, поиске, профиле; пункт повтора в меню профиля. Строка в DESIGN.md §8 до кода (ADR-048).
5. **Документы.** ADR-100, строка `CLAUDE.md` §2, `docs/deploy.md` — `SITE_ORIGINS`.
6. **Проверки.** `npm run test:record -- unit`, `typecheck`, `lint`; сборка сайта; снимок окна и тура в Chromium.
7. **Выкладка — за владельцем** (из облака нет доступа к серверу и Cloudflare): стойка — обычная выкладка
   (`docs/deploy.md`), затем `npm run site:deploy`; `REGISTRATION_OPEN=1` и миграция `20260926000025` — по ADR-098.

## Чего не делаем

- Не меняем API регистрации и модель данных: поля формы — те, что уже есть (имя, название гостиницы, почта, пароль).
- Не делаем вход через Google и т. п. — не просили.
- Не трогаем правила пробного периода (Q-141/143/144).
