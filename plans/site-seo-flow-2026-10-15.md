# «Сайт и SEO»: поток от филиала до заявок в календаре и продвижения (SITE/SEO)

Дата: 15.10.2026. Основание: поручение владельца 15.10.2026 (чат), ADR-149 (SiteSpec из проверенных блоков),
ADR-184 («Продвижение» единое для всех направлений), аудит `reports/sites-audit-2026-10-14/README.md`.
Связанный план модуля: `plans/promo-module-2026-10-15.md`.

## 0. Что хочет владелец (дословно по смыслу)

Филиал уже настроен (гостиница, салон или ресторан) → человек открывает «Сайт и SEO» → выбирает филиал → данные
филиала подтягиваются сами (адрес, цены, услуги/номера/меню, фото) → окно чата как в Lovable/Bolt (текст или
голос, подсказки) → три варианта дизайна на выбор или «другие варианты» → готовый сайт для сбора заявок → заявки
сразу встают в календарь (бронь номера / запись к мастеру / бронь стола) → правки → SEO продвигает сайт:
наполняет страницами и статьями.

## 1. Экран за экраном

### Шаг 1. Филиал
- Список филиалов организации с направлением и статусом сайта («нет сайта», «черновик», «опубликован»).
  Текущий филиал стойки выбран заранее. Один филиал — один сайт (Q-272).
- Справа карточка **«Что WETOP знает о филиале»** — без ИИ, из данных системы:

| | Гостиница | Салон | Ресторан |
|---|---|---|---|
| Основное | название, адрес, карта, телефон, WhatsApp | то же | то же |
| Каталог | категории номеров, цены «от» | услуги, длительность, цены | меню по категориям, цены |
| Люди | — | мастера и специализации | — |
| Время | заезд и выезд | часы работы, график | часы работы, сервис-периоды |
| Фото | фото номеров, библиотека | библиотека сайта | фото блюд, библиотека |
| Отзывы | оценки гостей | оценки визитов | оценки заказов |

- Чего не хватает — подсказки с кнопкой «Дополнить» (нет фото, нет часов, нет описания). Сайт можно делать и с
  пробелами, ИИ не выдумывает факты.

### Шаг 2. Чат (как Lovable)
- Одно поле ввода, микрофон (диктовка, ru/kk/en), отправка.
- Подсказки-чипы по направлению, например:
  - салон: «Сайт для записи на маникюр», «Акцент на мастерах», «Добавь акцию −20% на первое посещение»;
  - ресторан: «Сайт с меню и бронью столов», «Акцент на банкетах», «Покажи бизнес-ланч»;
  - гостиница: «Сайт с онлайн-бронированием», «Акцент на семейном отдыхе», «Покажи трансфер».
- ИИ задаёт 2–3 вопроса, только если ответа нет в данных филиала: цель (записи/брони/звонки), чем отличаетесь,
  есть ли акция. Ответы кнопками или текстом. Это существующий режим «План», ускоренный.

### Шаг 3. Три дизайна
- Три карточки с **живым мини-превью** главной страницы (тот же рендер, что у опубликованного сайта, на данных
  филиала, без вызова ИИ — мгновенно и бесплатно).
- Три заметно разных направления: «Светлый минимал», «Тёмный премиум», «Яркий тёплый» (тема + шрифт + раскладка
  hero + порядок блоков). Кнопка «Другие варианты» даёт следующую тройку.
- Выбор → ИИ пишет тексты под выбранный дизайн и цель (одна генерация).

### Шаг 4. Сайт для заявок (структура по умолчанию)
Сайт собирается как посадочная страница, задача которой — заявка:
1. Первый экран: оффер, город, кнопка «Записаться / Забронировать / Забронировать стол», рейтинг.
2. Почему мы: 3–4 преимущества из данных и ответов.
3. Каталог с ценами: номера / услуги и мастера / меню.
4. **Форма заявки** (виджет WETOP) — см. §2.
5. Отзывы.
6. Галерея.
7. Вопросы и ответы (FAQ, разметка FAQPage).
8. Контакты, карта, часы.
9. Повтор кнопки; на телефоне закреплённая кнопка «Записаться» и WhatsApp.
Доп. страницы: «Услуги»/«Номера»/«Меню», «Контакты», политика конфиденциальности.

### Шаг 5. Правки
Чат по всему сайту или по выбранному блоку, клик по блоку на превью, ручные поля, версии и откат (есть с MKT9).

### Шаг 6. Публикация
Адрес на домене платформы: `<имя>.wetop.ai` (§5, решение). Превью до публикации, одна кнопка «Опубликовать».

## 2. Форма → календарь (единая связь)

| Направление | Что выбирает посетитель | Куда попадает | Статус |
|---|---|---|---|
| Гостиница | даты, категория, гости | бронь в шахматке (`/w/book`, уже работает) | новая бронь, источник «Сайт» |
| Салон | услуга, мастер или «любой», время из свободных слотов | запись в календаре мастера | «Записан», источник «Сайт» |
| Ресторан | дата, время, количество гостей | бронь стола (план зала) | «Забронирован», источник «Сайт» |
| Любое | «Перезвоните мне» без слота | **заявка** во «Входящих» + задача ИИ-продавцу | «Новая заявка» |

Общее для всех: проверка свободного времени по тому же расписанию, что у стойки; защита от ботов (Turnstile),
лимиты частоты, повтор без дубля (ключ запроса); уведомление администратору (Telegram/WhatsApp) и
подтверждение клиенту; источник «Сайт» виден в аналитике и в бюджете (стоимость заявки).

## 3. SEO: контур продвижения после публикации

Вкладка «SEO» у сайта, пять блоков:

1. **Здоровье сайта** (авто, каждый день): заголовки и описания страниц, скорость, разметка schema.org по
   направлению (`Hotel`/`BeautySalon`/`Restaurant`+`Menu`, `LocalBusiness`, `FAQPage`, `AggregateRating`),
   карта сайта, языки ru/kk/en. Задачи «исправить» одной кнопкой.
2. **Запросы**: ИИ собирает семантику из направления, города, района и каталога («маникюр алмалинский район»,
   «хостел возле вокзала алматы», «бизнес-ланч абай»). Позже — реальные данные Google Search Console.
3. **Страницы под запросы**: услуга × район, тип номера, кухня/банкет — генерируются из каталога филиала,
   без выдуманных фактов. Черновик → «Опубликовать».
4. **Статьи**: план 4 статьи в месяц по запросам (уход после процедур, что посмотреть рядом с отелем, сезонное
   меню). ИИ пишет по фактам филиала; публикация — §5, решение.
5. **Карты и отзывы** (главный рычаг локального бизнеса): чек-лист Google Business Profile, 2ГИС, Яндекс Карт
   с одинаковыми названием/адресом/телефоном и ссылкой на сайт; просьба об отзыве после визита → отзывы на сайте.

Отчёт: показы и позиции (после подключения Search Console), заявки с сайта, стоимость заявки.

## 4. Бюджет

Пункт меню «Бюджет» объединяется с аналитикой: **«Бюджет и аналитика»** — одна страница с вкладками:
- **Сводка**: расходы, заявки по источникам (сайт, реклама, ИИ-продавец), стоимость заявки, выручка, ROMI;
- **Рекламный бюджет**: план месяца; расходы — ручные строки (как сейчас) плюс **автоматические из Meta**,
  которые подтягивает ИИ-таргетолог (источник «Meta», только чтение, без дублей);
- **Источники**: таблица по каналам.

Меню «Продвижение» после правки: Обзор · Сайт и SEO · Реклама · Конкуренты · Контент · Бюджет и аналитика.

## 5. Решения

| № | Вопрос | Предложение |
|---|---|---|
| D1 | Адрес сайтов клиентов на нашем домене | `<имя>.wetop.ai` (сертификат Cloudflare на `*.wetop.ai` бесплатный; `*.sites.wetop.ai` потребовал бы платный сертификат). Зарезервировать `app`, `api`, `www`, `admin`, `preview`, `mail` и т. п. Куки стойки остаются на `app.wetop.ai`. Пересматривает Q-271 (там был отдельный домен) |
| D2 | Статьи SEO | ИИ пишет черновик, публикация по кнопке владельца бизнеса (DATA_MODEL §29.10 запрещает автопубликацию ИИ). Автопубликация — только отдельным решением владельца |
| D3 | Заявка без слота | Новая сущность «Заявка» (site_leads) во «Входящих», ИИ-продавец перезванивает/пишет |

## 6. Срезы

| Срез | Что | Миграция |
|---|---|---|
| SITE-1 | Меню: «Сайт и SEO», «Бюджет и аналитика». Экран выбора филиала и карточка данных для всех направлений (чтение). Чат: чипы и голос. Три дизайна с живым мини-превью, новые сильно разные темы (включая тёмную) | нет |
| SITE-2 | SiteSpec v1: секции услуги, мастера, меню, часы, форма записи/брони стола; рендер, бриф и промпт генерации для салона и ресторана | нет (JSON) |
| SITE-3 | Лицензия конструктора и публикация для всех направлений: `tracked_sites.property_id` необязательный + `location_id`, триггер лицензии без ограничения HOSPITALITY | **да** |
| SITE-4 | Форма → календарь: публичные `/w/beauty/book`, `/w/food/reserve`; источник «Сайт» и ключ запроса у записей салона, `WEBSITE` у брони стола | **да** |
| SITE-5 | Заявки без слота (`site_leads`), уведомления | **да** |
| SITE-6 | Выкладка Worker `apps/sites` и wildcard `*.wetop.ai` | нет, доступ к Cloudflare |
| SEO-1 | Здоровье сайта, schema по направлениям, языки | нет |
| SEO-2 | Запросы и страницы под запросы | нет (страницы в SiteSpec) |
| SEO-3 | Статьи (план, черновики, публикация по кнопке) | возможно |
| SEO-4 | Карты и отзывы, Search Console | возможно |
| BUD-1 | «Бюджет и аналитика», источник расходов «Meta» | **да** (`marketing_expenses.source`, внешний id) |

Порядок: SITE-1 → SITE-2 → (миграции владельцем) SITE-3 → SITE-4 → SITE-6 → SEO-1…4; BUD-1 вместе с рекламой.
Каждый срез — PR в `main`, зелёный гейт, скриншоты владельцу.
