# Slice 3, шаг 3.4 — ручная бронь (план, 09.09.2026)

Источник требований: SPEC §4 (создание, изменение, аннуляция, переселение), DATA_MODEL §2
(Reservation → ReservationItem → Allocation; статус на проживании; `source` обязателен — Q-089),
ADR-006 (переселение = закрыть одну Allocation, открыть другую), ADR-008 (деньги integer minor units),
миграция 20260909000003 (овербукинг запрещает база). Ничего из этого не придумано здесь.

## Что делаем

| Операция | HTTP | Что происходит |
|---|---|---|
| Создать | `POST /reservations` | шапка + проживания (категория, даты, тариф, гостей) + контактное лицо (Guest + StayGuest); цена каждого проживания = **сумма `DailyRate` по ночам** для (категория, тариф, occupancy = гостей в проживании); нет цены хоть на одну ночь → 422. Ячейка — опционально (`unitCode`) |
| Изменить даты | `PATCH /reservations/:number/dates` | новые даты у шапки, всех проживаний и их назначений; цена пересчитывается по календарю; пересечение → 409 |
| Отменить | `POST /reservations/:number/cancel` | все проживания и шапка → `CANCELLED`, назначения удаляются (ячейки освобождаются). Штрафы/возвраты — вне шага (Q-091, Q-093) |
| Назначить / переселить | `POST /reservations/:number/items/:itemId/assign` | ячейка той же категории, активная; `fromDate` (по умолчанию заезд): старое назначение закрывается на `fromDate`, новое `[fromDate, выезд)`; пересечение с другой бронью или блокировкой → 409 |

Каждая операция — одна транзакция и одна запись `AuditLog` (`before`/`after`).

## Правила, взятые из документов (не решения агента)

- `source` обязателен, без значения по умолчанию (DATA_MODEL §2, Q-089 — самое строгое до ответа).
- Статус ведётся на проживании; статус шапки производный (DATA_MODEL §2 v0.3): все отменены → `CANCELLED`;
  иначе первый из `CHECKED_IN` → `CONFIRMED` → `TENTATIVE` → `CHECKED_OUT` → `NO_SHOW`.
- Одно проживание = одна ячейка (ADR-013); переселение через Allocation (ADR-006).
- Овербукинг ловит база: `isOverlapViolation` → HTTP 409 (миграция 20260909000003).
- Цена в minor units валюты тарифа; occupancy 1|2 (DATA_MODEL §5).

## Умолчания шага (сообщить владельцу, легко поменять)

- Новая ручная бронь создаётся сразу `CONFIRMED` (в Exely брони со стойки подтверждены сразу).
- Отменить и менять даты можно только у `TENTATIVE` / `CONFIRMED`; заселённого — нельзя (нужен выезд).
- Номер брони: `YYYYMMDD-XXXXXX` (дата создания в Asia/Almaty + 6 символов), уникален в объекте.
- Валюта шапки = валюта тарифа первого проживания; все проживания одной брони — в одной валюте, иначе 422.
