## 2. Изменения API — только чтение существующих данных

`GET /chessboard` (`apps/api/src/chessboard/*`, домен `packages/domain/src/chessboard/build.ts`):

| Поле | Куда | Откуда | Зачем |
|---|---|---|---|
| `cell.channel?: string` | `ChessboardAllocation`, `ChessboardCell` | `Reservation.channel` / `source` (`ReservationSource`) | бейдж канала (п. 3) |
| `cell.balanceMinor?: number` | `ChessboardCell` (только на клетке заезда) | `Folio` по проживанию, `balanceMinor` из `packages/domain/src/finance` | плашка «к оплате» (п. 4) |
| `row.unit.housekeeping` | `ChessboardUnit` | `Unit.housekeepingStatus` | бейдж уборки и фильтр (п. 5) |
| `unassigned[].guestLabel`, `balanceMinor` | `UnassignedStay` | заказчик брони, `Folio` | строка «Без ячейки» (п. 6) |

Модель данных не меняется (все поля уже есть в схеме). Деньги — integer minor units, в ответе как число тиынов;
форматирует `lib/money.ts` (`formatMoney`). Сумма к оплате — та же функция баланса, что в `/finance/*`,
без своей арифметики (ADR-008, AGENTS.md §15).

## 4. Порядок и доказательства (шаг 7 плана, п. 1–5)

1. Подтверждение этого плана и выбор В1.
2. Домен и API: красные тесты на новые поля (`build.test.ts`, `chessboard.service` unit) → зелёные;
   `npm run test:record -- unit`.
3. Экран: `tests/e2e/chessboard*.spec.ts` — сначала красные на слово статуса и окно подтверждения
   (проверка `role="dialog"` вместо `page.on('dialog')`), затем зелёные против живого API
   (`npm run test:record -- e2e tests/e2e/chessboard*.spec.ts --workers=1`).
4. Скриншот 1440×1000 и 1024×768 на синтетическом API сравнивается с макетом по участкам
   (шапка дат, полоса брони, строка «Без ячейки», меню) — список расхождений в отчёте
   `reports/slice-7-1-chessboard-<дата>.md`.
5. Сертификация Channex не затрагивается: `GET /chessboard` только читает, очередь ARI не меняется;
   `cli-ui-smoke.ts` 34/34 после среза.
6. Аудит шага 8 повторяется: `DESIGN_SLOP_UPDATE=1`, снимок и отчёт в коммит.

Чужие ошибки, найденные по пути, — списком в отчёте, не чиним.
