### Приём брони из канала — новая страница `/channels/events/[revisionId]`

| # | Что | Откуда данные |
|---|---|---|
| 10 | Цепочка «1. Ревизия Channex → 2. Бронь в PMS → 3. Ячейка на шахматке»: тип, как дошло, статус, канал, время объекта, `unique_id`, категория, даты, гостей, оплата канала; бронь — номер-ссылка, статус словом, период, стоимость, предоплата канала, к оплате, источник, плашка суммы; ячейка — код и категория, статус, период, ссылка на шахматку на эти даты | `external_events.payload` через `revisionFacts` (без `customer`, `guarantee`, `notes`, `guests` — ПД наружу не идут, ADR-018), бронь по `Reservation.externalId = unique_id`, остаток тем же `folioBalance` |
| 11 | Ревизия с ошибкой | «Бронь не создана: ревизия не обработана» и «Обработать заново» на месте |
| 12 | Неизвестная ревизия | «Страница не найдена», не пустая цепочка |

«Оплачено» как «стоимость минус остаток» не считается: на счёте бывают услуги и штрафы — показывается только
предоплата канала из самой ревизии. Сравнение «было → стало» при изменении база не хранит — показывается
текущее состояние брони.

## 2. API — только чтение существующих данных (перенесено из PR #9)

| Эндпоинт | Ответ |
|---|---|
| `GET /channels/channex/outbox/rows?status=&limit=` | `OutboxRow[]`: `kind`, `status`, `attempts`, `taskId`, `lastError`, `createdAt`, `sentAt`, `dateFrom`/`dateTo` (min/max по сообщениям), `roomTypes` (коды категорий по маппингу), `messages` |
| `GET /channels/channex/events?limit=&offset=&status=&type=&q=` | `{ rows: InboundEvent[], total }`; к строке — `uniqueId`, `otaName`, `confirmationNumber` |
| `GET /channels/channex/events/:revisionId` | `{ event, facts, categoryByRoomType, reservation, balances }` |

Модель не меняется. Чистые помощники с тестами: `outboxRowSummary(payload, mapping)`, `revisionFacts(payload)`
(`apps/api/src/channels`), `stayFacts` (`apps/api/src/chessboard/stay-facts.ts`, вынесен из шахматки и карточки).

## 4. Доказательства

1. Модульные: помощники и контроллер с фальшивым репозиторием (из PR #9, зелёные на этой базе).
2. UI на синтетическом API: новый спек плюс `workspace`, `manager-actions`, `design-reference`, затем полный набор.
3. Сквозные на локальном PostgreSQL 16 с сидом (25 спеков): `channex-certification` видит «закрыто» и цены по §14.
4. Снимки 1440: правка цены в ячейке, журнал интеграции, приём брони из канала.
