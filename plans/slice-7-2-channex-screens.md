## 2. API — только чтение существующих данных

| Эндпоинт | Что нового | Откуда |
|---|---|---|
| `GET /channels/channex/outbox/rows?status=&limit=` | строки очереди: `kind`, `dateFrom`/`dateTo` (min/max по сообщениям), `roomTypes` (имена категорий через маппинг), `messages` (число), `status`, `attempts`, `taskId`, `lastError`, `createdAt`, `sentAt` | `channel_outbox.payload` (массив сообщений ARI с `date_from`/`date_to`/`room_type_id`/`rate_plan_id`), `channel_mappings` |
| `GET /channels/channex/events?limit=&offset=&status=&type=&q=` | к строке события: `uniqueId`, `otaName`, `confirmationNumber` (бронь по `externalId`), ответ `{ rows, total }` | `external_events.payload.unique_id` + `reservations.external_id` |
| `GET /channels/channex/events/:revisionId` | событие + факты ревизии без ПД + бронь с проживаниями, ячейками и остатком счёта | те же таблицы, `folioBalance` |

Модель не меняется. Чистые помощники с тестами red → green: `outboxRowSummary(payload, mapping)` и
`revisionFacts(payload)` (что показывать наружу: `customer`, `guarantee`, `notes` не отдаём).
Полный ответ Channex база не хранит — сравнение «было → стало» при модификации не показываем (план 7.2).
