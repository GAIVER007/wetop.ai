# Срез 7.3 — Четыре действия управляющего с суммой до подтверждения (план, 16.09.2026)

**Статус: выполнен 16.09.2026** (отчёт `reports/slice-7-3-manager-actions-2026-09-16.md`) по поручению владельца «давай делай по порядку» (первый пункт списка после сведения
веток: `reports/mentor-plan-status-2026-09-16.md` §1 шаг 3). База — дизайн-система `main` (ADR-048): компоненты со
страницы `/design-system` (`ConfirmDialog`, `ActionMenu`, `AmountChip`), новых компонентов срез не добавляет.
Логика и решения взяты из среза 7.3 ветки PR #9 (`plans/slice-7-3-manager-actions.md` там же), где они были
подтверждены владельцем 15.09; API перенесён патчем, экраны собраны заново на компонентах текущей базы.

Документ ментора (часть 1, «боли стойки»): переселение с койки на койку, продление без повторного ввода, статус брони
из канала; часть 5, промпт «Действия из списка управляющего»: для каждого действия окно подтверждения или панель
сбоку и уведомление, одно имя действия на всём пути («Продлить» → «Проживание продлено»).

| 10 | Входящая бронь, которую PMS не смогла разобрать | только на `/channels` | плашка на шахматке «Входящая бронь требует разбора» из событий `FAILED`, действие «Разобрать» → `/channels` | Д4 |

Шахматка: окно переселения перетаскиванием остаётся `window.confirm` (та же категория, цена не меняется) — его
перевод на `ConfirmDialog` идёт в 7.4 вместе с остальными окнами вне карточки.

## 2. API — только чтение теми же функциями (Д5), перенесено из PR #9

| Эндпоинт | Ответ |
|---|---|
| `GET /reservations/:n/items/:i/move-preview?unitCode=&ratePlanCode=` | `{ unitCode, changesCategory, fromCategory, toCategory, nights, currentMinor, newMinor, ratePlanRequired, problem }` |
| `GET /reservations/:n/items/:i/extend-preview?nights=&ratePlanCode=` | `{ nights, departureDate, unitCode, addedMinor, newMinor, ratePlanRequired, nextNightsFree, problem }` |
| `GET /reservations/:n/cancel-preview?reason=cancel\|no_show&itemId=` | `{ reason, items: [{ itemId, unitCode, policy, dueNow, penaltyMinor }], totalPenaltyMinor }` |

`assign` / `extend` / `chargePenalty` считают теми же функциями (`repriceForUnit`, `priceAddedNights`, `penaltyFor`),
поэтому «сумма в окне = начисление» — это тест контроллера, а не обещание. Ничего не пишется, журнал и каналы не трогаются.
`DATA_MODEL.md` §6 получает абзац «Пересчёт при действиях стойки» — документация действующих правил, логика не меняется.
