## 1. Цель

Поручение владельца 12.09.2026: «берём код, который генерирует система, вставляем в сайт как счётчик —
он собирает всю аналитику посещений, источники и т. д.».

В Exely такого нет: раздел «Эффективность сайта» читает Google Analytics 4 (счётчик G-XLJ63SQTJ4), данных
за сентябрь — ноль, модуль бронирования Exely на объекте не подключён. Значит, строим своё:

```
сайт объекта  ──<script data-site=…>──▶  приёмник PMS (публичный)  ──▶  БД  ──▶  /analytics в PMS
```

Одна строка кода на сайт. Никаких Google-аккаунтов, данные сразу в нашей базе, без персональных данных.

**Доказательство готовности:** e2e-сценарий с контрольными числами (§11) сходится в ноль, плюс живая
проверка — событие с телефона через публичный адрес дошло до PMS (`reports/web-analytics-<дата>.md`).

## 2. Что входит и что нет

**Входит:** генерация кода счётчика; скрипт счётчика; публичный приёмник событий; хранение сессий,
просмотров и событий; экраны «Аналитика сайта» (сводка за период, посещаемость по дням, доля мобильных,
источники трафика, страницы, календарь спроса) и «Подключение» (код, статус «счётчик жив»).

**Не входит:** ревенью-метрики и распределение продаж по броням (это отчёты по броням, отдельный
разговор); конкурентная группа (SPEC п. 7); модуль бронирования для сайта (SPEC п. 6); привязка сессии к
брони — до появления формы бронирования на сайте связывать не с чем (задел в модели есть, §6);
геолокация по IP (IP не храним — §9); импорт истории из GA4 (вариант (в) ADR-025, позже, если нужно).

## 3. Как это работает

1. В PMS на `/analytics/setup` создаётся «сайт» (имя, домены). PMS выдаёт ключ `pms_…` и код:
   ```html
   <!-- PMS Luxx Aparts: счётчик посещений -->
   <script async src="https://<публичный адрес API>/a/pms.js" data-site="pms_5f3c9a1b2d4e"></script>
   ```
2. Владелец вставляет код в `<head>` сайта (Tilda/WordPress/самописный — Q-111).
3. Скрипт при каждой загрузке страницы шлёт `POST /a/hit` (см. §4). Приёмник проверяет ключ и домен,
   выводит источник и устройство, пишет сессию/просмотр (§5).
4. Экран `/analytics` считает метрики по определениям GA4 (те же, что в Exely — `docs/exely/analytics-2026-09-12.md`).

## 4. Счётчик (`/a/pms.js`, ~2 КБ, без зависимостей)

Что отправляет (`Content-Type: text/plain`, чтобы браузер не делал preflight-запрос; `navigator.sendBeacon`
при уходе со страницы, иначе `fetch` с `keepalive`):

```json
{ "k": "pms_5f3c9a1b2d4e", "v": "8d2f…", "s": "c1a4…", "t": "pageview",
  "u": "https://site.kz/rooms?utm_source=instagram&utm_medium=social",
  "r": "https://l.instagram.com/", "w": 390, "l": "ru-RU", "z": "Asia/Almaty", "ts": 1757664000000 }
```

| Поле | Что | Откуда |
|---|---|---|
| `k` | ключ сайта | атрибут `data-site` |
| `v` | ID посетителя — случайный UUID | `localStorage` (`_pms_v`); не cookie, к гостю не привязан |
| `s` | ID сессии | `sessionStorage` (`_pms_s`) + время последней активности; новая после 30 мин тишины или новой вкладки |
| `t` | тип: `pageview` · `ping` (раз в 15 с, пока вкладка видна) · `leave` · `event` | скрипт |
| `u`, `r` | адрес страницы и реферер | `location.href`, `document.referrer` |
| `w`, `l`, `z` | ширина экрана, язык, часовой пояс | браузер |
| `n`, `p` | для `event`: имя и параметры (≤ 2 КБ) | `pms('event', 'search', {arrival:'2026-10-01', departure:'2026-10-03', adults:2})` |

Поведение: перехватывает `pushState` (сайты-SPA); события, не ушедшие из-за обрыва сети, ждут в
`localStorage` до 24 ч и уходят при следующей загрузке; `pms('event', …)` — публичная функция для формы
поиска дат (календарь спроса). Путь `/a/…` и имя `pms.js` выбраны намеренно: списки блокировщиков рекламы
режут адреса со словами `analytics`, `collect`, `track`.

## 5. Приёмник (`POST /a/hit`, публичный)

- Без авторизации (как любой счётчик), CORS-ответ только для доменов сайта из `TrackedSite.hosts`;
  запрос с чужим `Origin`/`Referer` или неизвестным ключом получает 204 и не сохраняется (ничего не
  подсказывать спамеру).
- Лимиты: тело ≤ 4 КБ, путь ≤ 512, `props` ≤ 2 КБ и только ключи из allow-list (`arrival`, `departure`,
  `adults`, `children`, `category`, `rate`, `step`), ≤ 60 событий в минуту на посетителя, ≤ 600 в минуту на
  сайт (в памяти процесса; Redis — когда появится, ADR-011).
- Боты: User-Agent с `bot|crawler|spider|headless|lighthouse` — отбрасываются. (Playwright в e2e
  подставляет обычный UA.)
- Из запроса выводятся и сохраняются **только**: путь и заголовок страницы, хост реферера, `utm_*`,
  вид источника, тип устройства, семейство браузера и ОС, язык. **IP-адрес и полный User-Agent не
  сохраняются нигде, даже в журнале.**
- Классификация источника (домен): `utm_medium` ∈ {cpc, ppc, paid, paidsocial} или `gclid`/`yclid`/`fbclid`
  → `PAID`; `utm_medium` = email → `EMAIL`; `utm_source` задан → `SOCIAL`, если это instagram/facebook/tiktok/
  vk/telegram/whatsapp/youtube, иначе `REFERRAL`; реферер google/yandex/bing/duckduckgo → `SEARCH`;
  реферер из списка соцсетей → `SOCIAL`; иной чужой домен → `REFERRAL`; нет реферера или свой домен → `DIRECT`.
  `source` = `utm_source`, иначе хост реферера (`google.com`, `l.instagram.com` → `instagram.com`).
- Сессия ключом `(site_id, session_key)`: первый `pageview` создаёт запись с посадочной страницей и
  источником, дальше — `pageviews + 1`, `last_seen_at` по любому событию. Длительность = `last_seen_at −
  started_at` (ping раз в 15 с даёт время и на одной странице — GA4 считает так же).

Ответ всегда 204 за < 5 мс; запись в БД — после ответа, пачками (очередь в памяти, сброс раз в секунду или по
100 событий); при падении процесса теряется не больше секунды.

## 6. Модель данных — `DATA_MODEL.md` §11 (предложено, не утверждено)

`TrackedSite` (сайт + ключ + домены) → `WebSession` (сессия с источником и устройством) →
`WebPageview` (просмотр) и `WebEvent` (событие, например `search`). Все четыре — новые таблицы, существующие
не меняются. Задел на будущее: `WebSession.reservation_id` появится вместе с формой бронирования на сайте —
не сейчас. Миграция `20260912000009_web_analytics` — после «ок» на §11.

## 7. Отчёты и экраны

Паритет с Exely и что сверх него:

| Exely («Эффективность сайта») | У нас | Как считаем |
|---|---|---|
| Сессии | так же | число `WebSession` с `started_at` в периоде |
| Уникальные посетители | так же | `count(distinct visitor_key)` за период |
| Просмотры страниц | так же | сумма `pageviews` (повторные включены) |
| Страниц за сессию | так же | просмотры / сессии |
| Среднее время сессии | так же | среднее `duration_seconds` |
| Посещаемость сайта (график) | так же | сессии и посетители по дням |
| Посещения с мобильных (график) | так же + доля в тайле | `device = MOBILE` по дням |
| Источники трафика (график, распределение) | так же | по `source_kind` и `source`: сессии, посетители, просмотры, среднее время, доля |
| Календарь спроса | так же, если сайт шлёт `search` | `WebEvent.name = search` → по `props.arrival` |
| — | Отказы | сессии с одним просмотром и < 10 с |
| — | Страницы | топ путей по просмотрам |
| — | Статус счётчика | последнее событие, событий сегодня, домены |

Период: месяц (как Exely) и произвольный диапазон; даты — по часовому поясу объекта (Asia/Almaty).

API (localhost, как всё в PMS): `GET/POST /analytics/sites`, `GET /analytics/sites/:id/snippet`,
`GET /analytics/sites/:id/status`, `GET /analytics/sites/:id/summary|daily|sources|pages|demand?from&to`.
Публичные: `GET /a/pms.js`, `POST /a/hit`.

Экраны: `/analytics` (сводка, графики, источники, страницы, спрос — по правилам `dataviz`),
`/analytics/setup` (сайты, код для вставки, кнопка «Проверить»: страница ждёт первое событие).

## 8. Публичный адрес — жёсткое условие запуска

Приёмник должны видеть браузеры посетителей, а API слушает `127.0.0.1` и наружу выходит только быстрым
туннелем Cloudflare (`scripts/ops/channex-tunnel.sh`). **Адрес быстрого туннеля меняется при каждом
перезапуске** — код, вставленный на сайт, через день будет указывать на мёртвый хост, и в отличие от
Channex здесь нет опроса ленты, который подобрал бы потерянное. Поэтому:

- разработка и e2e — на `localhost`, публичный адрес не нужен;
- **живая проверка и запуск — только с постоянным адресом** (Q-112): именованный туннель Cloudflare на
  своём домене (бесплатно, нужен домен в Cloudflare) или хостинг API. До него счётчик на настоящий сайт
  не ставить.
- Тот же туннель сейчас пробрасывает **весь порт API** (`--url http://localhost:3001`), не только webhook.
  На постоянном адресе наружу должны смотреть только `/a/*` и `/channels/channex/webhook`; это условие
  записано в Q-112 и войдёт в `SECURITY.md` при запуске.

## 9. Персональные данные и право

Счётчик не собирает ПД: нет IP, нет полного User-Agent, нет cookies, нет имён/телефонов/почты, содержимое
форм не читается, `props` фильтруются по allow-list. ID посетителя — случайное число в `localStorage`
браузера, к гостю и брони не привязано. Это укладывается в ADR-018 (dev-БД в Сингапуре — только
обезличенное) и не требует согласия по 152-ФЗ/закону РК о ПД в части, где нет идентифицируемого лица.
Нужен ли на сайте баннер про счётчик, решает владелец (Q-113); скрипт умеет не запускаться до согласия
(`data-consent="wait"` + `pms('consent')`), если владелец так решит. Сигнал `navigator.doNotTrack` по
умолчанию не учитываем (GA4 тоже) — умолчание, легко поменять.

## 12. Умолчания (принимаются, пока владелец не скажет иначе)

- Сессия рвётся после 30 минут бездействия (GA4/Exely); ping раз в 15 с, пока вкладка видна.
- Уникальный посетитель = уникальный `visitor_key` за период; смена браузера = новый посетитель (как везде).
- Сырые данные хранятся 13 месяцев, дальше остаются только суточные итоги (агрегатная таблица — когда
  понадобится; на объёме хостела запрос по сырым строкам укладывается в миллисекунды).
- Один сайт по умолчанию; модель допускает несколько (мобильная версия, лендинг) — SPEC «архитектуру не
  делаем тупиковой».
- Скрипт грузится `async`, страницу не тормозит; при недоступном приёмнике сайт работает как ни в чём не бывало.
- Событий не из allow-list (`search`, `booking_step`, `phone_click`, `whatsapp_click`, `custom`) — нет.

## 14. Риски

| Риск | Что делаем |
|---|---|
| Быстрый туннель меняет адрес — код на сайте умирает | §8: на сайт только с постоянным адресом |
| Публичный приёмник — спам и мусор | ключ + домены + лимиты; чужое — 204 без записи |
| Блокировщики рекламы режут скрипт | пути `/a/pms.js`, `/a/hit` без стоп-слов; first-party домен при хостинге |
| Сайт-SPA не перезагружает страницу | перехват `pushState` |
| Проверка с телефона по Wi-Fi объекта покажет тот же источник | проверять через LTE; источник всё равно не по IP |
| Цифры разойдутся с GA4, если владелец оставит оба | определения те же; GA4 режется блокировщиками у части посетителей — наш счёт будет выше, это ожидаемо и объяснимо |
