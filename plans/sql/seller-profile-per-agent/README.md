# Профиль каждого агента — production cutover (разрешён и применён 30.09.2026)

Источник: подготовленная ветка `origin/claude/sa25-contract`, commit `0b345fed`, миграция `20260930000039_seller_profile_agent_key`. SQL обёрнут в транзакцию с lock_timeout 5s. После отдельного разрешения владельца канонический SQL добавлен в каталог миграций. В production применён вручную в транзакции и зарегистрирован с тем же checksum.

Изменение: ключ seller_profiles — agent_id вместо organization_id. Настройки рабочего продавца сохраняются; organization_id остаётся границей RLS. У организации можно сохранить отдельную инструкцию каждого агента. Удаления строк нет.

## Предварительные условия

- Приложение читает/пишет профиль по agent_id (текущий SellerProfilesRepository).
- Проверить SQL `SELECT seller_scope_assert()` и отсутствие agent_id IS NULL.
- Записать текущий SHA, ID образов API/web, число строк и хэши профилей без вывода текстов.
- Остановить конкурирующую выкладку штатным deploy lock; не удалять чужие lock-файлы.

## Backup и применение

1. На сервере создать закрытую директорию backup (umask 077).
2. Через существующее секретное окружение выполнить pg_dump --format=custom рабочей БД, без печати DSN и содержимого. Проверить архив командой pg_restore --list.
3. Выполнить migration.sql соединением владельца БД, ON_ERROR_STOP=1. При ошибке транзакция откатывается целиком.
4. Выполнить validate.sql: invalid_profiles = 0; PRIMARY KEY (agent_id). Число и хэши прежних профилей должны совпасть с backup snapshot.
5. После проверки зарегистрировать миграцию 039 в штатном Prisma-журнале и добавить тот же SQL в каталог миграций перед продвижением release. Не запускать SQL дважды.
6. Выкатить согласованные API/web, проверить health, SHA, чтение прежней инструкции и сохранение на отдельном тестовом агенте, не на рабочем продавце.

## Откат

До появления второй инструкции организации rollback.sql проверяет count и возвращает прежний ключ. Он НЕ удаляет инструкции.
После появления нескольких профилей откат схемы намеренно останавливается: использовать исправление вперёд либо восстановление backup только с отдельным решением владельца (восстановление теряет записи после backup). Откат приложения допускается только на версию, читающую по agent_id.
