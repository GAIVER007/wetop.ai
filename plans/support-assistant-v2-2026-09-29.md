## 1. Срезы

### S1 — кабинет техподдержки (этот PR)

Бот, список диалогов `GET /conversations` (новые параметры необязательны, прежний ответ не меняется):

| Что | Как |
|---|---|
| Пустые диалоги не показывать | `nonempty=1` — только диалоги, где есть хоть одно сообщение (отбор в SQL, до `limit`) |
| Последнее сообщение | поле `last_message: { role, text ≤ 160 знаков, at }` |
| Время ожидания | поле `waiting_since` — время первого сообщения пользователя после последнего ответа (бота или человека); последний ход не за пользователем — `null` |
| Очередь | `queue=new` — начат за последние 24 часа; `queue=waiting` — ждёт ответа (`waiting_since` не пусто); прежний `mode` — «нужен человек», «ведёт человек», «ведёт бот» |
| Закрытые | по умолчанию — только открытые (`is_active`), `closed=1` — закрытые |
| Закрыть обращение | `POST /conversations/{id}/close` → `is_active = false`, запись в журнал бота; следующее сообщение пользователя открывает новый диалог (так бот уже ищет диалог — по `is_active`) |

«Непрочитанные» в строгом смысле (кто из операторов что открыл) требуют новой таблицы у бота — это **Q-221**; до
ответа вместо них чип «Ждут ответа»: последнее слово за пользователем.

Приоритет — словом, без новых данных: «Срочно» — нужен человек; «Ждёт ответа» — последний ход за пользователем
(у диалога, который ведёт человек, — «ждёт оператора»); остальное — без метки. Порядок очереди: срочные, потом
дольше ждущие, потом по последней активности.

Стойка, «Платформа → Техподдержка → Диалоги»:

- чипы очереди с числами: «Все открытые», «Новые», «Ждут ответа», «Нужен человек», «Ведёт оператор», «Ведёт ИИ»,
  «Закрытые»;
- строка: кто пишет, приоритет, последнее сообщение (кто и что), сколько ждёт, режим;
- переписка — панелью справа от списка на широком экране (адрес `?id=`, список остаётся на месте), на телефоне —
  на весь экран с «← К списку»;
- действия по режиму: «Забрать диалог» (нужен человек / ведёт ИИ), «Вернуть ИИ» (ведёт оператор), ответ — форма
  внизу переписки, «Закрыть обращение» с подтверждением; у закрытого — только чтение;
- состояния: загрузка, пустая очередь (своя фраза на каждый чип), ошибка, «помощник не отвечает» (бот недоступен —
  503/502 от API) отдельно от «не подключён».

Проверки: pytest бота (red → green), unit API и клиента, UI-спек `tests/ui/support-queue.spec.ts` на подставном API
(red на прежнем экране → green), снимки 1440 и 390 в двух темах — `reports/support-assistant-s1-2026-09-29/`.

**Стоп S1:** снимки владельцу, S2 — после «да».

### S2 — окно чата (`widget.js`)

Тёмная компактная панель по токенам WETOP, SVG-иконки вместо эмодзи, приветствие и подсказки, статус помощника,
«свернуть» и «закрыть», время у сообщений, индикатор «печатает», «Повторить» у неотправленного, файл — название,
прогресс, удаление до отправки; телефон — окно на всю высоту над клавиатурой (`visualViewport`), фокус и
`aria-live`. Виджет общий с продавцом: тема задаётся атрибутом тега (`data-theme="wetop"` у стойки и wetop.ai),
у сайтов гостиниц остаётся прежний вид, пока владелец не скажет иначе. Проверки: спек «чат помощника»
(`tests/ui/playwright.assistant.config.ts`) и pytest отдачи виджета. **Стоп S2** — снимки.

### S3 — знания и поведение помощника

Проверенные знания — документы во вкладке «Знания» (справочник функций, настроек и типовых ошибок) и правила
в «Настройках»; данные вошедшего — только по подписи стойки (`platform_user`), инструменты бота уже режут по
организации — добавить тесты на чужую организацию; «не знаю — уточню или позову человека» — правило промпта и
eval-набор бота (`apps/ai-seller/eval`) на сложные и некорректные вопросы. Живые ответы модели из облачной сессии
не проверить — список проверок на сервере владельцу.
