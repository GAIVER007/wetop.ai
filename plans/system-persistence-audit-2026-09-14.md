Основание: владелец поручил проверить сохранение frontend → backend → Supabase и отображение связанных данных. Это проверка существующей утверждённой модели, без миграций и новых бизнес-правил (AGENTS.md §15).

1. Сверить текущий источник данных, API, общую базу и состояние Git.
2. Запустить отдельный тестовый экземпляр настоящего Nest API с настоящими Prisma-репозиториями и той же Supabase. Только внешняя публикация ARI заменяется тестовым перехватчиком; фоновые задачи и провайдерские команды отключены. Обычный preview продолжает работать отдельно.
3. Через настоящий Next frontend создать строго помеченные синтетические записи. Проверить отдельным соединением Prisma фактический коммит и повторное чтение после перезагрузки: бронь, гость, шахматка, доступность, счёт, сайт. Ошибочные операции не должны изменять данные.
4. Убирать только записи, созданные данным прогоном, по сохранённым ID и уникальной метке; не запускать общую e2e-уборку и выгрузку в каналы. В отчёт не включать данные существующих гостей или секреты.
5. Для подтверждённых ошибок получить RED, исправить и получить GREEN; прогнать unit, необходимые UI-проверки, типы, lint и сборку.
6. Зафиксировать покрытие и остающиеся неподключённые функции, проверить diff и отправить результат в тот же GitHub-репозиторий.

Новые сущности сообщений, ролей, акций и редакторы бизнес-настроек не добавляются скрыто в рамках аудита: решения по ним уже вынесены в QUESTIONS.md.
