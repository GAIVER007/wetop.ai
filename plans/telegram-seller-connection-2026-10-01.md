# Telegram и WhatsApp — подключение ИИ-продавца на сайте

01.10.2026. Пользователь попросил подключение через сайт: токен добавит сам после готовности.
Новый план и модель ниже ожидают подтверждения согласно AGENTS.md §1–2.

1. Проверить живые Аналитику, Настройки объекта и Интеграции; отдельно проверить WhatsApp signature,
   дедупликацию, чужого агента, ошибку отправки и повтор. Не считать HTTP 200 доказательством ответа.
2. В карточке выбранного агента сделать канал Telegram: токен → проверка личности бота →
   подключение → ссылка на бота и разрешённые тестовые Telegram user ID → последнее получение/ответ.
3. Секреты только на сервере, шифрование существующим механизмом; обычный GET никогда не возвращает токен.
   Запрос check не меняет webhook. При подключении не перехватывать существующий чужой webhook молча.
4. Входящий канал связывает сообщение с агентом по серверной записи, проверяет webhook secret,
   принимает личные текстовые сообщения разрешённых тестировщиков; не доверяет организации/агенту из тела.
   Update ID сохраняется до подтверждения приёма, обработка через очередь, дедуп и история через общий движок.
5. WhatsApp остаётся отдельным каналом того же агента, с существующей проверкой Meta и шифрованием;
   в интерфейсе ясно разделены проверенные credentials, webhook и фактический обмен.
6. Telegram на первом этапе — тест ответов, инструкции и чтения PMS. Источник брони Telegram не добавляется
   без отдельного решения; обещать запись брони до её выполнения нельзя.
7. Тесты: неверный токен, чужой webhook, неразрешённый тестировщик, повтор Update, restart/retry,
   неверный секрет, другая организация, отключение, Telegram ok=false при HTTP 200, ошибка доставки,
   отсутствие секретов в ответах/журнале. Затем UI, push, миграция по отдельному разрешению, deploy.

Зависимость: runtime продавца на 0004; подготовлен переход 0009. Новая Telegram-миграция не должна
неявно запускать сужение 0010. Порядок веток миграций спроектировать и проверить до production.
