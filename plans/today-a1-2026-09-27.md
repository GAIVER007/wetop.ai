# План PR A1 — Главная: иерархия экрана без новой бизнес-логики (27.09.2026)

> Основание: ТЗ `plans/tz-today-2026-09-27.md` §12.1 (на ветке PR #99), утверждено владельцем 27.09.2026
> вместе с разбивкой на PR («Начинай A1»), ADR-105 (в момент написания — ADR-103, перенумерован при слияниях с `main`, политика ADR-052). Объём — ровно список A1; API и расчёты не меняются,
> модель данных не трогается. После A1 — стоп: dark/light скриншоты, следующий PR после визуального
> подтверждения владельца. Дизайн-система по стилю не меняется — иерархия, плотность, композиция.

## Что меняется на `/today`

Порядок после A1 (ADR-105): шапка плотнее → полоса дня → операционный KPI strip → «Требуют внимания»
рядом с «Быстрыми действиями» → ссылки на модули. Аналитика за период уезжает целиком на новый экран.

| Было | Стало |
|---|---|
| Сводка «Требуют внимания: N» + часы отдельной строкой сверху | Сводка снята (блок один, ниже); часы — в строке дня |
| `PeriodBar`: сегодня/вчера/7 дней/месяц/прошлый месяц/свой отрезок | Полоса одного дня: «Сегодня · Завтра · [дата]» (`?date=` как раньше; `?period=` Главная больше не читает) |
| Шесть KPI за период + панели (загрузка, источники, категории, оплаты) | Переехали на `/management/dashboard` («Показатели за период») без изменений |
| «На стойке» внизу | Операционный KPI strip сверху: Проживают · Заезды · Выезды · Свободно · **Загрузка** · **К оплате**; числа-ссылки в существующие разделы |
| `QuickActions` слева, `DayAttention` справа внизу | «Требуют внимания» слева (шире), «Быстрые действия» справа — сразу под strip |
| — | Ряд ссылок внизу: Показатели за период · Оплаты · Статистика |

Плитка «Загрузка» — арифметика из уже загруженной шахматки дня: занято / (занято+свободно+заблокировано),
то же деление, что метр на `/management/statistics` (расчётов в API не добавляем). «К оплате» — прежнее
число `debtMinor` (долг уезжающих) с прежними предупреждениями о выехавших/не заехавших с долгом;
`data-testid` `c-*` не меняются — их читает `cli-system-trace` (ADR-047).

## Куда переезжает аналитика за период (функциональность не удаляется)

Новый экран **`/management/dashboard` — «Показатели за период»**: те же компоненты
(`PeriodBar`, `KpiGrid`, `OccupancyChart`, `SourcesPanel`, `CategoriesPanel`, `PaymentsPanel`),
тот же `GET /desk/dashboard`, те же определения ADR-047. Файлы переезжают
`apps/web/src/app/today/{kpi,dashboard-panels,daily-bars,period-bar,dashboard-section}.tsx` →
`apps/web/src/app/management/period/`; `PeriodBar` получает `basePath` (ссылки пресетов вели на `/today`).
Пункт меню — группа «Финансы и отчёты», первым; реестр `navigation.ts`. Стили остаются в
`today/dashboard.css` (подключается глобально из `layout.tsx`); перенос CSS — не в A1.

## Что не меняется

API и домен (`packages/domain/src/dashboard`, `/desk/dashboard`, `/desk/today`) — ни строки; модель
данных; `QuickActions` (вместе с `data-tour="quick-actions"` обучения ADR-100); `FirstSteps`;
`cli-system-trace` (читает `/today?date=` и `c-*` — сохранены); стиль дизайн-системы.

## Проверки

`typecheck`, `lint`, `unit`, UI-набор без базы (`--workers=1` — уроки ADR-100) — через `npm run test:record`,
до прогона `npm run test:status`. e2e (нужна локальная PostgreSQL и production-сборка) — по состоянию
`test:status` на изменённый набор. Скриншоты dark/light 1440 и 390 — из UI-набора
(`reports/ui-quality/today-*.png`) на данных фикстуры; **скриншоты на реальных данных Luxx** делаются
на стенде владельца или после выкладки — из контейнера рабочая база недоступна (ADR-018, SECURITY.md §3),
это ограничение названо в PR.
