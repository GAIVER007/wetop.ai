## Что видит человек

Раздел `/marketing/voice` (право `marketing`, как у остальных экранов «Продвижения»):

1. Сводка за месяц: звонков, отвеченных, просьб перезвонить, переводов на человека, отклонённых (неизвестный номер), средняя
   длительность. Числа только из журнала, при пустом журнале «Нет данных» с причиной, не нули.
2. Таблица звонков: время (часовой пояс объекта), маска номера, состояние, длительность, была ли просьба, был ли перевод.
3. Очередь «Просьбы перезвонить»: имя, телефон, пожелание, кнопка «Отметить обработанной». Единственное место, где виден
   полный номер.
4. Подключение: карточка-памятка (номер, правило маршрутизации, ключи) без полей ввода секретов. Значения ключей вписывает
   только владелец на сервере (`SECURITY.md`).

Хаб `/marketing`: четвёртая карточка «Голосовой агент» (значок «Скоро» до подключения, «Доступно» после), пункт меню в группе
«Продвижение». Видимость по направлениям (сначала салон) и за выключателем по AGENTS.md §28: список утверждает владелец.

## Как данные попадают из воркера в стойку

Воркер живёт отдельно (apps/ai-seller/voice) и базы платформы не видит. Предлагается (вариант Б, рекомендуемый):

воркер -> `POST /voice/events` API платформы (служебный ключ, заголовок `x-wetop-service-key`, как у `/bot/*`) -> таблицы
`voice_calls` и `voice_callbacks` -> `GET /marketing/voice/*` для стойки.

Почему так: изоляция организаций через RLS и `organization_id` как у остальных таблиц, отчёты «Продвижения» и «Аналитика
маркетинга» потом смогут считать звонки как источник. Отклонённые варианты:

- А. Читать файл журнала с тома воркера: стойка и воркер на разных хостах, нет прав, нет изоляции.
- В. Складывать в базу ИИ-продавца (alembic) и ходить через его панельный API: работает без миграции платформы, но звонки
  оказываются вне RLS платформы и вне отчётов маркетинга. Годится как запасной, если миграцию платформы не утвердят.

Потеря событий недопустима (AGENTS.md §11): локальный JSONL воркера становится outbox. Воркер дописывает событие в файл, фоновая
отправка повторяет до подтверждения, повтор идемпотентен.

## Правки к модели данных (предлагаются вместе со срезом 0)

- `VoiceCallback`: id, organizationId, voiceCallId, phone (канонический E.164), name (до 100), note (до 500), status
  NEW/DONE, doneAt, doneBy. Полный номер хранится только здесь, в `VoiceCall` маска.
- `VoiceProfile` по `agentId` (приветствие-хвост, имя голоса, номер администратора): нужен для нескольких объектов на одном
  воркере.
- Время событий ставит приложение (UTC), даты показа в часовом поясе объекта (§13).

5. Без утверждения модели данных остаётся только вариант В.
