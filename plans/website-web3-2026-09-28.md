# «Сайт и онлайн-бронирование»: срез WEB3 — вкладка «Бронирование»

Дата: 28.09.2026. Продолжение ADR-117 (WEB1 — `plans/website-web1-2026-09-27.md`, WEB2 —
`plans/website-web2-2026-09-28.md`). Владелец ответил «давай продолжай» на стоп после WEB2 — это «да» по снимкам WEB2
и разрешение на WEB3. Состав WEB3 из ТЗ владельца (п. 9, 10, 14, 24): состояние, предпросмотр, настройки только тех
возможностей, что есть в модели. После WEB3 — стоп и снимки, WEB4 (воронка и выручка) без отдельного «да» не
начинается.

Схема, миграции, API и сам виджет (`apps/api/src/web-booking/widget.js`) не меняются.

## 1. Что виджет умеет сейчас (аудит 28.09)

- В модели у сайта две настройки бронирования: `booking_enabled` и `booking_rate_plan_id` (`tracked_sites`). Больше
  ничего нет: ни подписи кнопки, ни языка, ни промокода, ни детей, ни валюты отдельно от тарифа.
- Виджет читает только `data-site` и `data-target` (куда встать на странице). Цвет меняется стилями сайта через
  переменные `.pmsw { --pmsw-accent: … }` — владелец сайта может, стойка не хранит.
- Гость видит: даты заезда и выезда, «Гостей» 1–4 (взрослые), «Показать цены» → категории тарифа сайта с ценой за
  весь период → имя, фамилия, телефон, почта по желанию, комментарий → номер брони и «К оплате при заселении».
  Бронь сразу подтверждена, без предоплаты (Q-114), гостю ничего не отправляется (Q-115), язык только русский
  (Q-116).
- Демо-страница есть на API: `/w/demo?k=…`, работает при включённом бронировании. Бронь с неё настоящая.
- Когда бронирование выключено, форма на сайте остаётся, но на «Показать цены» гость видит «Не удалось связаться с
  системой бронирования». Строка стойки «Виджет на сайте говорит, что бронирование недоступно» — неправда, её меняем.

## 2. Вкладка после WEB3

```
Онлайн-бронирование                                 ● Включено
Тариф «Стандартный»
Основной домен · Объект · Валюта · Тариф
[Открыть демо ↗]  [Установка виджета]

Когда гость выбирает даты на вашем сайте, WETOP показывает свободные места…

Что увидит гость
1. Даты и гости — заезд, выезд, от 1 до 4 гостей
2. Свободные категории тарифа «Стандартный» с ценой за весь период, ₸
3. Имя, фамилия, телефон; почта и комментарий — по желанию
4. Номер брони и «К оплате при заселении»: бронь сразу подтверждена
Пока не умеет: другие языки (Q-116), детей и промокоды, письмо гостю (Q-115), предоплату (Q-114).

Настройки бронирования
[✓] Принимать брони с сайта
Тариф [Стандартный ▼]   Виджет показывает категории и цены этого тарифа, отмена — по его правилам.
[Сохранить]
```

- «Открыть демо» — только когда бронирование работает и адрес демо настоящий (http/https); рядом одна строка, что
  бронь с демо настоящая. Раскрывашки «Установка виджета бронирования» больше нет.
- «Установка виджета» — боковое окно, как у счётчика в WEB2: код с «Скопировать код», куда вставить
  (`<div id="pms-booking">` там, где должна быть форма; `data-target` — если место другое), цвет кнопок стилями сайта
  (`--pmsw-accent`), проверка через демо и предупреждение про настоящую бронь.
- «Что увидит гость» — текстом по шагам виджета, без картинки-макета: макет разошёлся бы с настоящим виджетом при
  первой его правке. Живой вид — «Открыть демо».
- Выключено — строка состояния честная: «Форма на сайте цены не покажет»; кнопок демо и установки нет.

## 3. Что не делаем

- Конфигуратор подписи, цвета, языка, промокода, детей — этого нет в модели (п. 10 ТЗ: «не создавать ради
  дизайна»). Если нужно — сначала решение владельца и DATA_MODEL.
- Виджет и API не трогаем: сообщение «бронирование недоступно» прямо на сайте — правка виджета, отдельным решением.
- Воронка и выручка с сайта (WEB4), телефон и «только чтение» (WEB5).

## 4. Проверки

- unit: строка выключенного бронирования (`siteState`), проверка адреса демо — red → green.
- Подставной API: смена тарифа сайта (`bookingRatePlanCode` → тариф из списка, неизвестный — 400) и настоящий
  адрес демо по `POST /__test/control { bookingDemoUrl }` — чтобы UI-тесты видели то же, что стойка на сервере.
- UI-набор: состояния вкладки (включено, выключено, нет домена, пауза), «Открыть демо» только при работающем
  бронировании, окно установки с клавиатуры, смена тарифа видна в состоянии и в «Что увидит гость», axe вкладки и
  окна в двух темах на 390 и 1440 px; старые спеки — на окно вместо раскрывашки.
- typecheck, lint; снимки — `reports/website-web3-2026-09-28/`.
