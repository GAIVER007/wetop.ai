## 2. Схема адресов

| Адрес | Что | Где работает | Кто видит |
|---|---|---|---|
| `wetop.ai` и `www.wetop.ai` | главная платформы: о компании, для кого, возможности, блог, «Попробовать бесплатно», «Войти» | Cloudflare Pages — статический сайт, не зависит от Mac | все |
| `app.wetop.ai` | стойка WETOP | Mac → именованный туннель → 127.0.0.1:3000 | только после входа (Cloudflare Access) |
| `api.wetop.ai` | счётчик `/a/*`, виджет брони `/w/*`, `POST /channels/channex/webhook` | Mac → тот же туннель → 127.0.0.1:3001; любой другой путь — 404 | публично по назначению (`SECURITY.md` §11) |

Почему так: корень остаётся за продуктом и не падает вместе с Mac; стойка — отдельный адрес за входом; у публичной
части API отдельный адрес с белым списком путей, остальное API снаружи не существует.

## 3. Вход в стойку до собственных учётных записей

**Cloudflare Access на `app.wetop.ai`:** вход по одноразовому коду на почту, пускает только адреса из списка
владельца. Дополнительно `cloudflared` сам проверяет токен Access, прежде чем пропустить запрос на Mac
(`originRequest.access` — документация Cloudflare «Origin parameters»): даже ошибка в настройке адресов не откроет
стойку без входа. Код PMS для этого не меняется. Бесплатный план Zero Trust — до 50 пользователей; по отзывам в
сообществе Cloudflare, при выборе бесплатного плана Cloudflare просит привязать карту (план $0; в официальной
документации это не описано).

В стойке (UI, модель данных не меняется):
- `/login` вместо заглушки: «Вы вошли как <почта>» из заголовка `Cf-Access-Authenticated-User-Email` и кнопка
  «Выйти» (`/cdn-cgi/access/logout`); без Access (локально на Mac) — как сейчас;
- кнопка «Войти» на главной ведёт на `app.wetop.ai`.

Кто сделал действие — в журнал (ADR-023: «когда появится вход, к записи добавится, кто именно»): если в
`audit_logs` уже есть поле исполнителя — записывать почту из Access; если поля нет — это правка модели → вопрос
владельцу, не в этом срезе.

## 4. «Регистрация с пробным периодом» — развилка (решает владелец)

Самостоятельная регистрация — это учётные записи, организации-арендаторы, пробный период и раздельные данные
каждого объекта, то есть модель платформы v2 в `DATA_MODEL.md`. ADR-019 отложен, ментор 13.09 велел модель под
платформу не закладывать до конца переезда хостела.

**Предложение на сейчас:** кнопка «Попробовать бесплатно» открывает заявку в канал владельца (WhatsApp, Telegram
или почта) с готовым текстом; персональные данные заявителей у нас не хранятся — не нужны согласие, политика
обработки и таблица. Настоящая регистрация — отдельный срез после решения владельца; если решение пойдёт против
указания ментора, оно записывается ADR.

## 6. Именованный туннель и службы на Mac

- `~/.cloudflared/config.yml`: туннель `wetop`; `app.wetop.ai` → 127.0.0.1:3000 с `access.required`;
  `api.wetop.ai` → 127.0.0.1:3001 только для `/a/*`, `/w/*`, webhook; последнее правило — 404. Рецепт

- launchd `kz.luxx.pms.tunnel` переводится с быстрого туннеля на `cloudflared tunnel run wetop`; перерегистрация
  webhook при каждом перезапуске больше не нужна — адрес постоянный.
- Сторож и скрипты туннеля — под именованный туннель (конкретные места — §7, часть «Готовность к домену»).
- `PUBLIC_API_URL=https://api.wetop.ai` в `.env` (вписывает владелец, `SECURITY.md` §3) → перезапуск API →
  «Зарегистрировать webhook» на `/channels` → новый адрес в коде счётчика и виджета на `/analytics/setup`.
- Mac: питание от сети и запрет сна при закрытом экране — системные настройки меняет владелец.

## 7. Проход по модулям стойки — что нашёл аудит

**Как проверяли (14.09, только чтение):** три независимых разбора кода — «рабочее место», «управление», «продажи,
оболочка и готовность к домену»; каждый экран и каждая команда прослежены от страницы до таблицы Supabase. Плюс
живой обход 30 экранов и журналы служб за сутки. Пять самых серьёзных находок (Д1, Д3, Б1, Б2, Б3) перепроверены
по коду вручную.

**Итог:** все экраны читают настоящие данные Supabase через API; демо-данных, выдуманных цифр и вызовов
несуществующих адресов API нет, ответы API совпадают с тем, что ждёт экран; деньги везде в тиынах. Сверка слоёв
соседней сессии это подтверждает (`reports/system-trace-2026-09-14.md`). Проблемы — в надёжности команд, в ценах для
каналов и в честности отдельных экранов.

### 7.2 Волна 2 — брони, цены, деньги (каждое исправление: тест красный → зелёный)

| # | Дефект | Сценарий | Исправление |
|---|---|---|---|
| Б1 | **Смена дат молча меняет тариф** | в форме нет «оставить текущий», браузер отправляет первый тариф «Базовый»; API ставит его всем проживаниям → OTA-проживание пересчитано по базе и без штрафа за отмену | по умолчанию «— оставить текущий тариф —»; API уже умеет брать тариф проживания; у броней из Exely без тарифа API и сейчас требует выбрать явно — показать это понятным текстом (правило не придумывается) |
| Б2 | **Овербукинг** — несколько мест «назначить позже» в одной брони или два администратора одновременно | вместимость проверяется по каждому месту отдельно, без учёта соседних мест того же запроса и без блокировки | считать места всей брони вместе по категории; на время транзакции — блокировка категории в базе (`pg_advisory_xact_lock`) |
| Б3 | **Цена для меньшего числа гостей уходит в каналы как цена номера** | в тарифах задана цена на 1 гостя в двухместной → `ari-publisher.ts:107` шлёт её как цену номера; ночная выгрузка берёт цену полной вместимости (`ari.ts:139-153`) — до ночи OTA продают дешевле | дельта по тому же правилу, что ночная выгрузка: в канал уходит только цена для вместимости категории |
| Б4 | Недопустимые значения молча теряются в Channex | мин. срок 0 или цена 0 → Channex отвечает 200 с предупреждением → очередь пишет «отправлено» | проверка ввода (срок ≥ 1, цена > 0) в форме и API; предупреждения Channex — ошибка отправки с текстом и неисправность у сторожа (`docs/channex/site/api-v.1-documentation/ari.md`) |
| Б5 | Цены сохранены, а в очередь каналов не попали | цены, журнал и очередь пишутся разными шагами (`rates.service.ts:149-167`) | журнал и очередь — в той же транзакции, что и цены |
| Б6 | Успешное сохранение показано ошибкой, повтор создаёт дубль брони или оплаты | запись прошла, следующий шаг (очередь, журнал, перечитывание) упал → «Internal server error»; двойной клик | шаги после записи — в транзакции или не роняют ответ (неисправность у сторожа); кнопка заблокирована на время команды; текст «проверьте результат перед повтором» |
| Б7 | Сторно начисления за ранний заезд или поздний выезд не снимает блокировку ячейки | начисление ставит блок на соседнюю ночь, сторно его не трогает (`finance.service.ts:426-484`) → место не продаётся, остаток в каналах на 1 меньше | снимать связанный блок при сторно; если связи начисления с блоком в модели нет — вопрос владельцу, не угадывать |
| Б8 | «+1 ночь» для броней из Exely всегда отвечает ошибкой | у проживания нет тарифа, кнопка его не передаёт | форма продления с выбором тарифа, если у проживания его нет |
| Б9 | 500 на `/rate-plans` под нагрузкой | справочник читается внутри транзакции с ожиданием соединения 10 с (`reservations.repository.ts:1190`) | обычное чтение без транзакции; то же в расчёте цены виджета |

### 7.3 Волна 3 — экраны: честные подписи и понятные ошибки

- Карточка брони и новая бронь: сбой справочника тарифов или фонда → предупреждение, а не весь экран ошибки.
- Экран ошибки различает «нет связи» и «неверная дата или адрес» (400/404); общий экран ошибки для оболочки и
  выезжающей карточки.
- «Подключения»: таймаут запросов в Channex (сейчас страница может ждать 60 с); «Последний импорт» читает настоящий
  признак опроса ленты (сейчас всегда «Нет событий»); показывать схему базы.
- Журнал и вкладка «История» брони: поиск по всей истории в API (сейчас по последним 200 строкам — это ~17 ч из-за
  `exely.sync` каждые 5 мин), служебные `exely.sync` скрыты по умолчанию, ссылки на отменённые брони каналов живые.
- Шахматка: фильтр «Уборка» по статусу уборки (сейчас не срабатывает никогда), подписи блокировок по-русски,
  ссылка WhatsApp гостя (телефон не доходит до ячейки).
- «Сегодня»: просроченные заезды видны; строка свежести — порог под синхронизацию раз в 5 мин (сейчас 45 мин и
  текст «раз в 15 минут»).
- Счета: даты оплат и возвратов по Алматы (сейчас UTC — ночные оплаты «вчерашним» днём); сообщения формы оплаты;
  число гостей в формах брони и тарифов — по вместимости категории (сейчас жёстко 2).
- Гости: весь список на сегодня (сейчас первые 25 из ~80); повторы у групповых броней.
- Подписи ведут туда, куда написано: «WETOP AI Assistant» — это сводка, не ИИ; «Добавить гостя», «Принять оплату»;
  «Акции» в меню помечены «не подключено».
- «Номера»: доступность больше 62 ночей — ограничение в форме; сбой шахматки не прячется за «Нет данных».
- Тарифы: «Ушло в очередь каналов» — только если действительно ушло; кнопки не теряют список при сбое сети.
- «Неисправности»: «закрыты за сутки» — по времени закрытия; видно, что список обрезан.
- Настройки: подсказка «Счета» вместо «Финансы»; два адреса и противоречивые пометки в описании.
- Аналитика: текст ошибки API и предел периода; у «демо бронирования» — предупреждение, что бронь настоящая.
- Каналы: сбой сводки фонда не роняет страницу; время с часовым поясом; пустая таблица сопоставлений.
- Подтверждение перед удалением документа гостя и снятием блокировки.
- Печатные формы не трогаются (решение владельца 12.09).

### 7.4 Волна 4 — скорость (цель: карточка брони и «Сегодня» быстрее 2 с на этом Mac)

- «Сегодня»: шахматка грузится параллельно со сводкой; ассистент не грузит шахматку, которую не показывает.
- Карточка брони: одна проверка доступности на бронь вместо проверки на каждый период проживания.
- «Номера» и «Фонд»: дерево фонда читается один раз; настройки гостиницы не запрашиваются из базы на каждой странице.
- Журнал без полных снимков брони в списке; у отчётов тарифов и финансов — предел периода.
- Пул соединений и таймауты базы уже сделаны соседней сессией (f39eff9, ADR-043) — не дублируется.

### 7.5 Порядок и сроки

Главная `wetop.ai` и волна 2 от Cloudflare не зависят — начинаю с них сразу после подтверждения. Код волны 1
делается параллельно, переключение домена — после шагов владельца из §8. Волны 3 и 4 — следом. Каждая волна —
отдельные коммиты и запись прогонов в журнал тестов; соседняя сессия работает в том же дереве, поэтому правки идут
в отдельной ветке и вливаются в `main` перемоткой.

## 8. Что делает владелец — по порядку

1. **Cloudflare:** завести аккаунт (бесплатный) → «Add a domain» → `wetop.ai` → план Free → Cloudflare покажет
   два адреса серверов имён (NS).
2. **Spaceship:** домен `wetop.ai` → Nameservers → Custom → вставить оба адреса из Cloudflare → сохранить.
   Cloudflare пришлёт письмо, когда домен станет «Active» (обычно от минут до нескольких часов).
3. **Cloudflare Zero Trust:** придумать имя команды (например, `wetop`), выбрать план Free.
4. **Прислать в чат:** почты, кого пускать в стойку; канал для заявок «Попробовать бесплатно» (номер WhatsApp,
   Telegram или почта); что написать «о компании» (название, город, контакты) — или «пока без этого».
5. **На этом Mac, когда скажу:** `cloudflared tunnel login` и вход для выкладки главной — подтверждение в браузере.
6. **`.env`:** `PUBLIC_API_URL=https://api.wetop.ai`.
7. **Mac:** питание от сети, запрет сна.

## 9. Доказательства

- Снаружи: `https://wetop.ai` открывается; `https://app.wetop.ai` без входа — страница входа Cloudflare, почта из
  списка — стойка, чужая — отказ; `https://api.wetop.ai/a/pms.js` и `/w/widget.js` — 200, webhook без секрета —
  401, `/reservations` — 404.
- Channex: webhook на `api.wetop.ai`, живая бронь на staging доходит до PMS; остатки T6 — 0 расхождений.
- Модули: исправления — красный тест до правки и зелёный после; UI-набор, e2e, обход экранов и сквозная сверка
  после правок — через журнал тестов.
- Отчёт `reports/wetop-domain-2026-09-14.md`, решение ADR (адреса, вход, хостинг главной), `SECURITY.md` §11.

## 10. Что не входит

- собственные учётные записи, регистрация, роли (развилка §4, ADR-023);
- сервер в Казахстане (условие 1 `CUTOVER.md`, провайдера выбирает владелец, Q-070): при переезде адреса
  `app` и `api` останутся теми же, поменяется только то, куда смотрит туннель;
- внешний вид стойки (решение ментора 13.09);
- модули без хранилища: сообщения, акции, редакторы фото, политик, каталога и структуры номеров — остаются
  честно помеченными, пока их модель не утверждена.
