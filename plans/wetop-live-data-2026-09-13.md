## 2. Что делаю после «да» — без новых правил и без изменения модели

1. **Сквозные тесты на WETOP против живого API:** `npm run test:record -- e2e` (32 сценария: бронь, заселение,
   выезд, счёт, оплата, блокировки, цены, сайт). Перед прогоном — `ps` на чужой Playwright и свободная память.
   Результат — список того, что сломал редизайн.
2. **Починка найденного** в экранах и серверных действиях WETOP. Каждая ошибка: красный тест → исправление →
   зелёный (AGENTS.md §6). Модель, бизнес-правила и существующие контракты API не меняются.
3. **Живой цикл Channex staging через экраны WETOP** — как 11.09, но на новом интерфейсе:
   - бронь из канала (Booking CRS staging) → webhook → видна на «Сегодня», шахматке, в карточке и
     «Менеджере каналов»; перенос; отмена;
   - бронь со стойки `/reservations/new` → остаток в Channex −1; отмена → +1;
   - цена или ограничение в `/rates` → ARI → то же значение в Channex;
   - блокировка ячейки `/units/:code` → остаток в Channex;
   - сверка T6 `cli-channex-ari.ts 90` до и после — опасных расхождений 0.

   Гости вымышленные; тестовые брони убираются после прогона (`cli-e2e-cleanup.ts`); витрину `BDC-SHOW-22C80`
   не трогаю. Отчёт — `reports/wetop-channex-staging-<дата>.md`.
4. **Свежесть на экране:** в шапке WETOP «Exely: ЧЧ:ММ · Channex: последнее событие ЧЧ:ММ · очередь ARI: N».
   Новый маршрут только на чтение в модуле сторожа, где уже есть `lastExelySyncAt` — единственное новое
   в контракте API по этому плану. Модуль сторожа ведёт соседняя сессия — правка по согласованию с ней.
5. **Прогон экранов как сверка:** сегодняшний обход 35 экранов — скрипт `scripts/reconciliation/src/cli-ui-smoke.ts`,
   отчёт `reports/ui-smoke-<дата>.md`.
