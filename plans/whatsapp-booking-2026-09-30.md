# WhatsApp → подтверждённая бронь → шахматка

Владелец утвердил 30.09.2026 сценарий и структуру SellerBookingIntent для реализации и отдельной тестовой базы.
Производственная миграция требует отдельной подготовки и разрешения; внешние production-уведомления гостям в тестах не отправляются.

## Порядок
1. Завершить правила ответов обоих ботов: без автоматического запроса телефона, короткая справка, сохранение защит.
2. Проверить реальные версии PMS/бота, подписанный контекст поддержки и WhatsApp-контакт, наличие и цену.
3. Добавить намерение брони по DATA_MODEL: котировка, привязка к агенту/каналу, подтверждение, повтор.
4. Узкие внутренние маршруты создания котировки-намерения и подтверждения. Организация/объект выводятся из агента;
   модель не выбирает tenant и не присылает цену как доверенное значение. Отдельный ключ записи; ключ чтения не пишет.
5. Создать бронь и назначить ячейку в одной транзакции с фиксацией намерения. Цена изменилась/мест нет — 409,
   новая котировка и новое согласие; без свободной ячейки не создавать «подтверждённую» бронь без места.
6. В боте — выбрать предложение, показать даты/стоимость, получить явное согласие, вызвать подтверждение;
   контакт из проверенного WhatsApp webhook. Общий lead_hook не превращать в запись брони без подтверждения.
7. Ответ гостю только после commit с номером брони. Сбой доставки повторяет отправку, не бронирование.
8. Тесты: два подтверждения одновременно; повтор после потерянного ответа; другой payload с тем же ключом;
   занятое последнее место; изменившаяся цена; чужой агент; истёкшее предложение; отсутствие контекста канала;
   чтение в шахматке после записи; отказ доставки и повтор. Вымышленные гости, изолированная база.
9. Проверки, push; инструкция production migration/rollback; после разрешения — миграция и совместимая выкладка.

## Текущее состояние при аудите
- WHATSAPP уже разрешён в Reservation.source; Q-188 в старом плане устарел.
- GET /bot/availability существует; операция POST /bot/book отсутствует.
- WetopProviders.create_lead содержит старый неподключённый путь /w/book, контракт не годится для безопасной записи.
- factory в режиме wetop подключает leads=stub. Запись заявки не равна брони.
- Действующий образ бота старее agent-scoped кода репозитория; обновление всего образа требует сверки Alembic.
- Существующий внешний ID ручной брони разрешён только OTA, не использовать его скрыто для WhatsApp.
