# WhatsApp для ИИ-продавца Luxx Aparts — план (26.09.2026)

**Основание.** Ответ ментора 26.09: официальный путь верный, WhatsApp Cloud API Meta даёт напрямую, провайдер не
обязателен (добавляет панель и поддержку); с 1 июля 2025 Meta берёт плату только за шаблонные сообщения, обычные ответы
в течение 24 часов после сообщения клиента бесплатны; оформление начинать сейчас, параллельно с Channex. Цены сверены по
документации Meta (ссылки внизу). Развилка в ТЗ бота — `apps/ai-seller/TZ-luxx-aparts.md` §6 и Р2.

**Кто что делает.** Аккаунты Meta, документы, номер и токен — владелец. Открыть наружу адрес вебхука продавца и
проверить канал — агент готовит, владелец применяет на сервере. Токен в чат не диктуется: он вводится только в окне
«ИИ-продавец → WhatsApp» (бот хранит его шифрованным) и больше нигде не пишется.

## 0. Что есть сейчас (сверено с `main` 26.09 после `git pull`)

- **Канал WhatsApp в боте уже сделан** — С3, ADR-086, `plans/seller-partner-bot-2026-09-25.md`: у продавца дверь
  `GET/POST /channels/whatsapp/webhook/{организация}` (подтверждение подписки Meta, подпись `X-Hub-Signature-256`
  секретом приложения гостиницы, дедуп повторов, ответ только в окно 24 часа), отправка через Graph API токеном
  гостиницы, подключение — окно «ИИ-продавец → WhatsApp» в стойке (номер, токен, секрет → «Проверить» →
  «Подключить»). Шаги владельца — `docs/assistant/README.md`, строка 12.
- **Снаружи вебхук пока не виден:** в `deploy/cloudflared.example.yml` правила для продавца не было вовсе.
  **26.09 правило подготовлено** (ветка `claude/whatsapp-webhook-tunnel`): к продавцу — только
  `/channels/whatsapp/webhook/<uuid гостиницы>`, остальное — 404; на сервер его ставит владелец командами
  `docs/assistant/README.md` §6 «Вебхук WhatsApp продавца наружу».
- **Переписка гостей — персональные данные.** С настоящими гостями канал включается, когда база бота в Казахстане
  (ст. 12, ответ ментора; ADR-009, ADR-081). До переезда — только пилот на своих телефонах.
- Бизнес-аккаунта Meta и приложения под WhatsApp у гостиницы пока нет.

## 1. Решение владельца: какой номер

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| **А. Новый номер под бота** | Cloud API напрямую | быстро, без провайдера, основной номер не трогаем | гости пишут на основной номер — новый надо поставить на сайт и в Instagram |
| **Б. Основной номер переносим в API** | удалить WhatsApp на номере, подключить к Cloud API | бот отвечает там, куда гости уже пишут | приложение на этом номере перестаёт работать, сотрудники отвечают в «Диалогах» WETOP; история чатов из приложения не переносится |
| **В. Основной номер и в приложении, и в API** | «сосуществование» — только через партнёра Meta (Solution Partner / Tech Provider) | сотрудники остаются в приложении, бот работает через API | нужен провайдер; предел 20 сообщений в секунду; на номере отключаются рассылки, исчезающие сообщения и «просмотр один раз» |

**Рекомендую А сейчас** — пилот, пока бот учится WhatsApp: ничего не ломаем в основном канале. По итогам пилота —
Б или В. Когда WETOP станет Tech Provider (§5), вариант В будет доступен через нас самих.

**Решение владельца 26.09: вариант А — новый номер, пилот.** Основной номер и приложение сотрудников не трогаем;
после пилота решаем по основному номеру (Б или В).

По документации Meta: номер, на котором уже есть WhatsApp, к Cloud API не подключить, пока аккаунт на нём не удалён;
«сосуществование» подключается только через Embedded Signup партнёра; у нового бизнес-портфеля сначала не больше двух
номеров.

## 2. Владелец в Meta — по шагам

1. **developers.facebook.com** — зарегистрироваться разработчиком (через свой Facebook).
2. **business.facebook.com** → бизнес-портфель «Luxx Aparts»: юридическое название гостиницы, адрес, сайт
   `luxx-aparts.kz`, рабочая почта.
3. **Проверка бизнеса** (Центр безопасности → «Начать проверку»): документы юрлица или ИП гостиницы, подтверждение
   домена `luxx-aparts.kz`. Идёт несколько дней — запускать первым делом.
4. **developers.facebook.com → Create App** → сценарий «Connect with customers through WhatsApp» → привязать портфель.
5. **WhatsApp → API Setup**: тестовый номер Meta. На нём проверяем бота, пока идут проверки.
6. **Добавить настоящий номер** — по решению §1 это **новый номер**: своя SIM, принимает SMS или звонок, WhatsApp на нём
   не заводить (иначе к Cloud API не подключить). Отображаемое имя «Luxx Aparts» уходит на проверку Meta.
7. **Способ оплаты** в WhatsApp Manager — только для шаблонов (напоминание о заезде и т. п.). Ответы гостю в течение
   24 часов после его сообщения бесплатны.
8. **Постоянный токен**: Business Settings → System users → создать → дать права на приложение и WhatsApp-аккаунт →
   Generate token с правами `whatsapp_business_messaging`, `whatsapp_business_management`, `business_management`.
   **Токен и секрет приложения (App Secret) вводятся только в окне «ИИ-продавец → WhatsApp»**, в чат не диктуются
   и нигде больше не записываются.
9. **Webhook**: адрес и проверочное слово — с экрана подключения WhatsApp в стойке (§3); подписка на `messages`.

**Готово, когда:** номер в статусе Connected, имя одобрено, тестовое сообщение на номер доходит до webhook бота.

## 3. Подключение и проверка — агент и владелец

- **Что нужно:** сообщение на новый номер получает ответ продавца Luxx Aparts и видно в «Диалогах» раздела.
- **Почему:** канал в коде готов, не хватает номера Meta и открытого адреса вебхука.
- **Что делаем:**
  1. агент готовит правило туннеля: путь `/channels/whatsapp/webhook/*` → продавец (по образцу строки `assistant`
     в `deploy/cloudflared.example.yml`); владелец применяет его на сервере — **сделано 26.09** в ветке
     `claude/whatsapp-webhook-tunnel` (правило, тест, команды для веб-терминала);
  2. владелец в стойке: «ИИ-продавец → WhatsApp» — `phone_number_id`, токен, секрет приложения → «Проверить» →
     «Подключить»;
  3. владелец в консоли Meta: WhatsApp → Configuration → Callback URL и Verify token — с экрана подключения,
     подписка на `messages`;
  4. проверка со своего телефона: сообщение на тестовый, затем на новый номер → ответ бота, диалог в «Диалогах».
- **Чего не трогаем:** код канала, чат на сайте, основной номер гостиницы; настоящих гостей до переезда базы бота
  в Казахстан.
- **Готово, когда:** ответ пришёл в WhatsApp, диалог виден в «Диалогах», перехват сотрудником работает; в журнале
  бота нет текста переписки и номера без маски.

## 4. Деньги

- Ответы в течение 24 часов после сообщения гостя — бесплатно. Шаблоны вне окна — платно по тарифу Meta для страны.
- Провайдер для вариантов А и Б не нужен; для В — нужен, это его плата.

## 5. Потом: партнёры подключают свои номера сами

Чтобы партнёр подключал WhatsApp из раздела «ИИ-продавец» в два клика, WETOP становится **Tech Provider** у Meta:
проверка бизнеса WETOP (нужна зарегистрированная компания — зависит от юрисдикции) → проверка приложения с двумя
демо-видео (отправка сообщения и создание шаблона) → Embedded Signup в разделе. До этого номера партнёров
подключаются вручную по §2.
