# Навигация стойки сверху: вкладки в шапке вместо бокового меню (02.10.2026), СДЕЛАНО 02.10.2026, ADR-134

**Основание.** Поручение владельца 02.10.2026 со снимком чужой стойки (одна строка вкладок «Календарь,
Список броней, Номера, Уборка, Клиенты, Задачи, Касса, Отчёты, Уведомления, Настройки» с подчёркиванием
активной): «подключись к сайту и найди левое сайд меню, сделай его вот так, чтобы не слева было, а сверху;
чётко сделай, удобно». Облачная сессия, ветка `claude/great-cannon-41n7h4`. Модель данных, API и права не
меняются: правка только `apps/web` и тесты (AGENTS.md §15: UI по утверждённой модели).

## 2. Решения (поручение «делай», умолчания записаны)

1. **Одна модель меню, два вида.** `menuSections` (бывшие `sidebarSections`) задают порядок и состав; на
   компьютере (шире 960 px) они рисуются строкой вкладок в шапке, на телефоне и планшете, как раньше,
   выдвижным меню и нижней панелью. Права пунктов, `activeNavigation`, `routeRule` и гейт страниц не трогаются.
2. **Состав строки, как на снимке владельца: главное одним щелчком.** Главная, Шахматка, Брони, Гости,
   Номерной фонд, Продажи ▾, Финансы, Аналитика, Настройки ▾, Платформа ▾ (последняя только у главного
   администратора). Группа «Работа с гостями» распущена: её три экрана и есть работа смены, прятать их за
   раскрывашкой нет смысла. Группы с несколькими экранами («Продажи», «Настройки», «Платформа») открывают
   список под вкладкой по щелчку; один открытый список, Escape закрывает и возвращает фокус, щелчок мимо
   и переход закрывают. Список всегда в разметке (`hidden`), поэтому `aria-current="page"` у текущего
   экрана есть и при закрытом списке, как было у бокового меню.
3. **Активная вкладка** подчёркнута полосой 2 px цветом `--primary` (как подчёркивание на снимке), текст
   `--text`; наведение, фон `--row-hover` (DESIGN.md §8: наведение всегда фоном). Вложенные адреса
   подсвечивают свою вкладку по прежним правилам (`/hotel-settings/*` → «Настройки», `/rooms/*` →
   «Номерной фонд», `/channels/*` и `/ai-seller/*` → «Продажи»).
4. **Шапка из двух строк, обе липкие:** первая 56 px: знак WETOP, блок объекта с переключателем филиала
   (переехал из бокового меню), поиск ⌘K, «Демо», тема, меню профиля; вторая 44 px: вкладки слева, справа
   строка пробного срока и свежесть Channex (тоже из бокового меню). Итого `--header-h` = 100 px
   (токен `dimension.size.header` 72 → 100, `tokens.css` перегенерирован), до 960 px одна строка 60 px.
   Шахматка теряет 28 px высоты и получает 232 px ширины.
5. **Подпись «кто вошёл».** Роль словом («Владелец», «Управляющий», «Администратор · главный
   администратор») переезжает из подвала бокового меню в подпись кнопки профиля вместо названия объекта:
   объект теперь стоит рядом со знаком, а роль иначе негде увидеть.
6. **Сворачивание панели снято** вместе с памятью `wetop.sidebar` и токеном `--sidebar-w-collapsed`:
   у строки вкладок сворачивать нечего.
7. **Нижняя панель телефона** берёт первые четыре вкладки (Главная, Шахматка, Брони, Гости) плюс «Ещё»:
   пять ячеек сетки, как и было задумано (ADR-050); после 01.10 там стояла одна «Главная».
8. **Обучение**: цели `section-*` переносятся на вкладки; шаг «Работа с гостями» подсвечивает вкладку
   «Гости»; тексты шагов не меняются.
9. **Ширина.** На 1024 px строка из десяти вкладок занимает около 900 px: до 1279 px отступы вкладок 4 px и
   без зазоров. Прокрутки у строки нет: список группы стоит абсолютом под вкладкой, и overflow строки его
   обрезал бы (найдено снимком первого прогона).

## 3. Что делается

- `lib/navigation.ts`: `MenuSection`, `menuSections`, `menuSectionsFor`, `phoneNavigation`.
- `shell/top-menu.tsx`, `shell/top-menu.css`: строка вкладок с раскрывающимися списками, пробный срок и
  свежесть справа.
- `top-nav.tsx`: шапка из двух строк, знак и объект в шапке, `Sidebar` остаётся только внутри «Навигации»
  телефона; `shell/sidebar.tsx` без `collapsed`/`onCollapse`.
- CSS: из `premium.css`, `workspace.css`, `sidebar.css`, `glass.css` сняты правила `.workspace-sidebar`,
  `.is-collapsed`, `.sidebar-collapse`, `.is-compact`; `--sidebar-w` больше не нужен.
- Документы: DESIGN.md §4 (каркас), §8 (строка «Верхнее меню» вместо «Бокового»), §20.3 и §20.4;
  DECISIONS.md ADR-134; CLAUDE.md §2.

  по другим причинам, не чинятся.
- `typecheck`, `lint`, `unit` (сторож ИИ-слопа: снимок обновлён только по затронутым файлам), набор
  интерфейса меню, оболочки, ролей, платформы, филиалов и бюджета запросов.
- Снимки: `reports/top-menu-2026-10-02/`.

## 5. Не делается

Уборка, задачи, касса, уведомления со снимка владельца: таких разделов в WETOP нет, вкладки за ними не
выдумываются (AGENTS.md §16). Меню на планшете и телефоне остаётся выдвижным. Страница `/design-system`
для меню не заводится (её не было и у бокового меню).
