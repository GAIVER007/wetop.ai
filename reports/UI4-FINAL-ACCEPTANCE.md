## Сверка с визуальными концептами

UI3.1 подтверждает общую оболочку. На шахматке сетка занимает освобождённую ширину, но шапка страницы, набор контролов периода, KPI и оформление полос бронирований ещё отличаются от `chessboard_main.png`. Один popover периода относится к UI3.3. Beauty пока показывает базовую временную сетку без богатого представления мастеров из концепта. Food Service на пустом объекте показывает создание зала, поэтому план столов с расстановкой на этих снимках не подтверждён. Эти расхождения не скрываются под статусом готовности UI3.1.

Для сопоставления доступны [исторический экран до UI3.1](calendar-workspace-2026-10-07/light-1440.png) и [текущий экран после UI3.1](ui3-1-fixes-2026-10-11/board-light-1440.png). Исторический снимок сделан на более ранней версии и не считается точным pixel-diff с `758a0e4`.

Первый полный integration-прогон [упал](../tests/runs/entries/2026-10-12T06-06-11Z-integration-2f80.json) в `platform-p1-backfill`: тест ожидал `ACTIVE`, но находил `ARCHIVED` у `Location`. Отдельная проверка после очистки UI3.1-фикстуры оставалась красной, поскольку в локальной базе уже были старые записи. Сброс только собственной локальной PostgreSQL восстановил чистое состояние, после чего полный набор прошёл. Для нового вертикального UI3.1-теста добавлен `afterAll` с существующим endpoint очистки. Это тестовая изоляция, не изменение правил филиалов.

В широком UI-наборе проявилась календарная ошибка старого теста `analytics-v2.spec.ts`: тест ждал класс снижения загрузки в текущем месяце, а фактический ответ фикстуры для октября показывал 0 п.п. для номеров. Неизменённый тест упал дважды. Проверка теперь использует существующий helper, который рассчитывает направление по ответу API; целевой повтор зелёный. Полный локальный UI-набор на одном worker занимал больше четверти часа после 154 сценариев и был остановлен. Параллелить его на одной фикстуре нельзя по `TESTING.md`. До зелёного полного `release-checks` PR не подлежит merge.
