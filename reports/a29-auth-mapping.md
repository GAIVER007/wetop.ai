## Граница наборов

`unified-auth.spec.ts` остается более глубоким контрактом единого входа. Он дополнительно проверяет свойства `httpOnly` и `SameSite` cookie, возврат на исходный экран, работу сессии после reload, новую вкладку, завершение всех сеансов и резервный вход без JavaScript.

`login-lock.spec.ts` сохраняет ровно пять исходных проверок включенного замка. Его отдельная ценность после обновления состоит в проверке обычного выхода через меню администратора. Остальные четыре требования намеренно дублируют критические пользовательские границы, чтобы исходный приемочный набор не потерял ни одного требования.

## Конфигурационная зависимость

Тестам нужны четыре локальных процесса из auth-конфигурации: публичный сайт, стойка с `APP_AUTH_REQUIRED=1`, fixture API с `FIXTURE_AUTH_LOCK=1` и loopback proxy для имитации сетевого отказа `/auth/me`. По умолчанию используются порты `3002`, `3102`, `4313` и `4323`. Изолированный запуск может задать `AUTH_SITE_PORT`, `AUTH_WEB_PORT`, `AUTH_API_PORT` и `AUTH_PROXY_PORT`.

`tests/ui/playwright.auth.config.ts` запускает три файла и обнаруживает 18 тестов: 5 legacy-проверок, 7 проверок unified-auth и 6 проверок a27-auth-boundary.

Исторический результат A28 `unified-auth: 13/13` был составным. Внешняя конфигурация `a28-extra-unified-auth.config.ts` выбирала `unified-auth.spec.ts` и `a27-auth-boundary.spec.ts`. Первые 7 тестов принадлежали unified-auth, еще 6 проверяли безопасные состояния при ответах `/auth/me` 403, 500 и недоступной сети на двух ширинах в двух темах. Поэтому полный набор из 18 состоит из 5 login-lock + 7 unified-auth + 6 a27-auth-boundary.

При двух workers каждый worker получает собственные site, web, fixture API и auth fixture proxy. Второй runtime использует следующие четыре порта после заданных базовых значений. Proxy слушает только `127.0.0.1`, принимает только loopback HTTP upstream и дает boundary-тестам управлять отказом `/auth/me`; остальные запросы передаются тому же synthetic fixture API. Каждый Next-процесс запускается из отдельной временной копии приложения в игнорируемом `test-results/auth-runtime-*`. Копия исключает `.next`, `next-env.d.ts` и `node_modules`, затем использует ссылки на установленные зависимости и `packages` репозитория. Поэтому процессы не делят Next lock/cache, не переписывают отслеживаемый `next-env.d.ts`, а Turbopack остается внутри разрешенного корня репозитория. Для внешнего runtime конфигурация поддерживает явный `AUTH_TURBOPACK_ROOT`.

Изоляция исключает взаимный сброс fixture, отзыв сессий соседнего worker и совместную запись Next runtime. Каноническая команда сохраняет два Playwright workers:

```sh
npx playwright test --config tests/ui/playwright.auth.config.ts --workers=2
```

## RED до изоляции workers

Первый A29-прогон с двумя workers и одним общим fixture runtime дал 5 PASS и 7 FAIL. Оба файла параллельно вызывали `__test/reset`, а сценарий unified-auth завершал все сеансы общей синтетической учетной записи. В результате соседний worker возвращался на публичный вход вместо защищенного экрана. Исправление разделяет runtime по `TEST_PARALLEL_INDEX`, не уменьшает число workers и не добавляет повторов, skip или увеличенные таймауты.

Первый записанный запуск после изоляции был прерван до обнаружения тестов: Turbopack не смог обработать локальные URL из `NEXT_FONT_GOOGLE_MOCKED_RESPONSES`. Локальный font mock теперь передается только публичному site, который запускается с `--webpack`. Web остается на Turbopack, поскольку его client graph содержит поддерживаемые Turbopack импорты domain, несовместимые с Webpack. Этот запуск не является доказательством поведения auth и сохранен в журнале как прерванный.

Следующий запуск также завершился до обнаружения тестов: временная копия приложения не видела относительный импорт `../../packages/domain`. Подготовка runtime дополнена ссылкой на `packages`; исходный код пакетов не копируется и не изменяется.

Запуск `2026-10-08T17-10-01Z-e2e-3730.log` был прерван до тестов. Внешняя временная копия использовала симлинк `node_modules` за пределами корня Turbopack, поэтому Next не находил `next/package.json`. Runtime перенесен в игнорируемый каталог внутри репозитория, а тестовая настройка `NEXT_TEST_TURBOPACK_ROOT` оставляет возможность безопасно задать общий внешний корень.

Запуск `2026-10-08T17-11-17Z-e2e-8d44.log` обнаружил все 18 тестов и завершился результатом 14 PASS, 4 FAIL. Пять login-lock и шесть a27-auth-boundary прошли полностью. Три падения unified-auth произошли после того, как целевая страница уже была видима, но `page.goto` или reload продолжали ждать событие `load` от dev-сервера. Еще одно падение ожидало гидратацию диалога на холодном site worker. Навигации unified-auth теперь ждут `domcontentloaded`, а каждый worker заранее запрашивает корневую страницу своего site. Все три auth-файла также явно сбрасывают состояние loopback proxy перед каждым тестом, чтобы раннее падение boundary-теста не оставило сетевой отказ следующему файлу. Этот прогон не является финальным доказательством: во время него другой исполнитель изменил файл из e2e-отпечатка, и `test:record` отметил `codeChangedDuringRun`.
