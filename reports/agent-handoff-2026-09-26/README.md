# Перенос гостевого черновика в организацию

Реализованы защищённые /seller-agents и /seller-agents/claim, связь с утверждённым SellerAgent,
идемпотентный перенос с блокировкой, проверка членства OWNER/почты/доступности записи,
событие и audit в той же транзакции. Состояние всегда draft, trial не выдаётся.
В /create добавлена кнопка переноса; /ai-seller/agents показывает агенты текущей организации;
кабинет содержит переход «Мои агенты». Старый SellerProfile не перезаписывается.

База: только отдельная локальная PostgreSQL 55432/pmslocal. Рабочая Supabase не менялась.
Тесты: RED отсутствующий сервис; затем локальная база потребовала миграцию 20; GREEN два
интеграционных теста (сессии/изоляция и конкурентный claim), API/web typecheck, targeted ESLint.
Тесты используют вымышленные аккаунты; удаляют только собственные записи.

Ограничения: feature WIZARD_ENABLED остаётся выключен для production. Требуется ранее
согласованная миграция 23 (пока только локально). Нет scan/generate, гостевого чата,
редактирования нового агента и подключения его к runtime, автоматического возврата из
регистрации/письма другого устройства. Вход для переноса пока в отдельной вкладке.
Этот срез не завершает весь онбординг и не публикует его на домене.

Браузерная регрессия: 6/6, tests/runs/logs/2026-09-26T12-05-51Z-e2e-0bda.log.
Это регрессия существующих форм и кабинета; не доказательство входа/claim через полный AppModule.
Production web build: APP_UI_TEST=1 npm run build -w apps/web — PASS.
