## Схема знаний (база бота, миграция `0006`)

| Таблица | Что хранит |
|---|---|
| `support_knowledge` | `id`, `title`, `category`, `visibility`, `status`, `version`, `source`, `content`, `approved_by`, `approved_at`, `created_at`, `updated_at`; значения категории, видимости и статуса закреплены CHECK |
| `support_knowledge_versions` | снимок записи при каждой смене версии (кто и когда сохранил) |
| `support_knowledge_chunks` | чанки и векторы **только активной версии**; индекс hnsw — в Postgres |

Категории: `PRODUCT`, `HOW_TO`, `TROUBLESHOOTING`, `BILLING`, `INTEGRATIONS`, `SECURITY`, `KNOWN_ISSUE`, `RUNBOOK`.
Миграция `0006` добавляет только новые таблицы и не трогает существующие; откат — `drop` четырёх таблиц. Модель данных
PMS (`DATA_MODEL.md`) не менялась: знания живут в базе бота.

## Матрица видимости (клиентский разговор)

| Видимость | Что получает модель |
|---|---|
| `PUBLIC_SUPPORT` | текст записи; можно пересказывать |
| `INTERNAL_SUPPORT` | текст с пометкой «внутреннее: объясни своими словами, не цитируй» |
| `PLATFORM_ADMIN_ONLY` | **ничего**: запись до модели не доходит (строже, чем «не цитировать»). Доступна только аудитории `platform_admin` (песочница S9, закладка есть, в клиентском пути не используется) |

## Семантика статусов

| Статус | Отвечает клиенту | Индекс | Как попасть |
|---|---|---|---|
| `DRAFT` | нет | нет | создание; правка `ACTIVE`; возврат вручную |
| `ACTIVE` | **да, единственный** | есть | только публикация: нужен `approved_by` (главный администратор, id подставляет платформа из сессии) |
| `OUTDATED` | нет | нет | вручную, интерфейс поменялся |
| `ARCHIVED` | нет | нет | вручную |

Правка активной записи: версия +1, статус `DRAFT`, `approved_by` сбрасывается, чанки удаляются (умолчание Q-S3-1).
Повторная публикация чанки пересобирает, дублей нет.

## Контракт `search_knowledge`

- Аргумент один: `query`. Аргументов «кто», «организация», «видимость», «статус» нет; лишний аргумент реестр отвергает.
- Ответ модели: до трёх записей, у каждой название, категория словами, версия, уровень уверенности `HIGH/MEDIUM/LOW`,
  пометка для внутренних, текст (до 2000 знаков). **Идентификаторов записей модель не получает**; в клиентском ответе их
  нет. Слабое совпадение (`LOW`) или пусто — «не знаю: уточнит человек».
- Метаданные (`knowledgeId`, версия, видимость, оценка, источник, уверенность) возвращает `kb.search()` и пишутся в
  `support_knowledge_usage`; оператор видит их в кабинете.
- Пороги: `support_kb_high` 0.85, `support_kb_medium` 0.78 — оценка, калибруется на eval-наборе (S10).
- Агент не «учится»: команд создать, опубликовать, править у бота для модели нет (тест на имена инструментов);
  закрытие обращения знаний не пишет. Из закрытого обращения оператор создаёт **пустой черновик по шаблону**
  (название «Знание из обращения от …», переписка не копируется) и сам дописывает.

## Что видит оператор

«Платформа → Техподдержка → База знаний»: чипы статусов с числами, поиск, отбор по категории и видимости, таблица, запись
(поля, версия, источник, кто утвердил, история версий), «Сохранить», «Опубликовать» с подтверждением, «Пометить
устаревшим», «В архив», «Вернуть в черновик». В диалоге — блок «На основании» (какие знания и версии легли в ответ) и, у
закрытого, «Создать знание из обращения». Старые документы — вкладка «Документы» (прежняя «Знания»), без изменений.
Снимки: `catalog-*`, `entry-*`, `entry-published-1440`, `draft-from-conversation-1440` (light/dark, 1440/390).
