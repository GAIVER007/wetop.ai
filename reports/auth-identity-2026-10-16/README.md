## 1. Схема сущностей

```
User (почта уникальна) ──< Membership (роль OWNER/MANAGER/STAFF, ACTIVE/SUSPENDED) >── Organization (граница RLS)
  │                         └──< MembershipScope (бизнес или филиал, роль места)              │
  ├──< Session (организация сессии, 12 ч, отзыв строкой)                                     ├──< Business (vertical)
  ├── PasswordReset, EmailVerification (только хеши, одноразовые)                             │     └──< Location (филиал)
  ├── PlatformAdmin (раздел «Платформа», команда на сервере)                                  │           └── Property (только гостиница, 1:1)
  └──< Employee.userId (рабочая карточка; логина сама не даёт) >── Business                  └──< Invite (роль ≠ OWNER, 7 суток)
Customer / Guest: посетители бизнеса, без учётной записи и входа.  «Project», projectId: в коде нет.
```

| Сущность | ID | Где создаётся | Уникальность | Кто читает и меняет |
|---|---|---|---|---|
| User | uuid сервера | регистрация, принятие приглашения, платформа | `email` (нижний регистр) | сам (профиль), сервисная роль |
| Organization | uuid сервера | регистрация, платформа | нет (имя не ключ) | члены; правит главный администратор |
| Business | uuid сервера | регистрация (первый), «Филиалы» | нет | члены по области; владелец, управляющий |
| Location | uuid сервера | регистрация (первый), «Филиалы» | нет | члены по области |
| Property | uuid сервера | регистрация гостиницы, онбординг | `location_id` | члены по области |
| Membership | (user, organization) | регистрация, приглашение | составной ключ | роль меняет владелец |
| Session | uuid, ключ только хешем | вход, подтверждение, переход организации | `token_hash` | сам человек (список, выход) |

Где показать владельцу идентификаторы для поддержки: «Настройки → Организации» уже показывает название организации и
карточки филиалов; предложение: строка «Номер для поддержки» в «Профиль → Доступ» с коротким кодом организации и филиала
(первые 8 знаков uuid). Код только для разговора с поддержкой: авторизации он не даёт, сервер права по нему не выдаёт.

## 2. Реестр экранов и действий

| Экран, кнопка | Маршрут → API | Статус проверки |
|---|---|---|
| wetop.ai «Регистрация», «Попробовать бесплатно», «Начать бесплатно» | диалог сайта → `/api/site-auth/register` → `POST /auth/register` | браузер (салон), интеграция (все три направления) |

| «Выслать заново» | `POST /auth/email/resend` | интеграция (повтор не создаёт сущностей) |
| wetop.ai «Войти» | диалог → `/api/site-auth/login` → `POST /auth/login` → `/scope/resolve` | браузер (Enter, ошибка у поля, старый пароль отклонён) |
| Резервный вход `/auth/fallback` | `POST /auth/login`, `POST /auth/register` | существующие UI-тесты, руками не проходил |
| «Забыли пароль» `/login/reset` | `POST /auth/password-reset/request` | браузер: нейтральный ответ, письмо поймано |
| `/login/set-password` | `POST /auth/password-reset/confirm` | браузер: короткий пароль отклонён, новый работает, старый нет |
| Приглашение `/invite/:token` → «Принять» | `POST /auth/invites/:token/accept` → set-password | браузер: открытие ссылки ничего не принимает, принятие ведёт в верную организацию |
| «Выйти» | `POST /auth/logout`, кука удаляется | браузер: защищённая страница после выхода ведёт на вход |
| «Завершить все сеансы» | `POST /auth/logout-all` | существующие тесты |
| «Профиль → Доступ → Ваши организации → Перейти» | форма → стойка `/auth/organization` → `POST /auth/organization` | **новое**: браузер, HTTP, интеграция |
| Смена пароля в профиле | `POST /auth/password` есть, **экрана нет** | API доказан тестом гонки; экран: решение чата №3 |
| Смена почты | **нет** ни API, ни экрана | Q-AUTH-6 |
| «Получить доступ» (noscript) | `/auth/fallback?mode=register` = регистрация нового клиента | прочитано в коде |

Назначение «Получить доступ»: только регистрация нового клиента WETOP. Запроса членства в чужой организации и
восстановления без почты в продукте нет (Q-AUTH-4, Q-AUTH-5); приглашение принимается только по ссылке из письма.

## 4. Покрытие цепочек

| Цепочка | Чем доказано |
|---|---|
| А. Регистрация владельца, только свой контекст | `auth-identity-chains` (три направления: организация TRIAL, один бизнес нужного направления, филиал, объект только у гостиницы, OWNER, без сессии до подтверждения, лишние поля тела игнорируются); браузер салон и ресторан |

| Г. Существующий человек в другой организации | `auth-identity-chains` (аккаунт один, пароль не меняется, повтор и параллельный повтор ссылки: ничего) |

| Е. Сброс пароля, гонки, ошибки записи | `reset-token-http` (существующий: один победитель, откат при сбое, вход по старому паролю во время сброса); D2; браузер |

| К. Рабочие разделы каждого направления | браузер: салон → настройка салона и «Сегодня», гостиница STAFF → «Отель ещё не настроен», ресторан → настройка |
