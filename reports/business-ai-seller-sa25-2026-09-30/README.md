# SA2.5 «Agent-scoped runtime narrowing», отчёт

Ветка `claude/charming-heisenberg-ainaqm` (PR #174), сужение, `claude/sa25-contract`.
План, `plans/business-ai-seller-sa25-2026-09-30.md` §10, выкладка, `docs/ops/sa25-agent-scope.md`,
решения, ADR-127 дополнения (3) и (4).

## Что изменилось

Предположение рантайма «организация = продавец» снято. Продавца находят по `agent_id`:
ключ виджета и его домены, адрес вебхука WhatsApp, панель (`X-Agent`), ход движка, клиент,
диалог, дедупликация, знания, факты, котировка PMS. Организация осталась границей арендатора:
ключ модели (секрет платформы, Q-SA-10), дневной предел, срок расширения, RLS.

| Шаг выкладки | Что | Где |
|---|---|---|
| A | PMS `035`: предпроверка, строгие `seller_agent_ensure`/`bind_location`, backfill | эта ветка |
| B | Бот `0009`: расширение (колонки `agent_id`, `agents.location_id`, новые индексы рядом со старыми) | эта ветка |
| C | Код API и бота переведён на `agent_id` | эта ветка |
| D | Регрессия и смоуки Luxx | за владельцем, `docs/ops/sa25-agent-scope.md` |
| E | PMS `036` и бот `0010`: сужение ключей | `claude/sa25-contract`, отдельный релиз после D |

## Что нашлось по дороге

- 034: агент, заведённый триггером при вставке принятого профиля, оставался черновиком, исправлено в 035.
- Тесты второго агента идут на схеме после сужения (`tests/contract_schema.py`): до неё индексы шага «расширить» держат прежние ключи.

## Ограничения

- Второй агент в организации отвечает гостям только после релиза сужения.
- Агенты в бот до SA9 не передаются: у черновика нет двери.
- Отчёт использования, дневной предел и ключ модели остались по организации.
- `apps/ai-seller/src/ai/engine.py` тронут (два поля области хода вместо одного).
- CI на GitHub красный без логов (минуты Actions), проверено локально.
