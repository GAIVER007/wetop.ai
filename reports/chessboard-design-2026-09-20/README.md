# Шахматка — проверка дизайна, 20.09.2026

Поручение: улучшить существующую шахматку. План —
`plans/chessboard-design-2026-09-20.md`, решение — ADR-058.

## Результат

- Заголовок и «Новая бронь» отделены от управления периодом.
- Стрелки, текущий период, «Сегодня» и переключение вида собраны вместе.
- Ручные даты доступны по кнопке «Даты»; сохранён GET-переход с from/to.
- Поиск, категория, тип и статус собраны в панели над сеткой.
- Дата и день недели читаются вместе; свободные и занятые места имеют подписи.
  На узком экране показатели располагаются компактнее; длинные категории не
  перекрывают счётчик мест.
- Легенда вынесена под календарь; подробная инструкция раскрывается отдельно.
- Неделя остаётся видом по умолчанию. Меню действий, открытие карточек, создание
  по свободной клетке, блокировки, уборка и закрепление шапки/номеров сохранены.

Снимки `before-*` фиксируют исходный интерфейс. `light-*` / `dark-*` — итог на
1440, 1024, 768, 390 и 320 px. На телефоне 390 px сетка начинается примерно на
402 px вместо 660 px исходного снимка. Все снимки используют вымышленные данные
UI-стенда, а не настоящих гостей.

## Границы проверки

Browser-тесты: Chrome → настоящий Next.js → синтетический loopback API. Это
проверка интерфейса и вызовов существующих действий, не новая проверка записи в
Supabase или синхронизации Channex. Схема, API, данные, финансовая логика и правила
размещения в этом изменении не менялись. Unit-тест плана drag не означает live-перенос
настоящей брони.

Проверка кода: новое состояние ограничено раскрытием формы дат; новых запросов,
зависимостей или изменения маршрутов нет. Формат периода вычисляется на сервере
из уже проверенных stay dates. Стили ограничены шахматкой, действующие пороги
адаптивности и цели управления 44 px проверены без ослабления условий тестов.
