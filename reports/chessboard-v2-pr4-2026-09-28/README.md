## Что сделано

- **Куда можно бросить (§26).** Когда бронь взяли, каждая строка сетки получает пометку «можно» или
  «нельзя» — по клеткам уже загруженной сетки, без запросов на строку (§69). Над строкой под курсором —
  призрак: имя гостя или причина. Закрытая строка drop не принимает (браузер показывает запрет).
  Сервер проверяет ещё раз (§50) — сетка лишь заранее говорит то, что видно.
- **Правило домена учтено заранее.** Команда `assign` переселяет в другую категорию только всё
  проживание целиком. Поэтому при броске в другую категорию переезд идёт с первой ночи плашки, а не
  с взятой клетки (раньше такой бросок за середину брони получал отказ сервера). Если заезд раньше
  окна, строка другой категории закрыта: весь срок на экране не проверить.
- **Окно переселения (§27):** заголовок с номером брони (DESIGN.md §14), гость, «R02 → R07», даты
  отрезком и ночи, «Стоимость не изменится» или «Разница стоимости: +21 000 ₸» и какой станет цена.
  Сумма — тот же предпросмотр API, что и раньше.
- **Продление за край (§29):** подпись «До 2 окт., +1 ночь, +8 000 ₸» до отпускания; сумма —
  предпросмотр продления API на выбранное число ночей (один запрос на число, не на движение мыши).
  Поверх чужой брони или блокировки — конфликт виден сразу, после отпускания команда не уходит.
  Ночи за краем окна и гонку с другим администратором ловит ответ предпросмотра («занято на новые
  ночи») и сама команда.
- **§49 облегчённо:** после подтверждения призрак стоит на новом месте с «Сохраняем…», при отказе
  исчезает. Данные сетки не подменяются — источник правды сервер.
- **§54:** ошибки словами — «Не удалось переселить: …», «Не удалось продлить проживание: …».

## Что не делалось и почему

- **§28 мгновенное переселение без вопроса** — по плану (Б-8): любое переселение может менять
  деньги или категорию, окно с суммой остаётся всегда.
- **§30 сокращение за край — gap, нужно решение владельца.** Сократить проживание сейчас можно
  только командой смены дат (`PATCH /reservations/:number/dates`). Она меняет даты всей брони,
  не работает для заселённых (`assertCanChangeDates`: только «не подтверждена» и «подтверждена») и
  для переселённых проживаний, и у неё нет предпросмотра суммы. §30 требует показать изменение
  стоимости до подтверждения. Без нового чтения в API («сколько будет стоить смена дат») сделать
  это честно нельзя — это изменение API, отдельным решением.
