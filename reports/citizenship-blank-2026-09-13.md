### Первый запуск упал, хотя работа была выполнена

`PrismaClientKnownRequestError … P2028: A commit cannot be executed on an expired transaction`
(таймаут 5000 мс, прошло 7670 мс). Одна транзакция на 401 гостя — `updateMany` плюс 401 строка
журнала — не уложилась в таймаут интерактивной транзакции Prisma через пулер в Сингапуре.
База при этом обе операции применила и закоммитила: данные и журнал согласованы (401 = 401),
частичной чистки нет. Второй запуск уже ничего не нашёл и напечатал «чистить нечего».

Дефект скрипта исправлен: чистка идёт пачками по 100 гостей, у каждой транзакции явный таймаут
60 с, а после записи скрипт задаёт базе контрольный вопрос и печатает, сколько строк осталось.
Разбиение на пачки покрыто тестом `scripts/reconciliation/src/chunk.test.ts` (red → green).

## Что это значит для стойки

Гражданство у броней каналов архивный источник не передаёт — его вводит администратор с паспорта при заселении.
Пока строка из пробелов считалась заполненной, проверка молча пропускала таких гостей. Теперь
заселение остановится и попросит код страны. Объём на ближайшие две недели:

| Дата заезда             | Заездов | Без гражданства |
| ----------------------- | ------: | --------------: |
| 13.09                   |      23 |              21 |
| 14.09                   |      13 |              10 |
| 15.09                   |      18 |               8 |
| 16.09                   |       4 |               4 |
| 17.09                   |       4 |               1 |
| 18.09                   |      18 |              17 |
| 19.09                   |       3 |               3 |
| 20.09–27.09             |      32 |              15 |
| **всего 13.09 … 27.09** | **115** |          **79** |

Это не последствие чистки, а её цель: до неё те же гости проходили заселение без кода страны.
Работы у администратора не прибавляется — паспорт он берёт в руки в любом случае, а поле одно.
На экране «Сегодня» такие брони помечены «нет гражданства», на карточке брони — «гражданство
не указано». Заранее заполнять ничего не нужно: код вводится в момент заселения.

## Живая проверка на объединённом коде

После слияния с новым интерфейсом стойки (срез 10) прогнаны сквозные тесты в браузере:
сутки гостя целиком (бронь → гражданство и документ → заселение → услуга → оплата → выезд)
и заселение/выселение/незаезд. Оба зелёные, брони автотестов убраны автоматически.

## Правило закреплено в базе (миграция применена 13.09.2026)

Чистка убрала последствия, миграция убрала причину. `guests.citizenship` и
`guest_documents.issue_country` больше не `CHAR(3)`, а `VARCHAR(3)` с проверкой
`IS NULL OR ~ '^[A-Z]{3}$'` (DATA_MODEL §3 v1.3, миграция `20260913000011_citizenship_alpha3`,
откат — `down.sql` рядом). Пустая строка теперь не превращается в пробелы молча, а отвергается.

| Проверка после миграции    | Значение               |
| -------------------------- | ---------------------- |
| тип обеих колонок          | `character varying(3)` |
| ограничения `*_alpha3`     | оба на месте           |
| гражданство NULL / кодом   | 1484 / 484             |
| значений вне формата       | 0                      |
| записей о чистке в журнале | 401                    |

Доказательство — `tests/integration/citizenship-column.test.ts`: база сама отвергает `''`, `'   '`,
`'kaz'`, `'KZ'` и то же самое для страны выдачи документа. На старой колонке тест был красным,
после миграции — зелёный. Прогон целиком: 428 тестов, e2e «сутки гостя целиком» на новой схеме
прошли без правок в коде.
