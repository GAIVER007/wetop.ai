## P1 Fixes

### AI Seller (O2 = A)

- Права `seller` и `dialogs` отнесены к организационным (`ORGANIZATION_LEVEL_PERMISSIONS`, `packages/domain/src/accounts/scopes.ts`). Эти два права используют только маршруты ИИ-продавца и `/seller-agents`, других маршрутов с ними нет, поэтому лишнего закрыто не было.
- Ограниченный получает 403 на всех 44 проверенных маршрутах (профиль, промпт и версии, ключ модели, WhatsApp, диалоги, takeover, reply, заметки, каталог, агенты, `agents/options`, `POST agents`); бот при этом не вызывается. Владелец и неограниченный менеджер работают как раньше.
- Использована существующая модель (`RoleGuard`), параллельной системы прав нет. Снимок `navigation-rights.baseline.json` обновлён на три строки (`/ai-seller*`, `restrictedManager`: `denied`).

### Guest (O3 = A)

- Новая узкая метка `@OrganizationLevel` (`apps/api/src/auth/organization-level.decorator.ts`) и проверка в `RoleGuard`, повешена на `GuestsController`: список, поиск, справочник, карточка, превью, изменение, заметки, документы. Право `desk` общее со стойкой гостиницы, поэтому закрыть правом нельзя.
- Бронь существующему гостю по `guestId` (`reservations.service.ts:356`) закрыта ограниченному; бронь с новым гостем работает как раньше.
- Схема `Guest` и данные не менялись.

## P2 Fixes

### system/connection (A2)

`apps/api/src/database/connection.ts` берёт объект через `propertyRef` по области запроса; служебный путь (сторож, e2e, скрипты) по имени сохранён. Отказ области уходит человеку как 403/404, а не прячется за «база недоступна». Тест `system-connection`: было 4 красных из 8, стало 8 из 8.

### onboarding / self (A3, F6)

`GET /onboarding` не отдаёт черновик места без назначения; `GET /auth/registration-context` для ограниченного называет только назначенные бизнес и филиал; `GET /auth/me` не подтверждает указатель на не назначенное место, чтобы стойка вела на выбор филиала. Владельца и обычный онбординг это не меняет.

### Employee locations (F4)

`apps/api/src/beauty/schedule.ts` (`setLocations`): область вызывающего считается через существующие `roleAt` и назначения. Ограниченный не может добавить мастера в филиал вне области (403), привязки и график вне области не снимаются, пустой список снимает мастера только с филиалов внутри области. Филиал вне области, где мастер уже работает, в теле допускается и ничего не меняет (форма отдаёт список целиком, строгая проверка ломала бы сохранение). Тест: было 5 красных из 14, стало 14 из 14.

### customerId (F5): НЕ ИСПРАВЛЕНО, нужно решение владельца

См. раздел «Required Owner Decisions».

### Fail-closed scope (F4a, O4 = A)

`author.interceptor.ts` и `scope.ts`: различены «заголовка нет» (организация, как раньше) и «заголовок есть, но отклонён» (чужой, архивный, битый, без бизнеса, повтор ключа): второе даёт 403 «Выберите филиал заново». Исключения с обоснованием: `@Public`, `service`, `self` (в том числе `GET /auth/me`, по которому стойка восстанавливает указатель), `platform`, `@ScopeAware` (выбор филиала и сводка вызываются до выбора). Цепочка восстановления проверена тестом: устаревшая кука, затем `/auth/me` 200 с пустым контекстом, затем `/branches` (ограниченному только его филиал), затем выбранный указатель открывает `/tasks`. `POST /tasks` со stale-указателем возвращает 403 и ничего не пишет.

## Beauty Customer 409 (U3-b)

`apps/api/src/beauty/appointments.ts`: создание клиента ловит только `P2002` (уникальный индекс не менялся) и отвечает 409 «Клиент с таким телефоном уже записывается: повторите запись через несколько секунд»; транзакция проигравшего откатывается целиком. Тест: было 3 красных из 8 (`[201, 500]`), стало 8 из 8, три прогона подряд стабильно. Food не менялся (его 409 уже управляемый).

## Security Matrix

| Actor | Target | AI-продавец | Гости | self / registration-context | Отклонённый указатель |
|---|---|---|---|---|---|
| owner, неограниченный manager | своя организация | ALLOW | ALLOW | ALLOW | 403 (кроме исключений) |
| ограниченный manager | свой филиал | **DENY (O2=A)** | **DENY (O3=A)** | только назначенное | 403 |
| ограниченный manager | другой филиал | DENY | DENY | DENY | 403 |
| ограниченный manager | другой бизнес / вертикаль | DENY | DENY | DENY | 403 |
| любой | чужая организация | DENY | DENY | DENY | 403 |

Операции: чтение, создание, изменение, удаление там, где они есть на маршруте. Безопасность держится на API и сервисе, не на UI.

## Remaining Risks

1. **Последствия O3 = A для ограниченного администратора гостиницы** (реализовано как задано, ничего не обходилось):
   - Печать регистрационной карточки и договора (`reservations/[number]/print`, `print/contract`): страницы зовут `guestsApi.card` без `catch`, будет необработанная ошибка. Это штатная операция стойки.
   - Единственный пункт меню гостиницы «Гости и бронирования» (`/guests`) покажет ошибку загрузки; список броней доступен кнопкой «Список броней».
   - Карточка гостя, «Дни рождения» покажут ошибку; ссылки из броней и шахматки на карточку гостя ведут на эту ошибку; подсказки «гость уже есть» по телефону пусты (бронь с новым гостем работает).
   - Сегодня затрагивает **ноль** человек (O1: `0 rows`), но решение нужно **до** включения ограниченных сотрудников в гостинице.
2. F3 и F5 (см. выше) не исправлены.
3. F4b (BUSINESS-указатель выбирает самый ранний филиал бизнеса) не менялся.
4. Страницы `/ai-agents*`, `/ai-seller/*` по прямому адресу у ограниченного открываются и показывают ошибку загрузки, а не редирект (UX, не утечка).
5. Серверные действия стойки с устаревшей кукой до срабатывания `ScopeGate` покажут «Выберите филиал заново» (раньше молча работали на самом раннем объекте).
6. Резервные клиенты API вне веба с устаревшим указателем получают 403 вместо данных самого раннего объекта (это и есть решение O4).

## Final Verdict

**CORE-SECURITY-FIX-01 INCOMPLETE (по букве раздела 20 ТЗ)**

P1 scope/security findings **closed**, regression tests **green** (176 из 176, 64 красных на чистом `main`), O1 показал отсутствие затронутых пользователей.

Remaining confirmed P2 security boundary issues, исправление которых запрещено ТЗ до утверждения политики:

- F3: каталоги уровня бизнеса (мастера, услуги, клиенты Beauty и Food, меню и сотрудники ресторана) читаются и пишутся из роли одного филиала;
- F5: явный `customerId` берёт клиента сети по организации и создаёт связь `CustomerBusiness` чужого бизнеса.

**CORE-03 MUST NOT START** до одного из двух: (а) решения владельца по F3 и F5 и их исправления, либо (б) явного письменного принятия этих двух P2 как известного отложенного риска. Если выбрано (б), разрешение на CORE-03 даёт владелец.
