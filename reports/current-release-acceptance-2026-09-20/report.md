## Исправленные причины сбоев проверок

1. `local-db.sh` заполнял `pms_test` дважды: `test:schema`, затем второй
   `seed-local`. PostgreSQL отклонял пересекающиеся размещения (`23P01`).
   Второй засев удалён; PostgreSQL из явно выбранного PATH имеет приоритет.
   Новый регрессионный тест подставляет все внешние команды и не касается БД.
   RED: `11-49-34Z-unit-4a9c`; GREEN: `11-50-01Z-unit-fcff`.
   Затем новая локальная PostgreSQL успешно создана и засеяна всеми миграциями.
2. Изолированному e2e API не хватало SESSION_SECRET для accounts middleware.
   Задан отдельный тестовый секрет только для изолированного стенда, с возможностью
   переопределения E2E_SESSION_SECRET. Production-конфигурация не меняется.
   RED: `11-54-04Z-unit-f9d4`; GREEN: `11-54-27Z-unit-2ae8`.
3. В тесте аналитики pageview и search могли попадать в разные пакеты коллектора.
   До открытия серверного отчёта проверяется сохранение обоих событий в БД.
   Исходный сбой: `11-54-32Z-e2e-71c2`. Проверки интерфейса сохранены полностью.
4. Bash на macOS воспринимал символ рядом с `$v` как часть имени переменной
   в сообщении отказа остановки ARI. `${v}` устраняет аварийный выход.
   Два существующих отрицательных теста были красными в
   `11-59-15Z-unit-caa4`; проверяется отказ с понятным сообщением, а не
   ложный успех. Настоящие ARI start/stop и отправка в Channex не вызывались.

Все ID выше имеют префикс `2026-09-20T`; полные логи — `tests/runs/logs/`.
Первый общий unit-прогон при одновременной нагрузке браузера имел также таймауты.
При ограничении двумя workers остались только два воспроизводимых Bash-сбоя.
