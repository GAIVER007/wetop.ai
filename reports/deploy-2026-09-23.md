## Почему выкладка не сделана

| Контур | Что нужно | Что в контейнере |
|---|---|---|
| Стойка `app.wetop.ai` | SSH на `187.77.145.152`, затем `git pull` и `docker compose up -d --build` | `ssh` есть, но соединение с портом 22 отваливается по таймауту: сеть окружения этот адрес не пускает, ключа тоже нет |
| Сайт `wetop.ai` | Токен Cloudflare для `wrangler pages deploy` | `CLOUDFLARE_API_TOKEN` не задан |
| Даже проверка результата | Открыть `https://app.wetop.ai` и `https://wetop.ai` | оба дают код 000 — исходящий доступ к ним закрыт |

`git push` и слияние выкладкой не считаются (`docs/deploy.md`, шапка): на сервере по-прежнему прежний код.

## Что нужно от владельца — ровно две вещи

1. **Сеть окружения.** В настройках облачного окружения (меню окружения в заголовке сессии → Edit,
   раздел сетевого доступа) разрешить `187.77.145.152`, `app.wetop.ai`, `wetop.ai`, `api.wetop.ai`
   и `api.cloudflare.com` — либо выбрать более широкий уровень доступа.
2. **Токен Cloudflare.** Там же, в настройках окружения, добавить переменную `CLOUDFLARE_API_TOKEN`
   (права: Cloudflare Pages — Edit). Значение вписывает владелец, в чат его присылать не нужно;
   новая сессия его подхватит.

Плюс доступ к серверу: ключ или разрешение на `ssh root@187.77.145.152`.

## Команды выкладки, если делать самому

Сайт (с Mac, где есть вход в Cloudflare):

```bash
git pull
npm run site:deploy          # сборка + wrangler pages deploy apps/site/out --project-name wetop-site
```

Стойка (на сервере, `docs/deploy.md` §1а):

```bash
cd /root/wetop && git pull                 # должен прийти 2d47897 или новее
cd deploy && docker compose -f compose.yml -f compose.hostinger.yml up -d --build api web
docker compose -f compose.yml -f compose.hostinger.yml ps
```

Проверка после (не «200 и ладно», а по существу):

```bash
curl -s https://api.wetop.ai/health                                   # база отвечает
curl -s https://app.wetop.ai/auth/options | grep registrationEnabled  # должно быть false
docker compose -f compose.yml -f compose.hostinger.yml exec -w /app api node -e "console.log(process.env.BUILD_ID)"
```

`REGISTRATION_OPEN` в серверном `.env` не менять: там `0`, и пустое значение регистрацию **открывает**.
Миграций эта выкладка не несёт — откат возвращает прежний образ без работы с базой.
