Поручение: «давай пуш деплой все обновления». **Оба контура выложены и доказаны** — стойку владелец
обновил на сервере, главную выложил с Mac. Ниже — что готово, чем доказано и на какие грабли наступили.

## Сайт `wetop.ai` выложен и доказан

Выкладку делал владелец с Mac после того, как нашлась причина отказа (ниже).

| Проверка | Результат |
|---|---|
| `pages deploy` | `Uploaded 19 files (37 already uploaded)`, 2,49 с |
| Адрес выкладки | `https://aac93581.wetop-site.pages.dev` |
| Домен | `curl -s https://wetop.ai/ \| grep -c "Три экрана"` → **1** |

«Три экрана, на которых держится смена» — заголовок витрины, которого в прежней главной не было:
значит, на домене именно стеклянная редакция, а не кэш прежней.

### Почему wrangler предлагал создать проект

У владельца **два аккаунта Cloudflare**, и wrangler по умолчанию взял не тот:

| Аккаунт | ID | Pages-проекты |
|---|---|---|
| `a555tzn@gmail.com` | `6a9a85bbf56dbab7bdca5814b80c08fa` | нет ни одного — под ним и был вход |
| `Zapoinov95@gmail.com` | `aa05d3443b086b6c6e6b3392ee17ab56` | `wetop-site` → `wetop.ai`, `www.wetop.ai` |

Проект никуда не девался. В такой ситуации wrangler не ругается, а предлагает **создать новый** —
соглашаться нельзя: получился бы пустой проект без домена, а сайт остался бы прежним. Лечится
указанием аккаунта: `CLOUDFLARE_ACCOUNT_ID=aa05d344… npm run site:deploy`. Записано в `docs/deploy.md` §2.

### Попутно: сборка чуть не ушла со старым кодом

Первая попытка шла на дереве, где `git pull` падал, — сборка успевала собраться и уехать. Обошлось:
в клоне на Mac уже был `6d5c4ef9`, то есть вся стеклянная работа, и на домен уехала новая главная.
Правило на будущее — **сначала `git pull`, потом `site:deploy`**: `site:deploy` собирает то, что лежит
в рабочей копии, и про отставание от `main` ничего не знает.

## Команды выкладки, если делать самому

Сайт (с Mac, где есть вход в Cloudflare) — **это осталось сделать**:

```bash
git pull
npm run site:deploy          # сборка + wrangler pages deploy apps/site/out --project-name wetop-site
```

Стойка (на сервере, `docs/deploy.md` §1а) — **выполнено 23.09**:

```bash
cd /root/wetop && git pull                 # должен прийти 2d47897 или новее
cd deploy && docker compose -f compose.yml -f compose.hostinger.yml up -d --build api web
docker compose -f compose.yml -f compose.hostinger.yml ps
```

Проверка после — **только изнутри контейнера**, портов на хосте нет:

```bash
docker compose -f compose.yml -f compose.hostinger.yml exec api wget -qO- http://127.0.0.1:3001/health
docker compose -f compose.yml -f compose.hostinger.yml exec api wget -qO- http://127.0.0.1:3001/auth/options
docker compose -f compose.yml -f compose.hostinger.yml exec -w /app web sh -lc 'cat apps/web/.next/BUILD_ID; ls -l apps/web/src/app/glass.css'
```

`REGISTRATION_OPEN` в серверном `.env` не менять: там `0`, и пустое значение регистрацию **открывает**.
Миграций эта выкладка не несёт — откат возвращает прежний образ без работы с базой.
