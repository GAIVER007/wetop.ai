## Что было не так

- **Пустое состояние собирал каждый экран по-своему:** `div.empty-state` с `h3` и иконкой («Номера»,
  «Гости», главная), с `h3` без иконки (карточка гостя), одним `p` (шахматка), `td.empty-state` («Журнал»),
  `section.empty-state` (экран ошибки, «не найдено»). Компонента не было.
- **Два CSS для одного класса спорили:** `workspace.css` — grid, отступ 52 px, `h2` 18 px, текст `line-height 1.7`;
  `premium.css` — flex, отступ 44 px, `h3` 15 px, **текст 12 px** (основной текст по правилам — 14 px). Побеждал
  тот, что грузился позже.
- **Скелетон** — три CSS-класса без компонента и без правила про читалку; в каталоге он стоял внутри секции
  «Панель», а не как состояние сам по себе. **Экран сбоя** (`ErrorState`) существовал, но в каталоге его не было,
  и разницу «нет связи» / «отклонённый запрос» можно было увидеть только сломав API.
- Аудит 18.09 (`reports/design-audit-2026-09-18.md`, п. 7): «пустой вид, загрузка, ошибка — нет».

## Что сделано

- **`ui.tsx`:** `EmptyState` (иконка, заголовок «чего нет», текст «что сделать», `actions`), `Skeleton`
  (`title` / `stat` / `row` / `text`, `aria-hidden`), `LoadingState` (`aria-busy`, живая подпись `role="status"`
  словом, скелетоны формы содержимого; без крутилки — §8). `ErrorState` не менялся — он уже различает
  4xx («проверьте адрес… повтор даст тот же ответ») и обрыв («проверьте подключение», кнопка «Повторить
  загрузку», ссылка «Подключения API»).
- **Один CSS в `globals.css`** для `.empty-state`, `.loading-state`, `.skeleton*`: отступы токенами
  (`--space-8` / `--space-6`), заголовок 15/600, текст 14 px, действия в ряд; `td.empty-state` остаётся ячейкой
  («Журнал»). Дубли из `workspace.css` и `premium.css` удалены, `.empty-state__actions` из `directory.css`
  переехал сюда. Скелетон стал виден в светлой теме (основа `--primary-soft`, блик `--surface-muted`).
- **Каталог `/design-system`:** секция «Пусто, загрузка, сбой» — три состояния с пояснениями; сбой показан
  дважды (`API_503` и `API_404`) через `ErrorDemo` в `demos.tsx` (объект `Error` из серверного компонента в
  клиентский не передать).
- **`DESIGN.md` §8:** строка «Скелетон, пустое состояние — частично» стала «Пусто, загрузка, сбой — есть с 20.09».
- **Попутно, из CI на PR #25:** (1) на списке броней после «Убрать поиск» поле поиска показывало прежний запрос —
  при мягком переходе React переиспользует поле, и `defaultValue` не обновляется; поля поиска и дат получили
  `key` по значению (`reservations/page.tsx`); (2) сквозной `web-analytics` ждал сводку отчёта, но не строку
  спроса — событие поиска уходит своей пачкой, и экран открывался до неё (`an-demand-row` 0 из 1); теперь
  ожидание включает строку спроса; (3) `npm run db:local -- reset` падал: с 19.09 `test:schema` сам засевает
  `pms_test` сидом из аудита, а второй сид `seed-local` клал проживания `STAND-…` на те же койки (23P01) —
  второй сид только в пустую схему.
