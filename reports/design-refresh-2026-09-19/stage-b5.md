# WETOP — состояния в списке броней B5

20.09.2026. Основание: `tasks/todo.md` (B5 — после B4: «внедрить загрузку/ошибку без потери контекста списка;
затем повторять отдельными срезами для остальных маршрутов»), поручение владельца «продолжай». Облачная
сессия (Linux, без `.env`), ветка `claude/relaxed-carson-ekb1gc`. Это B5 — только маршрут «Брони».

## Что было не так

- Отказ API на списке уходил в корневой `error.tsx`: вместо экрана «Брони» — общая страница «Не удалось
  загрузить данные» без заголовка раздела и фильтров; администратор не видел, какой период и статус он выбрал,
  и не мог поправить условия, не уходя со страницы.
- Пока список шёл из базы (Сингапур, один запрос — сотни миллисекунд), маршрут показывал корневой скелетон
  главной: заголовок «Брони» появлялся только вместе с данными.
- Проверить это было нечем: у синтетического API был отказ по пути (`failPath`), но не задержка.

## Что сделано

- **`reservations/page.tsx`:** запрос списка ловится самой страницей; при отказе заголовок, подзаголовок,
  форма поиска и дат, чипы статусов и адрес с условиями остаются, вместо строк — `ErrorState`
  (`load-error.tsx`, `data-testid="reservations-error"`): «Проверьте подключение и повторите запрос» и кнопка
  «Повторить загрузку» (`router.refresh()` — перечитать с теми же условиями, ничего не сбрасывая) или, для
  отклонённого запроса, «Сервер отклонил запрос (код N): проверьте адрес страницы и даты в нём». Ни счётчика
  «0 бронирований», ни пустого состояния при отказе нет.
- **`reservations/loading.tsx`:** заголовок «Брони» сразу, под ним `LoadingState` («Загружаем список
  броней…», `aria-busy`) со скелетонами строк (B4).
- **`reservations/error.tsx`:** сбой вне запроса списка — тот же `ErrorState`, но с заголовком раздела.
- **Синтетический API:** знак `delayPath` / `delayMs` в `/__test/control` — задержка ответа по одному пути;
  сброс его снимает.

Файлы: `apps/web/src/app/reservations/{page,loading,error,load-error}.tsx`, `scripts/preview/fixture-api.ts`,
`tests/ui/reservations-states.spec.ts` (вместо `requests.spec.ts` из списка среза — там счётчик запросов, а
здесь состояния; счётчик на `/reservations` не изменился).
