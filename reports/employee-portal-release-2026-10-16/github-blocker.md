# Фактический блокер отправки кандидата на GitHub

16.10.2026 после локальных зелёных гейтов выполнен обычный push в `feat/employee-portal-release-20261016`. GitHub отклонил его:

> refusing to allow an OAuth App to create or update workflow `.github/workflows/release-checks.yml` without `workflow` scope

Изменение workflow необходимо: существующий полный гейт должен запускать новый portal UI набор и настоящую отдельную restore-проверку. Убирать эти проверки ради push нельзя. Workflow не ослаблен, ветка release не менялась, чужие прогоны не отменялись.

Проверен только уже имеющийся альтернативный Git transport, с BatchMode и StrictHostKeyChecking. SSH push остановился на `Host key verification failed`: доверенного host key github.com в данном SSH-контуре нет. Проверка подлинности не отключена, новые SSH ключи и авторизация не создавались, состояние авторизации/секреты не выводились.

`git ls-remote` после отказа не обнаружил удалённую ветку кандидата. Поэтому PR и удалённый `release-checks` для этого кандидата пока НЕ созданы. Ранний зелёный gate на main не является проверкой этого кандидата. Вымышленной ссылки на PR/Actions нет.

## Безопасная передача владельцу

Кандидат и журнал сохранены в собственной именованной локальной ветке. Рядом с внешними доказательствами подготовлен Git bundle с нужными коммитами и prerequisite main `c46ef1c52bbc99e50e27c9dd396c261d0b825d22`. Точный итоговый SHA и SHA256 bundle приведены в итоговом внешнем handoff.

Владелец/администратор может импортировать эту ветку из bundle в свой доверенный клон, проверить SHA и отправить её своим существующим GitHub-доступом, который разрешает изменение workflow. Токены/ключи не присылать в чат. Расширение прав hermes не требуется и агентом не выполнялось.

После успешного push: создать PR этой ветки в main, запустить существующий `release-checks` на точном SHA feature-ветки через Actions `workflow_dispatch`, дождаться всех требуемых проверок. Только после зелёного гейта владелец рассматривает merge. Далее действуют отдельные production SQL, backup/restore, KZ S3 и Cloudflare границы из [owner-handoff.md](owner-handoff.md). Этот документ не разрешает обход этих границ или новую схему выкладки.
