# Деньги брони одним шагом: отчёт среза 07.10.2026

План: `plans/finance-payments-direct-2026-10-07.md`. Решение: ADR-151. Модель: `DATA_MODEL.md` §6 v2.12, §24 п. 7.
Ветка `claude/youthful-wozniak-vin0pp`, PR #265. Схема и миграции не менялись.

## Что увидит владелец

Вкладка «Счета» карточки брони, в каждом счёте проживания сверху вниз:

1. **Принять оплату**: способ, сумма (остаток по умолчанию), примечание, одна кнопка. Запроса оплаты для этого не нужно.
2. **Проживание и услуги**: таблица начислений. У строки проживания кнопка «Изменить цену» (поле с текущей ценой и
   подпись, что при смене дат или категории цена снова посчитается по тарифу). У остальных строк «сторно». Под таблицей
   форма «Добавить»: услуга, скидка (процент или сумма, причина; только владельцу и управляющему), штраф, корректировка.
3. **Оплаты**: у проведённого платежа кнопки «Вернуть» (раскрывает форму с остатком платежа по умолчанию),
   «Изменить» (панель справа: способ, сумма, примечание; прежний платёж остаётся аннулированным, дата сохраняется)
   и «Аннулировать» (вопрос с суммой). У аннулированного платежа действий нет, строка приглушена.
4. Возвраты строкой, ранний заезд и поздний выезд, закрытие счёта, как было.

Ниже счетов свёрнутый блок **«Отправить гостю счёт на оплату»** (прежние запросы оплаты Kaspi, ссылка банка,
реквизиты); раскрыт сам, пока есть ожидающие запросы.

«Финансы → Операции»: у платежа гостя кнопка «Аннулировать» с тем же вопросом; с возвратом или чеком API откажет словами.

Администратор без права `refunds` видит только «Принять оплату» и «Начислить» (услуга, штраф, корректировка).

## Ограничения, записанные вопросами

- Q-276: дата платежа при правке не меняется (замена хранит дату старого платежа).
- Q-277: ошибочный возврат не аннулируется; закрывается новым платежом с примечанием.
- Платёж с выданным чеком меняется только возвратом: чек пробит на сумму (§26, провайдер не выбран, Q-050).
