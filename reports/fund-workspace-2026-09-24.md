# Номерной фонд: создание и ежедневная работа — 24.09.2026

## Результат

Три связанные вкладки: номера/койки, категории, доступность. Дублирующий /rooms перенаправляет
в /inventory. Каталог по умолчанию — компактный список с редактированием; карточки и фильтры сохранены.
Категории показывают тип продажи и вместимость одного размещения, раскрываемый состав, создание,
переименование, добавление комнаты и переходы в тарифы/шахматку. Технические Exely ID не занимают экран.
Доступность: даты и быстрые периоды, фильтры категории/типа, только свободные, конкретное место
передаётся в бронь вместе с датами. Ошибка API не подменяется нулём. Сохранён предел 62 ночей.

## Сохранение

Новые GET/POST/PATCH /inventory/categories, POST/PATCH /inventory/rooms работают через Nest/Prisma.
Категория связывается с явно выбранным тарифом либо новым тарифом с названием пользователя.
Цены вводятся отдельно существующим календарём. Комната и явно перечисленные койки создаются
атомарно. Записи относятся к объекту текущей организации; изменения журналируются; кэш фонда
сбрасывается. Дубли обозначений дают 409 и откат всей операции. Для новой пустой категории
исправлена вместимость в сводке: берётся её настройка, а не ноль.

Схема и миграции не менялись. PII и внешние API не затронуты. Производственная ARI не отправлялась.
Редактирование сейчас меняет название категории и обозначение физической комнаты. Тип, вместимость,
коды существующих единиц, архивирование/удаление и перенос коек между комнатами не изменяются:
для этого нужны отдельно определённые правила сохранения истории и действующих броней.
Роли не добавлены: применяется действующая аутентификация и изоляция по организации (ADR-023/061).
Коды мест остаются глобально уникальными согласно существующей схеме.
