# O2a: безопасный загрузчик сайтов гостевого мастера, отчёт об SSRF (09.10.2026)

Модуль `apps/ai-seller/src/site/wizard_fetch.py`, тесты `apps/ai-seller/tests/test_wizard_fetch.py` (62 теста). Без модели, без базы, без интерфейса.
Тесты идут на подставном транспорте и DNS (`httpx.MockTransport`): внутренний адрес не должен **дойти до транспорта**, это и проверяется.

## Как устроена защита
1. Проверяются адреса, а не имена: имя резолвится, **все** полученные адреса должны быть публичными, иначе отказ целиком.
2. Соединение идёт на **закреплённый** проверенный IP; имя уходит в `Host` и SNI. Второго обращения к DNS нет, ребайндинг не работает.
3. Каждый редирект (не больше 3) проходит все проверки заново. Ответ режется по фактическим байтам (до 2 МБ), сжатое распаковывается с потолком на выход, всё укладывается в общий срок 10 с, `trust_env=False` (прокси из окружения не обходит проверку).

## Доказательство
- Сначала красные: модуля нет (`ModuleNotFoundError`), затем зелёные **62 из 62** на Python 3.13 в контейнере (как в образе бота), без `conftest` платформы (нужны только httpx, pytest, pytest-asyncio).
- **Мутации, по одной, файл восстановлен после каждой.** Красные: редиректы без проверки (2 теста), проверка только первого адреса ответа (1), числовые имена не отбрасываются (2), соединение по имени вместо IP (4), порты не проверяются (2), NAT64 не проверяется (1), список закрытых сетей пуст (1), предел размера выключен (2), тип содержимого не проверяется (5), общий срок снят (1), без SNI (1).
- **Две мутации выжили, и это объяснено:** отдельные ветки `IPv4-mapped` и `6to4`. На Python 3.13 стандартная библиотека сама считает такие адреса не публичными, поэтому тест на 3.13 их не различает. На Python 3.9 адрес `2002:7f00:1::1` имеет `is_global=True` (проверено в контейнере и на Mac), и там это единственная защита. Ветки оставлены как страховка от разницы версий, прямого теста на них нет.
- **Живая проверка по настоящей сети и DNS** (контейнер, не часть набора): `https://example.com/` и `http://example.com/` читаются (настоящий TLS с закреплённым адресом и SNI работает), `https://www.iana.org/domains/reserved` читается; `localhost`, `127.0.0.1`, `metadata.google.internal`, `169.254.169.254`, `0x7f000001` отклонены; **`http://localtest.me/` (публичное имя с A-записью 127.0.0.1) отклонён как `address`**; `httpbin.org/redirect-to?url=http://127.0.0.1/` отклонён на втором переходе; `expired.badssl.com` дал неточный код `dns` (исправлено на `connect`, добавлен тест).

## Что не доказано и ограничения
- Распаковка с потолком (`decompress(data, max_length)`) проверена тестом на бомбу по итогу (`too_large`), но не по памяти: мутация, снимающая `max_length`, тесты не краснит. Защита от выделения гигабайта одним куском держится на коде, замера памяти нет.
- Соединение пробуется с первым адресом ответа; если он не отвечает, второй не пробуется (`ponytail`-ограничение).
- Ссылки на соседние страницы (П6) не реализованы: отдельным коммитом в O2b после этого отчёта.
- DNS-ребайндинг проверен подставным резолвером, а не настоящим атакующим DNS-сервером.
- Полный набор `pytest` бота (с `conftest` платформы) здесь не запускался: нужны зависимости образа (torch и др.). Новый файл с ним не взаимодействует (нет импортов `src.config`, `src.dependencies`).
- Загрузчик пока никуда не подключён: ни маршрута, ни вызова из мастера (это O2b).
