# Слияние `origin/main` в `claude/trusting-ramanujan-gi6uzl` — 19.09.2026

Этап Э0 п. 3 ТЗ переезда (`plans/server-kz-tz-2026-09-18.md`): до сервера ветка обязана нести всё, что
дошло до `main`. Слито `6293ad4` (PR #19, ветка `claude/blissful-meitner-ipoauv`): вход по коду на почту
и регистрация живьём, `scripts/ops/repo-sync.sh`, разбор скорости (журнал одним SQL, кэш дерева фонда и
настроек, пределы периодов), окна подтверждения вместо `window.confirm`, спеки без кодов объекта
(`tests/e2e/pick-category.ts`), интеграционные тесты на локальной базе (`npm run db:local`),
`overdue` → `overdueArrivals`. Облачная сессия, Linux, без `.env`.

## 1. Размер

54 файла в конфликте, ~110 блоков; 15 в API, 20 на стойке, фикстура синтетического API (7 блоков),
`playwright.config.ts`, 14 сквозных спеков и помощник окна подтверждения, 3 UI-спека, `.github/workflows/checks.yml`.
Ещё ~400 файлов слились сами — среди них были дубли, которых git не видит (§3).

## 2. Правило

Ничего не выброшено: там, где обе ветки сделали одно и то же, оставлена одна реализация — та, что
проверена живее или является надмножеством; где сделали разное — обе, рядом. Каждая замена ниже названа.

## 4. Дефекты, которых не было ни в одной ветке по отдельности

1. **`finance-audit-transaction.test.ts`** (main) подделывал `property.findFirstOrThrow`, а ветка читает объект
   через `propertyIdRef` (`findFirst`, один раз на процесс) — подделке добавлен `findFirst`.
2. **`reservation-directory.ts`**: константы `DEFAULT_PAGE_SIZE`/`MAX_PAGE_SIZE` из ветки и числа из `main` — линтер
   поймал неиспользуемые константы; используются константы.
3. **`unit-blocks.spec.ts`** снимал блокировку через `page.once('dialog')`, а `unit-actions.tsx` из `main` спрашивает
   окном стойки — спек переведён на `confirmAction(page, 'Снять блокировку')`.
4. **`audit-list.test.ts`** (интеграционный, main) ждал строку без поля `author` — поле добавлено в ожидание, и на
   живом Postgres проверено, что JOIN с `users` выполняется.
5. **Сид стареет.** `chessboard.spec` красный: занято 0. Сид держит занятость −10…+2 ночей вокруг дня засева, а
   `ensureTestSchema` пересевал только пустую схему — сид от 16.09 к 19.09 пуст. Теперь день отметки
   `refreshed_at … (сид)` сверяется с сегодняшним по Алматы, и схема засевается заново сама (`seedIsStale`,
   red → green в `tests/unit/test-data-source.test.ts`; копия рабочих данных не стареет).
6. **Стенд UI тоже живёт вокруг «сегодня».** `chessboard-week.spec` ждал свободное воскресенье у `R03`, а
   проживание фикстуры `TEST2` стоит на ней с сегодняшнего дня на три ночи: с пятницы по воскресенье спек был
   красным независимо от кода (19.09 — суббота). Теперь спек берёт первый номер со свободной воскресной
   клеткой, как сделала бы смена.
7. **UI-набор в два воркера.** `test:record -- e2e` навязывает `--workers=2`, а фикстура UI одна на всех
   (`__test/reset`, `showcase`, `failPath`): первый полный прогон уронил `channex-screens` не по коду. Набор
   гоняется только с `--workers=1` в конце команды (записано в `TESTING.md`).

## 6. Не проверено отсюда

Живая dev-БД, архивный источник, Channex, launchd, туннель, письмо с кодом через Resend — только с машины стойки. Вход по
