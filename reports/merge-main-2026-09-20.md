# Второе слияние `origin/main` в `claude/trusting-ramanujan-gi6uzl` — 20.09.2026

Продолжение этапа Э0 п. 3 ТЗ переезда (`plans/server-kz-tz-2026-09-18.md`). Пока шла подготовка PR по
первому слиянию (`reports/merge-main-2026-09-19.md`), `main` ушёл вперёд ещё на 344 файла: слито
`eb6752b` — PR #21 (**вторая, независимая реализация срезов 7.1–7.4**: предпросмотр суммы, окна
подтверждения, тексты и форматы §6/§14, шахматка со статусом, каналом и долгом, правка цены в ячейке),
PR #24 (**приглашения в организацию**, срез 13 этап 7), переезд боевых адресов на сервер Hostinger
(`ca4d478`), обновление главной и общих элементов (`48149c7`), ADR о поэтапном редизайне.
Облачная сессия, Linux, без `.env`.

## 1. Размер

44 файла в конфликте: 4 документа, 4 файла API, 17 экранов и библиотек стойки, фикстура синтетического
API, 15 сквозных спеков, 1 UI-спек. Ещё ~300 файлов слились сами — и часть из них несла дубли, которых
git не видит (§3).

## 2. Правило

То же, что 19.09: ничего не выброшено, дубли сведены к одному. Там, где обе ветки сделали **одно и то же**
разными руками, оставлена одна реализация — та, что доказана живее или шире; где сделали **разное** —
обе, рядом. Каждая замена названа ниже.

## 3. Срезы 7.1–7.4: две реализации одного среза сведены к одной

Обе ветки выполняли один и тот же план (`plans/design-system-2026-09-14.md`, ADR-048), поэтому совпали
по смыслу и разошлись по устройству. Взята основа `main` — она прошла полный UI-набор и сквозные на
своей стороне и покрыта сторожами `design-rules.test.ts`; из нашей ветки перенесено то, чего в ней нет.

| Что | Решение |
|---|---|
| Предпросмотр суммы | Один маршрут `main`: `GET …/items/:itemId/preview?action=move\|extend\|cancel\|no_show`. Три наших (`move-preview`, `extend-preview`, `cancel-preview`) сняты вместе с их типами в `lib/api.ts` |
| Расчёт предпросмотра | Наши частные помощники (`resolvePlanId`, `priceAddedNights`, `repriceForUnit`) возвращены в `reservations.service.ts`: `preview` зовёт **те же функции, что и сами действия**, а не повторяет их тело — иначе окно и счёт разъезжаются при первой правке правила |
| Занятость следующей ночи | Наш `nextNightsFree` (плюс `unitCode`) добавлен в ответ `main`: кнопка «+1 ночь» говорит «R01 занята 24.09 — сначала переселите» **до** окна, а не получает 409 после |
| Переселение в чужую категорию | Форма назначения `main` дополнена нашим окном с суммой: предпросмотр → `ask` → `requestSubmit` |
| Окна подтверждения | `useConfirm`/`previewLine` из `main` (одно окно на экран, общий текст), наши `ConfirmDialog` с `data-testid="move-amount"` и прочими сняты; спеки переведены на текст `main` |
| Очередь и журнал каналов | Наши экраны (`outbox-table.tsx`, `events-table.tsx`, страница ревизии, `GET /channels/channex/outbox/rows`, `GET …/events`) — шире: фильтры, поиск, постраничность, цепочка «ревизия → бронь → ячейка». Таблица `main` (`recentOutbox`, `GET …/outbox/messages`) снята вместе с `OutboxMessageRow` и `reservationNumber` в `recentEvents`; ссылка на бронь в нашей таблице получила `data-testid="event-reservation"`, которым пользуется спек `main` |
| Правка цены в ячейке | Наша (тиыны не теряются, `minorToInput`, уведомление и ошибка у самой ячейки). Тексты и оформление таблицы взяты у `main`: русские заголовки, «закрыто» словом, месяц кнопками-значками, даты словами. `RatesToastScope` снят — уведомления даёт общий `ToastProvider` в `layout.tsx`. `rates.css` нашей ветки снят: те же классы уже есть в `globals.css` |
| Плашка «входящая бронь требует разбора» | Наша (`review-callout`, считает `FAILED` через `GET /channels/channex/events`); `failed-revisions` из `main` снята, спек переведён |
| `formatMinor` | Живёт в `lib/format.ts` (наш перенос: его берут и клиентские компоненты), `api.ts` реэкспортирует. Сторож §14 из `main` знал только `lib/api.ts` — в список исключений добавлен `lib/format.ts` |

## 4. Приглашения (срез 13, этап 7) вложены в наш экран входа

В `main` экран входа — только по коду на почту; у нас на нём живут оба входа (Q-146, умолчание «оба»).
Блок приглашений, страница `/invite/<ключ>` и действия `inviteAction`/`acceptInviteAction` перенесены как
есть; `authApi` получил `invites`, `invite`, `inviteByToken`, `acceptInvite` и заголовок с токеном
(`authHeaders(info, token)`), `login/page.tsx` — список ожидающих и открытие формы сразу на шаге кода
после принятия. Дубли сведены: `logoutAction` из `main` снят (у нас `signOut` уже отзывает сессию),
приглашения в синтетическом API вложены в нашу секцию `/auth/*`. Спек `tests/ui/invites.spec.ts`
переключает форму на вход по коду — по умолчанию открыт вход по паролю.

## 5. Дефекты, которых не было ни в одной ветке по отдельности

1. **Сборка стойки падала.** `board-grid.tsx` из `main` берёт `messengerLinks` из `lib/api`, а наш
   `api.ts` читает cookie сессии через `lib/session` (`next/headers`) — Turbopack тянул его в клиентский
   бандл: «You're importing a module that depends on next/headers». Значение берётся из `lib/format`,
   типы — по-прежнему из `api.ts`.
2. **Пересев устаревшего сида ронял весь сквозной прогон** ещё до первого спека: «сид построен с
   пересечениями: 1». Наш `seedIsStale` (19.09) засевает заново, а `seedTestData` рассчитан на пустую
   схему — поверх вчерашних броней новые даты налезают на соседние ячейки. Введён `refreshPlan`
   (пересев по непустой схеме → сперва снять данные) и `wipeTestData`; служебные таблицы остаются.
   Тест red → green: `tests/unit/test-data-source.test.ts`, живьём — `e2e` 25/25.
3. **Шрифт 11 px** у строки «Вы вошли» в меню профиля (наш экран входа) — сторож §6 из `main` его ловит;
   заменён на `var(--text-xs)`.
4. **Подготовка теста первичной настройки сервера падала по сроку** (10 с) на полном наборе: она делает
   настоящий `git clone --bare`. Сроку дан явный предел 120 с, как у самих проверок этого файла.
5. **`.profile-signed-in`, `dialog[open]`, «Оставить как есть»** — спеки нашей ветки ждали наши тексты и
   локаторы; переведены на окна `main` (`tests/ui/manager-actions.spec.ts`, `tests/e2e/desk-tasks.spec.ts`,
   `tests/e2e/cancellation-penalty.spec.ts`).
6. **Эталоны `design/reference/kit` для Linux** сняты до токенов `main`: `--border-input` в `main`
   потемнел ради контраста 3:1 (`neutral.250` → `neutral.475`), и секция «Токены» на `/design-system`
   перестала совпадать с картинкой. 13 снимков для Linux пересняты в контейнере (`--update-snapshots`);
   снимки `-darwin` (машина владельца) не тронуты.
7. **Два спека `main` про каналы** (очередь строками, ссылка на бронь) ходили по её разметке и сеялись
   `design-seed`; переведены на наши экраны и витрину `showcase`, ссылке на бронь в нашей таблице дан
   `data-testid="event-reservation"`. Тест `main` про правку цены снят как дубль: `channex-screens.spec.ts`
   проверяет ту же ячейку строже (Enter, Escape, ноль, ошибка сервера).
8. **Спеки ждали даты и подписи до §14:** «01.10» в календаре цен вернулась (в столбце на 31 строку
   короткая дата читается быстрее слов, сырая осталась в `datetime`), подпись «Min stay» в массовой
   правке стала «Мин. ночей», дата выезда в строке проживания читается из `datetime`.
9. **`AttentionSummary` на главной** после `Suspense` из нашей ветки читал день стойки вторым запросом.
   День берётся один раз на показ (`cache` React в `today/desk-section.tsx`) — правило «путь с данными —
   один запрос на показ» (`tests/ui/requests.spec.ts`) осталось в силе.
