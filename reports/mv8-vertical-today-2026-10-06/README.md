# MV8 Vertical Today: отчёт

Дата: 06.10.2026. Ветка `claude/blissful-newton-6pa4ky`. База: `main` `c6044ba` (влит PR #256 SCOPE-HARDENING).
Решение: ADR-MV8-TODAY (`DECISIONS.md`). Строка дизайна: DESIGN.md §8 «„Сегодня“ салона и ресторана (MV8)».

## Сверка с PR #256

Сделано поверх SCOPE-HARDENING, без второго выбора филиала:

| Что из #256 | Как использует MV8 |
|---|---|
| `/scope/resolve` и выбор после входа | без изменений; `/today` стал общим разделом (`SHARED`), поэтому `next=/today` сохраняется у всех направлений |
| сброс устаревшего указателя | `/today` зовёт `requireVertical` со всеми тремя направлениями, сброс идёт прежним путём |
| выход снимает `wetop_scope` | без изменений |
| `GET /branches` как источник | загрузка ресторана берёт пояс филиала из `selectedWorkspaceBranch` (тот же `GET /branches`) |
| гостиничный `propertyRef` | гостиничная Главная вынесена в `hospitality-today.tsx` без изменений поведения |
| `/branches/overview` только гостиницы | без изменений; сводка салона и ресторана по филиалам в MV9 |

Изменений backend, схемы, миграций и правил бизнеса не понадобилось.

## Что сделано

1. Расчёт показателей `apps/web/src/app/today/vertical-metrics.ts` (только счёт статусов из ответов API).
2. Загрузка `vertical-load.ts`: салон зовёт только `GET /beauty/appointments`; ресторан зовёт залы, столы и брони за день и за вчера, дочитывая все страницы.
3. Общий `/today`: `dispatch.ts` выбирает экран по `/auth/me`, ключ `business:location`; Главная гостиницы вынесена без изменений.
4. «Сегодня» салона: плитки «Записей», «Впереди», «Мастеров», «Завершено», «Не пришли», «Отменено»; внимание: неподтверждённые записи и записи к мастеру без столбца; «Ближайшие записи», до пяти.
5. «Сегодня» ресторана: «Бронирований», «Гостей в бронях», «Сидят сейчас», «Свободно столов сейчас» (из активных), «Не пришли», «Отменено»; внимание: брони без стола; «Ближайшие брони», до пяти.
6. Стартовая страница всех направлений `/today`; в меню салона и ресторана первым пунктом «Сегодня» (у гостиницы «Главная», у ресторана «Бронирования» на месте).

Зафиксированные решения владельца применены без отступлений: мастеров `day.columns.length` с подписью «Мастеров», «Мастер недоступен», справочник мастеров не грузится, впереди BOOKED | CONFIRMED с `endMinutes > currentLocalMinute` по `startMinutes`, максимум 5; `seatedNow`, `freeNow` и занятость стола по формулам из поручения. `today-widgets.tsx` не удалён.

## Чего нет и что за владельцем

- Денежных плиток у салона и ресторана нет: деньги записи и брони ресторана не решены (Q-252 и далее).
- В стенде `branches-ui` нет модуля финансов, поэтому у гостиничной Главной блок «Деньги» там показывает «Нет данных»; на рабочем API модуль есть, MV8 его не трогал.

- Merge, выкладка и MV9 не делались.
