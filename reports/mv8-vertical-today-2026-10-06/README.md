# MV8 Vertical Today: отчёт

Дата: 06.10.2026. Ветка `claude/blissful-newton-6pa4ky`. Первая версия на `main` `c6044ba` (после PR #256 SCOPE-HARDENING); после ревью владельца перебазирована на `main` `6a6a46b` (MKT3, миграции 060 и 061) и исправлена по замечаниям, раздел «Поправки по ревью».
Решение: ADR-MV8-TODAY (`DECISIONS.md`). Строка дизайна: DESIGN.md §8 «„Сегодня“ салона и ресторана (MV8)».

## Сверка с PR #256

Сделано поверх SCOPE-HARDENING, без второго выбора филиала:

| Что из #256 | Как использует MV8 |
|---|---|
| `/scope/resolve` и выбор после входа | без изменений; `/today` стал общим разделом (`SHARED`), поэтому `next=/today` сохраняется у всех направлений |
| сброс устаревшего указателя | `/today` зовёт `requireVertical` со всеми тремя направлениями, сброс идёт прежним путём |
| выход снимает `wetop_scope` | без изменений |
| `GET /branches` как источник | загрузка ресторана берёт пояс филиала из `selectedWorkspaceBranch` (тот же `GET /branches`) |
| гостиничный `propertyRef` | гостиничная Главная вынесена в `hospitality-today.tsx` без изменений поведения |
| `/branches/overview` только гостиницы | без изменений; сводка салона и ресторана по филиалам в MV9 |

Изменений backend, схемы, миграций и правил бизнеса не понадобилось.

## Поправки по ревью владельца (06.10, PR #259)

Решение по ресторану: «Ближайшие брони» остаются `BOOKED | CONFIRMED` и `endsAt > capturedNow`; начавшаяся бронь, гость которой ещё не сел, видна; статуса «опаздывает» нет.

1. **Гостиница больше не угадывается.** `todayScreen` даёт `UNRESOLVED` при `vertical = null`, незнакомом направлении, у салона и ресторана без Business или филиала. Без указателя филиала `/today` ведёт через `/scope/resolve` (тот же выбор, что после входа), с указателем на `/branches` (повторный автоматический выбор дал бы то же самое, цикла нет). Второго выбора филиала нет.
   **Исключение на ваше подтверждение:** анониму без сессии при выключенном замке входа (открытый стенд разработки, на нём идёт весь `tests/ui`; в production-образе замок включён всегда, и аноним до `/today` не доходит) `/today` показывает гостиничную Главную единственной гостиницы стенда, как до MV8. Без исключения около сотни гостиничных спеков `tests/ui` уходили на выбор филиала: у анонима нет ни сессии, ни филиала. Вошедший человек этим путём не идёт, для него правило строгое (тест `dispatch.test.ts`). Если исключение не подходит, альтернатива: стенд `tests/ui` входит в систему перед каждым спеком; это большая правка набора, отдельным решением.
2. **Смена суток у салона.** Местная дата момента счёта не равна `day.date`: ошибка «Сутки филиала сменились. Обновите страницу.», значения 1440 и -1 удалены, числа двух суток не смешиваются.
3. **Утверждённый набор показателей.** Салон: Запланировано (BOOKED + CONFIRMED), Подтверждено (CONFIRMED), Завершено (DONE), Мастеров (`columns.length`); внимание: ждут подтверждения (BOOKED), не пришли (NO_SHOW). Ресторан: Запланировано (BOOKED + CONFIRMED дня), Сидят сейчас, Завершено (COMPLETED дня), Свободно столов сейчас; внимание: без стола (BOOKED и CONFIRMED), ждут подтверждения, не пришли. Плиток «Записей», «Впереди», «Отменено», «Бронирований», «Гостей в бронях» больше нет. Денег нет, статусы домена не менялись.
4. **Одна бронь в двух ответах ресторана** берётся по более новому `updatedAt`; к дню относится, если начинается не раньше местной полуночи филиала.
5. **Моковый стенд `tests/ui`:** день салона без даты теперь «сегодня» в поясе филиала, как у настоящего API (`todayIn`); раньше мок отдавал фиксированное 12.10, и правило смены суток честно показывало ошибку на «Сегодня» салона.
6. **Снимки пересняты** (12): гостиница 390 light без окна обучения. Окно обучения на снимках помечено пройденным тем же приёмом, что в наборе UI.

Проверено попутно: гостиничное обучение у салона и ресторана само не открывается. Его монтирует только гостиничная оболочка (`top-nav.tsx`), правка не понадобилась; браузерный тест закрепляет это правило как страховку, RED у него нет, потому что поведение было верным и до MV8.

RED → GREEN поправок:
- выбор экрана: 3 из 6 красных (гостиница вместо UNRESOLVED, нет `unresolvedTarget`) → 6/6;
- расчёт: 7 из 16 красных (старые показатели, нет проверки суток, нет выбора по `updatedAt`) → 16/16;
- загрузка: 2 из 6 красных (сутки, полночь ресторана) → 6/6;
- браузер: тест «без подтверждённого направления гостиница не угадывается» на старых `page.tsx` и `dispatch.ts` красный → зелёный; вся матрица `branches-ui` 26/26.

## Чего нет и что за владельцем

- Денежных плиток у салона и ресторана нет: деньги записи и брони ресторана не решены (Q-252 и далее).
- **Ограничение стенда, не состояние реального `/today`:** в стенде `branches-ui` не подняты модули финансов и каналов, поэтому на снимках гостиничной Главной блок «Деньги» показывает «Нет данных», а в шапке «Нет связи с API». Код гостиничной Главной MV8 не менял; на рабочем API эти модули есть.
- Снимок ресторана со 105 бронями без стола искусственный: это нагрузочный засев для доказательства дочитывания больше 100 броней, а не пример реального дня.
- «Ближайшие брони» ресторана показывают и брони, окно которых уже началось, но не закончилось (то же правило, что «впереди» у салона). Если владелец хочет только ещё не начатые, это одна строка в `foodToday`.
- Merge, выкладка и MV9 не делались.
