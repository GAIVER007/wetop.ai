## Контур и контракт

Изолированный PostgreSQL 17.6, localhost 55933, `pms_test`. Полный Nest AppModule, `AUTH_REQUIRED=1`, web `APP_AUTH_REQUIRED=1`. Обычные AuthService, SessionGuard, RoleGuard, scope и RLS через `wetop_app`. Подменён только внешний ARI publisher на Noop; внешние маршруты/планировщики отключены. .env, production-данные и ключи не копировались. Синтетические пользователи имеют домен example.invalid, пароль существует только во временном контуре и в памяти теста.

Подтверждённые пути: `/auth/fallback` выполняет настоящий вход. `/register/complete` проверяет существующую регистрацию и кнопкой «Продолжить» устанавливает проверенный scope. `/register/setup` открывает мастер выбранного Business/Location. Самостоятельный URL параметр vertical не меняет направление. OWNER/MANAGER могут писать, STAFF и READ_ONLY только читают. Гостиница с готовым фондом перенаправляется к `/today` без повторного provision. Для входа гостиницы проверено также прохождение `/onboarding` и подтверждение контекста через существующую страницу complete.

## Причина и исправление

На точном a5c5050c полный отказ API после ввода имени и Save убирал форму. `signedInUser` превращал любой ApiError в null при серверной проверке страницы. Повторный автоматизированный Save при четырёх отказах сохранял поля, но не предлагал безопасный retry; отдельная перезагрузка при отказе API воспроизвела уход на Главную. Потеря формы не заявляется для каждого Submit. Полный API воспроизвёл дефект независимо от прежнего тестового адаптера.

Теперь только подтверждённый 401 означает отсутствие сессии. Команда выполняется через same-origin JSON route без повторного page render; POST проверяет Origin, каждый запрос сохраняет обязательные API guards и scope. Network/timeout/503 оставляют поля и кнопку «Повторить». После неопределённого ответа сначала читается progress: совпавшие филиал, версия, draft и ожидаемый переход подтверждают уже выполненную команду; она не повторяется. 409 оставляет локальный ввод и требует явной загрузки серверной версии. Запреты 401/403 не превращаются в успех.

U05 выявил устаревший шаг из browser history. Shell сверяет progress при монтировании без SSR; поздний ответ не применяется после начала редактирования/команды. Проверка возврата и сохранённых полей оставлена прежней. Схема, финансовые и booking правила не изменены.

## Доказательства и локальная диагностика

RED: [форма до отказа](evidence/RED-before.txt), [форма исчезла](evidence/RED-final.png). Unit регрессия API 503 первоначально упала: ожидалось исключение, получен null.

GREEN вручную: [ошибка связи с сохранёнными полями](evidence/GREEN-outage-settled.png), [повтор и reload](evidence/GREEN-retry-reload.png). В первой попытке localhost Origin проверялся по внутреннему hostname; до принятия результата исправлено на настроенный APP_URL. Cross-origin и отсутствие Origin отдельно запрещены unit тестами.

Первая полная UI попытка: 19 PASS, U05 реальный cache дефект; U06 снимал baseline до завершения сохранения, U09 ожидал не тот штатный маршрут. Вторая попытка: 20 PASS, дополнительный SSR refresh не решил U05 и исключён. Тестовые ожидания результата не удалялись и не ослаблялись. После исправлений предыдущий полный набор: 22 PASS. Окончательный запуск дополнительно проверил A/A2 и точный 401: 22 PASS. Для 401 реальный ответ читается до его передачи браузеру, который сразу следует на вход; это устраняет потерю Network response body при навигации, результат API не подменяется.

Локальный unit запуск с максимальным параллелизмом: 42 FAIL, преимущественно таймауты shell tests. Повтор 12 упавших файлов последовательно: 101 PASS, 2 FAIL из-за Bash 3.2/macOS UTF-8 parsing у неизменённых скриптов. Те же два файла с LC_ALL=C, без правки проверок/кода: 29 PASS. Отдельный auto-deploy: 16 PASS. Полный итоговый unit с LC_ALL=C и двумя workers: 3345 PASS, 5 FAIL (5000ms shell timeout в auto-deploy/guard-run), 4 прежних SKIP. Исходные assertions/deadlines сохранены; локальный полный unit не объявляется зелёным. Те же shell suites повторяются отдельно, окончательный результат подтверждает полный CI. Полный Linux CI остаётся обязательным.
