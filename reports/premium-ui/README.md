# WETOP.AI — UI/UX по ТЗ владельца, 13.09.2026

Дизайн реализован в существующем Next frontend. Это работающие страницы и компоненты, не изображение или отдельный прототип.

## Запуск на другом компьютере

Node 24. После получения обновлений:

```sh
npm ci
npm run generate -w packages/database
```

Для визуальной демонстрации без backend:

```sh
npm run dev:demo
```

Откройте `http://127.0.0.1:3000/today`. Данные вымышленные; сессия демонстрационного сервера временная. Она не подключается к БД, Channex, eQonaq и оплатам. Деморежим не является эмуляцией всех правил PMS.

Для рабочих данных запустите обычный API и frontend (`npm run dev -w apps/api`, `npm run dev -w apps/web`), настройте серверные environment variables вне Git. Для production выполните `npm run build -w apps/web` и перезапустите приложение. Изменения не переносят секреты/БД между компьютерами.

## Реализовано

- Общие light/dark/system токены, сохранение темы, системная тема при первом входе, спокойная сине-голубая палитра, Lucide, системная типографика, единые формы/таблицы/панели/статусы.
- Shell с панелью 232/76 px, поиском ⌘K/CtrlK, меню администратора, уведомлениями, помощником. Drawer меню на планшете и нижняя навигация на телефоне.
- Dashboard: показатели, ближайшие заезды/выезды, задачи, быстрые действия с выбором брони, сводка, график и доли размещения из API. Не подменяет отсутствие ответа нулями.
- Шахматка: периоды, даты, поиск, категории, типы единиц и фильтры состояния на первую дату. Сохранены sticky-оси, свободная клетка → создание, перетаскивание → существующая команда переселения.
- Карточка брони открывается справа и по прямой ссылке. Вкладки, расчёт, оплаты, продление/переселение/заселение и печать используют существующие формы. Карточки гостей имеют вкладки и переход к счетам проживания.
- Постраничный список броней, стоимость, оплаты, баланс, источник, поиск и фильтры. API-проекция не меняет модель и команды.
- Номера: карточки/список, поиск, тип и доступность; все существующие страницы гостиницы, финансов, каналов и маркетинга используют общую систему.
- Новый экран входа, предпочтения и сообщения. Вход явно не создаёт сессию до подключения auth. Сообщения сохраняют только черновик в памяти вкладки. Помощник отвечает готовой сводкой данных, свободный LLM-диалог пока не подключён.

## Границы

API не передаёт время каждого ожидаемого заезда, полную историю переписки или статус auth; UI не придумывает эти сведения. Карточки номерного фонда используют статус доступности на сегодня; готовность уборки уточняется в карточке единицы. Список гостей по умолчанию показывает заказчиков из 25 последних подходящих броней, глобальный поиск гостей сохранён. Полноценные редакторы акций/фото/удобств отсутствовали и остаются отмечены как неподключённые.

Цифры dashboard обозначают размещения и единицы продажи: 16 ROOM и 72 BED — 88 единиц, это не то же самое, что число физических гостей. Бизнес-правила, деньги и схема данных не переписаны ради макета.

## Проверка

Результаты финальных запусков и скриншоты добавляются после завершения проверки. Unit/изолированный UI не заменяют интеграционную проверку реальной БД и провайдеров.
