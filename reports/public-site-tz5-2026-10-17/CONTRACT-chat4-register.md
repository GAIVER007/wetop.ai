# Контракт кнопки «Начать работу» для чата №4 (авторизация)

Сайт форму регистрации не реализует заново: кнопка открывает существующее окно `apps/site/src/components/auth-dialog.tsx`,
окно шлёт запросы в стойку. Ниже то, на что сайт опирается; меняет это только чат №4.

## Кнопка

- Ссылка `<a data-auth="register" href="https://wetop.ai/?vertical=<VERTICAL>#register">Начать работу</a>`
  (`lib/site.ts` → `registerLink(undefined, vertical)`). На страницах салонного направления `vertical=BEAUTY`,
  гостиничного `HOSPITALITY`, ресторанного `FOOD_SERVICE`; на главной без `vertical`.
- Щелчок перехватывается, открывается окно в режиме регистрации; `#register` в адресе тоже открывает окно.
- `vertical` только подсказка: в окне заранее выбран этот тип бизнеса, человек может выбрать другой.
  Организацию, роль и права страница не создаёт.
- Без JavaScript: `https://app.wetop.ai/auth/fallback?mode=register` (запасная страница стойки).

## Запросы окна (стойка `https://app.wetop.ai`, `credentials: 'include'`)

| Шаг | Запрос | Ответ, который ждёт сайт |
|---|---|---|
| Открытие окна | `GET /api/site-auth/options` | `{ registrationEnabled: boolean }`; `false` → форма не показывается, окно зовёт написать |
| Создание аккаунта | `POST /api/site-auth/register` | 200 `{ email, sent: true }`; ошибка: любой не-2xx с `{ message }` |
| Повтор письма | `POST /api/site-auth/resend` `{ email }` | 200; не чаще раза в минуту (кнопка ждёт) |
| Вход | `POST /api/site-auth/login` | по контракту чата №4 |

Тело `register` (проверено тестом `auth-dialog.spec.ts`):

```json
{ "email": "…", "name": "…", "businessName": "…", "vertical": "BEAUTY",
  "password": "…", "phoneCountry": "KZ", "phone": "…", "privacyAccepted": true, "locale": "ru" }
```

## Состояния окна

- **Успех:** только после ответа 200 от `register`: заголовок «Проверьте почту», адрес почты, повтор письма с паузой.
- **Ошибка стойки:** текст `message` из ответа в `role="alert"`, окно остаётся на форме, «Проверьте почту» не показывается.
- **Стойка недоступна:** текст о сети и ссылка на запасную страницу `…/auth/fallback?mode=register&vertical=<VERTICAL>`.
- **Без согласия с политикой** или пустые поля: запрос не уходит, окно говорит, что заполнить.

## Что проверено, а что нет

- Проверено с **подставным** обработчиком (`tests/site/auth-dialog.spec.ts`): главная → «Для салонов красоты» → «Спа»
  → «Начать работу», выбран BEAUTY, ответ 409 даёт ошибку без ложного успеха, повтор с 200 даёт «Проверьте почту».
- **Не проверено:** настоящая регистрация в стойке, письмо, подтверждение почты, первый вход.
  Статус: «переход и окно проверены с тестовым обработчиком», не «регистрация работает на production».
- Нужна общая проверка на одном кандидате сайта (`claude/public-site-tz5`) и кандидате авторизации чата №4,
  без второй реализации формы.

## Условие, которое касается регистрации

Владелец 17.10.2026 утвердил **пробный период 7 дней**. Продукт приведён к ним PR #619 (`TRIAL_DAYS = 7`,
ADR-TRIAL-7-DAYS-20261017); `/terms/` говорит 7. Организации, созданные до слияния, сохраняют прежний срок.
Сайт сроков в кнопках не печатает (ADR-147).
