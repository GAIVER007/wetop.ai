# Закрытие самостоятельной регистрации — 20.09.2026

Владелец подтвердил временное ограничение по Q-152. `POST /auth/register`
возвращает 403 до обращения к БД, если API явно не запущен с
`SELF_REGISTRATION_ENABLED=1`. Пустое значение, `0`, `true` и `yes` не включают
регистрацию. Стойка получает состояние от `GET /auth/options` без кэша.
Отказ API, повреждённый JSON и неполный ответ оставляют регистрацию закрытой.

На `/login` нет предложения создать организацию; `/register` и
`/login?mode=register` показывают вход сотрудников и причину ограничения.
Ранее открытая форма тоже получает серверный отказ, cookie сессии не создаётся.
Вход, приглашения, восстановление пароля и управление сеансами сохранены.
Схема БД, деньги, бронирования, доступность и production-интеграции не менялись.

## Оставшиеся ограничения

- Это ограничение новых регистраций, **не tenant isolation**. Существующие
  организации и сессии не разделены и не отозваны. Q-152 остаётся открытым.
- [Аудит lockfile](dependency-audit.json): 7 уведомлений по пакетам (5 high,
  2 moderate, 0 critical), включая агрегаты Prisma. Новых зависимостей нет;
  lockfile не менялся. Цепочки и условия достижимости ранее описаны в
  [разборе зависимостей](../ui-quality/DEPENDENCIES.md). Автоматический downgrade
  Prisma/ExcelJS, предлагаемый `audit fix --force`, не применялся.
- Выкладка на сервер не выполнена: 20.09.2026 SSH к существующему серверу WETOP
  на порту 5555 отверг доступный ключ (`Permission denied (publickey)`).
  Профиль другого сервера с n8n не используется. Push/merge не считаются деплоем.
  Порядок безопасной выкладки и ограничение отката — в [docs/deploy.md](../../docs/deploy.md).
