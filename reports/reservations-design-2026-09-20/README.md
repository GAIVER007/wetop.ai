# Брони — дизайн и проверки, 20.09.2026

План: `plans/reservations-design-2026-09-20.md`. Решение: ADR-059.

## Что изменено

Единая панель поиска, дат и статусов; текущий статус обозначен aria-current.
На телефоне все статусы доступны через select, без скрытых за краем вкладок.
Фильтры и пагинация используют прежние параметры URL и серверный API.

В таблице выделены имя и номер брони, даты и ночи, место, источник, статус,
стоимость и остаток. На планшете строки складываются в две колонки карточек,
на телефоне — в одну. Повторного вывода DOM или клиентской копии данных нет.
Бронь открывается прежней ссылкой в панели, деньги используют прежние компоненты.
Новых полей, подсчётов KPI, API и изменений БД нет.

`before-*` — исходный вид, `light-*` / `dark-*` — итоговый интерфейс на пяти
ширинах: 1440, 1024, 768, 390 и 320 px. Все данные на снимках вымышленные.

## Push и deploy

Поручение выполнять push/deploy после завершённой правки закреплено в AGENTS.md §18.
Для этой задачи доступ к действующему серверу проверен до реализации:

- Документированный ключ `~/.ssh/pms_lux_hostinger` отсутствует.
- Управление Chrome вернуло `Computer Use permissions are not granted`.
- Владелец получил запрос включить доступ к панели Hostinger либо настроить SSH.

Следовательно, публичная выкладка этим отчётом **не подтверждается**. Рабочий
сервер, указанный в `docs/deploy.md`, — 187.77.145.152, клон `/root/wetop`, Compose
`pms-lux`. Старый Mac-туннель и соседний сервер с n8n для обхода не используются.
Перед выкладкой нужно проверить фактическое состояние, сохранить образы для
отката и применить текущий main к API/web, сохранив env, ARI и cloudflared.
Сравнение с последним документированным серверным commit 2de53a3 не содержит новых
миграций; это не заменяет проверки фактического SHA сервера перед deploy.
