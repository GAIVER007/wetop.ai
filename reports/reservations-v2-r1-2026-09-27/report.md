## Что изменилось против редакции 21.09

- Панель фильтров: большая карточка (поиск, «С», «По», «Показать», два ряда чипов со словами
  «Период»/«Статус») → две компактные строки: поиск + отрезки + «Даты» (раскрывает «С/По») +
  «Показать»; ниже чипы статусов с числами. Таблица начинается в первом экране (§66.1–2).
- Колонки: Гость / Источник / Место / Проживание / Статус / Стоимость / К оплате →
  **Бронь / гость → Проживание → Размещение → Источник → Финансы → Статус** (§10 ТЗ).
- «Стоимость» + «К оплате» слиты в «Финансы»: стоимость и состояние по счетам. У отменённой брони
  больше не бывает зелёного «оплачено» при пустом счёте: теперь «—», «к возврату N ₸» или
  «возвращено» — по данным Folio/Payment/Refund (§15–16, `finance-state.ts` + юнит-тесты).
- Статус в строке — слово о брони в единственном числе («подтверждена», «проживает», «отменена»…);
  чипы фильтра остаются во множественном («Проживают 6»).
- Пометки «заезд сегодня» / «выезд сегодня» — вычисляемые, без новых статусов в модели (§12, §54).
- «N размещений» у групповой брони (§23); частично назначенная — «⚠ K без размещения» с числом
  (формулировка владельца 27.09); одиночная без ячейки — «⚠ без ячейки» словом DESIGN.md §9.
- Кнопка WhatsApp из строки снята (§11) — меньше шума и экспозиции ПД; телефон в карточках.
- Плотность «Обычно / Компактно» (localStorage), липкая шапка таблицы, карточки ≤1200 px под шесть
  колонок.
- API `GET /hotel/reservations`: в строку добавлены только поля проекции `chargedMinor`,
  `refundedMinor`, `itemsCount` — уже считались, не отдавались. Схема, команды, финансовая логика,
  пагинация не тронуты (§66.22–25, 29). Серверная пагинация и один запрос без N+1 — были, аудит §57
  в плане среза.

## Что осталось за срезом (по ТЗ §65)

R2 — фильтры (источник/оплата/размещение/семантика даты), `?view=…`, сортировки; R3 — quick preview;
R4 — действия по статусу; R5 — карточка; R6 — «удержан штраф» и подача возвратов; R7 — связки с
Главной/шахматкой/гостями; R8 — производительность и доступность сверх текущего. Быстрые виды
«Будущие» и «Требуют внимания» появятся в R2 вместе с поддержкой API. Trial READ_ONLY закрыт в
`main` (Q-144 — Б, ADR-102): полоса и запрет записи — общий механизм; «Брони» при «только чтении»
прячут «Новую бронь» и остаются читаемыми целиком (тест и снимок `read-only-1440.png`).
