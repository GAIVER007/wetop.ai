# Обнуление базы и проверка Channex после переезда на сервер

19–20.09.2026. Решения: ADR-052 (Exely больше не источник, база обнулена), ADR-053 (вход по паролю).
Выполнял владелец по командам агента; проверки в базе и в браузере — агент.

## 1. Проверка связи с базой (прямыми запросами к Supabase)

Проект `bobbkvlnjppvqwrpzmvz`, `ap-southeast-1`, PostgreSQL 17, healthy. Через Session pooler занято
11 клиентов из 15 (API 5 + служебные), все простаивают; с Mac подключений нет. Запас есть, но разовые скрипты —
только с `DATABASE_POOL_MAX=1`.

## 3. Channex после очистки — работает, доказано живьём

- Полная выгрузка: 200, `availabilityValues: 5, restrictionValues: 20`, окно 20.09.2026–01.02.2028;
  очередь через 30 с — `pending 0, failed 0`.
- Пробный вызов webhook: Channex → `https://api.wetop.ai/channels/channex/webhook` → 200, «секрет принят».
  **Первый успешный вызов с 16.09** — до переезда туннеля не было.
- Живой круг (`cli-channex-wetop-cycle.ts`, staging, гость вымышленный):
  остаток до брони PMS 36 = Channex 36 → бронь Booking.com `BDC-WETOP-MU9GFRA8` (10→11.10, категория
  `exely-5074688`) пришла в PMS **за 6 с** → карточка: OTA, Booking.com, CONFIRMED, ячейка 5 → остаток
  35 = 35 → отмена из канала дошла **за 5 с** → остаток 36 = 36.
- Две проверки скрипта по экранам стойки — FAIL с HTTP 200: скрипт ходит без сессии и получает страницу
  входа. Это следствие включённого замка (ADR-053), не дефект; скрипту нужен вход по служебному ключу или
  сессия — отдельная правка. Запись отчёта упала на `EACCES`: файловая система образа только для чтения,
  отчёт писать в примонтированную папку — тоже отдельная правка.

## 4. Что осталось

1. Снять Cloudflare Access с `app.wetop.ai` (приложение `wetop-desk` в Zero Trust) — иначе два входа подряд.
2. Ключ почтовой службы в `.env` — без него `accounts invite` печатает ссылку вместо письма.
3. `CUTOVER.md`: условие 2 («двойной ввод сменой») переформулировать — сверять с Exely больше нечего.
4. Код Exely (импорт, `cli-sync-day`, проверка `exely.stale`) — не удалён; удалять отдельным решением,
   импорт из дампа может ещё понадобиться.
5. Сессия входа по паролю живёт 12 часов (ADR-049) — владелец вошёл 19.09 вечером, к утру 20.09 разлогинен.
   Если это мешает — обсудить срок.
