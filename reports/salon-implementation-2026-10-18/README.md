# Салон: перенос черновиков, первый проверяемый срез

## Объём

Владелец утвердил перенос черновиков салона по этапам. Это не закрытие всех сценариев: реестр `scope-register.json` содержит 94 уникальных сценария и ссылки на три исходниковых аудита. Отдельно отражены отсутствующие сущности/API и вопросы правил, которые нельзя выводить из демонстрационных цифр.

База первого среза: main `8a5ab9480109ca7881df6d7a856b1a17cea135d9`. Ветка `feat/salon-draft-implementation-20261018`. Используется прежнее дерево, не новая копия проекта.

## Реализовано

- `/reports` салона теперь отдельный серверный экран вместо редиректа в краткую аналитику.
- Обзор, услуги, специалисты и статусы. Период передаётся URL-параметрами и сохраняется при переключении вкладок/перезагрузке.
- Полная детализация услуг/специалистов вместо top-5; завершённый визит считается один раз на строку детализации, многострочные визиты не задваиваются.
- Используется существующий `branchReportDay` → защищённый beauty API. Нет новых таблиц, SQL/миграций или новых финансовых правил.
- Стоимость завершённых услуг не обозначается оплатой/прибылью/зарплатой. Валюты раздельны, формат учитывает JPY/KWD; вычисления BigInt.
- Текущее ограничение до 31 дня, scope/timezone/day проверяются, частичный результат при ошибке дня не выводится.
- Календарные пересечения через полночь отбираются по локальной дате начала. Исторический специалист берётся из строки визита при отсутствии в активных columns.
- Позиционный доступ не расширялся. `pageOpen` запрещает `/reports` не-OWNER в ASSIGNED-режиме до загрузки данных, даже при finance.view/journal.view. Food/Hotel ветки страницы сохранены.
- Исправлены два исходных lint-дефекта merged security-тестов; существующий тест таблицы клиентов приведён к текущему разделению таблицы и инструментов импорта, без ослабления запрета read-only.
