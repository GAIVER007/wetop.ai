# Beauty: текущие исправления и фактические доказательства

База: `445a8fcf6bc0edeffeff935802db216bb1b6e1f5`. Это продолжение реализации, не новый аудит и не заявление о готовности всех94 требований. Production не изменялся.

## Продукт

- Персональные цена и длительность выбранного специалиста уже опубликованы в445a8fcf6: публичный профиль → слоты → сохранённая запись. Предыдущие19 unit и12 реальных DB-проверок относятся к отдельному законченному срезу.
- Локальная проверка CSV доступна сотруднику через существующий инструмент клиентов. Готовые строки, повторы и ошибки вычисляются без записи клиентов. Флаг `canImport` по-прежнему ограничивает долговременные import jobs владельцем; права существующего legacy-импорта500 строк этим исправлением не переопределяются.
- Подсказка запрета ранней неявки использует реальный `canUpdate`, передаваемый журналом. Явный запрет имеет приоритет над устаревшим `canEdit`.

## Схема, безопасность и восстановление

- Десять таблиц ordinary133–137 внесены в явный канонический перечень tenant-таблиц. Проверки не исключают неизвестные таблицы по префиксу. FORCE RLS и отсутствие доступа к чужой организации проверены отдельно; оставшийся held-пакет сохраняет all-or-none контроль.
- В137 закреплён search_path двух пропущенных helpers расписания. Тела и финансовые правила функций не изменены. SHA-256 в manifest пересчитан по действительным байтам. Из первоначальных10 SQL изменены только down135 и up137; восемь остальных совпадают с4eae8954 побайтно. Историческая и текущая ситуации различены в runbook.
- Restore восстанавливает точные ограничения из mixed-миграций132,134–137 через отдельный ACL-only companion внутри прежней общей транзакции. Это не шестая schema-миграция, DDL повторно не исполняется. Отсутствующий companion и частичный Beauty-пакет закрывают операцию ошибкой.
- Исправлен резолвер Prisma CLI: используется объявленный `package.json.bin`, а не неверный package main `build/types.js`. Алгоритм проверен на действительном пакете7.10.0, совпадающем с lockfile `packages/database/node_modules/prisma`; никаких новых зависимостей не добавлено.

## Synthetic fixtures, не ослабление продукта

- Законные scope-назначения акторов сохраняются один раз при seed. Проверки stale/revoked membership и частичного доступа к филиалам не обходятся.
- Сначала удаляются дочерние appointment_lines в пределах исходного фильтра fixture, затем родительские записи. Никаких отключений FK, триггеров или history guards.
- Проверка старого scalar-exclusion заменена точной проверкой включённого canonical line-trigger, блокировки мастера, полуоткрытого диапазона и отсутствия ограничения по филиалу. Для второго мастера положительный сценарий получает законное назначение услуги.
- При дополнительной проверке обнаружена лишняя скобка, скрытая старым catch cleanup. Catch полностью удалён, ошибка42601 воспроизведена в записанном REDfcd5. После исправления строгий cleanup и все11 сценариев прошли в95d3. Ошибки очистки больше не превращаются в зелёный результат.
- UI-локаторы согласованы с текущими названиями и видимыми карточками. Native drag проверен в обе стороны, assertions сохранены. Timeout/retry/skip и production authorization не ослаблены.
