# Исходниковый review первого среза отчётов салона

**Вердикт: требуются исправления; не является разрешением на merge/deploy.** Проверено только чтением исходников и git diff в `feat/salon-draft-implementation-20261018`. Код, тесты, браузер, процессы, авторизация, сеть и БД не запускались/не изменялись. Создан только этот документ. Заявленные родителем 28 зелёных unit-тестов здесь не перепроверялись. Наличие beauty schema в main не доказывает применение held migrations или работоспособность на runtime БД.

## Обязательные находки

### P1 — Календарный day endpoint не соответствует выбранному правилу периода: переход через полночь ломает весь отчёт

`apps/web/src/app/reports/salon-report-data.ts:51–55` требует, чтобы **каждая** полученная запись начиналась в запрошенный локальный день. Но `apps/api/src/beauty/appointments.ts:204–210` выбирает записи по **пересечению любой строки услуги с сутками** (`startsAt < конец && endsAt > начало`), а не по дате начала записи. Поэтому обычная запись, начавшаяся вчера и закончившаяся сегодня, приходит в сегодняшнем ответе и делает отчёт недоступным. Многострочная запись со строками в соседние сутки имеет тот же эффект. `beautyPeriod` также запрещает повтор ID, поэтому простое удаление проверки дня без нормализации приведёт к повторному падению на периоде из двух дней.

**Исправление:** явно применить правило атрибуции визита периоду (если правило — локальная дата начала, отфильтровать календарные overlap-строки по ней и нормализовать ID до агрегации), либо использовать period/report источник с нужной семантикой. Не ослаблять проверки филиала и timezone. Добавить тесты перехода через полночь, попадания только хвоста в период, многострочного визита через сутки и повторного появления визита в ответах соседних дней. Текущий тест `wrong-day` закрепляет ошибочное предположение об endpoint.

### P2 — Отображение валют жёстко делит любую сумму на 100

`salon-reports.tsx:52,54,65` вызывает `formatMoney`, а `apps/web/src/lib/money.ts:12–14` использует постоянный делитель 100. При этом новый отчёт допускает исторические валюты: `beautyPeriod` проверяет только три заглавные буквы и группирует по валюте. Для валют с 0 или 3 дробными знаками величина на экране будет неверна (JPY/KWD). В существующем `management/analytics/vertical/metrics.ts:69–81` уже есть bigint-safe `moneyText`, учитывающий число дробных знаков валюты.

**Исправление:** использовать currency-aware форматирование либо доказательно ограничить поддерживаемые валюты контрактом валидации. Покрыть не только KZT/USD, но и валюту с отличным от двух числом minor digits. Группировка по валютам сама по себе проблему отображения не решает.

### P2 — Исторические специалисты теряют имя в отчёте

`salon-report-data.ts:9,35` берёт имена только из `day.columns`; day endpoint наполняет эти колонки только **ACTIVE** сотрудниками, назначенными в текущий филиал (`appointments.ts:185–188`). Исторический DONE-визит уволенного/переведённого специалиста остаётся в appointments, но таблица показывает «Мастер» вместо его имени; несколько таких строк визуально неразличимы. Endpoint уже отдаёт `employeeName` в строках (см. `appointmentView` и использование этого поля в `apps/web/src/app/appointments/page.tsx:23–27`).

**Исправление:** брать имя строки услуги/визита как доступный fallback до общего «Мастер». Тест: DONE-визит специалиста, отсутствующего в columns, с несколькими специалистами в items.

## Границы доступа и семантика денег

- Новый серверный guard `salon-reports.tsx:18–20` выполняется до выбора филиала/загрузки данных и использует именно `pageOpen(access, 'reports', '/reports')`.
- `/reports` отсутствует в `BEAUTY_ROUTES`. Следовательно, `navigation.ts:813` закрывает маршрут **всем не-OWNER позициям ASSIGNED**, включая позицию с finance/journal permissions; LEGACY использует старое `reports`. Это не утечка назначенным должностям и соответствует требованию не вводить новые permissions. Не следует «чинить» это добавлением маршрута в finance без отдельного решения и проверки источника.
- `branchReportDay` — не финансовый endpoint: `api.ts:4891` вызывает `/beauty/appointments`, защищённый `journal.view` (`appointments.ts:1107–1109`). Специальный `/beauty/finance/day` имеет отдельный `finance.view` и проекцию без лишних телефонных данных/заметок/деталей графика (`appointments.ts:1096–1118`). Текущая безопасность нового экрана держится на запрете ASSIGNED в pageOpen, а не на том, что branchReportDay якобы авторизует finance amounts. Для OWNER/LEGACY этот срез не расширяет API-права. При будущем открытии позициям finance нужно сменить/обосновать источник, а не снимать guard.
- UI корректно называет суммы стоимостью оказанных услуг из DONE price snapshots; явно не называет их поступлениями, прибылью или зарплатой (`salon-reports.tsx:52,58`).
- Выбранный филиал берётся из `/branches` с совпадением businessId и locationId (`workspace-context.ts:16–21`); backendFetch передаёт оба scope значения. Loader проверяет ответ locationId/timezone/date и не возвращает частичные итоги при ошибке дня.

## Что подтверждено чтением

- `periodDates` проверяет настоящий календарный YYYY-MM-DD, порядок и максимум 31 день. Loader требует точную непрерывную последовательность дат.
- `beautyPeriod` проверяет уникальность ID **всех записей**, неизвестные статусы; для DONE — целые неотрицательные суммы и валюту. Суммы и сравнение line totals вычисляются через BigInt, без Number-конверсии общего денежного значения.
- Многострочный DONE-визит: одна запись в currency totals; каждый item увеличивает services; один визит на каждого уникального специалиста/услугу. Сумма items сверяется с суммой визита.
- Нет top-5/slice: все записи дня запрашиваются без take, все группы выводятся из Map. Пагинации у данного beauty day endpoint нет.
- Статистика сохраняет `/management/analytics` и добавляет `/reports`; ресторанный redirect не меняется. Исходящие ссылки отчёта ведут в аналитику и `/appointments` с from/to; appointments действительно читает эти параметры. Вкладки отчёта сохраняют период. Доступ к назначениям назначениям ссылок по-прежнему должен проверяться целевыми страницами; само наличие ссылки прав не даёт.
