## Что сделано

1. **Дневной предел на гостиницу.** Перед вызовом модели — расход гостиницы за местные сутки (UTC+5)
   из `messages.tokens_used`. Выше `LLM_DAILY_TOKENS_PER_ORG` (по умолчанию 150 000; 0 — выключен)
   модель не зовётся: гостю — «Сейчас не могу ответить, администратор свяжется с вами.», диалог помечен
   «нужен человек» (пометка, бот и дальше отвечает), владельцу — алерт `llm_budget` один раз в сутки
   на гостиницу (ключ алерта несёт дату, окно молчания — сутки). Гостиница со своим ключом (окно
   «Модель») и помощник платформы — без предела. Сбой подсчёта ход не глушит: модель зовётся.
   Файлы: `src/ai/budget.py` (новый), `src/ai/engine.py` (шаг «модель»), `src/config.py`,
   `src/alerts/raise_alert.py`, `src/alerts/dedup.py`.
2. **Второй путь к модели.** `LLM_EMERGENCY_BASE_URL` + `LLM_EMERGENCY_API_KEY`: аварийная ступень идёт
   к поставщику напрямую, мимо роутера, — лёг роутер, аварийная всё равно отвечает. Только на ключе
   платформы; задано одно из двух — предупреждение в журнале и прежний путь. Файлы: `src/ai/llm.py`,
   `src/config.py`.
3. **Отчёт о расходе.** `python -m src.jobs.usage_report --month 2026-09` — по гостиницам: диалоги,
   ответы бота, токены (вход, из него кэш, выход), стоимость по `LLM_PRICES` (за 1 млн токенов
   «вход/кэш/выход», в валюте, в которой записаны цены), признак «ключ сейчас: свой/платформы».
   Помощник в отчёт не входит; текста переписки, имён, телефонов и id гостей в отчёте нет (тест).
   Файлы: `src/jobs/usage_report.py` (новый), `src/ai/budget.py` (месяц по UTC+5).
4. **Разбивка расхода и кэш.** Миграция бота `0005_message_usage` (только добавление колонок, `down` есть):
   у ответа бота — `llm_model`, `tokens_input`, `tokens_cached`, `tokens_output`; `tokens_used` остаётся
   суммой. Каскад складывает разбивку по раундам инструментов. Метка кэша Anthropic на первом системном
   сообщении (правила и профиль гостиницы) — по `LLM_PROMPT_CACHE_MARK`, по умолчанию выключена.
   Файлы: `migrations/versions/0005_message_usage.py`, `src/db/models.py`, `shema-bd.sql`,
   `src/ai/llm.py`, `src/ai/engine.py` (шаг «записать»).

Новые переменные вписаны в шаблон бота `apps/ai-seller/env.example` (правило бота «настройки без строки
в шаблоне не существует» проверяют тесты). Шаблон платформы `.env.example` не тронут: переменные только
у продавца. Включение для владельца — `docs/assistant/README.md` §5 и шаг 13 §6.

- **Метка кэша выключена по умолчанию.** Роутер в шаблоне — polza.ai; понимает ли он `cache_control`

- Ядро (`src/ai/engine.py`) тронуто в двух местах: шаг «модель» (проверка предела до каскада) и шаг

## Замечено рядом — не чинил (правило бота: «скажи, но не чини молча»)

1. **Алерт `llm_down` объявлен, но нигде не выпускается.** Когда все три модели отказали, гость получает
   «администратор свяжется», а владелец — ничего, и диалог не помечен. Правка небольшая (алерт с пределом
   потока + пометка диалога) — по «делай».
2. **Расход виден не весь.** Ход, где ответ не доставлен (канал отказал), в историю не пишется — его
   токены не видят ни предел, ни отчёт; токены неудачных ступеней каскада (модель вернула мусор) тоже
   не считаются. Для цены это небольшой недосчёт; точный учёт — запись расхода на каждый вызов модели
   (новая таблица — решение владельца).
3. **Предел считает весь расход гостиницы за сутки**, включая ответы на её ключе, если партнёр снял ключ
   посреди дня. Это строже, а не мягче; какой ключ платил за прошлый ответ, база не хранит (ещё одна
   колонка — решение владельца).
