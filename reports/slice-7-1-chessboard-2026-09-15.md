## 2. API — только чтение существующих данных (план §2)

`GET /chessboard` (`packages/domain/src/chessboard/build.ts`, `apps/api/src/chessboard/*`):

| Поле | Откуда | Тест |
|---|---|---|
| `cell.source`, `cell.channel` | `Reservation.source`, `Reservation.channel` | `build.test.ts` «клетка проживания несёт канал…» (красный → зелёный) |
| `cell.balanceMinor` (тиыны строкой) | `Folio` проживания: `charges` (без сторно), `allocations`, `refunds` → `folioBalance` из домена финансов | `stay-facts.test.ts` (красный → зелёный: сторно не считается, без счёта поля нет) |
| `row.unit.housekeeping` | `InventoryUnit.housekeepingStatus` | `build.test.ts` |
| `unassigned[].guestLabel`, `source`, `channel`, `balanceMinor` | заказчик брони, счёт | `build.test.ts` |

Репозиторий берёт счёт одним `include` на выборку (без N+1). Модель данных не менялась. Деньги — integer
minor units, арифметика — та же функция, что у `/finance/*` (ADR-008). Попутно записанное про `apps/api/src/hotel/reservation-directory.ts:132` **оказалось ошибкой разбора**
(проверено 15.09 срезом 7.4): `voided: false` там стоит потому, что сам запрос уже отбирает `charges`
с `voidedAt: null`, — сторнированные начисления в баланс списка не попадают. Дефекта нет.

- Живые сквозные тесты (`tests/e2e/chessboard*.spec.ts`): нужна dev-база. Изменения в них: сверка по
