# Сквозная проверка WETOP — 14 сентября 2026

## Результат и исправление

Основные рабочие операции проходят через **Next.js → server actions → NestJS → Prisma → Supabase**. В live-проверке используются настоящие таблицы и закоммиченные записи, а не fixture API. Отдельное чтение созданной брони обычным API на 3001 подтвердило, что обычное приложение и проверка используют одну базу.

Обнаружена и исправлена потеря ввода оплаты при обновлении счёта. Изменение `folio.balanceMinor` пересоздавало форму: сумма и примечание стирались. В live-прогоне вместо введённых 1,25 ₸ записался полный остаток синтетического счёта; тест остановился и ошибочная тестовая запись была удалена после проверки её принадлежности прогону. Существующие платежи не затрагивались. Независимый UI RED воспроизвёл замену 1,25 на 15 000,00. Теперь введённые поля сохраняются; нетронутая сумма продолжает следовать остатку. Расчёт и backend-запись финансов не менялись.

Сам live-набор не подменяет БД. Для исключения влияния на каналы он запускает отдельный экземпляр того же API, где заменён только ARI publisher; фоновые операции, внешние ключи и команды провайдеров отключены. Не запускается общая e2e-уборка, которая может отправлять ARI. Инструкция: [tests/live-system/README.md](../../tests/live-system/README.md).

## Channex и источник данных

Прямой GET диагностики обычного API вернул **READY**, `environment=staging`, объект доступен; 5 сопоставленных категорий, 10 тарифов. Это проверка доступа чтением, а не доказательство production-синхронизации. Последнее входящее webhook-событие на момент проверки: 2026-09-13 19:25:21 UTC. В `npm run dev` фоновые pull/outbox/full-sync/webhook-health/guard по ADR-038 выключены. Наличие ключа и READY не означает, что локальный процесс сам непрерывно импортирует новые заказы.

Supabase REST-ключи не используются вместо серверной PostgreSQL-связи: рабочие репозитории используют `DATABASE_URL`. Секреты находятся в игнорируемой `.env`; на другом компьютере нужен тот же проект GitHub и собственная приватная конфигурация подключения к этой же базе.

| Структура номеров и категорий | Реальный импортированный фонд доступен для чтения; редактора структуры нет |
| Настройки гостиницы, заезды/выезды, штрафы | Реальные настройки читаются; редакторы политики/расчётного часа не реализованы. Не путать с работающими командами заселения/выселения брони |
| Каталог услуг | Читается из БД, существующую услугу можно начислить на счёт; редактора каталога/цен нет |
| Фото, описание и удобства | Нет полноценного редактора/хранилища медиа. Решение читать контент Channex зафиксировано в Q-125, но текущие страницы не реализуют весь этот поток |
| Сообщения | Только черновики в памяти текущей страницы, явно обозначенные в UI. Не сохраняются в Supabase; отправка не подключена |
| Акции и маркетинговые рассылки | Модель скидок, кампаний и отправок не реализована; интерфейс честно обозначает недоступность |
| Вход и роли | Реальной авторизации и проверки прав пока нет; API слушает loopback. Q-061…064 и модель доступа остаются отдельным этапом |
| Аналитика сайта | Сайты и отчёты используют БД; работа счётчика на внешнем сайте требует опубликованного HTTPS API и установки кода |

Эти ограничения не скрываются фиктивным «сохранено» или локальными данными. Для новых сущностей/правил остаются решения в QUESTIONS.md и утверждение модели по AGENTS.md §2. Аудит не равен завершению всех перечисленных будущих модулей, cutover в production или нагрузочному тестированию.
