# Восстановление UI-FIX-01

Кандидат находится в технической ветке `codex/ui-fix-01-20261012`, draft PR https://github.com/GAIVER007/wetop.ai/pull/431.

Для восстановления используйте отдельный clone, затем `git checkout` точного SHA из candidate.json. Не меняйте общий рабочий checkout и не запускайте проверки на общей dev-базе.

`npm ci --no-audit --no-fund` и `npm run generate -w @pms/database`. Runtime-инструкция: tests/ui-fix-01-runtime/README.md. Нужны собственный loopback PostgreSQL 16, pms_test и wetop_app. Почта подставная; SQLite KB и fake embedder локальны; ML и внешние AI не используются.

UI отказов использует tests/ui/playwright.alt.config.ts и собственные порты. Перед браузерными тестами проверьте свободные порты и замки. Не удаляйте чужие замки и не прерывайте процессы.

Артефакты CI доступны по ссылке в candidate.json. `before` и `after` из Linux capture сравнивают одинаковые маршруты, темы и размеры на двух SHA. Runtime before/after означают состояние данных до/после действия на кандидате, а не код старого и нового релиза.

Сверка файлов: `shasum -a 256 -c SHA256SUMS`. Не восстанавливайте .env, cookies, трассы или реальные данные из артефактов: они не входят в пакет.

Для восстановления содержимого без истории используйте candidate.diff на чистом checkout diffBaseSha (интегрированный main) из candidate.json: `git apply --index candidate.diff`, затем `git write-tree`. Полученный tree должен совпасть с treeSha в candidate.json. Такой новый commit будет иметь другой SHA; принимающая CI-ссылка относится только к исходному точному candidateSha. Для точного SHA используйте checkout из опубликованной технической ветки. candidate.patch является точной копией binary diff, применяется через git apply, а не git am. История и метаданные авторов не экспортируются в архив. Для истории используйте опубликованную техническую ветку. Исходное воспроизведение и before-снимки относятся к targetMainSha; diffBaseSha отдельно указывает основание восстановительного патча.

Исторические PNG дедуплицированы по точному SHA256 только в передаваемой копии. После распаковки выполните `python3 restore-historical-images.py /путь/к/отдельной/папке`, если нужны исходные пути всех попыток. Скрипт проверяет SHA256 и не перезаписывает отличающиеся файлы. Исходные снимки рабочей сессии сохранены отдельно без удаления.
