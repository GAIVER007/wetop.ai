## D-01 [P2] Ответ PATCH после очистки даты рождения возвращает прежнюю дату

Статус: production-static. Доказательство по точному коду production, runtime-мутация не выполнялась.

Условие: у клиента есть birthDate, PATCH передаёт `birthDate:null`. Домен принимает null. Сервис сохраняет null, но формирует ответ через `b.birthDate ?? found.birthDate?.toISOString().slice(0,10) ?? null`. Поэтому ответ содержит прежнюю дату, хотя БД очищена. Это несогласованный API-контракт. Текущий drawer делает refresh и не использует возвращённую дату, поэтому видимый сбой drawer этим пунктом не утверждается.

Доказательство: [food.service.ts, строка 384](production-delta-sources/apps/api/src/food-service/food.service.ts:384), доменная проверка [customer-marks.ts](production-delta-sources/packages/domain/src/food/customer-marks.ts). Исправление должно различать отсутствие поля и явно переданный null; нужен отдельный API-тест очистки. В этом аудите код не исправлялся.
