## Салон с реальной БД: каскад fixture и ограниченный повтор

Первый прогон: 0 passed, 11 failed, 4 служебных capture skipped из 15. Первый сценарий действительно создал услуги, мастера и запись через UI. Серверные actions создания и переноса вернули сообщения об успехе. Тест остановился на `toBeHidden()` окна переноса с лимитом 5 секунд, окно оставалось видно.

Следующие десять failed происходят при подготовке, не являются десятью независимыми ошибками салонных экранов. Playwright после failed завершает worker и выполняет afterAll. `beauty.spec.ts:98-100` вызывает cleanup; fixture удаляет собственные Organization/User (`fixture-api.ts:161-183`). Повторный cleanup также получает `No record was found for a query`.

Для проверки оставшихся действий выполнен ограниченный повтор 11 сценариев по одному: для каждого свой новый fixture-сервер и собственная синтетическая организация, исходные тесты и API не изменяются.
