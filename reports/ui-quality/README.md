# Проверка WETOP — 13 сентября 2026

Проверен существующий frontend, настоящий Next.js, маршрутизация, server actions и изолированный API на loopback. Использованы только вымышленные гости. Production БД, Channex, OTA и финансовые провайдеры не изменялись.

## Исправления

- Повторяющиеся query-параметры больше не обрушивают поиск гостей и журнал. На границе всех страниц параметры нормализуются: берётся первое значение, как у URLSearchParams.get. Неверные даты, статус и номер страницы оставляют доступную форму и ссылку сброса.
- Неверный месяц тарифов не отправляется в API; массовый редактор не появляется с повреждённым контекстом. Диапазон шахматки ограничен существующим `MAX_CHESSBOARD_DAYS` из domain. Пустые поля дат получают согласованные значения.
- Увеличен слишком мелкий текст интерфейса. Цвета ссылок, статусов и вторичного текста проверяются на светлых, тонированных и тёмных поверхностях. Удалены белые фоны в тёмной теме. Поля на телефоне имеют 16px; диапазон шахматки перестроен в две колонки, пятая карточка показателей занимает всю строку. Safari отдельно не проверялся.
- Таблицы с горизонтальной прокруткой доступны с клавиатуры. Подписаны поля дат, тарифов, назначений, начислений, оплат и возвратов. Увеличена область кнопки показа пароля.
- Команды проживания, отмены брони, сторно, дополнительных услуг, закрытия счёта и удаления документа защищены от повторного вызова во время запроса. Ошибка транспорта отображается без автоматической повторной отправки финансовой команды.
- Локальные данные списка, карточки гостя, брони и номера теперь используют разные устойчивые идентификаторы. Создание в демонстрации возвращает введённые данные новой брони. Уборка и блокировки относятся к выбранному номеру. Оплата отображается строкой счёта. Это состояние в памяти демонстрации, не подтверждение операции в рабочей БД. Демо не воспроизводит все бизнес-ограничения; настройка сайта в fixture представлена одной записью.
- Исправлен воспроизведённый сброс полей после отказа server action: оплата, начисление, возврат, заметки брони, даты, состав гостей, назначение места, профиль и документ гостя, блокировка номера, добавление сайта. Возвращаются только известные текстовые поля формы; успешное сохранение очищает состояние ошибки. Финансовые правила не изменены.
- Отсутствующие внешние страницы демо счётчика и виджета больше не открывают 404; в их месте показан статус подключения.
- Длинный прогон воспроизвёл смену суток в Алматы: reset тестового источника теперь создаёт записи на актуальную дату, вместо даты старта процесса. Финансовые/операционные даты рабочего backend не менялись.
- Скрипт демонстрационного API включён в TypeScript-проверку. Некорректный запрос больше не завершает весь процесс просмотра.

## Что нельзя считать проверенным

Без рабочего backend нельзя честно подтвердить эксплуатационную готовность Channex/OTA, оплат/возвратов, авторизации и разграничения прав. Изолированные проверки не доказывают нагрузочную устойчивость БД, многопользовательскую конкурентность и доступность внешних сервисов. Отсутствующие редакторы и транспорты перечислены выше, а в интерфейсе обозначены как неподключённые.

Запуск: `npm ci`, генерация Prisma по инструкции корня, затем `npm run dev:demo` → http://127.0.0.1:3000/chessboard. Демонстрация работает только в development на loopback; состояние теряется при перезапуске. Обычный frontend продолжает использовать настроенный APP_API_URL.

## Review

Проверка выполнена по пяти направлениям: корректность, читаемость, архитектура, безопасность и производительность. Новые общие функции ограничены нормализацией query, возвратом разрешённых текстовых полей и блокировкой команд; API-контракты и domain-правила сохранены. Синтетические данные не вынесены в production-клиент. Клиентская блокировка повторного клика не заменяет серверные транзакции и идемпотентность. Изменение демонстрации — отдельная группа файлов для review, без правок БД или внешних интеграций.

Проверка не закрывает отсутствующие продуктовые возможности: авторизацию/роли, рассылки, загрузку фото, акции, постоянное хранение черновиков, LLM и production-провайдеры.
