# Приёмка общей главной: обязательные сквозные сценарии

Это критерии выпуска, не выполненные проверки. Применяются к одному и тому же протестированному commit; отчёты прежних макетов не заменяют эти сценарии.

## Деньги и выплаты

- [ ] Документ100000, первая оплата40000: оплаченные расходы40000, долг60000. Цифры здесь иллюстрируют сценарий в minor units, не данные бизнеса.
- [ ] Вторая допустимая частичная оплата уменьшает тот же долг, категория на главной учитывает обе уникальные операции.
- [ ] Повтор одного idempotency key возвращает тот же результат без второй кассовой операции; иной payload с тем же ключом отвергается.
- [ ] Два параллельных запроса не могут оплатить больше долга. После конфликта нет orphan cash/payment/settlement.
- [ ] Старый экран приёмки и новый документ видят одинаковый оплаченный остаток. Связь требует BarSupplierPayment именно данной приёмки.
- [ ] Нельзя связать чужую кассовую операцию, входящую оплату, перевод, VOIDED или источник другой валюты.
- [ ] Повторно привязать одну операцию ко второму документу невозможно даже прямым SQL.
- [ ] Отмена выплаты отражается и в документе, и в кассе; запрещено молча менять сумму/дату проведённого документа.
- [ ] Сумма категорий равна расходам по валюте. Неклассифицированные расходы видимы, не теряются.
- [ ] Ни себестоимость, ни бюджет маркетинга, ни сумма закупки не прибавляются к кассовым расходам.
- [ ] Валюты выводятся отдельно. Недоказанная историческая валюта означает PARTIAL, не ноль и не подстановка текущей валюты.

## Периоды и источники

- [ ] Все карточки и графики используют один generatedAt и timezone выбранного филиала.
- [ ] today = начало местных суток до generatedAt, week = шесть предыдущих местных дат плюс сегодня, month = начало календарного месяца до generatedAt.
- [ ] Проверены полночь, граница месяца, DST и записи ровно на границе.
- [ ] График и карточка сходятся по каждой валюте и типу метрики. Сравнение использует равную временну́ю отсечку, не полный прошлый день против части сегодняшнего.
- [ ] Салон: выручка по DONE снимкам цен, оплаты отдельно. Выборка полная, не первая страница.
- [ ] Ресторан: CLOSED заказы и POSTED продажи бара не смешиваются с оплатами; отдельные источники не удваиваются через кассу.
- [ ] Гостиница: начисления и поступления читаются только из Property выбранного Location, не LUXX_APARTS_PROPERTY по константе.

## Загрузка

- [ ] Изменение графика мастера завтра не меняет мощность вчера; перенос/отмена записи сохраняют историю влияющих полей.
- [ ] Ресторан: walk-in, посадка по брони, пересадка и освобождение отражаются одним lifecycle, заказ не создаёт дубль посадки.
- [ ] Изменения количества/вместимости столов и доступности номеров не переписывают прошлую мощность.
- [ ] Неделя/месяц: отношение суммарной занятой к суммарной доступной мощности одной единицы измерения, не среднее процентов.
- [ ] Незавершённые/неизвестные участки отражены coverage; нет восстановленной из сегодняшнего состояния «точной истории».
- [ ] Номера, койки, часы мастеров и столо-минуты не смешиваются в общий бессмысленный процент.

## Изоляция и UI

- [ ] Без сессии и без reports API не раскрывает финансы. Подмена location/business/organization в заголовках/параметрах не расширяет scope.
- [ ] Ограниченный сотрудник видит только назначенные филиалы; прямой SQL под runtime ролью проверяет RLS, не только superuser.
- [ ] Один филиал: нет пустого сравнения/лишнего выбора. Несколько: корректная область и сравнение сопоставимых данных.
- [ ] Новое неподдержанное направление не получает гостиничный fallback.
- [ ] Один шаблон главной, Inter, flat surfaces, без кольца и без постоянного sidebar.
- [ ] 320/390/768/1440, обе темы, keyboard/axe, пустой/ошибка/нет прав/частичные данные/наполненный экран.
- [ ] Проверена сверка строки БД → API → видимые значения и график, не только скриншоты.

## Выкладка

- [ ] Unit/integration/API/browser/typecheck/lint/build зелёные на итоговом коде, реальные команды и логи в журнале.
- [ ] Held migration проверена на изолированной PostgreSQL, backup/restore rehearsal и совместимость старого кода доказаны.
- [ ] Production migration только через установленный владельцем узкий helper с утверждённым пакетом или root-терминал владельца; никаких самостоятельно выданных root-прав.
- [ ] Main merge, release-checks, release и фактическая версия контейнеров подтверждены отдельно.
- [ ] На app.wetop.ai после входа показан новый общий экран с реальными ответами. HTTP200/login redirect не является приёмкой функции.
- [ ] Только после этой точки очередь остальных разделов становится следующим активным этапом.
