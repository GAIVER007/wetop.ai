# Срез 9 «Бронирование с сайта» — доказательства, 12.09.2026

План: `plans/slice-9-web-booking.md` (поручение владельца 12.09.2026: «виджет на сайт показывает свободные даты,
с сайта можно сразу бронировать, бронь уходит в систему — делай»). Решение — ADR-026, модель — `DATA_MODEL.md`
§11 v1.2 (миграция `20260912000010_web_booking` применена к dev-БД).

## Что вставить на сайт

Два кода с карточки сайта на `/analytics/setup` (ключ у обоих один):

```html
<!-- PMS: счётчик посещений — в <head> каждой страницы -->
<script async src="https://<адрес API>/a/pms.js" data-site="pms_5f3c9a1b2d4e"></script>

<!-- PMS: виджет бронирования — там, где должна быть форма -->
<div id="pms-booking"></div>
<script async src="https://<адрес API>/w/widget.js" data-site="pms_5f3c9a1b2d4e"></script>
```

Виджет: заезд, выезд, гостей → «Показать цены» → категории со свободными местами и ценой за период →
«Забронировать» → имя, фамилия, телефон, почта, комментарий → номер брони. Бронь сразу в PMS: источник «сайт»,
статус «подтверждена», ячейка назначена, счёт открыт, остаток ушёл в Channex.

## Умолчания (ждут владельца, не блокируют)

- **Q-114.** Бронь с сайта без предоплаты остаётся `CONFIRMED` — как в модуле архивный источник: место снимается сразу, двойной
  продажи между сайтом и стойкой нет. Альтернативы: ждать подтверждения стойкой; автоотмена без оплаты.
- **Q-115.** Уведомление гостю (почта/SMS) — провайдера нет; гость видит номер брони на экране.
- **Q-116.** Языки виджета (KZ/EN), окно бронирования, текст правила отмены.

## Что это даёт

В архивный источник «Модуль бронирования» на объекте не подключён (`docs/retired-source/analytics-2026-09-12.md`), 389 из 390 прямых
броней заводились руками. Теперь бронь с сайта идёт тем же путём, что со стойки, и видна в аналитике с источником
(поиск, соцсети, реклама).
