# Снимки WEB1 «Сайт и онлайн-бронирование» — 27.09.2026

Стоп-гейт WEB1 (ADR-107, план `plans/website-web1-2026-09-27.md`): WEB2 начинается только после визуального «да»
владельца по этим снимкам. Снимал `tests/ui/website.spec.ts` («снимки WEB1»): браузер → `next dev` → подставной API.
Сайт на снимках учебный: без домена он стоит на заглушке `example.invalid`, как боевой «Сайт Luxx Aparts» на
`luxx-aparts.example`; для «подключённого» состояния тест вписывает `luxxaparts.kz` и последнее событие «2 минуты
назад». Числа отчёта — из подставного API, не данные объекта.

| Файл | Что на нём |
|---|---|
| `overview-placeholder-{light,dark}.png` | «Обзор», когда у сайта только заглушка: «Сайт ещё не подключён» и «Подключить сайт» вместо зелёной карточки |
| `overview-{light,dark}.png` | «Обзор» подключённого сайта: домен, «Работает», «Открыть сайт», четыре факта |
| `overview-{light,dark}-390.png` | то же на телефоне |
| `booking-{light,dark}.png` | «Бронирование»: состояние, домен, объект, валюта, тариф; форма и код виджета |
| `analytics-{light,dark}.png` | «Аналитика»: прежний отчёт внутри модуля, без кнопки «Подключение счётчика» |
| `settings-{light,dark}.png` | «Настройки»: домены, счётчик, код под раскрывашкой, «Опасная зона» |
| `integrations-{light,dark}.png` | «Интеграции» без панели «Сайт и бронирования» |
| `menu-{light,dark}.png` | меню: один пункт «Сайт и онлайн-бронирование» в «Продажах», в «Настройках» сайта нет |

Красная полоса «Укажите HTTPS-адрес API» на «Настройках» — от подставного API (адрес кода там относительный);
на сервере с `PUBLIC_API_URL=https://api.wetop.ai` её нет.
