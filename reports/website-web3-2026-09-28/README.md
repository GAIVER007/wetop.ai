# Снимки WEB3 «Сайт и онлайн-бронирование → Бронирование» — 28.09.2026

Стоп-гейт WEB3 (ADR-117, дополнение 28.09; план `plans/website-web3-2026-09-28.md`): WEB4 (воронка и выручка с сайта)
начинается только после визуального «да» владельца по этим снимкам. Снимал `tests/ui/website.spec.ts` («снимки WEB3»):
браузер → `next dev` → подставной API. Учебный сайт начинает с заглушки `example.invalid`, потом тест вписывает
настоящий домен и адрес демо — как у API на сервере.

| Файл | Что на нём |
|---|---|
| `booking-placeholder-{light,dark}.png` | Адреса сайта нет: «Не принимает брони · Нет адреса сайта», «Добавить домен», кнопки демо нет, «Установка виджета» есть |
| `booking-on-{light,dark}.png` | Работает: «Включено», «Открыть демо» и «Установка виджета», «Что увидит гость» по шагам виджета, «Пока не умеет» |
| `booking-install-{light,dark}.png` | Окно «Установка виджета бронирования»: код, место и цвет, проверка, предупреждение о настоящей брони |
| `booking-on-{light,dark}-390.png` | То же на телефоне |
| `booking-off-{light,dark}.png` | Выключено: «Форма на сайте цены не покажет», кнопок демо и установки нет |

Код виджета на снимках — заглушка подставного API (`<div data-booking></div>`); на сервере там настоящий тег с ключом
сайта.
