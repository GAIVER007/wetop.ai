# Свой раннер GitHub Actions на сервере

## Зачем

21.09.2026 выяснилось, что проверки на GitHub не идут вовсе: каждая падает за две секунды с
«The job was not started because recent account payments have failed or your spending limit needs to be
updated». Причина не в коде и не в неудавшемся платеже — в настройках аккаунта стоит **бюджет Actions
$0 со «Stop usage: Yes»**, а включённые в бесплатный план минуты на месяц выбраны ($12 из $12, целиком
на `wetop.ai`). Пока так, «зелёный CI» как условие допуска не работает ни на одной ветке.

На self-hosted минуты **не тарифицируются вообще**. Сервер у нас есть, и он большую часть суток
простаивает: 7 % процессора и 27 % памяти из 8 ГБ на момент разбора.

## Что уходит на свой раннер, а что остаётся

| Задача | Где | Почему |
|---|---|---|
| `lint · typecheck · unit · главная` | свой раннер | базы не нужно |
| `UI · часть 1..3/3` | свой раннер | основной расход минут, базы не нужно |
| `стойка на синтетическом API` | свой раннер | сводная проверка, одна команда |
| `миграции · integration · e2e` | раннеры GitHub | нужен `services: postgres`, то есть Docker внутри раннера |

**Сокета Docker у раннера нет и не будет.** Он дал бы коду из любой ветки права root на машине, где
рядом работают чужие проекты (`vilkabot2`, `traefik`) и боевая PMS. Поэтому задача с базой остаётся на
GitHub и молчит, пока минуты не восстановлены. Это известное ограничение, а не недосмотр.

Раннер один и берёт задачи по очереди: три части UI пойдут друг за другом, а не параллельно. Прогон
станет дольше, но он будет — сейчас его нет совсем.

## Установка (владелец, один раз)

1. Токен регистрации: репозиторий → Settings → Actions → Runners → New self-hosted runner. Со страницы
   нужен только `--token`. Он живёт час и нужен **только при первой настройке**: дальше она лежит в томе,
   и перезапуск контейнера токена не требует.
2. На сервере, рядом с `compose.yml`, файл `.env` (вписывает владелец, в чат не диктуется):

   ```
   RUNNER_REPO_URL=https://github.com/GAIVER007/wetop.ai
   RUNNER_TOKEN=…
   ```

3. Поднять:

   ```
   cd /root/wetop && docker compose -f scripts/ops/ci-runner/compose.yml up -d --build
   docker compose -f scripts/ops/ci-runner/compose.yml logs -f runner
   ```

   В логах должно появиться «Connected to GitHub» и «Listening for Jobs», а в Settings → Actions →
   Runners — зелёный раннер с меткой `wetop`.

## Обновление раннера

GitHub перестаёт принимать раннер, отставший больше чем на один выпуск. Настройка лежит в томе, поэтому
обновление — это пересоздание тома и новая регистрация:

```
docker compose -f scripts/ops/ci-runner/compose.yml down -v
docker compose -f scripts/ops/ci-runner/compose.yml up -d --build   # с новым RUNNER_TOKEN в .env
```

## Безопасность

- репозиторий приватный: чужих форков, которые могли бы запустить свой код на нашей машине, нет;
- нет сокета Docker, нет путей хоста, нет `.env` боевой PMS — только свой том;
- `no-new-privileges`, потолки 3 ГБ памяти и 1,5 процессора, чтобы браузерные проверки не душили стойку;
- раннер работает не от root: `playwright install --with-deps` зовёт apt через sudo внутри контейнера.

## Критерий готовности

В Settings → Actions → Runners раннер зелёный; следующий PR показывает `lint · typecheck · unit` и три
части UI выполненными (не «failing after 2s»), а задача с базой — по-прежнему не запущенной, пока не
решён вопрос с минутами.
