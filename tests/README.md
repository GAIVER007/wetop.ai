# tests

| Папка          | Что покрывает                                    |
| -------------- | ------------------------------------------------ |
| `unit/`        | Функции, доменные правила, расчёты денег и дат   |
| `integration/` | API endpoints, БД, адаптеры интеграций (sandbox) |
| `e2e/`         | Playwright, критичные сценарии стойки            |

Инструменты: Vitest (unit, integration), Playwright (e2e). Запуск: `npm test`, полная проверка: `npm run check`.
Прогоны с записью в журнал, что уже доказано на текущем коде и известные грабли — [`TESTING.md`](../TESTING.md):
`npm run test:status`, `npm run test:record -- <unit|integration|e2e|typecheck|lint>`.
Первый тест — `unit/scaffold.test.ts`: пакеты `@pms/*` резолвятся по имени.

## Правила

1. **Red before green** (AGENTS.md §6): новый bugfix или business rule начинается
   с падающего теста. Тест, который никогда не был красным, не считается доказательством.
2. **No real guest data** (AGENTS.md §8, ADR-010): все тестовые гости вымышленные.
   Запрещено копировать реальные ФИО, телефоны, паспорта, email, документы в fixtures.
3. Минимальное покрытие — 80%, включая unit, integration и E2E.

## Окна дат: у каждого спека свои сутки

Сквозные тесты создают **настоящие брони на настоящих койках** общей dev-базы. Пока окна дат
пересекались, прогон в два воркера падал то на `unit-blocks`, то на `cancellation-penalty`, а
поодиночке каждый был зелёным: два спека занимали одну койку на одну ночь. Теперь у каждого спека
свой отрезок будущих суток — константа `BASE` рядом с его `plus()`:

| Спек                    | BASE | Сутки от сегодня |
| ----------------------- | ---: | ---------------- |
| `check-in-out`          |    0 | +3 … +6          |
| `desk-day`              |    4 | +10 … +11        |
| `desk-tasks`            |    6 | +13 … +16        |
| `finance`               |    9 | +18 … +19        |
| `stay-extras`           |   10 | +21 … +24        |
| `chessboard-drag`       |   14 | +26 … +28        |
| `desk-edit`             |   18 | +30 … +31        |
| `print-forms`           |   18 | +33 … +35        |
| `chessboard-unassigned` |   28 | +38 … +46        |
| `cancellation-penalty`  |   28 | +48 … +52        |
| `full-day`              |   28 | +54 … +55        |
| `unit-blocks`           |   18 | +58 … +60        |

Вне таблицы: `web-booking` бронирует на завтра (+1 … +2) — виджет показывает настоящую доступность,
далёкие даты тут не годятся; `manual-reservation` работает на фиксированных 2027-05-10 … 12.

**Добавляете спек, который создаёт брони** — задайте ему `BASE` за последним занятым днём и допишите
строку сюда. Пересечение поймает `tests/unit/e2e-windows.test.ts`: он читает сами файлы спеков и падает,
если отрезки наложились или у спека с `plus()` нет `BASE`.

## Интеграционные тесты и живая БД

`tests/integration` ходит в dev-БД через пулер Supabase. В `vitest.config.ts` это отдельный проект с
`fileParallelism: false`: параллельные PrismaClient вычерпывают сессии пулера, и 11.09.2026 три файла
отвалились по обрыву соединения, просидев 2,5 часа на таймаутах; по одному проходят за ~2,5 минуты.
Запуск только их: `npx vitest run --project integration`.

Брони автотестов e2e занимают настоящие ячейки и убираются `tests/e2e-teardown.ts` после прогона;
вручную — `npm run e2e:cleanup`.

**Воркеры e2e (12.09.2026).** По умолчанию Playwright берёт половину ядер (здесь 4). API dev-базы в
Сингапуре отвечает ~2 с на простой запрос, и при четырёх параллельных тестах действия форм (server actions)
не укладываются в 30 с ожидания — срывы «Сохраняю…» без ошибки в интерфейсе. Полный прогон гонять так:

```bash
npm run test:record -- e2e
```

Внутри то же `npx playwright test --workers=2`, плюс лог и строка журнала. 31/31 за 13 минут; в четыре воркера
тот же код дал 9 срывов по таймауту.
